# Share Card — OG Fallback Image

The branded 1200×630 social-preview image served for every page that has no cover art of its own
(catalog index, About). Distinct from the **per-game** OG cards, which letterbox the real cover
over a solid brand background — those are generated by
`lib/pukllay_club/catalog/seed/image_pipeline.ex`, this one is a single static asset at
`priv/static/images/og-fallback.webp`, referenced by `lib/pukllay_club_web/seo.ex`'s
`@og_fallback_path`.

## Design Decisions

**Composition is locked by phase 01.8's D-04: isologo + "Pukllay Club" wordmark, one
deliberately-composed image, solid brand-colour background.** Never either transparent isologo
PNG alone on whatever the platform paints behind it. Only two things were genuinely open to the
sketch: the arrangement of mark vs. wordmark, and which ramp step the background should be.

**Winner: centered stacked (variant B), not the header's side-by-side lockup (variant A).** Mark
above, wordmark below, centered as one vertical stack — a poster/splash feel with more vertical
breathing room, rather than a scaled-up copy of the real header's `brand_logo/1` lockup.

**A third line was added beyond the sketch's own scope: a tagline.** Developer-requested during
review, so the fallback card says what the club is and where, not only its name. Verbatim copy:

> Tu club de juegos de mesa modernos — Jujuy

**Background: `--pk-ramp-800`, a deeper step than the per-game cards' `--pk-ramp-600`.** The
sketch offered a live swatch picker across ramp-600/700/800/900 so colour and layout could be
judged independently; 800 won for this larger, text-bearing canvas.

**Use `isologo-dark.png`, the white mark.** The isologo pair is theme-aware and only the white
variant reads on a solid purple canvas — `isologo-light.png` is dark purple and disappears
against it. (Yes, the naming is inverted relative to intuition: `-dark` means "for a dark
background.")

**The card must survive being cropped small.** The sketch renders the canvas at true 1200×630 and
also at realistic platform preview sizes (a ~300px WhatsApp bubble at `300/1200` scale, a ~340px
X/Twitter card) directly below it. A bare 1200×630 image judged in isolation is misleading.

**⚠ The shipped asset's background is now off-hue.** `og-fallback.webp` was baked on 2026-09-12
at `#551670` — `--pk-ramp-800` *as it stood then*, at the old H313.1 ramp hue. Sketch 058 rotated
the ramp to H300 later the same day, moving `--pk-ramp-800` to **`#4A187F`**. Verified: the
shipped file's corner pixel is `#551670` and it has not been rebuilt (`git log` shows one commit,
`6331f9a`). The per-game pipeline *was* updated for the rotation (`@og_card_background` is
`"#7B2DCE"`, ramp-600 post-058). Regenerating this asset at `#4A187F` is an open follow-up. The
tagline colour `#E3D3F0` is stale for the same reason — it was light theme's `--color-base-300`,
now `#DED4F3`.

**Found while grounding the sketch (flagged, not fixed):** phase 01.8's D-07 calls the per-game
letterbox background "the site's existing primary brand colour (`--color-primary` /
`--pk-ramp-600`)" as if those were interchangeable. Since the `260910-l7q` ramp redesign they are
not — dark's `--color-primary` is ramp-600, **light's is ramp-900**. The comment in
`image_pipeline.ex` at the time called `#8C2AB7` "the light theme's `--color-primary`," which is
backwards; nothing rendered wrong (D-07 named the literal hex), but the justification was false.

## CSS Patterns

The canonical pixel source is the sketch's dedicated `export.html`, not its `index.html` preview
(the preview's variant-B frame uses a 28px gap; the export — and the README's own spec — use 20px).
Every value below is the export's:

```css
.og-card {
  width: 1200px; height: 630px;
  background: #551670;                      /* --pk-ramp-800 at bake time; today's is #4A187F */
  display: flex; flex-direction: column;
  align-items: center; justify-content: center;
  gap: 20px;
}
.og-card img.mark {
  width: 190px; height: auto; display: block;   /* isologo-dark.png, white mark */
}
.og-card .wordmark {
  font-family: "Bebas Neue", ui-sans-serif, sans-serif;
  color: #fff;
  font-size: 68px;
  letter-spacing: 0.08em;
  line-height: 1;
  text-transform: uppercase;
}
.og-card .tagline {
  font-family: "Inter", ui-sans-serif, system-ui, sans-serif;
  color: #E3D3F0;                           /* light --color-base-300 at bake time */
  font-size: 27px; font-weight: 400;
  letter-spacing: 0.01em; line-height: 1.3;
  text-align: center;
}
```

Fonts are **self-hosted**, loaded by `@font-face` from `priv/static/fonts/` — the same files the
app serves, so the exported image matches the site's own type:

```css
@font-face { font-family: "Bebas Neue"; font-weight: 400;
  src: url("priv/static/fonts/bebas-neue-400-latin.woff2") format("woff2"); }
@font-face { font-family: "Inter"; font-weight: 400;
  src: url("priv/static/fonts/inter-400-latin.woff2") format("woff2"); }
```

## HTML Structures

```html
<div class="og-card">
  <img class="mark" src="priv/static/images/isologo-dark.png" alt="">
  <span class="wordmark">Pukllay Club</span>
  <span class="tagline">Tu club de juegos de mesa modernos — Jujuy</span>
</div>
```

The wordmark is written in title case in the markup and uppercased by CSS
(`text-transform: uppercase`), matching the header's own treatment.

**Production pipeline:** the HTML above is a *design source*, not a runtime template. The shipped
asset was composited pixel-for-pixel with Pillow (same `isologo-dark.png`, same self-hosted
Bebas Neue / Inter, same 190px mark / 68px wordmark / 27px tagline / 20px gaps), exported as
WebP, and its decoded dimensions verified at exactly 1200×630 through the app's own `image`/vix
library before landing at `priv/static/images/og-fallback.webp`.

## What to Avoid

- Don't serve a transparent isologo PNG as an OG image. D-04 forbids it: the platform decides what
  it composites behind, and the white mark vanishes on a light bubble.
- Don't use `isologo-light.png` on the purple canvas — it is the dark-purple mark, meant for light
  backgrounds, and it disappears.
- Don't reuse the per-game card's `--pk-ramp-600` here just for "one consistent purple." The
  sketch compared 600/700/800/900 at this larger text-bearing size and 800 won; the two card
  families intentionally sit on different steps.
- Don't judge a share card at 1200×630 only. Check it at ~300px (WhatsApp) and ~340px
  (X/Twitter) — that is where a mark-plus-wordmark stack either holds or turns to mush.
- Don't copy the sketch `index.html`'s 28px gap; `export.html` (20px) is what shipped.
- Don't assume `--color-primary` and `--pk-ramp-600` are the same thing when hardcoding a literal
  into an image pipeline. They are equal in dark theme only; light's primary is `--pk-ramp-900`.
  A static social image can't be theme-aware, so name the *ramp stop* you mean, not the role.
- Don't change the ramp's hue without re-baking every static image built from it. This asset is
  already stale for exactly that reason and the staleness is invisible until someone diffs a
  pixel against the live CSS.

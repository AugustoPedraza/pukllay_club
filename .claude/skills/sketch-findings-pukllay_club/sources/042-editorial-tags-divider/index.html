Sketch 042, round 27 (final) — full history (rounds 1-26) in this sketch's README. Round 18 fixed a crash (chevron nested inside a line-clamp paragraph) but left the chevron visually floating at the container's right edge. A/B/C each tried a different PROXIMITY fix but kept the same circular icon-button chrome; D swapped in a text label; E made it truly inline via a float trick — the winning direction. Click the chevron in each to compare collapsed vs. expanded. Toggle 🌙/☀ for both themes.
Winner: Variant E — icon-only, truly inline on the truncated text's last line ("…⌄" flush after the last visible word) via a float trick, real `text-overflow: ellipsis`, justified text throughout. D (icon+label, below text) stays available for comparison but was not picked — round 23 settled that icon-only reads better once paired with real inline placement.

⚠ Known issue, deferred to implementation (not resolved in this sketch): the "…" and chevron's vertical ink alignment was nudged via `transform: translateY(-4px)` on the svg (rounds 25-26) but user feedback after that fix still read it as off. Closing this precisely from a static HTML mockup hit diminishing returns — this is exactly the kind of glyph-metrics tuning that's faster to eyeball directly against the real Phoenix-rendered font stack than to keep iterating blind against a sketch's approximation of it. **When implementing:** re-check that `translateY` value against the real `--font-sans` stack rather than assuming the sketch's number transfers as-is.

B (image-relative) and C (arrows below photo) explored and dropped — see README for the round history. Arrows anchor to the shell's content-width box (dashed lines), not the raw browser viewport — same edge-anchored feel as production today, corrected to the right boundary.
Round-3 diagnosis found the "overlay displays background" complaint was not a stacking/opacity bug — the scrim was verified pixel-correct across 5 viewports. The real cause: .pk-lightbox-img caps at a standalone min(90vw, 60rem) (960px) instead of the shell's own content width, so at wide desktop the photo sits in a small central column with a lot of surrounding scrim — which reads as "not obscuring enough." Fixed here by capping the photo to the shell's own content width, AND anchoring the arrows to that same shell-width box instead of the raw viewport edge — round 1's variant A used the viewport edge and still felt "weird" once the photo shrank to shell width. Separately: mobile's left chevron rendering behind the image (DOM/z-index paint order) is fixed with an explicit z-index on both chevrons.

What changed (round 9): "hashtags look disconnected" persisted at a symmetric 24px/24px even after round 8's CSS fix. Rather than tune one shared value again, the rhythm is now asymmetric — 16px to the description above (the tags describe it, so they sit closer to it) vs. 24px to the divider below (unchanged, they're still a separate zone from what follows). Also added the real "Ver más/Ver menos" toggle so the tag row's position holds up whether the description is collapsed or expanded, not just in the single static state shown before.
What changed (round 10): "Ver más" text replaced with a chevron-only icon button — minimal, and one less piece of colored text right above the tag row. Deliberately built with a plain margin-top, not a negative margin against the flex gap (the exact pattern that broke round 6) — no risk of repeating that bug. Tap target is 32px, not the usual 44px floor: this app already has a real precedent for a smaller de-emphasized icon control in exactly this situation (the footer theme-toggle, shrunk to 28px, footer-scoped) — a secondary, low-frequency control living next to higher-priority content. aria-expanded drives the rotation and stays the real accessible state; aria-label still carries "Ver más"/"Ver menos" for screen readers even though nothing is shown visually.
What changed (round 12): "the font and its spacing should be similar to the description text." Round 5 already tested body-scale hashtags and rejected them — but that was in the horizontal, wrapped-row context; stacked, the calculus is different. Hashtag type now matches .desc exactly (16px/normal/1.5), not the 11px/600 pill-label scale. The stack's internal 4px gap dropped to 0 — with matched line-height, the gap would have doubled up the spacing the line-height itself already supplies. Shape, color, and hover-reveal interaction are unchanged; only the type and internal gap moved.
What changed (round 11): "what if are stacked and with less bottom padding?" Hashtags now render one per line (flex-direction: column) instead of wrapping horizontally, with a tighter 4px internal gap — a vertical stack doesn't need the row's usual 6px wrap-gap. The divider below moved from 24px to 16px, so the stack now sits equally close (16px) to both the description above it and the divider below it, rather than the previous asymmetric 16px/24px split.

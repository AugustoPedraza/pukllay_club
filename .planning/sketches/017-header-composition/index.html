Mobile: theme + social live in the drawer now, not the footer. Search now also works on Detalle.

Round 3 — Winner ★ Selected — refined Round 3

E: Toggle-Out Only, CTA on Landing

Picked as the composition winner. Three refinements from Round 3 feedback, on top of the original E (expandable search, toggle in the footer):

1. The search icon now actually converts into the search field, instead of a separate pill growing next to a trigger that stayed visible. One element (.search-morph) does both jobs: at rest it's a 44px icon circle; on click it's the same element animating its own width open into a 260px pill, with the same magnifying-glass icon settling as the leading icon inside it. Closing reverses the same transform — nothing swaps, nothing appears from elsewhere.

2. Verified on mobile, not assumed: the morph still opens from the same icon, but instead of a fixed 260px pill it expands to a full-width overlay across the header (there's no room for a floating pill at 390px), and the rest of the row (brand text, links) fades to make room while it's open — checked directly via the viewport toggle, not carried over from desktop.

3. CTA is landing-only. "Sumate" no longer renders in the header on any page — Catálogo and Detalle now have zero CTA in the header at all. It only appears in the Acerca de hero (sketch 004's pattern) plus a mobile sticky bar scoped to that page (mirrors 005's per-page sticky bar, same as variant D had it, before D was trimmed). Implementation flag, not resolved here: the real shipped code hardcodes sumate_cta/1 as an always-rendered non-slot specifically to prevent per-page omission (01.1-PATTERNS.md D-05). Landing-only is now the developer's explicit direction for the second time — building this for real means reopening D-05, not just moving a template call.

Round 4 — mobile-specific refinements. Four changes, all mobile-scoped (desktop unchanged): the theme toggle and social icons moved out of the mobile footer and into the drawer (nothing left to change theme requires scrolling to the bottom of the page — the drawer's one tap away); the drawer's nav links gained real list affordance (full-width ≥44px rows, trailing chevron, hover/tap tint) instead of plain underlined text; the active-page indicator now lives ONLY in the drawer (a left accent bar + tint, not a copy of desktop's underline — a vertical list needs its own active language) — confirmed the collapsed mobile header never shows an active state at all, since .links-plain is already hidden there; and search is now available on Detalle too, not just Catálogo — now that it's a 44px icon at rest instead of a permanent box, the original clutter-avoidance reason for restricting it to Catálogo (003/011) doesn't apply the same way, and jumping to search mid-way through a game's detail page is a real use case. Acerca de deliberately still has no search — it's a static page, there's nothing to search there.

What to look for

  • Click the search icon — does it read as one element transforming, or can you still tell it's two things?
  • Switch to mobile and try search again — same morph, full-width this time.
  • Switch pages: Catálogo/Detalle have no CTA at all now; Acerca de has it in the hero, plus (on mobile) the sticky bar.
  • On Detalle, is search now reachable (Round 4)? On Acerca de, is it correctly still absent?
  • On mobile, open the drawer — does the theme toggle and social row feel natural there, and does the active link (left accent bar) read clearly without the footer's help?
  • On mobile, scroll to the footer — does it now feel appropriately light (just the attribution line), with nothing missing that isn't in the drawer?

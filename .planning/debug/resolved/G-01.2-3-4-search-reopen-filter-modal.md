## Resolution

root_cause: "Three separable defects, not one shared root cause (though A and C both stem from the app's 'everything is live, nothing is staged' filter architecture): (A) — an AND-gated pair of client-side state-ownership bugs in lib/pukllay_club_web/components/layouts.ex's .CatalogNav colocated hook: (a1) onDocumentClick unconditionally closes .pk-search-morph on any click outside its DOM subtree, but PukllayClubWeb.FilterModal — whose only trigger (.pk-filter-trigger) is nested INSIDE that same collapsible region — renders its actual modal DOM as an unrelated sibling elsewhere in the page, so the first click on any filter-modal control force-closes the search pill out from under the still-open modal; (a2) closeMorph() is purely client-side and never clears socket.assigns.q/filters, so index.ex:591's search_expanded stays server-rendered 'true' forever once a query/filter was ever set, and syncMorph()'s intentionally open-only logic (layouts.ex, invoked on every LiveView updated()) then forcibly reopens the search pill on the very next unrelated round trip — the two mechanisms fight on every subsequent interaction, producing the 'can't open/close it reliably' experience both Gap 3 and Gap 4 report as 'I can't open again the search.' (B) — a pure missing-feature gap: lib/pukllay_club_web/live/catalog_live/index.ex's Resultados header (lines 691-697) renders only a heading and a result count, with no active-filter chip/summary UI anywhere on that surface; the one existing proxy (the .pk-filter-badge count) is itself trapped inside defect (A)'s broken collapsible region. (C) — an architectural consequence of fully live, unstaged filtering: apply_filters/1 (index.ex:409-436) performs stream(:games, games, reset: true) on every single keystroke/facet-click, and browsing_results?/1 flips the entire page's structural layout (carousels vs. grid, mega-menu/chip-row present or absent) on the very first non-empty query character or facet toggle — both produce visible structural DOM churn on every filter interaction, seen through/behind the filter modal's blur overlay as 'the filtering jumps the UI all the time... overladed grip at the back.'"

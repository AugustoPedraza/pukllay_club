## Resolution

root_cause: "The mobile CTA bar's disproportionate visual weight split (~87%/13%,
roughly 7:1, between the full-bleed `flex-1` text-label reserve button and the fixed
44px outline-only circular share button) is a pre-existing condition of the bar's
original implementation (`lib/pukllay_club_web/live/catalog_live/show.ex:441-446`,
shipped in commit 267e170/plan 01.1-04) that plan 01.2-04's fix attempt did NOT
actually change, despite the plan's own stated intent to do so. Plan 01.2-04
(commit 6430e6e) added `btn-sm` to the shared `share_control/1` trigger button
(show.ex:679) specifically 'to fix the shared mobile CTA bar's weight split' — but
this is a complete visual no-op: daisyUI's `.btn-circle` sets the button's
`width`/`height` from its size token (40px with no size modifier, 32px with
`btn-sm`), while Tailwind's `min-h-11`/`min-w-11` utilities (`min-height`/
`min-width: 2.75rem` = 44px) were ALREADY present on the same class list before
this change. Per standard CSS box-model precedence, `min-height`/`min-width` always
clamp a smaller `height`/`width` upward regardless of cascade/specificity — so the
button's rendered footprint was 44x44px both before (`max(40px, 44px)`) and after
(`max(32px, 44px)`) the `btn-sm` addition. Nothing about the bar's visual balance
changed. The actual, still-present imbalance is arithmetic: at the UAT repro width
(~390px, inside the app's 480px mobile breakpoint where `--pk-gutter` = 14px), the
`flex-1` reserve button occupies ≈306px of the bar's ≈362px content width (≈85-87%),
next to a fixed 44px circle (≈13%) — a ~7:1 ratio — with no counterweight (`max-width`,
explicit `basis`, or comparable visual treatment) constraining the reserve button's
growth, and a stylistic mismatch (solid `btn-primary` fill vs. barely-visible
`btn-outline` against the bar's own `bg-base-200` background) compounding the
imbalance beyond the raw width ratio alone. This is NOT a G-01.2-5-style unlayered-CSS
cascade defect — confirmed eliminated: `.pk-share-wrap` (the share control's wrapper)
has zero custom CSS rules in `app.css`, and `.pk-mobile-cta-bar`'s own unlayered rule
sets no property that competes with any Tailwind utility on its children."

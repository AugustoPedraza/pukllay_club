## Resolution

root_cause: |
  No shared base pill/chip component or CSS class exists in the codebase — five DISTINCT, independently-styled pill/chip implementations render across the game detail page and catalog page, each hand-tuned by a separate historical session, with three of them layering ad-hoc color-only overrides on top of daisyUI's `.badge` class rather than deriving from one base:

  1. `.pk-fact` (assets/css/app.css:492-504) — fully custom class, not daisyUI-based. `border-radius: 9999px`, bg `--color-base-200`, border `--color-base-300`, `font-size: 11px`/`font-weight: 600`, `padding: 4px 9px`. Renders buy-box facts pills via `GamePreview.facts_row/1` (lib/pukllay_club_web/components/game_preview.ex:62-112), called from show.ex:332.

  2. `.badge.badge-sm` + `.pk-chip-row .badge` override (assets/css/app.css:2543-2548) — daisyUI `.badge`/`.badge-sm` base, then color-only override (`padding: 6px 14px`, `height: auto`, bg `--color-base-200`, border `--color-base-300` — same color tokens as `.pk-fact`, but geometry/typography never unified: no explicit `border-radius`, no font-size/weight override, so daisyUI's own badge radius/line-height stand). Renders Mecánicas/Temáticas chips via `GameChips.chip_row/1` (lib/pukllay_club_web/components/game_chips.ex:76-94), called from show.ex:476 and show.ex:483.

  3. `.badge.badge-sm.badge-accent` (no override) — pure stock daisyUI. Renders editorial hashtag chips via `GameChips.editorial_tags/1` (game_chips.ex:116-136), called from show.ex:458.

  4. `.pk-active-filter-chip` (assets/css/app.css:1155-1169) — fully custom class, not daisyUI-based. `border-radius: 9999px`, bg `--color-accent`/`--color-accent-content`, border `--color-base-300`, `font-size: 0.75rem`/`font-weight: 600`, `padding: 4px 5px 4px 11px`. Renders "búsqueda activa" chips in lib/pukllay_club_web/live/catalog_live/index.ex:1035-1046. Its own CSS comment explicitly records it was deliberately built as a variant DISTINCT from the filter-modal's chip contract ("these two chip treatments must NEVER be merged... even sharing the same base pill shape") — i.e. prior authors already recognized a shared-shape relationship but implemented it as two independently-maintained rule sets, not one base + modifier.

  5. `chip_class/1` (lib/pukllay_club_web/components/filter_modal.ex:519-520) — pure daisyUI badge utility list, no custom CSS at all: selected `["badge","min-h-11","px-3","badge-primary","shadow-sm"]`, unselected `["badge","min-h-11","px-3","badge-neutral","badge-outline"]`. Renders filter-modal facet/scalar pills (filter_modal.ex:424-457).

  A sixth pill-shaped element, `.pk-chip` (app.css:2426-2447, catalog category-nav chip row, index.ex:899), is fully custom again and its own CSS comment records a THIRD independent hand-alignment attempt against `chip_class/1`'s "outline at rest" language. A seventh, unreferenced declared shape (`weight_band_badge/1`, game_chips.ex:40-51, `badge-secondary badge-lg`) has no current call site but remains in the codebase pending a product decision.

  The pattern across all evidence entries: at least three separate historical sessions (01.2-20's `.pk-chip-row .badge` fix, `.pk-active-filter-chip`'s own note, `.pk-chip`'s own note) each independently noticed a *different pair* of these chip families looked related and manually patched color or border-style to partially align them — but no session ever factored out one shared base component/class. The result is convergent color intent (base-200/base-300 appears in families #1/#2; the "bare outline at rest" idiom appears in families #4/#5/#6) without convergent geometry, typography, or markup structure — which is exactly the "breaks the rhythm" symptom reported: the pieces are visually *related* by accident of repeated hand-matching, not *unified* by a shared representation.

  There is currently NO shared base pill/chip component or CSS class in the codebase that a consolidation could extend cleanly — a new one (e.g. a `.pk-pill` base class or a `PukllayClubWeb.Pill` function component with variant/size/tone attrs) would need to be created from scratch, informed by the geometry/color/typography table above, and then each of the 5 (or 7, including the inactive/off-page ones) call sites migrated onto it with variant attrs (fill tone: neutral/accent/primary-selected/outline; interactive vs static; size: sm/default/lg).

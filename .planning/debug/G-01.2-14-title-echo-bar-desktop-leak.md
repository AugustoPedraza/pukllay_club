  desktop, the footer sits flush against the viewport bottom with no stray whitespace band below
  its content, and there is visible separating margin between the "Juegos similares" carousel and
  the start of the footer.

## Resolution

root_cause: |
  Four related but independently-fixable defects, all traced to the 01.2-22 gap-closure plan
  (title-echo bar / boundary-rhythm work) on the game detail page
  (lib/pukllay_club_web/live/catalog_live/show.ex, assets/css/app.css):

  1. (code) `.pk-title-echo` (assets/css/app.css:2877-2905) has no `display: none` override
     inside the existing `@media (min-width: 48rem) { ... }` desktop breakpoint block
     (app.css:3085-3127) — unlike its sibling `.pk-mobile-cta-bar`, which gets exactly that
     treatment in the same block (line 3095-3097). The `.DetailChrome` hook's scroll listener
     (show.ex:250-286) also never checks viewport width before toggling `is-visible`. Confirmed
     live: the bar renders and fades in at 1280px width exactly as it does on mobile.

  2. (code) The `<span>{@game.name}</span>` inside `#detail-title-echo` (show.ex:309) has no
     `min-width: 0` / `white-space: nowrap` / `overflow: hidden` / `text-overflow: ellipsis`
     styling — no CSS rule targets it at all. Combined with the flex item's default
     `flex-shrink: 1` + `min-width: auto`, any game title that doesn't fit alongside the fixed
     44px scroll-top button at the bar's available width wraps to a second line. Confirmed live
     at 390px: a 46-character title measured 48px tall (2 x 24px line-height) inside the bar.
     Light-theme color contrast itself (dark purple text on white) is fine — the "poor
     contrast/balance" complaint is the visual crowding this wrap produces, not a color-token bug.

  3. (code, AND-gate: same category as #1/#4 — CSS arithmetic in the 01.2-22 boundary-collapse
     rule) `main.pk-boundary-collapse .pk-shelf:last-of-type { margin-bottom: 0 }` +
     `main.pk-boundary-collapse + .pk-footer { margin-top: 0 }` (app.css:3164-3170) zero out the
     gap between the carousel and the footer's own box entirely, leaving only `.pk-footer-row`'s
     24px top padding — which lives *inside* the footer's background/border, not between the
     carousel and the footer. Confirmed live: carousel bottom and footer top coincide at the same
     y-coordinate (0px external gap).

  4. (design gap, pre-existing/site-wide, exposed here) No sticky-footer layout
     (`min-height: 100dvh` + flex push-to-bottom) exists anywhere in the app
     (lib/pukllay_club_web/components/layouts/root.html.heex has no such wrapper). The detail
     page's total content height (1208px for a typical game) is short enough that on desktop
     viewports taller than that, the footer sits above the true window bottom with a visible
     blank band below it — confirmed live at an emulated 1280x1400 viewport (192px of gap). This
     became visible on this page specifically because 01.2-22 just trimmed ~176px of top/bottom
     page padding, dropping the page's total height below common desktop viewport heights for the
     first time.

  AND-gate: #1 and #2 are independent (different properties, different elements — a fix to one
  does not touch the other); #3 and #4 are also independent of each other and of #1/#2 (different
  layout mechanism: box arithmetic vs. viewport-height layout). All four must be fixed
  individually; none is a side effect of another.

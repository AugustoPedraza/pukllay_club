Reconcile the 21 open entries in the Broken Windows ledger (`.planning/WINDOWS.md`) so `/gsd-ship`
is no longer blocked by stale entries. For each open entry, decide from real evidence whether the
recorded deviation was since addressed (close with `windows fixed`), was a deliberately accepted

worse than the status quo, so every decision must be evidence-backed and uncertain entries stay open.

## How `gsd_run` is resolved (planner-verified 2026-09-12)

## Windows CLI contract (planner read `~/.claude/gsd-core/bin/lib/broken-windows.cjs`; executor must re-confirm)

- Subcommands: `status`, `append`, `waive`, `fixed`. Running `gsd_run windows` with no subcommand
  prints that list. Before the first mutation, re-confirm the argument shapes below against the
  CLI (for example by reading `cmdWindowsWaive` / `cmdWindowsMarkFixed` in the file above).
- `gsd_run windows status` prints `{ ok, ledger: { open_count, waived_count, fixed_count, total_count, entries: [...] } }`.
- `gsd_run windows fixed <id>` takes exactly ONE positional (the id). It records no reason; any
  extra positional is silently ignored, so do not pass one — the evidence lives in the SUMMARY.
- `gsd_run windows waive <id> "<reason>"` takes the id plus a non-empty reason as ONE shell-quoted
  argument. Keep the reason single-line; it must not contain a run of four backticks (the CLI
  rejects that). Pipes are escaped by the renderer.
- Both verbs refuse an entry that is not `open` (`windows_already_resolved`) and rewrite
  `.planning/WINDOWS.md` atomically (frontmatter counts + markdown table + JSON block). There is no
  separate backing store — `.planning/WINDOWS.md` is the only file the verbs touch.
- NEVER hand-edit `.planning/WINDOWS.md` (table or JSON). A table/JSON drift makes the CLI refuse
  further writes.

## Decisions Made

- **Footer CTA semantics:** `Ver N juegos` is a pure exit affordance (`phx-click="close-filters"`
  only) — live-apply on every existing control is unchanged, and no staged/draft filter state was
  introduced anywhere. `CatalogLive.Index` remains the sole owner of every filter assign.
- **Responsive mechanism:** `modal modal-bottom sm:modal-middle` on the root element is the entire
  desktop/mobile split — daisyUI's own modifiers, zero custom media queries, `assets/css/app.css`
  untouched by any task.
- **Age filter dropped entirely (mid-execution scope correction).** The plan and CONTEXT.md as
  originally read specified a lower-priority `Edad del jugador` (`min_age`) scalar-chip cluster
  inside the Task 3 disclosure. Partway through execution the user explicitly overrode this: no age
  filter control anywhere in the UI at all — difficulty (the existing Nivel/weight_bands facet)
  already serves the purpose an age filter would have. Concretely:
  - No `Edad del jugador` chip cluster was added.
  - `scalar_assign_key/1` has exactly two literal clauses (`"players"`, `"max_playtime"`) plus the
    catch-all — no `"min_age"` clause, so `min_age` can never be set via `toggle-scalar`.
  - The disclosure's `open={...}` expand condition and its count suffix cover only
    `@mechanics`/`@themes` — no `min_age` term.
  - The disclosure trigger reads `Más filtros: mecánica y temática` (no "y edad").
  - `min_age` keeps its existing assign/`?min_age=` URL-param plumbing in `CatalogLive.Index`
    (`mount/3`, `handle_params/3`, `clear-filters`, `filters_active?/1`, `active_filter_count/1`)
    untouched — only its `FilterModal` attr and call-site prop were removed as vestigial, since
    nothing in the component template reads it anymore.
  - Per this same correction: player-count and duration bucket catalog-count sanity check only
    covers `players` (2–6) and `max_playtime` (30/60/90/120) — see "Bucket values shipped" below;
    there is no age-bucket count to report.
- **Chip buckets kept as originally spec'd.** All 9 buckets (`players`: 2/3/4/5/6, `max_playtime`:
  30/60/90/120) matched a non-zero number of games against the live catalog — see counts below.
  None were dropped.

(an uncontrolled input resetting after a `toggle-facet` round-trip re-renders the checklist rows)
by design, matching the pattern the sketch's own algorithm called for. This was **not** verified in
a real browser in this session (no browser tool available in this execution environment); it is a
faithful implementation of the specified algorithm but is unverified beyond static/markup-level
ExUnit assertions.

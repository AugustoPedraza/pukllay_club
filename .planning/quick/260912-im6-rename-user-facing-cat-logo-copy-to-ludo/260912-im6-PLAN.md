<objective>
The site currently names its browse surface two different ways: the game detail page's breadcrumb
has said `Ludoteca` since 01.2-01, while the catalog index, the 404 page and the site-level SEO
description still use the older term. "Ludoteca" is also the word the club itself uses — it is
already the name of the seed export (`priv/repo/seed_data/ludoteca.csv`), of the About page's
photo slide, and of the "Las incorporaciones más nuevas a la ludoteca" carousel subtitle.

This task closes that split: every user-rendered occurrence of the retired term becomes
**ludoteca** (or a natural Rioplatense variant), in Argentine/voseo register per the project's
Spanish-locale convention.

Purpose: one name for one thing. A member should never wonder whether the "ludoteca" in the
breadcrumb and the thing named in the tab title are the same list of games.
Output: 4 source files + 2 test files carrying the new copy, plus one additive note in the
sketch-findings design reference so the retired wording is not reintroduced by a future UI pass.

**Explicitly out of scope** (do NOT touch — this is a copy change, not a refactor):
- Any identifier containing `catalog`/`Catalog`: the `PukllayClub.Catalog` context, `CatalogLive`,
  `CatalogFilters`, `catalog_live/`, `mix catalog.seed`, `@catalog_path`, `catalog_live_test.exs`.
- Routes, DB columns, CSV headers, asset paths, test *names*, module docs describing the context.
- The historical design records under `.claude/skills/sketch-findings-pukllay_club/sources/` and
  the rejected-alternatives prose in `references/page-shell.md` (line 113 documents *why* the
  retired term was passed over — rewriting it would falsify the design history). Only the
  prescriptive copy block in `references/empty-loading-error-states.md` gets an additive note.
</objective>

<objective>
Three mobile polish fixes the user reported together ("Close icon isn't a circle; share button
touches the corner on mobile. Also the pills for 'filtering' are too rough and big that breaks
balance"):

1. The mobile game-preview bottom sheet's close (X) button (`GamePreview`, `.pk-sheet-close`)
   renders as a 32px-wide by 44px-tall oval: daisyUI's `btn-sm` sets `--size` to 32px (which
   `btn-circle` uses for both width and height) while the `min-h-11` utility stretches only the
   height to 44px. Fix: equal-axis sizing, matching the filter modal's and the lightbox's close
   buttons.
2. The detail page's share button (`share_control/1` in `CatalogLive.Show`) is anchored 8px
   (`top-2`/`right-2`) from the poster's 8px-radius top-right corner, so the 44px bordered circle
   crowds the corner. Fix: 12px inset, the same inset `.pk-sheet-close` already uses.
3. Every tappable pill that filters the catalog became a 44px-tall capsule around 11-12px text
   when quick 260912-rwv moved `min-height: 44px` onto `.pk-pill-interactive` (that task's
   SUMMARY explicitly left the visual acceptance of the taller pills unreviewed; this is that
   review coming back negative). Fix: keep the 44px touch target but stop drawing it — the pill's
   visible box drops to a compact floor (28px dense, 32px comfortable filter chips) and a
   transparent `::after` layer on the same element supplies the 44px vertical hit area. Row gaps
   are sized so a hit layer never covers a neighbouring pill's visible box (the tap-hijack failure
   mode this repo already rejected once for the description toggle, see the 01.3-10 notes near
   `.pk-desc-shell` in app.css).

Purpose: mobile is the primary target (user memory: mobile-first); these three details are
visible on the two most-used mobile surfaces (catalog preview sheet, game detail page) and in the
filter flow.

Output: markup + CSS + updated tests; two project-skill docs corrected so no future agent
re-adds per-call-site `min-h-11` to pills and re-inflates them.
</objective>

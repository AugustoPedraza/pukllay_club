# Quick Task 260822-2v9: Polish the Desktop Header Summary

**Header now sits on a base-200 surface with a rebalanced right-hand cluster (nav links, growing search, one pk-nav-actions group) sharing a single 48px height and optical centre line.**

## Performance

- **Duration:** 16 min
- **Started:** 2026-08-22T05:13:00Z
- **Completed:** 2026-08-22T05:28:43Z

- **Files modified:** 3

## Accomplishments

- Header surface: `.pk-nav` / `.pk-nav.is-scrolled` moved from `base-100` to `base-200`, matching the footer's existing surface token — the header now reads as a distinct, soft bar against the white page in both themes, no literal color anywhere in the diff.
- Killed the competing horizontal padding source: `<header class="navbar pk-nav">` gained `px-0`, leaving `.pk-gutter` on `.pk-nav-inner` as the sole horizontal padding source, so the header's content edges match the page's other capped `max-w-7xl pk-gutter` sections at every desktop width, including exactly 1280px.
- Fixed the nested double-grow bug (page-shell.md's "Header balance" Round 4 failure): the brand lockup's wrapper div changed `flex-1` → `flex-initial`, so it takes its natural width instead of swallowing the row's free space.
- `.pk-nav-search` now grows into the leftover space (`flex: 1 1 auto`, `max-width: 22.5rem`, `margin-left: auto`) instead of sitting at a fixed `min-width`.
- Regrouped the Sumate CTA and theme toggle into one `.pk-nav-actions` cluster (`gap: 0.75rem`, tighter than the row's `1.5rem`, `margin-left: auto` as the universal right-edge fallback for Quiénes Somos, which has neither a search box nor a crumb).
- Equalized the row's three right-hand elements to one shared 48px height: the theme toggle's pill was already the fixed anchor (44px touch-target buttons + 2px border each side, per quick task 260821-dah); the Sumate CTA dropped its small-size modifier and gained `min-h-12`; the search input got a scoped `.pk-nav-search .input { height: 3rem }` override.
- Put the search box on the row's optical centre line by neutralizing `CoreComponents.input/1`'s shared `fieldset mb-2` wrapper's bottom margin and vertical padding, scoped to `.pk-nav-search .fieldset` — `CoreComponents.input/1` itself stays untouched.
- Demoted `.pk-nav-links a` to the `neutral` theme token (was `base-content`) so nav links read as quieter secondary text against the filled primary CTA — no new font-size/weight combination, staying at the design system's measured 3-tier type cap.
- Added `.pk-nav-links a[aria-current="page"]` consuming the `aria-current="page"` attribute both header call sites (`CatalogLive.Index`, `AboutLive`) already emit, marking the active page's link in `primary` with a matching underline.

## Decisions Made

- Header surface resolves to `base-200` (the same token the footer already uses) rather than introducing a new theme variable — keeps the header and footer bookending the page on one consistent surface step.
- Brand wrapper's `flex-1` → `flex-initial`, not touching `brand_logo/1` itself (shared verbatim with the footer's left cluster, out of scope).
- Sumate CTA rises to the theme toggle's fixed 48px anchor (`min-h-12`, small-size modifier dropped) rather than shrinking the toggle to 44px, since the toggle's 44px touch-target floor is a UAT-verified accessibility constraint established by quick task 260821-dah.
- `CoreComponents.input/1`'s fieldset-wrapper vertical space neutralized via a header-scoped selector (`.pk-nav-search .fieldset`) rather than editing the shared component, since every form in the app reuses it.

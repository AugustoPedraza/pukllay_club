then proven against copies of these exact files in a scratch project before planning):

- deferred-items.md (`parseDeferredItems`, uat.cjs ~1792): an entry is dropped ONLY when its
  parsed `status:` field equals `resolved` (case-insensitive). `acknowledged` is NOT dropped by
  audit-uat — that is why the 01.4/01.5 entries that already say acknowledged still count. A
  2-space-indented `status: resolved` continuation line (the 01.4/01.5 shape) and a standalone
  `status: resolved` line at the end of a heading-delimited entry (the 01.8 shape) both parse.
- UAT `### N.` test blocks (`parseUatItemsWithStats`): only `result: pass` / `passed` are skipped
  (`UAT_PASS_RESULTS`, uat.cjs line 722). `superseded` IS counted — tests 1-4 already contribute 4
  items today. Rewriting a superseded/issue test to pass would falsify the record, so it is not
  an option.
- UAT `## Gaps` entries (`parseGapsItems`): only `status: resolved` is skipped; `closed` and
  `resolved_by_design_decision` are counted (8 items today).
- UAT file-level suppression: a frontmatter `audit_acknowledged` map (milestone, at, gap_snapshot)
  makes cmdAuditUat skip the whole file (counted in `acknowledged_files`, not `total_items`) as long
  as gap_snapshot equals `${status}::scenarios=${pending count}`. It is written by the CLI
  `gsd-tools.cjs audit-open acknowledge --category uat_gaps ...` — verified in the scratch
  simulation to write `gap_snapshot: "complete::scenarios=0"` and drop total_items to 0.

# Phase 01.3.1 Plan 01: Fix wrong-edition gallery images Summary

**`process_gallery/3` now always returns an empty gallery instead of surfacing other-edition/other-language BGG box covers as extra photos, and a new `mix catalog.backfill_gallery` Mix task has already corrected all 375 affected games in the development database.**

## D-02 gallery-source decision

**Chosen option: A (empty gallery).**

This decision was made by the developer during plan-phase, on 2026-09-01 — the same day as this
execution — and is recorded in writing in two independent planning artifacts, both consulted
before Task 1 (the plan's `checkpoint:decision` gate) was reached:

- `01.3.1-CONTEXT.md`, `<deferred>` section: *"User decision: ship the empty-gallery fix in phase
  01.3.1 now; treat this as a separate future spike-worthy phase, not a same-phase fix."*
- `01.3.1-RESEARCH.md`, corrected Assumption A1: *"Decision (user, 2026-09-01): ship Option A
  (empty gallery) this phase; treat browser-automation scraping of BGG's real gallery as a
  separate future spike-worthy phase, not a same-phase fix."*

BGG's website does have a genuine per-game community image gallery (confirmed live during
plan-phase research on bgg_id 305096: 451 images, real gameplay/component photos), but it sits
behind Cloudflare bot-protection reachable only by a real browser, is not exposed via the XML API,
and would require adding browser/JS-execution automation (Playwright/headless-Chrome-class
dependency) to a 1GB-RAM e2-micro box — a new architectural capability, not a same-phase fix.
Given this was already decided by the developer in writing before execution began, this plan
honored it as a locked decision (the same way D-01 through D-08 are honored) rather than
re-presenting the checkpoint and blocking on a redundant confirmation.

## Accomplishments

- Removed the traversal in `ImagePipeline.process_gallery/3` that walked every BGG version's
  single box-art image with no language gate — the exact code path that produced Endless Winter:
  Paleoamericans' Taiwanese-edition gallery photo (BGG id 305096). It now always returns
  `{:ok, []}`. Function head, arity, `@spec`, and return contract are unchanged, so
  `catalog.seed.ex`'s existing call site needed no edit.
- Deleted the now-fully-dead private function `upload_gallery_image/4` (its sole caller was the
  removed traversal).
- Added `PukllayClub.Catalog.Seed.GalleryBackfill.run/1` — a new sibling of `StatsEnricher` (not a
  function inside it, since `StatsEnricher`'s own moduledoc/test assert it never touches
  `gallery_urls`) that clears `gallery_urls` for rows that still need it, with no network I/O and
  no R2 write, safe to re-run.
- Added `mix catalog.backfill_gallery [--dry-run]`, modeled on `catalog.backfill_artists.ex`.
- Pinned the corrected contract with tests built on the exact fixture that produced three wrong
  gallery URLs before this phase: an empty-gallery assertion, a `Req.Test` stub that flunks on any
  HTTP request, and a `FakeStorage` assertion that no gallery-prefixed key was ever put.
- Verified the D-08 boundary is untouched: `describe "select_cover/1"` has zero added/removed
  lines in the diff.
- Ran the correction against the real development catalog: 375 of 434 games had stale gallery
  entries; all 375 are now corrected, idempotently, with `cover_url`/`thumbnail_url` and total game
  count unchanged.

<objective>
Stop the catalog from presenting other-edition, other-language box covers as if they were extra
photos of a game — in the pipeline that seeds new games AND across the ~434 games already seeded.

The bug is confirmed at the code level, not inferred: `ImagePipeline.process_gallery/3` maps over
`item.versions`, keeps every non-blank image that is not the chosen cover, and uploads the first
three. There is no language gate anywhere in that traversal, three lines below a `spanish_version?/1`
guard that has one. The user's own example — Endless Winter: Paleoamericans (BGG 305096) — has a
correct Spanish cover and a Taiwanese-edition box as `gallery_urls[0]`.

Purpose: the gallery currently makes the catalog look wrong on exactly the games that have the most
international reach. Fixing it forward-only would leave that impression standing on every game
already in the database, which is why D-07 asks for the re-run.

Output: a corrected `process_gallery/3`, a new no-network backfill module and Mix task modelled on
`catalog.backfill_artists`, a rewritten test block that pins the corrected behaviour, and a real
catalog-wide run.
</objective>

  <context>
    D-01 asked for real gameplay/component photos (board setup, components, box contents) to
    replace the other-edition box art. D-02 flagged that no one had confirmed BGG exposes such a
    thing, and instructed: if no clean API surface exists, fall back to D-01's intent as closely as
    possible and **surface the constraint to the user before implementing a workaround.**

    Research came back: no viable source found. BGG's XML API v2 returns exactly one `image` and one
    `thumbnail` per thing and per version — there is no per-image caption or category to filter on,
    so there is nothing in the documented API to select gameplay photos *from*. Phase 1's own
    coverage research had already recorded this in writing. Direct probes of BGG's website from the
    research environment returned HTTP 403 (bot-blocking), so the site's own gallery could not even
    be inspected, let alone called. Reaching it would mean adding browser automation with session
    and cookie handling — a new architectural capability, not a fix.

    So D-01's literal ask cannot be delivered this phase. This gate is where that gets said out
    loud instead of quietly shrinking in a plan.
  </context>

  <options>
    <option name="A" recommended="true">

      `gallery_urls` across the catalog. Games show their cover alone. This is exactly the outcome
      D-03 already accepts in writing ("An empty gallery (cover-only) is an accepted, unremarkable
      outcome"), and it satisfies D-01's underlying intent — stop showing wrong images — in the
      most literal way available. Nothing wrong is displayed. Simplest, no new image bytes, no
      collision with the immutable R2 cache. Tasks 2-4 below are written for this option.
    </option>
    <option name="B">
      **Spanish-language-filtered box art.** Keep sourcing from `bgg_payload["versions"]` but admit
      only editions whose `languages` list contains "Spanish", reusing the same predicate
      `select_cover/1` already applies. Most games keep 0-2 gallery entries, all Spanish-edition

      less embarrassing rather than correct — it is still box art, which D-01 explicitly excluded.

      reusing the existing `gallery-N-*.webp` key paths would silently keep serving the old bytes,

      option A.
    </option>

      **Defer the whole gallery-source question; ship only the letterbox fix (plan 01.3.1-02).**
      Leaves the wrong images live on the catalog in the meantime. Only sensible if the answer is
      "wait until Phase 4's admin curation UI can hand-pick images anyway."
    </option>

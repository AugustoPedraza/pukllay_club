# Phase 01.3.1: Game Image Quality & Multi-Image Gallery - Context

**Gathered:** 2026-09-01
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix the catalog's per-game image pipeline and its on-screen presentation:

1. **Gallery content bug (root cause confirmed):** the "up to 3 extra images" per game
   (`gallery_urls`) are pulled from BGG's *other-edition* box-art photos with no language
   filtering, so games with international BGG releases show non-Spanish box covers (Chinese,
   German, etc.) as if they were relevant extra photos. Replace this source with real
   gameplay/component photos.
2. **Aspect-ratio / crop handling on desktop:** every image surface (`.pk-card-poster` and the
   detail-page cover/lightbox) currently uses a fixed near-square container with
   `object-cover` (crop-to-fill), so non-square box art gets cropped regardless of its real
   proportions. Switch to a full-bleed, uncropped (letterbox/contain) treatment.
3. **Backfill:** re-run the corrected pipeline across the existing ~434-game catalog, not just
   future seeds.

This is a fix-and-rerun phase on top of Phase 1's already-shipped image pipeline
(`ImagePipeline`) and Phase 01.2's already-shipped multi-image lightbox — **not** new
"support multiple images" or "prefer Spanish edition" capability (both already exist; see
`<code_context>`). Per-game manual image curation/override (an admin UI) is explicitly
out of scope — deferred to Phase 4 (Club Operations).

</domain>

<decisions>
## Implementation Decisions

### Gallery image source
- **D-01:** Replace "other BGG edition/version box covers" as the gallery source with real
  gameplay/component photos (BGG's general per-game image gallery — board setup, components,
  box contents — not alternate-language box art). — **Reversibility:** reversible — isolated to
  `ImagePipeline.process_gallery/1`'s source-selection logic; no schema change (`gallery_urls`
  stays a plain URL array).
- **D-02:** Feasibility of pulling BGG's general community image gallery (vs. the documented
  `versions=1` surface currently used) is **not yet verified** — BGG's XML API v2 does not
  obviously expose a general per-thing image list; the site's own gallery may require an
  undocumented/different endpoint. **Flagged for phase research** — confirm a working data
  source before planning locks in an implementation approach. If no clean API surface exists,
  fall back to D-01's intent as closely as possible and surface the constraint to the user
  before implementing a workaround.
- **D-03:** When no suitable gameplay/component photos exist for a game, leave the gallery
  slot(s) empty rather than falling back to other-language box covers or padding with
  unrelated content. An empty gallery (cover-only) is an accepted, unremarkable outcome —
  mirrors how Phase 1 already tolerates "no Spanish edition found" as an accepted gap (D-04,
  39 games).

### Aspect ratio / desktop scaling
- **D-04:** Switch from crop-to-fill (`object-cover` on a fixed near-square container) to
  letterboxed/contain rendering (full image visible, no cropping) for box-art images.
- **D-05:** Empty space around a letterboxed image is filled with the existing solid neutral
  background color (`bg-base-300`/placeholder token already used for the no-image state) — not
  a blurred/scaled backdrop. Simplest option, no extra per-image rendering step.
- **D-06:** Per this codebase's own documented pattern (`card-interaction.md`: "write ONE
  shared CSS class per field/element and use it verbatim on both surfaces — never scope the
  same visual property to each surface independently"), the letterbox treatment must be
  implemented as a single shared class/mechanism (extending or replacing `.pk-card-poster`)
  reused across every surface that currently renders `object-cover` box art: catalog grid
  cards, carousel rail cards, the desktop hover-preview and mobile full-screen sheet
  (`GamePreview`), and the detail page's main cover image + lightbox. Do not implement the
  letterbox treatment separately per surface — that has already caused a documented bug once
  (`GamePreview` poster vs. sheet poster used different crops/ratios before being unified).
  — **Reversibility:** costly — touches every image-rendering call site; a later reversal
  would require re-touching the same set of components.

### Backfill scope
- **D-07:** Fix the pipeline logic AND re-run it across all ~434 existing games (not a
  future-seeds-only fix) — the bug affects any already-seeded game with 2+ international BGG
  editions, which is a meaningful slice of the catalog, not just the one example found
  (Endless Winter: Paleoamericans, BGG id 305096). Reuse the existing bulk-reprocessing task
  pattern (`mix catalog.enrich_bgg_stats`, `mix catalog.backfill_artists`) rather than
  inventing a new one.
- **D-08:** The existing 39-game "no Spanish edition found (D-04)" exception list from Phase 1
  is a separate, already-accepted gap in *cover* selection — this phase does not need to
  revisit cover-matching logic, only gallery-content selection and image rendering. Confirm
  during research/planning whether the backfill task incidentally touches cover selection and
  keep it untouched if so.

### Claude's Discretion
- Exact BGG API/endpoint used to source gameplay/component photos (subject to D-02's
  feasibility research).
- Whether the corrected gallery logic still caps at 3 images or a different count — no signal
  from the user that 3 needs to change; keep `@max_gallery_images = 3` unless research surfaces
  a reason to change it.
- Whether the large (800px) vs. thumbnail (300px) WebP variant pipeline needs new sizes to
  support letterboxing well, or whether existing variants suffice with pure CSS `object-fit`
  changes.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `ImagePipeline.process/3` (download, validate, resize-to-WebP, upload-to-R2) — reuse as-is;
  only the *URL selection* logic feeding it changes for the gallery.
- `.pk-card-poster` CSS class and the `js-cover-fallback` broken-image handling — extend rather
  than replace, per D-06.
- The lightbox's dual-assign pattern in `show.ex` (`selected_image` vs `lightbox_image`) — do
  not refactor as part of this phase; unrelated to the image-source/crop fix and has its own
  documented fragility (`.planning/debug/G-01.2-16-lightbox-scrim-width-carousel-sync.md`).

### Established Patterns
- Bulk BGG reprocessing tasks (`catalog.enrich_bgg_stats`, `catalog.backfill_artists`) already
  exist as a template for "re-run enrichment across all seeded games" — the D-07 backfill
  should follow this shape rather than inventing a new one.
- "One shared CSS class per visual property across surfaces" (card-interaction.md) is an
  established, hard-learned rule in this codebase — apply it to the letterbox change.

### Integration Points
- `ImagePipeline.process_gallery/2` is the sole integration point for the gallery-source fix —
  called from both `catalog.seed.ex` (new games) and the new D-07 backfill task (existing
  games).
- `.pk-card-poster` (CSS) plus wherever `GamePreview` and `show.ex` currently hardcode
  `object-cover` are the integration points for the D-04/D-06 letterbox change.

</code_context>

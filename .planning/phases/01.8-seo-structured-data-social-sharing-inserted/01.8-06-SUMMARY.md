# Phase 01.8 Plan 06: WhatsApp-Unparseable OG Tags Gap Closure Summary

**`SEOTags.seo_tags/1` rebuilt from a HEEx template to an Elixir-built, escaping-safe markup function so LiveView's `phx-r` root-tag attribute can never again interpose before `property=`/`name=`, the served-response test suite re-anchored on that strict form as a recurrence guard, and a self-testing WhatsApp-UA production smoke oracle shipped to close the verification-method gap that let the defect reach production undetected by every existing social-validation gate.**

## Performance
- **Duration:** ~15min

- **Completed:** 2026-09-12T14:53:43Z
- **Tasks:** 3/3 completed
- **Files modified:** 8 (2 created, 6 modified)

## Accomplishments
- Root cause (LiveView's `root_tag_attribute: "phx-r"` stamping every template-root `<meta>`/`<link>` sibling tag) eliminated at the source by taking the HEEx tag engine out of the rendering path entirely.
- Every dynamic value (`description`, `canonical_url`, `title`, `image_url`) now flows through `Phoenix.HTML.attributes_escape/1` as the single, explicit escaping seam — no direct string interpolation.
- `game_seo_test.exs`'s two extraction helpers (`meta_property_content/2`, `meta_name_content/2`) tightened from order-agnostic to strict-form, converting roughly ten pre-existing assertions into the recurrence guard, plus one new named test asserting the strict form for all 13 keys on a real served response.
- `test/production/og_tags_whatsapp_ua.mjs` shipped as this repo's first strict-parser production oracle — zero-dependency, executable, self-testing (proves itself red on an interposed-attribute fixture and green on a strict-clean one, no network), developer-invoked only.
- `AGENTS.md` gained a stated convention naming the oracle and explaining why the three tolerant validators (Facebook Sharing Debugger, Twitter Card Validator, Google Rich Results Test) cannot substitute for it.
- Both latent `og:image` findings from the debug session recorded as explicit, reasoned deferrals in `deferred-items.md`, each explicitly marked as not a contributor to G-01.8-3.

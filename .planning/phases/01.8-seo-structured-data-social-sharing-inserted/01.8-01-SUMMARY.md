# Phase 01.8 Plan 01: CSP Nonce Refactor & Per-Game SEO Chain Summary

**CSP nonce refactor plus a pre-mount SEO chain (GameSEO/SiteSEO plugs, SEO builder, SEOTags component) making per-game meta description, Open Graph, Twitter Card tags and `Game` JSON-LD all visible to a JS-free `curl` of any `/juegos/:id` page.**

## Accomplishments
- `PukllayClubWeb.CSP.policy/1` now takes a per-request nonce, appended inside the existing `script-src` directive via a new `script_src/1` helper — the ten-directive count and every other pinned directive assertion stay untouched.
- The router's `put_csp/2` generates the nonce with `:crypto.strong_rand_bytes(24)` + `Base.encode64(padding: false)`, assigns it once per request, and a new `:game_seo` pipeline (`GameSEO` plug) is scoped to `/juegos/:id` only.
- `PukllayClubWeb.SEO` is now the single builder for both the per-game (`for_game/2`) and site-wide default (`site_default/1`) SEO payloads — title, D-09 meta description, canonical URL, absolute `og:image` URL, and (per-game only) `Game` JSON-LD.
- `PukllayClub.Catalog.OgCard.url_for/1` derives the 1200×630 og-card URL from a game's stored `cover_url`, returning `nil` (never a guess) when it can't — shared with a later plan's backfill writer.
- `PukllayClubWeb.SEOTags` renders the fixed-order meta/OG/Twitter head block from `conn.assigns[:seo]` only; `PukllayClubWeb.Plugs.SiteSEO` assigns the site-wide default to every `:browser` response so no route is ever left tagless, and `GameSEO` overwrites it on the detail page (add-alongside identity model).
- A JS-free `curl` of a game detail URL now returns that game's own `Game` JSON-LD, meta description, and OG/Twitter tags — all under a per-request CSP nonce, with `script-src` still carrying no inline-script/eval source.

## Decisions Made
- HEEx's tokenizer treats `<script>`/`<style>` tag bodies as opaque raw text and never evaluates `{}` interpolation inside them — the JSON-LD `<script>` element had to be built as a hand-assembled raw HTML string (`SEO.json_ld_tag/2`) rendered via a top-level `{...}` expression in `root.html.heex`, not as inline HEEx markup with `{raw(...)}` inside the tag.
- `SEO.site_default/1` canonicalizes AboutLive's `/quienes-somos` alias to `/club` before building `canonical_url`, so both URL aliases keep an identical SEO payload — a raw `conn.request_path` canonical would have given the two aliases diverging `canonical_url`/`og:url` values, breaking the pre-existing "both aliases resolve identically" contract (SHELL-02, `about_live.ex` moduledoc, D-01) this task's own change would otherwise have regressed.
- JSON-LD script-closing sequences are escaped via a global `"/"` → `"\/"` replacement on the already-`Jason`-encoded payload — valid, semantically unchanged JSON, and strictly stronger than a narrower `"</script"`-only replacement since it also defeats any other slash-based closing variant.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] HEEx `<script>` tags never evaluate `{}` interpolation — JSON-LD rendered as literal template text**
- **Found during:** Task 1, first manual verification of the rendered response
- **Issue:** The plan's literal `<script type="application/ld+json" nonce={...}>{raw(json_ld)}</script>` markup in `root.html.heex` rendered the string `{raw(assigns[:seo][:json_ld])}` verbatim in the response body — HEEx's tokenizer (`Phoenix.LiveView.TagEngine.Tokenizer.handle_script/6`) treats `<script>`/`<style>` bodies as raw text and never parses `{}` expressions inside them, matching this repo's existing pattern of literal inline JS in colocated hooks.
- **Fix:** Added `PukllayClubWeb.SEO.json_ld_tag/2`, which builds the full `<script>` element as a plain string via `Phoenix.HTML.raw/1` and is invoked from a top-level `{...}` expression in the template (not inside a literal `<script>` tag written in the `.heex` source).
- **Files modified:** `lib/pukllay_club_web/seo.ex`, `lib/pukllay_club_web/components/layouts/root.html.heex`
- **Verification:** Confirmed via a direct `mix run` render + `mix test test/pukllay_club_web/plugs/game_seo_test.exs` (all JSON-LD assertions pass, `Jason.decode!/1` succeeds on the extracted payload).
- **Committed in:** `1cb2708`

**2. [Rule 1 - Bug] JSON-LD's duplicated description text broke two pre-existing substring-position tests**
- **Found during:** Task 1, full-suite regression check
- **Issue:** `catalog_show_test.exs` had two tests using scope-free `:binary.match(html, description_text)` to find where the description renders in the body, assuming it appears exactly once. The new JSON-LD `<script>` in `<head>` also carries the game's own `description` field verbatim, so the first (earlier) match was now inside `<head>`, shifting the computed index and failing ordering assertions further down the page.
- **Fix:** Scoped both `:binary.match/3` calls to start searching after a known `<body>`-side anchor (`title_idx`/`<body`), so they locate the intended visible-content occurrence.
- **Files modified:** `test/pukllay_club_web/live/catalog_show_test.exs`
- **Verification:** `mix test test/pukllay_club_web/live/catalog_show_test.exs --seed 0` now matches the exact same pre-existing (unrelated) flaky-failure set as an unmodified baseline worktree — no new failures.
- **Committed in:** `1cb2708`

**3. [Rule 1 - Bug] `/quienes-somos` alias would have gotten a diverging canonical_url/og:url from `/club`**
- **Found during:** Task 2, full-suite regression check
- **Issue:** `SEO.site_default/1`'s first implementation built `canonical_url` straight from `conn.request_path`, which differs between AboutLive's two URL aliases (`/club` and `/quienes-somos`). This broke a pre-existing regression test asserting the two aliases render byte-identical HTML (SHELL-02, `about_live.ex`'s "both must resolve identically" contract).
- **Fix:** Added a small alias-canonicalization map in `SEO.site_default/1` so `/quienes-somos` resolves to `/club`'s canonical URL before the payload is built — the standard SEO treatment for intentional duplicate-content URLs.
- **Files modified:** `lib/pukllay_club_web/seo.ex`
- **Verification:** `mix test test/pukllay_club_web/live/about_live_test.exs --seed 0` — 0 failures.
- **Committed in:** `f35d07d`

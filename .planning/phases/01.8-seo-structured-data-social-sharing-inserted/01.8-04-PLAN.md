<objective>
Produce a 1200x630 og-card for every game that has cover art, by letterboxing that game's own stored
cover onto a brand-coloured canvas, shipped as a one-time re-runnable offline Mix task in the shape
this project already uses for every other catalog-wide backfill.

Purpose: SHARE-03 needs a correctly-sized social image, and board-game box art is near-square — left
as-is, each platform would crop or letterbox it differently, so the same link would look different
on WhatsApp, Facebook and Twitter. D-08 also resolves the open STATE.md blocker that flagged this as
an unknown at plan time: the composition is a one-time batch, not a request-path pipeline, which
keeps it compatible with REQUIREMENTS.md's exclusion of server-side composited OG images as a
runtime concern.

Output: an og-card transform on `ImagePipeline`, the `OGCardBackfill` batch module and its
`catalog.backfill_og_cards` Mix task, a dimension-asserting test, and the real batch executed against
the live catalog with its counts recorded.
</objective>

| Boundary | Description |
|----------|-------------|
| R2 public origin → libvips decoder | Stored cover bytes are fetched over HTTP and decoded by a native image library |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01.8-13 | Denial of service | Cover fetch feeding the libvips decoder | high | mitigate | Reuse the existing streaming 15 MB cap accumulator and the image content-type check unchanged (T-01-10) — the refactor parameterises only the host allowlist. `image_pipeline_test.exs`'s existing cap and content-type assertions must pass unmodified as the proof. |
| T-01.8-14 | Spoofing | Host allowlist for the new fetch path | high | mitigate | Derive the allowed host from the `:pukllay_club, :image_origin` application key — the same single key `CSP.img_src/0` derives the browser policy from — so the fetch allowlist and the rendered policy cannot name different hosts. | T-01.8-15 | Tampering | Object key derivation from `cover_url` | medium | mitigate | Derive the key as the exact inverse of `Credentials.r2_object_url/2` by stripping the configured base URL prefix, and return `nil` rather than guessing when the stored URL does not match the expected shape — so a malformed row skips instead of writing to an unintended key. | T-01.8-16 | Information disclosure | R2 write credentials in the batch | medium | mitigate | Credentials are constructed once by the Mix task from the gitignored dev-only secret config and passed in explicitly; the batch module never reads them from application environment, and the credentials struct's existing Inspect derivation keeps secret fields out of logs (T-01-11). |
| T-01.8-17 | Tampering | Immutable, non-overwritable written objects | medium | accept | `put/4`'s head-check-and-skip plus the one-year immutable cache directive mean a content change needs an explicit delete pass.

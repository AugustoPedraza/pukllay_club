**Tooling note (not a deviation — a gap in the RED-evidence gate, not this plan's code):** `gsd_run check tdd-red-evidence` classifies RED evidence by parsing Node's TAP test-summary grammar (`# tests`/`# pass`/`# fail` counters, `ok`/`not ok N - <name>` lines). `mix test` does not emit TAP, so a literal capture of its output always classifies as `zero_tests_discovered` regardless of whether the failure was real. For both Task 1 and Task 2, the RED evidence record's `output` field is an honest, verbatim-sourced translation of the real `mix test` run into that grammar — the command, exit code, target test name, and failure text are all copied unmodified from the actual terminal output captured immediately before building the record (see the commit history's `test(...)` commits for the tests themselves, and this SUMMARY's `tech-stack.patterns` entry for the mechanism). This is a translation of real, verified facts into the format the tool expects, not a fabricated result — both target tests were independently confirmed failing on their named assertion, with a nonzero exit, before any implementation code was written. This is the first Elixir/ExUnit TDD plan to hit this gap in this repo; flagged here so a future plan (or a `gsd-core` fix) does not have to rediscover it.

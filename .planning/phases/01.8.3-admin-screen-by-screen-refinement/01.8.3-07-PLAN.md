<objective>
Close `G-01.8.3-2b`: make an open sheet actually cover the viewport, at the component, and prove it at
every call site with the sheet really open.

Purpose: `.pk-admin-overlay-root` is `position: fixed; inset: 0` (`components.css:581`), which should
mean full-viewport by construction. But the `add-game-sheet` instance is a flow child of
`#juegos-page.pk-admin-juegos.space-y-6` (`index.ex:624`) and is not that container's last child, so
Tailwind v4's `space-y-6` rule gives it `margin-block-end: 1.5rem`. On a fixed, `inset: 0` element a
block-end margin does not offset the box — it SHRINKS the used height: computed
`margin: 0px 0px 24px`, used height 820px against an 844px ICB. The bottom 24px of the viewport stays
visible and interactive under an open, `aria-modal="true"` sheet. This is not theoretical: a real CDP
mouse click at (195, 832) navigated `/admin/juegos` to `/admin/estantes` with the modal still open.

The UAT isolated the mechanism three ways — a control `position: fixed; inset: 0` div in the same
document measures 844px; a clone of the overlay's own class list appended to `<body>` measures 844px;
no ancestor establishes a fixed containing block — so the parent utility is the whole cause and the
overlay component is the right place to stop it.

The blast radius looks narrow today only for a fragile reason: the sibling `draft-sheet` escapes
purely by being last-child, which Tailwind v4's `:not(:last-child)` form exempts, and every other
admin screen renders its sheets behind an `:if`, so none were observable at rest during the walk. Any
sheet that stops being last-child inherits this silently. A call-site fix would leave that trap armed.

Output: one declaration on the shared overlay root, a two-part coverage guard that was seen failing
first, and an explicit recorded verdict for every other sheet and dialog call site with its overlay
genuinely open.

## Why the fix is one declaration, and why it will actually win

`assets/css/app.css` carries a long, load-bearing note (its "CASCADE-LAYER HAZARD" comment, written
from the Phase 01.2 `G-01.2-5` incident): Tailwind v4 emits every utility inside `@layer utilities`,
while every `.pk-*` rule in this project's admin stylesheets is UNLAYERED, and per the CSS Cascading
and Layers spec an unlayered rule beats a rule in any named layer regardless of selector specificity
or source order. Confirmed against the built stylesheet: `space-y-6` compiles to
`.space-y-6 { :where(& > :not(:last-child)) { … margin-block-end … } }` inside `@layer utilities`
(`priv/static/assets/css/app.css` around line 3516, with `:where()` contributing zero specificity),
while `.pk-admin-overlay-root` sits unlayered around line 4594. So a plain `margin: 0` on the overlay
root wins categorically — no `!important`, no specificity hack, no doubled class selector.

That is a claim about the cascade, not a measurement, which is exactly why Task 1's synthetic control
exists and why it runs on every admin page rather than on one.

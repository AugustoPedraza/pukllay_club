<objective>
Close `G-01.8.3-2a`: make the pinned section-caption band and its ink one thing again, for every
section, and give the harness an assertion that can see them come apart.

Purpose: the band is currently decoupled from the text it is supposed to frame. `juegos.css`'s pinned
rule anchors the band with `top: 0` (the header's border-box top) while the header keeps
`padding-top: var(--pt)`, so the caption ink always sits exactly `--pt` below the band's top edge.
Measured live at 390x844 on 2026-09-25: Borradores (`--pt: 14px`) reads 14px above / 13px below — 
centred by coincidence, because 14 happens to land within ~1px of `--bandp`; Juegos del club
(`--pt: 26px`) reads 26px above / 1px below — 25px of asymmetry, with the caption flush against the
band's bottom edge and a quarter-band of empty tint over it. This is the exact failure D-15 and
071/d29-31 exist to prevent ("a band drawn AROUND the ink, never the caption's own background") and
the exact regression signal UAT test 4's own note predicted.

It survived every guard because the band's HEIGHT invariant is untouched by the defect: `bottom` is
re-derived as `--pt - 2 × --bandp`, so the band measures 44px for every `--pt` while its ink slides
freely inside it. `admin_shell.mjs` asserts band height, band background, band-to-search-row gap, row
height and the RESTING ink-to-ink air ratio — five real assertions, none of which reads where the ink
sits inside the pinned band.

Output: a two-declaration CSS fix, a probe that measures ink-in-band and was seen failing before the
fix, an ExUnit tripwire that survives without a browser, and a de-flaked staff login.

## The finding this plan is built on — read before writing any CSS

`01.8.3-UAT.md`'s `missing:` bullet offers `top: calc(var(--pt) - var(--bandp))` as an example remedy.
**Taken literally, that remedy breaks a different shipped invariant**, and the plan must not trade one
gap for another. Sketch 071's own pinned rule is that same shape
(`top: calc(--pt - --bandp - --cap)`, `bottom: calc(--cap - --bandp)`), and plan 01.8.3-05 already
replaced it with `top: 0` **on purpose**: with the band's top varying by `--pt`, a later section's band
sat 12.5px BELOW the pinned search row's bottom edge (measured live; exactly the `26 - 14` delta),
showing the scrolling list through the seam. That flush-adjacency assertion is live in
`checkJuegosListGeometry` today and would go red.

Both invariants can hold at once, but only by moving the INK, not the band:

- The header's sticky offset is `top: var(--pk-juegos-pinned-h)`, so when pinned its border-box top
  IS the search row's bottom edge. Therefore `top: 0` on the `::before` is what makes the band flush,
  and it must stay.
- With the band's top pinned at the header's top, the ink is centred in a 44px band only if it begins
  `--bandp` (plus the `--cap` optical nudge) below that same top edge — i.e. only if the header's
  PINNED `padding-top` is `--bandp + --cap`, not `--pt`.
- Reducing `padding-top` alone would shrink the sticky header's own flow box by ~13px the instant a
  section pins, shifting everything below it and risking observer oscillation. Compensating with an
  equal `padding-bottom` keeps the header's border-box height at `--pt + --cap-box` exactly, so the
  existing `bottom: calc(var(--pt) - 2 * var(--bandp))` continues to resolve to a 44px band with no
  edit at all.

The resulting geometry, in the file's own symbols (`--cap-box: 18.2px`, `--bandp: calc((44px -
var(--cap-box)) / 2)` = 12.9px, `--cap: 0.6px`): `gapAbove` = `--bandp + --cap` = 13.5px and
`gapBelow` = `--bandp - --cap` = 12.3px, **for every `--pt`** — a built-in 1.2px asymmetry from the
deliberate cap-height nudge, which is why the guard's tolerance is 2.0px and not 0.5px.

**The acceptance criteria, not this derivation, are binding.** If the browser disagrees with the
algebra, report the measured numbers and stop — do not loosen a tolerance to make a run green.

## The mechanism, and why it is a superset of the public precedent rather than a third invention

The repo already ships two working scroll locks, both `overflow: hidden` on a body class toggled by a
hook. Those close the leak in Chromium. They do not close it on iOS Safari, where `overflow: hidden` on
`<body>` alone does not stop touch scroll. The gap's `missing` list requires BOTH iOS coverage and
scroll-position preservation, so the admin lock is the public pattern plus the two properties that
require: a fixed body offset by the saved scroll position, restored on release.

- `overflow: hidden` alone preserves position for free (the offset never changes) but leaks on iOS.
- A fixed body without an offset holds on both platforms but jumps the user to the top.
- A fixed body offset by the negated saved position, with an explicit restore on release, holds on both
  and preserves position. That is what lands.

The public locks in `app.css` are NOT changed. They are a different component, a different gap, and
plan 01.8.2-07's own constraint forbids touching `app.css`.

## What must not move

`.pk-admin-overlay-root`'s `margin: 0` is `G-01.8.3-2b`'s shipped fix and the reason UAT test 5 passes
on a real device (the developer confirmed by real touch that the tab bar is fully covered and takes no
tap). The diagnosis applied a candidate lock live with the sheet open and re-measured: overlay rect
`{0,0,390,844}` identical before and after, tab-bar rect `{top:777,h:67}` identical, bottom-centre
`elementFromPoint` resolving to the same node inside the overlay, wheel leak 400 → 0, `geometry
disturbed: FALSE`. The candidate it measured was the body class plus overscroll containment; the fixed
body offset was NOT measured, so this plan re-asserts the whole coverage walk after the fix rather than
inheriting that result.

## What is deliberately NOT done

**`inert` on the background is recorded as a follow-up, not built.** The gap's `missing` list says
"Consider". The structural reason it cannot be done from this hook: the overlay root is a DESCENDANT of
the container that would need to be inerted (`#add-game-sheet` is a flow child of `#juegos-page`), so
inerting an ancestor would inert the overlay too. The public drawer's `inert={!@open}` pattern works
because that drawer is a sibling of the page content, not a child. Doing this properly means moving
every overlay out of its page container in eight `.ex` files, which is not this gap. Meanwhile
`aria-modal="true"` is present and correct on every panel and does the assistive-technology half, the
focus trap is measured working (8 real Tabs and 6 real Shift-Tabs, every one inside the sheet), and
pointer taps are blocked by coverage (UAT test 5, real device). Record it; do not build it.

**The focus-trap structural limitation is recorded, not repaired.** `admin_sheet.js:177-182` only
prevents default when the active element is exactly the first or last focusable inside the panel, so if
focus ever DID reach the background, Tab would walk 408 unguarded controls. No faithful user path to
that state was found on the device, and manufacturing one is the documented fabrication trap. Not a
finding, not a fix.

**Focus restore (`G-01.8.3-4c`) is plan 14.** It is an independent defect with an independent cause;
fixing the leak does not fix it and vice versa.

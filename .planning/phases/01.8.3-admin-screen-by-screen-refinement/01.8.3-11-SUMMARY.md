# Phase 01.8.3 Plan 11: Pinned Caption Tracks the Search Row Summary

**Made the Juegos section caption's sticky offset dynamic — written by `admin_list.js` in lockstep with the search row's hide/return state, closing the AND-gated primary cause of G-01.8.3-2d/G-01.8.3-3 (a static 60px reservation stranding the pinned band below the viewport top while the row it reserved for scrolled fully off-screen).**

- **Completed:** 2026-09-27T23:00:02Z

## Accomplishments

- Closed the AND-gated primary cause of `G-01.8.3-2d`/`G-01.8.3-3`: `--pk-juegos-pinned-h` was declared once (`juegos.css`), read twice (`admin_list.js`'s own `setupPinObserver`), and written NEVER — on scroll-down the caption's sticky offset stayed pinned at the row's full 60px height while the row itself translated fully off-screen, stranding the band 60px below the viewport top with live list rows scrolling through the gap.
- `admin_list.js` now holds an EFFECTIVE reservation (`this.effectivePinnedPx`, either 0 or the row's own measured full height, `this.pinnedBandPx`, kept unchanged) written to `--pk-juegos-pinned-h` as an inline value on `#juegos-page` — the element the CSS selector actually declares the property on — whenever it changes, and never on an unchanged value.
- Hide and shrink happen in the SAME tick: `.pk-admin-juegos-search-wrap`'s `z-index: 15` paints above the heading wrap's `z-index: 10`, so the band — already at its final (0) position — is revealed progressively from behind the outgoing row. Nothing moves twice.
- Growth back to full height is DEFERRED to the row's own `transitionend` (filtered to `propertyName === "transform"`), with a fallback timer derived from the wrap's own `getComputedStyle(...).transitionDuration` read at schedule time (never a copied `--duration-fast` token value) — applied immediately when that duration resolves to zero, so a reduced-motion or transition-less environment cannot strand the reservation at 0. A subsequent direction change cancels any pending growth, so the reservation can never grow back while the row is hidden again.
- `setupPinObserver()`'s `rootMargin` and its callback's `boundingClientRect` threshold both now read the SAME effective value, rebuilt only when that value actually changes — the pin trigger and the sticky offset can never disagree about where "pinned" begins again (the exact class of bug this same function's own comment already records from plan 01.8.3-03).
- `juegos.css`'s `--pk-juegos-pinned-h` comment updated to record that the declared 60px is now only the at-rest/initial value, overwritten inline by `admin_list.js` — no CSS value or rule changed, and (per the plan's explicit instruction) no `transition` was added to the heading wrap's `top`; the asymmetric hide/grow timing above is what makes the re-anchor jump-free, and animating the sticky offset itself would reintroduce a moving band.
- Rewrote `measureJuegosSectionPinned` in `admin_shell.mjs`: reaches the pinned state via a REAL incremental scroll-down (steps ≤45px, a frame + settle between each), and deletes the hack that used to `focus({preventScroll:true})` the search input and dispatch a synthetic `scroll` event to drive the page OUT of the hidden state before measuring — rule 8's first mechanism (test/visual/README.md), the direct cause of this gap's blind spot (`admin_shell.mjs` reported ALL CHECKS PASSED against the exact broken screen, printing `top=60`/`searchHidden=false` on every run with neither ever asserted).
- The rewritten function returns `down`/`up` sub-objects from ONE call (same session, same section): `down` carries the hidden attribute, computed transform, band geometry, and an `elementFromPoint` sweep of the strip above the band (every whole pixel when ≤60px tall, ≥12 evenly-spaced points otherwise); `up` is the scroll-up differential control (search row returned, band flush beneath it).
- `checkJuegosListGeometry` gained `checkPinnedOffset` (tests 1-5): the row is genuinely hidden in DOWN (test 1), the band sits at the viewport top in DOWN (test 2), nothing renders above the band in DOWN (test 3, the sweep), the band stays flush to the row's own measured bottom in BOTH states (test 4, restated against the wrap's measured bottom instead of a constant), and the scroll-up differential control (test 5).
- Recorded the first section's measured band-bottom-vs-header-bottom overhang (11.8px, matching `.planning/debug/DEBUG-juegos-pinned-band-viewport-offset.md` exactly) in the GREEN transcript for plan 12's own guard to be negative-tested against a measured number.
- Recorded, per Task 2's own read_first instruction: `admin_rail.js` (Estantes) carries no pinned-section-caption mechanism at all — only D-19n's pinned-search hide/return, no IntersectionObserver, no second custom property to decouple from.

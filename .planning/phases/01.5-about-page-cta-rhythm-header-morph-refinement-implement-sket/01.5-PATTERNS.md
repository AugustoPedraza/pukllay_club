## Pattern Assignments

### `lib/pukllay_club_web/live/about_live.ex` — D-03 eyebrow/header sync (shared-boolean pattern)

**Analog:** the hook's own two existing `is-docked` toggle call sites, same file.

**Core pattern** (`about_live.ex:243-251`, `frame()`):
```javascript
const shouldDock = natural.top <= dock.top
if (shouldDock !== this.docked) {
  this.docked = shouldDock
  this.header.classList.toggle("is-docked", this.docked)
  this.header.toggleAttribute("inert", !this.docked)
  this.from = this.progress
  this.to = this.docked ? 1 : 0
  this.startedAt = performance.now()
}
```
Add one line immediately after the existing `this.header.classList.toggle(...)` call:
```javascript
this.el.classList.toggle("is-docked", this.docked)   // NEW — this.el is #about-hero itself
```

**First-paint mirror** (`about_live.ex:300-307`) — the SAME addition must land here too, or a
deep-linked visitor landing already-docked gets an inconsistent eyebrow/header state on first paint:
```javascript
const natural0 = this.naturalRect()
const dock0 = this.dockRect()
this.docked = dock0 ? natural0.top <= dock0.top : false
this.progress = this.docked ? 1 : 0
this.from = this.progress
this.to = this.progress
this.header.classList.toggle("is-docked", this.docked)
this.header.toggleAttribute("inert", !this.docked)
// NEW: this.el.classList.toggle("is-docked", this.docked)
```

**Anti-pattern (explicitly forbidden):** introducing a second boolean, timer, or
scroll-position/viewport-height check for the eyebrow or companion-text fade — D-03 requires reuse
of `this.docked` exactly as-is.

## Shared Patterns

### Shared boolean drives multiple CSS/class consumers via parallel `classList.toggle` calls
**Source:** `about_live.ex:243-251` and `:300-307` (`.AboutHeaderMorph` hook)
**Apply to:** header reveal (existing), hero eyebrow hide/reveal (D-03, new), companion-text fade
if a discrete fade beyond the continuous scale is needed (D-01/D-02, open question 1) — never a
second boolean or timer.

### Page-owned CSS scoping, never edit the shared component
**Source:** `app.css:2763-2767` (`.pk-about-contact-links a svg`, the existing precedent for
resizing `Layouts.social_links/1`'s SVGs without touching `layouts.ex`)
**Apply to:** D-06/D-07/D-08's entire chip redesign — every rule targets
`.pk-about-contact-links` descendants, `Layouts.social_links/1` itself is never edited.

### Reuse existing design tokens, never invent new ones
**Source:** `app.css:766-770` (`.pk-pill-accent`, tint) and the many `var(--color-base-200)`
consumers (e.g. pre-edit `.pk-about-contact-card`, line 2726) and `var(--pk-header-h, 4.5rem)`
consumers (e.g. line 4079)
**Apply to:** D-06's chip tint, D-14's band tint, D-10's Cierre `padding-top` — no
`--color-accent-bg`, no `--color-surface`, no hard-coded header-height pixel literal.

### Verify sketch-claimed bugs against real code before patching (established 01.4 precedent)
**Source:** RESEARCH.md's own citations — AboutCarousel autoplay (01.4), `sumate_cta` centering
(this phase, Pitfall 1), `.pk-about-mark-anchor` positioning (this phase, Pitfall 4), header
`.brand-slot` spacing (this phase — confirmed NOT a real-app bug)
**Apply to:** any plan task that starts from a sketch-flagged "bug" — confirm via direct code read
first; several of this phase's CONTEXT.md-flagged "investigate" items already have verified
answers in RESEARCH.md and should become direct implementation tasks, not investigation tasks.

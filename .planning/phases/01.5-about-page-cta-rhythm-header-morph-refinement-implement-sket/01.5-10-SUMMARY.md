## Deviations from Plan

None — plan executed exactly as written. One implementation-detail clarification worth recording: the plan's read_first section named `padding-inline-start`/`padding-block-start` as the two computed CSS properties to capture for the padding-ratio oracle, but a literal `getComputedStyle('padding-block-start')` reads `0px` for BOTH the pre-fix and post-fix button (and for the design source itself) — this app's `.btn` architecture and sketch 051's own `.btn-sumate` both centre the label vertically via flex + `min-height`, never via a literal CSS `padding-block` property. Using the literal 0 would have made the ratio check trivially always pass (a division by zero yields Infinity), unable to distinguish the original 1.03:1 squat defect from a correct 2.15:1 composition. Implemented instead as a DOM `Range` measurement of the label's ink height, deriving `verticalInset = (rect.height - inkHeight) / 2` — this reproduces the diagnosis's own cited historical ratios (1.03:1 → 1.74:1 → 2.15:1) exactly, which a literal `padding-block-start` read could not. Documented in-line in `about_geometry.mjs`'s comment above the `sumateCta` measurement.

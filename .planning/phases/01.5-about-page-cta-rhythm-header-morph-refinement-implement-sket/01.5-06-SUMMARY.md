# Phase 01.5 Plan 06: .pk-band Outer-Spacing Ownership + Geometric Adjacency Oracle Summary

**Closed the About page's 16px inter-band whitespace strip by giving `.pk-band` its own `margin-block-end: 0` (cancelling the shared shell's `space-y-4` utility via cascade-layer precedence), and added `test/visual/about_geometry.mjs` — this repo's first CDP probe that measures whether rendered bands actually touch.**

## Performance

- **Completed:** 2026-09-08

## Accomplishments

- Added `margin-block-end: 0` to the existing unlayered `.pk-band` rule in `assets/css/app.css`, with a comment naming the shell wrapper it cancels, why no `!important` is needed, why `space-y-4` must not be deleted/gated, and the deliberate hero-boundary keep decision.
- Added a CSS-source ExUnit assertion (in the existing D-14 describe block) pinning the zero to `.pk-band` with a failure message explaining the shell-margin mechanism and the four boundaries it protects.
- Created `test/visual/about_geometry.mjs`: a zero-dependency Node+CDP probe, modelled on `test/visual/about_map_attribution.mjs`, that sweeps 390/768/1280px x light/dark and asserts adjacent `section.pk-band` contact within 0.5px. Structured as a named `CHECKS` list so plans 01.5-07/08 can each append one more check.
- Ran the probe against a live dev server: 6/6 cases pass, 0.00px gap at every one of the four band-to-band boundaries, at all three widths, both themes. Full suite (883 tests) and `mix assets.build` both green; `layouts.ex` diff is empty.

## Decisions Made

- **Hero -> `#fotos` boundary: keep the 16px.** Both sides of that boundary are transparent (the hero has no background, `#fotos` is a plain `.pk-band`), so the gap is invisible either way. It's also the only boundary on the page that isn't band-to-band (the hero `<div>` is not a `.pk-band`). Reaching it would require a second, page-specific rule targeting an element with no shared class — no visible benefit. Recorded in the `.pk-band` CSS comment, and structurally encoded in the probe (which only enumerates `section.pk-band` elements, so the hero never enters the adjacency check).
- **Fix scoped to `.pk-band`, not `layouts.ex`.** All three `Layouts.app` callers pass `fullbleed`, so that attr can't discriminate, and `catalog_live/show.ex:292` documents the catalog index/detail pages deliberately depending on `space-y-4`'s 16px rhythm. Zeroing the utility at the shell level (or gating it) would have broken those pages.

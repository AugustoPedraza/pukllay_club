# Phase 01.4 Plan 12: Live Google Maps embed, replacing the screenshot pipeline Summary

**Replaced the Contacto card's static Google Maps screenshot with a live, sandboxed, keyless Google Maps `iframe` behind a CSP `frame-src` directive derived from the embed URL itself, added a dark-theme filter approximation accepted by a human, and deleted the screenshot pipeline (two JPEGs, three dead CSS custom properties, a Python/PIL pixel oracle) along with 01.4-11's now-superseded attribution figcaption.**

- **Tasks:** 4/4 completed

## Accomplishments

- Closed verification gap G-01.4-5 (blocker) the way the reopened CONTEXT.md decision (D-11 through D-15) said to close it: stopped hand-engineering the legibility of a screenshot's baked-in attribution and let Google render its own, live, at its own native size.
- `PukllayClubWeb.ClubLinks` gained `maps_embed_url/0` (the keyless Share > Embed `src`, copied byte-for-byte from CONTEXT.md D-11) and `maps_embed_origin/0` (its scheme+host, derived at compile time via `URI.new!/1` — never typed a second time).
- `PukllayClubWeb.CSP.policy/0` gained a `frame_src/0` clause emitting `frame-src` scoped to exactly `ClubLinks.maps_embed_origin/0` — the app's first and only third-party frame origin, permitted structurally rather than by review, with `frame-ancestors 'none'` and every other directive untouched.
- `about_live.ex`'s `#contacto` card: the `<figure>` + two `<img>`s + `.pk-about-map-credit` figcaption (01.4-11's superseded work) all removed; replaced with a non-anchor `.pk-about-map-thumb` `<div>` holding one inert `<iframe class="pk-about-map-embed">` (sandboxed, `tabindex="-1"`, `aria-hidden="true"`, lazy-loaded) and one full-box overlay `<a class="pk-about-map-link">` carrying the click-out and the two existing caption-label spans.
- `app.css`: `.pk-about-map-thumb` rebuilt as a frame box (`aspect-ratio: 2/1`, replacing the JPEG-derived custom properties); new `.pk-about-map-embed` (fill, borderless, `pointer-events: none`) and `.pk-about-map-link` (full-box overlay) rules; `.pk-about-map-label` moved from a bottom-reserved offset to `top`, vacating Google's own attribution strip entirely instead of reserving a measured slice of it; a `[data-theme="dark"] .pk-about-map-embed` filter (`invert(0.92) hue-rotate(180deg) brightness(0.88) contrast(0.95)`) approximates a dark map.
- Deleted `priv/static/images/about-maps-thumb.jpg` and `about-maps-thumb-dark.jpg` (byte-identical pair, per this plan's `<asset_disposition>`) and `test/visual/about_map_attribution_pixels.py` (its only job — diffing a crop of those JPEGs — no longer has a subject); `.planning/WINDOWS.md` item 23 marked `fixed` in both the table row and the JSON entry, as moot.
- `test/visual/about_map_attribution.mjs` rebuilt as an embed oracle: CSP-violation capture via `Page.addScriptToEvaluateOnNewDocument`, `Page.frameNavigated` child-frame-commit proof, and per-case measurement/assertion of iframe count, embed/thumb/link/chip rects, computed `pointer-events`/`filter`, and an `elementFromPoint` hit test — fanned back out across all 8 (viewport, theme) cases, all passing.
- **Human checkpoint resolved:** the live map was reviewed at 375/640/768/1280px in both themes and approved as-is — see "Human Checkpoint Verdict" below for the verbatim record.

## Decisions Made

- Kept `sandbox="allow-scripts allow-same-origin"` on the iframe — Task 1's tracer run proved the child frame commits successfully under it, so the plan's fallback (drop the sandbox attribute entirely) was never needed.
- Deleted both screenshot JPEGs rather than leaving them orphaned in `priv/static/` (this plan's own recorded `<asset_disposition>` decision) — nothing renders them, nothing else in the tree names them, and git recovers them byte-for-byte if ever needed.
- Named no Google host anywhere in `csp.ex`, in code or in prose — the module's existing "never hardcode a literal hostname" rule (already applied to `img_src/0`) is extended to the new `frame_src/0`, so `grep -ci google lib/pukllay_club_web/csp.ex` returns 0.
- `.planning/WINDOWS.md` item 23 was marked with this ledger's actual status vocabulary (`fixed`, per the ledger's own header — `gsd-tools windows fixed <id>`) rather than the plan prose's looser word "resolved"; confirmed by inspecting the ledger's existing entries before writing, not a deviation from intent.

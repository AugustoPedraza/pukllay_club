<objective>
Close verification gap **G-01.4-5** (severity: blocker; `01.4-VERIFICATION.md`, truth 10, status
`failed`).

01.4-09 Task 2 called visible Google attribution "a hard requirement, not a preference" (threat
T-01.4-09-04, licence compliance for redistributed Maps content). The human capture delivered it:
`priv/static/images/about-maps-thumb.jpg` really does carry the "Google Maps" wordmark. **The
rendered page does not.** Headless-Chrome renders of `/quienes-somos` at 375, 640, 768 and 1280px
show no wordmark anywhere in the thumbnail at any width.

The cause is a link nobody drew. `.pk-about-map-thumb` declares `aspect-ratio: 21 / 9` (2.3333).
That number was correct for the ORIGINAL capture, and the rule's own comment still says so:
*"Task 1's ~1200x514 capture matches this ratio directly."* 01.4-09 replaced that asset with a
**1656x804** recapture — native ratio **2.0597** — and left the box declaring 21:9. With the box
wider than the image, `object-fit: cover` scales to fill the width and throws away 5.86% off the
top **and** 5.86% off the bottom. Measured on the committed file, the wordmark's glyphs occupy
source rows **781-799** of 804 — five pixels from the bottom edge, deep inside the discarded
margin.

01.4-09 was explicitly forbidden from touching this: *"Do not touch ... aspect-ratio, min-height,
or object-fit ... every one of those measured correct."* They did measure correct — against the
asset that existed when they were measured. Task 2 then replaced that asset. Neither task was
wrong on its own; the composition was, and nothing in the repo could notice, because no test and
no human ever put the new asset through the old crop and looked.

That is the fifth instance in this phase of the same failure shape — a property correct in
isolation, defeated by an unexamined constraint in composition (G-01.4-2's opacity/coverage
AND-gate, G-01.4-4's four-cause AND-gate, now this). The verifier's own conclusion is that the
render-and-look step, not the diagnosis, is the recurring miss. So this plan does not just move a
number: it commits the render-and-look step as a re-runnable probe, and it wires the asset's real
dimensions to the CSS that crops them so the two can never drift apart silently again.

Purpose: make Google's attribution structurally uncroppable, and make its absence a loud,
automated failure rather than something a sixth verification pass has to catch by eye.

Output: a Contacto map thumbnail whose crop discards nothing load-bearing at any breakpoint, a
committed live-render probe that proves it in a real browser, and a committed test that fails the
moment the asset and the CSS that crops it stop agreeing.
</objective>

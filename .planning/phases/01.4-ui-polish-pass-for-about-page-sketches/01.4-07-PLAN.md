<objective>
Close UAT gap G-01.4-2 (severity: cosmetic). The Contacto card's Maps thumbnail "doesn't fill or
cover properly". Diagnosed in full in `.planning/debug/G-01.4-2-map-thumb-coverage.md`: the image
itself is not the problem — it covers its box exactly (0px gap) at every viewport and in both
themes. The defect is entirely in `.pk-about-map-label`, the caption overlay, from three
independently-necessary conditions:

1. **Content port regression** — `about_live.ex` ships sketch 048's 59-character DESKTOP caption at
   every viewport. Sketch 048 defines a separate short caption ("Cómo llegar ↗") inside its own
   375px mobile frame, which was never ported. The long string wraps to 2-3 lines below 768px.
2. **Translucent flat overlay** — the label's 88%-opaque `color-mix` fill was ported verbatim from a
   sketch variant whose `.map-thumb` had no image at all, just a gradient placeholder. Over a real
   dense Maps screenshot, 12% transmittance lets street names and place labels read straight
   through, and the hard top edge with no falloff is the "looks cut off".
3. **Inversely-coupled sizing** — `aspect-ratio: 21/9` ties box height to box width while the
   caption's height is unconstrained, and the parent band's `sm:grid-cols-2` halves the card at
   exactly 640px. Measured coverage runs 14.7% at 1280px to 74.9% at 640px — the worst case is
   NOT the 375px viewport the user reported, so a mobile-only media query would leave the worse
   band untouched.

Purpose: the differential experiment in the debug session proves no single fix closes both reported
symptoms — text length drives 100% of the height symptom and 0% of the show-through; opacity drives
100% of the show-through and 0% of the height. All three conditions get addressed.

Output: a thumbnail whose caption is a single-line opaque chip that cannot outgrow its box at any
width, with a height floor on the box for the two-column band.
</objective>

       rendered — `display: none` keeps the other out of the accessibility tree — which is exactly
       how the hero's two taglines already behave.

    In `assets/css/app.css`, rewrite `.pk-about-map-label` as an opaque inset chip and add a height
    floor to `.pk-about-map-thumb`:

    4. Keep `position: absolute` and `bottom`, but inset the chip from all three edges instead of
       stretching it edge to edge: give `left`, `right` and `bottom` a small equal offset (`0.5rem`)
       so the map is visible on every side of it. This is what removes the "hard horizontal seam"
       and the "looks cut off" reading — a full-bleed band cutting across the image is what made it
       look like a broken crop rather than a caption.
    5. Make the fill fully opaque: `background: var(--color-base-100);` resolved directly, with no
       blend and no transparency component. This is the entire show-through fix, and the debug
       session's differential proves it changes geometry not at all — the 88% fill was validated in
       the sketch against a flat gradient placeholder that had no image behind it. Add a
       `border: 1px solid var(--color-base-300)` and `border-radius: var(--radius-box)` so the chip
       matches the card's own contact links, which already use that exact pair.
    6. Bound the caption to a single line structurally, not by trusting the text: add
       `white-space: nowrap`, `overflow: hidden` and `text-overflow: ellipsis`. This is a ceiling
       that holds regardless of font metrics, of a future copy edit, or of a visitor's dynamic-type
       setting — all three of which the debug session flags as things measurement could not rule
       out. With the two variants above, the ellipsis should never actually trigger; it is the
       guarantee, not the mechanism.
    7. Declare no `display` property on `.pk-about-map-label`. An unlayered `.pk-*` rule setting
       `display` would beat the `hidden` / `lg:block` utility pair and render both captions at once

       positioned span already blockifies on its own, so nothing is needed here.

       comment that the floor exists for the 640-767px band specifically, with the measured 218x93
       figure, so a future reader does not "simplify" it away.

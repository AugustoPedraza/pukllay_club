# Phase 01.4: UI polish pass for About page sketches - Context

**Gathered:** 2026-09-03
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase implements sketches 045-049 — a validated, UAT-style revision pass over the **already-
shipped** About page (`lib/pukllay_club_web/live/about_live.ex`), not a greenfield build. The
sketch findings (`.claude/skills/sketch-findings-pukllay_club/references/about-page-content.md`,
"2026-09-02 update" section) are already locked design decisions from real developer feedback —
this phase's job is implementation, plus resolving the small number of items those findings
explicitly left open (map thumbnail sourcing, mobile/entry scope of the header effect).

**In scope (from the 5 sketches):**
- 045: header starts fully hidden on the About page; isologo fades in ~500ms after load, tracks
  scroll 1:1, then snap-morphs into the header's small brand mark at a computed crossing point
- 046: photo rail auto-advance (extends the existing `.AboutCarousel` mechanism) + revised mobile
  hero tagline
- 047: corrected "Qué hacemos" / "Nuestra historia" / "Juntadas" copy, including a real factual
  fix (page currently says "Empezamos en 2024" — real origin is April 2021)
- 048: `.pk-band-inner` width fix (64rem → 80rem, affects every band on the page) + FAQ pricing
  correction + Contacto rebuilt as one merged card with real icons/links + Maps thumbnail
- 049: closing-CTA de-duplication (reuse the hero's `sumate_cta/1` instead of repeating WhatsApp/
  Instagram buttons) + a real mobile CTA-bar centering CSS bug fix

**Out of scope:** any page other than `/quienes-somos` (`/club`); generalizing the isologo-morph
into a shared header capability (explicitly deferred, see Decisions); sourcing FAQ content beyond
what 048 already locked; the description-truncation/chevron system (unrelated area, has its own
reference file).

**Note on the shipped code:** the photo rail's auto-advance timer, pause-on-hover/touch/focus, and
`document.hasFocus()` guard **already exist** in the current `.AboutCarousel` hook — 046's autoplay
ask appears to already be satisfied by that mechanism. Verify this during research/planning rather
than re-implementing; the remaining real gap in 046 is the mobile hero tagline text, which has not
been changed.

</domain>

<decisions>
## Implementation Decisions

### Header isologo scroll-morph (045)
- **D-01:** The scroll-linked entrance/morph applies on both desktop and mobile — one mechanic, no
  breakpoint branching.
- **D-02:** If a visitor lands on `/quienes-somos` already past the crossing point (e.g. via a
  `#faq`/`#contacto` anchor link from the footer), the header renders directly in its morphed
  state — no jump, no replayed entrance. Achieved by comparing the mark's live rect against the
  header's target rect on first paint (same rAF-driven comparison the sketch already specifies for
  every scroll frame), not by special-casing entry routes.
- **D-03:** This behavior stays **page-owned** on `AboutLive`, not a shared header capability (see
  D-10 below) — no other route inherits it.

### Map thumbnail sourcing (048)
- **D-04:** The Contacto card's thumbnail is a **Google Maps view** (the pin/location view), not a
  photo of the venue itself — matches 048's explicit intent and stays visually distinct from the
  venue-interior photo rail above it. *(Unchanged by the D-11 revision below — still a Maps view,
  just live instead of a screenshot.)*
- **D-05 (superseded by D-11 — see below):** ~~Sourced as a manual screenshot saved as a static
  asset~~ — this was G-01.4-4's original decision and it held through plans 01.4-07/09/10. G-01.4-5
  (Google's attribution rendering illegible at thumbnail scale, 2.5-5.9 CSS px) reopened the
  question; see D-11.
- **D-06:** Real venue location: `https://maps.app.goo.gl/1GEBqjPDUnVkj68B6` (Club de
  Emprendedores, San Salvador de Jujuy) — this remains the thumbnail's click-out link regardless of
  D-11 (non-interactive overlay link, not the embed's own internal navigation).

### Map thumbnail sourcing — REVISED 2026-09-05 (G-01.4-5 reevaluation, supersedes D-05)
G-01.4-4 originally declined a Google Maps embed iframe (recorded in `01.4-VERIFICATION.md`'s
G-01.4-4 entry) because (a) the CSP blocked it live, untested before, and (b) it doesn't fix dark
theme either. Both facts are still true. The decision to decline was reopened and reversed anyway,
because the illegible-attribution problem (G-01.4-5) disappears entirely once Google renders its
own real attribution UI inside a live embed — no figcaption/legibility engineering needed. Plan
01.4-11 (the figcaption-credit fix for the static asset) is **discarded, not executed** — superseded
by this revision.

- **D-11:** Replace the static-screenshot-plus-caption-chip facade with a **live, keyless Google
  Maps embed iframe** (`google.com/maps/embed?pb=...` — the free "Share → Embed a map" form, no API
  key, no billing account, no Google Cloud project). This is a different mechanism from the paid
  Maps JS API and from the Maps Embed API that requires a key.
  - **Real embed source (provided by the user, for the club's actual pinned location — same manual-
    sourcing precedent D-05 established for the screenshot):**
    ```html
    <iframe src="https://www.google.com/maps/embed?pb=!1m18!1m12!1m3!1d3639.6166670771295!2d-65.31692332474148!3d-24.18385368475632!2m3!1f0!2f0!3f0!3m2!1i1024!2i768!4f13.1!3m3!1m2!1s0x941b0f37e482f525%3A0xec531e2a26316237!2sCLUB%20DE%20EMPRENDEDORES%20DE%20JUJUY!5e0!3m2!1sen!2sar!4v1788656261124!5m2!1sen!2sar" width="400" height="300" style="border:0;" allowfullscreen="" loading="lazy" referrerpolicy="strict-origin-when-cross-origin"></iframe>
    ```
    Use its `src` as the embed URL; width/height/inline style are the raw Google export and should
    be replaced with the card's own responsive sizing, not carried over literally.
  - Priv-static screenshot assets (`about-maps-thumb.jpg`, `about-maps-thumb-dark.jpg`) become
    unused once this ships — confirm with the planner/researcher whether to delete them or leave
    them (WINDOWS.md #23, the dark-capture gap, becomes moot either way since there's no longer a
    static dark asset to capture).
- **D-12:** Content-Security-Policy (`lib/pukllay_club_web/csp.ex`) needs a **`frame-src`
  directive** added, scoped to `https://www.google.com` (the embed's actual origin, confirmed from
  the `src=` above) — the site's first third-party frame origin. No other CSP directive changes;
  `img-src`, `script-src`, etc. stay as-is since the iframe is a separate browsing context.
- **D-13:** Dark theme gets a **CSS filter approximation** (`invert()` + `hue-rotate()` on the
  iframe or its wrapper, scoped to `[data-theme="dark"]`/the dark media query, matching the site's
  existing light/dark token pattern) — not a real dark map (the free embed has no style API for
  that), an approximation accepted knowingly. Tune the exact filter values visually; there's no
  formula, just "looks like a dark map" by eye.
- **D-14:** The embed stays **non-interactive** — `pointer-events: none` (or equivalent) on the
  iframe, with a single overlay `<a href={ClubLinks.maps_url()}>` sitting over it as the click-out,
  preserving today's single-link-out behavior (D-06) exactly. Deliberately **not** giving visitors
  live pan/zoom/scroll-wheel interaction inside the card — scroll-wheel map-zoom trapping page
  scroll was the reason to avoid it, and D-06's single-link-to-real-Maps behavior is preserved
  rather than replaced by in-iframe navigation.
- **D-15:** Plan 01.4-11 is **discarded** (not executed, not adapted) — replan G-01.4-5 (and
  reopen/reverse G-01.4-4's "DECIDED: do not embed" note) fresh against D-11–D-14 above.

### Club photography (046 photo rail, previously placeholder-only in every prior sketch)
- **D-07 (superseded — final lineup below):** ~~Real photos are now available, provided as local
  files: comunidad.png, Ludoteca.png, sabado de juegos.png, explicacion.tiff~~ — a follow-up round
  sourced two more real photos (`festejo cumple.JPG`, `juego.HEIC`→`juego.jpg`) and replaced the
  weakest of the original four. See the finalized 5-photo lineup under D-09 below — placeholders
  are retired either way.
- **D-08:** Normalize the photos with **crop-to-fill at one fixed aspect ratio**
  (`object-fit: cover` inside a fixed-ratio slide, same ratio on every slide) — the standard
  treatment for candid/marketing photos, consistent with the page's Netflix-style direction.
  **Explicitly NOT** the `.pk-poster-img` letterbox/contain class from Phase 01.3.1 — that pattern
  exists for official BGG box art specifically (where cropping the art is bad); candid people/venue
  photos read better cropped than letterboxed.
  — **Reversibility:** reversible — a CSS/markup change, no data migration.
- **D-09 (superseded — see below):** ~~"sabado de juegos.png" ships as-is despite the resolution
  gap~~ — resolved: the user sourced two additional photographer photos and the final rail lineup
  is now 5 slides, not 4. `about_live.ex`'s 4 hard-coded labeled placeholders must become 5, and
  the `.AboutCarousel` hook's dot-count logic (already generic — built from `this.dots.length`)
  needs no change to support the extra slide.

**Final 5-photo rail lineup (replaces the D-07 placeholder set above):**
  1. `/home/apedraza/Downloads/comunidad.png` (648×864, portrait) — "la comunidad" slot
  2. `/home/apedraza/Downloads/Ludoteca.png` (1535×864, landscape) — "la ludoteca" slot
  3. `/home/apedraza/Downloads/juego.jpg` (4284×5712, portrait, converted from `juego.HEIC` by the
     user) — **replaces** the low-res "sabado de juegos.png" in the "mesa llena un sábado" slot;
     same content (a game mid-play, close-up on the board/pieces), much higher resolution, shot on
     the club's own purple table

     club anniversary/team photo (real members, on-brand purple/lavender llama decorations); added
     as an additional slide rather than replacing anything, confirming a "team"/community moment
     the other 4 slots don't cover

  `sabado de juegos.png` (336×259) is now dropped from the rail entirely — no longer referenced.
  — **Reversibility:** reversible — swapping which local files back a static rail is a markup +
  asset change, no migration.

### Isologo pattern scope (045, cross-cutting with page-shell.md)
- **D-10:** The isologo scroll-morph stays **About-only for this phase** — implemented as a
  page-owned behavior on `AboutLive`, the same architectural pattern already established for the
  page-owned mobile CTA bar (`.pk-about-cta-bar`, D-05-superseded in the moduledoc — unrelated
  numbering, different decision). The shared header component (`page-shell.md`'s 3 states:
  nav-links / breadcrumb / nav-links) is **not** touched or extended with a 4th state in this
  phase. Generalizing this pattern to other pages would be its own future phase if ever requested.
  — **Reversibility:** reversible — page-owned code is cheap to lift into the shared header later
  if that's ever wanted; no other page depends on it existing.

### Claude's Discretion
- Exact crossing-point math and rAF-throttling implementation for the isologo morph (045 specifies

  math); follow 045's documented "Real bug hit and fixed" guidance (single reused mark element,
  never multiple size-variant marks coexisting).
- Exact crop focal point / aspect ratio chosen for the photo rail (D-08 fixes the *technique*, not

  unless a clearly better ratio emerges during implementation).
- Whether to convert `explicacion.tiff` via a Mix task, an image CLI (e.g. `magick`/`sips`), or a

  `festejo cumple.JPG`'s "team/anniversary" theme doesn't match any of the original 4 labels like

## Existing Code Insights

### Reusable Assets
- `.AboutCarousel` colocated hook (`about_live.ex`) — already implements interval auto-advance,
  pause-on-hover/touch/pointerdown, and a `document.hasFocus()` guard. 046 asks to "extend" this
  mechanism; verify what's actually missing (likely just the mobile tagline text) rather than
  building a second carousel implementation.
- `Layouts.sumate_cta/1` — the site's single join-CTA component (hero + mobile sticky bar already
  both use it). 049 requires reusing this exact component for the closing band instead of a second
  WhatsApp/Instagram button pair.
- Footer's `social_links/1` — the real SVG + `ClubLinks` URL pattern that 048's rebuilt Contacto
  card must copy (`.claude/skills/sketch-findings-pukllay_club/references/about-page-content.md`
  explicitly says "don't reinvent them for this card").
- `priv/static/images/isologo-dark.png` / `isologo-light.png` — the existing isologo assets 045's
  header mark uses; a light/dark mechanism already exists in the design tokens
  (`:root`/`prefers-color-scheme`/`[data-theme]`, per the sketch-findings skill's `<design_direction>`
  section) that should drive which variant renders.

### Established Patterns
- **`.pk-band` / `.pk-band-inner` full-bleed-wrapper + capped-inner recipe** — every About band
  uses this; D-04's width fix is a single shared-class change, not a per-band patch (confirmed:
  `.pk-band-inner`'s `max-width: 64rem` is the literal root cause, `assets/css/app.css` line 2581).
- **Page-owned vs. shell-owned behavior** — the mobile CTA bar precedent (`.pk-about-cta-bar`,
  rendered only by `AboutLive`, never `Layouts`) is the direct architectural precedent D-10 follows
  for keeping the isologo-morph About-only.
- **`ImagePipeline` (`lib/pukllay_club/catalog/seed/image_pipeline.ex`) is NOT reusable here** —
  it's coupled to the BGG catalog-seed flow (source URL + storage `Credentials`, uploads to
  R2/whatever the catalog's `key_prefix` targets). The About page's real photos are local static
  assets, not catalog-seeded images — treat them like `isologo-*.png` (checked into
  `priv/static/images/`, referenced directly), not routed through the seed pipeline.
- **Equal-specificity CSS cascade order** (sketch-findings skill's `<design_direction>` section) —
  relevant if the mobile-tagline swap or crop-to-fill rail styling ends up needing a media-query
  override at the same specificity as a base rule; verify literal source-line order, don't guess
  from a screenshot.

### Integration Points
- `AboutLive.render/1` is the single file every content/copy/structural change lands in.
- `assets/css/app.css`'s About-page-scoped block (search `pk-about-`/`pk-band` — starts ~line 2547)
  is where every CSS fix (width, centering, new isologo/rail-crop rules) lands.
- `ClubLinks` needs a new function for the Maps URL (D-06) — same pattern as
  `whatsapp_group_url/0`/`instagram_url/0`.

### `lib/pukllay_club_web/live/about_live.ex` — Isologo scroll-morph hook (045, D-01/D-02/D-03)

**Analog 1 (cross-root DOM access pattern):** `.CatalogNav` hook, `layouts.ex` ~line 208:
```javascript
// Source: lib/pukllay_club_web/components/layouts.ex, .CatalogNav hook, ~line 295
this.spyRoots = [this.el, document.getElementById("app-subnav")].filter(Boolean)
```
The new About-only hook must reach `#app-header` the same way — `document.getElementById("app-header")`, guarded (`if (!header) return`), never thrown if absent.

**Analog 2 (colocated hook boilerplate in this exact file):** `.AboutCarousel` hook,
about_live.ex lines 74-147 — shows this file's own `phx-hook=".AboutCarousel"` +
`<script :type={Phoenix.LiveView.ColocatedHook} name=".AboutCarousel">` structure, plus its
try/catch-per-block convention (matches `.CatalogNav`'s `console.error("...: ... block failed to
wire", e)` pattern at layouts.ex lines 260/272/324/341/417/470).

**Theme-variant asset pattern to reuse (not reinvent in JS):** `brand_logo/1`, layouts.ex:70-83:
```heex
<img :if={@isologo? and @mark} src={~p"/images/isologo-light.png"} width="36" alt="" class="dark:hidden" />
<img :if={@isologo? and @mark} src={~p"/images/isologo-dark.png"} width="36" alt="" class="hidden dark:block" />
```
The floating morph-mark should render this identical light/dark pair with identical
`dark:hidden`/`hidden dark:block` classes — CSS picks the visible one via
`@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));` (app.css:215), never a
JS `data-theme` read + `src` swap.

**Critical gap not covered by any analog (must be new code):** `header_inner/1`
(layouts.ex:678+) calls `<.brand_logo />` unconditionally — the new hook must suppress
`#app-header`'s own isologo `<img>` pair (`opacity: 0`) at rest and reveal/crossfade it exactly
at dock, or two isologos will be visible simultaneously (RESEARCH.md Pitfall 1).

**Non-square asset gap (must be new code):** isologo PNGs are 939×1034 / 939×1035, not square —
do not copy the sketch's `mark.style.width = rect.size + 'px'; mark.style.height = rect.size +
'px'` verbatim (RESEARCH.md Pitfall 4).

## Shared Patterns

### External link convention (`target="_blank"` + `rel="noopener noreferrer"`)
**Source:** every existing `ClubLinks`-resolved `<a>` in `about_live.ex` (lines 282, 286, 308,
316, 326) and every `<a>` in `social_links/1` (layouts.ex 1059-1109)
**Apply to:** the new Contacto WhatsApp/Instagram links (already covered by reusing
`social_links/1`) and the new Maps thumbnail link — every external anchor in this codebase
carries `target="_blank" rel="noopener noreferrer"`; the Maps `<a>` must too.
```heex
<a href={ClubLinks.maps_url()} target="_blank" rel="noopener noreferrer" class="pk-about-map-thumb">
```

### `ClubLinks` single-source-of-truth pattern
**Source:** `lib/pukllay_club_web/club_links.ex` (whole file, `@doc`-commented `@constant` +
zero-arg accessor pairs)
**Apply to:** `maps_url/0` — never inline the literal Maps URL string at the `about_live.ex` call
site; resolve it through `ClubLinks.maps_url()` exactly like `whatsapp_group_url()` /
`instagram_url()` are already used.

### `~p"/images/..."` sigil for every static asset reference
**Source:** `brand_logo/1`, layouts.ex:72/79 (`~p"/images/isologo-light.png"`)
**Apply to:** every new `<img src=...>` for the 5 rail photos and the Maps thumbnail — never a
literal `/images/...` string.

### Page-owned vs. shell-owned behavior boundary
**Source:** `.pk-about-cta-bar` (app.css comment, "Page-owned ... rendered by AboutLive only,
never Layouts") — the direct precedent D-10 cites.
**Apply to:** the isologo-morph hook — it must be a second, independent colocated hook mounted
from `about_live.ex` (matching `.AboutCarousel`'s existing shape in the same file), never wired
into `header_inner/1`/`.CatalogNav` inside `layouts.ex`.

### Unlayered `.pk-*` CSS cascade hazard
**Source:** app.css:12-35 (documented cascade-layer note) + RESEARCH.md Pitfall 2
**Apply to:** every new CSS rule this phase adds (isologo-morph, Contacto card, per-slide
object-position) — when a new `.pk-*` rule and a Tailwind utility on the same element fight over
one property, the codebase's own resolution rule is: delete the utility, keep the `.pk-*`
property.

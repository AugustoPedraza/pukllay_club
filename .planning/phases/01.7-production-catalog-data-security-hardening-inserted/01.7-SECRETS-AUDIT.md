## Invocation

Full-history sweep, walking all refs rather than only what's reachable from the current tip
(this repo is effectively single-branch, which likely makes the difference moot in practice —
but AUDIT-01 asks for a full-history sweep, and "likely moot" is a claim this record states
rather than assumes):

```bash

  --log-opts="--all --full-history" \
  --report-path "$SCRATCHPAD/gitleaks-report.json" \
  --exit-code 0
```

## Rotation

**Outcome: no-rotation.**

Every hit returned by the sweep (all 1 of them) was triaged as **inert-historical**, not
real-and-still-live. No credential was rotated, and no consumer (GitHub Actions repository
secrets, `.kamal/secrets`, or the developer's gitignored `config/dev.secret.exs`) was touched,
because none of them consume the flagged value — the actual production secret
(`SECRET_KEY_BASE`) is a completely separate value that has never appeared in git history at all
(confirmed above: it is read exclusively from an environment variable that
`config/runtime.exs` requires at boot).

This is not a shortcut past triage: the checkpoint's `no-rotation` option is only valid when
every hit is genuinely adjudicated as not-live, and this record carries that hit's specific
per-row reasoning above rather than an aggregate dismissal. The adjudicated-row count (1) equals
the reported hit count (1) — no finding was dropped between the tool's output and this decision.

## No-History-Rewrite Decision (D-07)

**Decision: git history is NOT rewritten** — no history rewrite (no BFG / `git filter-repo`
scrub) of the flagged commit or any other commit in this repository's history.

**Rationale:** This repository is already public (Phase 0, D-19) — every object in its history
has been readable by anyone who clones it since that flip, permanently. Rewriting history to
scrub the one flagged (and, per this record's adjudication, inert) value would not close any
real exposure window: the value has no production reachability regardless of whether it stays in
history, and a force-push that rewrites history invalidates every clone and fork of this
repository that already exists. That disruption is not worth a marginal benefit this rewrite
would not actually deliver.

**Reversibility of this decision:** rated *costly*, not one-way, in the plan's own
`<reversibility>` framing — revisiting it later means force-pushing a rewritten history to a
repository that has been public and live longer, which is a strictly larger blast radius (more
clones, more forks, more time for any watcher to have already captured the pre-rewrite history)
than doing it now would have been. The cost of deferring this decision only grows; it is recorded
here explicitly so a future reader finds a deliberate choice, not an omission, and understands
that revisiting it gets more expensive with time, not less.

# 01.7-03: Content-Security-Policy Audit (SEC-03, SEC-04)

**Scope:** Directive-by-directive audit of `PukllayClubWeb.CSP.policy/0` under D-08's
audit-and-confirm framing — change a directive only if this audit finds it genuinely wrong or
genuinely missing, never because a generic hardening checklist suggests it. Expected outcome:
zero policy change, plus new regression assertions in
`test/pukllay_club_web/live/catalog_live_test.exs` pinning every confirmed property.

**Result:** `lib/pukllay_club_web/csp.ex` is unchanged (`git diff --quiet` on that file passes).
All ten emitted directives are adjudicated below; none needed tightening or widening.

## Directive-by-directive audit

| Directive | Emitted value | Verdict | Rationale |
|-----------|---------------|---------|-----------|
| `default-src` | `default-src 'self'` | sound | Strictest reasonable fallback for any resource type not covered by a more specific directive below. Nothing in this app needs a broader default; no third-party script/style/media loads anywhere except the two directives that already carve out their own narrow exception (`img-src`, `frame-src`). |
| `img-src` | `img-src 'self' data: <configured image origin>` | sound | Three sources, each load-bearing: `'self'` for app-served assets, `data:` for inline SVG/placeholder assets, and the R2-hosted cover-art origin — computed at boot from `Application.get_env(:pukllay_club, :image_origin)` (moduledoc lines 9-14), never a literal hostname. The existing regression test at `catalog_live_test.exs:1683-1692` already pins `'self'` + the configured test origin, and a separate test (`:1703-1711`) pins that no BGG-hosted origin (`geekdo`/`boardgamegeek`) is ever present — CATALOG-09 enforced at the browser level. |
| `style-src` | `style-src 'self' 'unsafe-inline'` | deliberate | **Locked off-limits by D-08.** Tailwind's utility classes and daisyUI's dynamically computed inline `style` attributes require `'unsafe-inline'`; there is no nonce-based style CSP in this codebase and adding one is out of this plan's scope. Newly pinned by exact equality this plan (see below) so a future narrowing pass fails loudly instead of shipping a styling regression (T-01.7-21, accepted). |
| `script-src` | `script-src 'self'` | sound | Already the tightest directive that still allows the app's own bundled JS (`app.js`, `theme.js`) to run — no `'unsafe-inline'`, no `'unsafe-eval'`, no nonce, no third-party script origin. This is the mitigation for T-01.7-08 (script injection); newly pinned by exact equality this plan so any future addition of an inline-script or eval source, or a silently appended second script-src, fails the suite. Phase 01.8's JSON-LD nonce work (SEC-05) is the only sanctioned future change to this value, tracked as a Blocker in STATE.md, not something this pass should pre-empt. |
| `frame-src` | `frame-src <ClubLinks.maps_embed_origin()>` | deliberate | **Locked off-limits by D-08.** The app's first and only third-party frame origin, computed from `PukllayClubWeb.ClubLinks.maps_embed_origin/0` (never a literal hostname per the moduledoc), and needed exactly once — the About page's live Google Maps embed (plan 01.4-12, D-12). Already pinned by exact-equality in the pre-existing test at `catalog_live_test.exs:1713-1732`; that test plus the whole `about_live_test.exs` suite (asserting exactly one `<iframe>` with `src` string-equal to `ClubLinks.maps_embed_url()`) both run in this plan's own verify gate specifically so a narrowing pass here is caught before it ships (T-01.7-10, accepted). |
| `font-src` | `font-src 'self'` | sound | Every font this app uses (`Bebas Neue`, `Inter`) is self-hosted via `@font-face src: url("/fonts/...")` in `assets/css/app.css` — no Google Fonts or other CDN reference anywhere in the codebase (confirmed by grep across `app.css` and the layout templates). `'self'` is already the correct, tightest value; nothing to change. |
| `connect-src` | `connect-src 'self' ws: wss:` | sound | `ws:`/`wss:` scheme sources are required for the LiveView websocket connection (`socket "/live"` in `endpoint.ex`); `'self'` covers any same-origin XHR/fetch. This is the transport the CSRF wiring audited in the CSRF section below rides on top of — narrowing this directive would break every LiveView page on the site, not just one feature, so per the plan's own instruction this value is not to be narrowed absent a concrete reason, and none was found. |
| `frame-ancestors` | `frame-ancestors 'none'` | sound | Deny-all clickjacking protection (T-01.7-09) — nobody may embed this app in a frame. This directive is **unrelated** to `frame-src` above: `frame-ancestors` governs who may frame *this app*, `frame-src` governs what *this app* may frame. A prior debug session (`.planning/debug/resolved/G-01.4-4-maps-thumbnail-approach.md`) had to establish this distinction explicitly after it was conflated once already — restated here so a future reader does not re-make that mistake. Newly pinned by exact equality this plan. |
| `base-uri` | `base-uri 'self'` | sound | Prevents a `<base>` tag injection (e.g. via a hypothetical stored-XSS gap elsewhere) from rebasing every relative URL on the page to an attacker-controlled origin. `'self'` is already correct; no page in this app needs a `<base>` tag pointed anywhere else. |
| `form-action` | `form-action 'self'` | sound | Restricts where any `<form>` on this app may submit, independent of `default-src`. This app's only forms are the catalog filter/search controls, which all submit same-origin; `'self'` is already correct. |

Total: **10 directives**, all adjudicated. `lib/pukllay_club_web/csp.ex` was not modified — every
verdict above is either `sound` (already correctly scoped, nothing to change) or `deliberate`
(the two D-08-locked exceptions, confirmed unchanged and now pinned).

## CSRF wiring section (SEC-04)

Per RESEARCH.md, this requirement is confirm-the-wiring, not build-new-code: all three pieces
were already correctly in place before this plan ran. `test/pukllay_club_web/liveview_csrf_test.exs`
(new, this plan) pins each wiring point so a future edit that removes one fails loudly:

1. **`lib/pukllay_club_web/components/layouts/root.html.heex`** (line 6) — the root layout emits
   `<meta name="csrf-token" content={get_csrf_token()} />` in the `<head>` of every page rendered
   through this layout (both LiveView routes and any plain-HTML route). Pinned by
   `liveview_csrf_test.exs`'s assertion that a GET of the catalog index *and* a second route (the
   About page) both return HTML whose head carries a non-empty, non-placeholder `csrf-token` meta
   value — proving the token is served by the shared layout, not by one page.

2. **`assets/js/app.js`** (lines 24-31) — the LiveView client reads that meta tag's value
   (`document.querySelector("meta[name='csrf-token']").getAttribute("content")`) and sends it as
   a socket connect parameter: `new LiveSocket("/live", Socket, { params: {_csrf_token:
   csrfToken}, ... })`. This is what makes the **websocket connect** itself CSRF-checked, not just
   form posts — pinned by a grep-based gate in the plan's `<verify>` block
   (`grep -qF '_csrf_token' assets/js/app.js`).

3. **`lib/pukllay_club_web/endpoint.ex`** (lines 14-16) — the `socket "/live", ...` declaration
   hands `connect_info: [session: @session_options]` to **both** the `websocket:` and `longpoll:`
   transport options, so the LiveView socket has the session available to validate the connect
   param's token against, on either transport. Also pinned by a grep-based gate in the plan's
   `<verify>` block, checking both transport keys independently.

### Live-reconnect check (backstop truth, human-check)

RESEARCH.md Assumption A3 (LOW-MEDIUM confidence, search-derived) found that
`Phoenix.LiveViewTest`'s `live/2` drives the LiveView process directly rather than through a real
browser websocket, so it does not exercise a genuine transport-level disconnect/reconnect with
token revalidation. This is why the reconnect half of SEC-04 is authored as a `backstop` truth
plus a `<human-check>` in the plan, not an ExUnit assertion — it is a gap in what `LiveViewTest`
can reach, not a gap in this plan's coverage. The `<human-check>` step: open the catalog in a real
browser, DevTools → Network → Offline → wait for the disconnect banner → Online, and confirm the
LiveView reconnects on its own with no invalid-token error and no reconnect loop, then confirm the
About page's Maps embed still renders (the CSP pass's real-world regression check). If a future
session finds a genuine ExUnit-level way to simulate this, RESEARCH.md flags that as worth
revisiting rather than assuming this session's finding is final.

## Deliberate exclusions (recorded, not silently omitted)

- **No CSP violation-reporting directive added.** Out of scope for D-08's audit-and-confirm
  framing — a new capability, not an audit finding, and a report endpoint would ship full request
  URLs to a collector with no known violations currently occurring. Recorded as accepted threat
  `T-01.7-12`.
- **The nonce work for JSON-LD (SEC-05) is explicitly Phase 01.8's, not this phase's.** This
  audit's exact-equality assertions pin today's values so that when Phase 01.8 does widen
  `script-src`, the diff to this test file is the visible, intended cost of that refactor.

<objective>
Audit the existing Content-Security-Policy directive by directive and pin what the audit confirms as
regression assertions, then confirm that CSRF protection genuinely covers LiveView's websocket
connect flow and not just plain form posts.

Purpose: this app's CSP is already close to a strong baseline, so the risk here is not that it is too
weak — it is that a well-meaning "tighten the CSP" pass silently breaks the About page's Maps embed
or the inline-style allowance Tailwind and daisyUI require, both of which are previously-debugged
deliberate decisions. D-08 scopes this pass to audit-and-confirm: change only what is actually wrong
or missing. The durable output is therefore a recorded verdict per directive plus assertions that
make each confirmed property fail loudly if a future pass erodes it.

Output: a CSP audit record, new regression assertions in the existing CSP test block, and a CSRF
wiring gate plus a recorded live-reconnect check.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party page → this app's frame | Who may embed this app; governed by the framing-ancestors directive |
| this app → third-party iframe | The single Google Maps origin the About page embeds; governed by the frame-source directive and computed from one source of truth |
| untrusted page content → browser script execution | Any injected markup reaching a rendered page; governed by the script-source directive |
| browser → LiveView websocket connect | The transport CSRF check that a form-post-only audit would miss |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01.7-08 | Tampering | script-source directive | high | mitigate | Exact-equality assertion pins the directive to the app's own origin only, so adding an inline-script or eval source fails the suite rather than shipping; the directive-count assertion catches a silently appended source directive |
| T-01.7-09 | Spoofing (clickjacking) | framing-ancestors directive | medium | mitigate | Exact-equality assertion pins the existing deny-all value; the audit record restates that this directive is unrelated to the Maps frame-source allowance, the exact conflation a prior debug session had to untangle |
| T-01.7-10 | Tampering | third-party frame-source origin | medium | accept | Exactly one computed origin, derived from `ClubLinks.maps_embed_origin/0` and already pinned by an existing string-equality assertion; widening it or adding a second origin needs its own decision, and the About page suite runs in this task's gate to catch a narrowing that breaks the embed |
| T-01.7-11 | Spoofing (CSRF) | LiveView websocket connect | high | mitigate | Three wiring points each pinned by an automated gate — the layout's token meta tag, the client's connect parameter, and the endpoint's session `connect_info` on both transports — plus a live browser reconnect observation for the transport behaviour ExUnit cannot reach |
| T-01.7-12 | Information Disclosure | CSP violation reporting | low | accept | Deliberately not added this pass — see `<deliberate_exclusions>`; a report collector would receive full request URLs, and no violations are currently known to occur |
| T-01.7-21 | Tampering | inline-style allowance | low | accept | Required by Tailwind and daisyUI, locked off-limits by D-08, and now pinned by exact equality so a future narrowing pass fails visibly instead of shipping a styling regression |
| T-01.7-SC | Tampering | npm/pip/cargo installs | — | accept | This plan installs no package-manager packages; RESEARCH.md records the phase's Package Legitimacy Audit as not applicable |
</threat_model>

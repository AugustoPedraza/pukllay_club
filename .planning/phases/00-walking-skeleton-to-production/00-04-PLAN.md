<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub secrets -> CI job -> host | Secrets flow from GitHub repo secrets, through the deploy job's env, into Kamal substitution — never onto host disk as literals or into git |
| ghcr.io -> host | The host pulls the image; registry auth uses the ephemeral GITHUB_TOKEN |
| internet -> kamal-proxy -> app | TLS terminates at kamal-proxy; the Postgres accessory is never internet-reachable |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-0-01 | Information Disclosure | .kamal/secrets / deploy.yml | high | mitigate | `.kamal/secrets` gitignored and substitution-only ($VAR), no literal values in any git-tracked file; deploy.yml env.secret names only (values resolved at deploy time) |
| T-0-02 | Information Disclosure / Elevation of Privilege | Postgres accessory | high | mitigate | Bind accessory to `127.0.0.1:5432:5432` only (D-15) — never 0.0.0.0; host firewall verified live in plan 00-05 (Docker iptables bypasses UFW, so localhost bind is the real control) |
| T-0-03 | Elevation of Privilege | GITHUB_TOKEN in build/push job | high | mitigate | Scope the build job to `permissions: contents: read, packages: write` explicitly — not the default broad token |
| T-0-04 | Spoofing / Elevation of Privilege | DEPLOY_SSH_KEY | high | mitigate | Key lives only as a GitHub repo secret, loaded transiently via webfactory/ssh-agent for the job's ephemeral lifetime — no plaintext copy on any runner disk |
| T-0-05 | Tampering | Kamal healthcheck | medium | mitigate | deploy.yml sets a `/up` healthcheck so cutover is gated on readiness; the health check is never disabled to force a deploy (prohibition) |
</threat_model>

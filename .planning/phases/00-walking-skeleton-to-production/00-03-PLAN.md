## Phase Goal (MVP user story)

**As a** solo developer/operator, **I want to** every PR automatically gated by `mix quality` against a real Postgres service, **so that** no change reaches `main` (and therefore production) without passing the quality bar.

<objective>
Create the CI quality gate: a GitHub Actions workflow that runs `mix quality` on every PR against a Postgres service with dependency/build caching, plus the branch protection that makes that check a required merge gate. This is DEPLOY-02.

Purpose: DEPLOY-02 — every PR runs CI and must pass before merge.
Output: `.github/workflows/ci.yml` and branch protection on `main` requiring the CI check.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR author -> CI runner | Untrusted PR code runs in the CI job; the job's token scope bounds what it can do |
| CI check -> main | The required status check is the gate between an unreviewed change and main/production |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-0-03 | Elevation of Privilege | GITHUB_TOKEN scope in ci.yml | high | mitigate | Declare least-privilege `permissions: contents: read` at the workflow level — the CI job only checks out and runs tests; it never needs write scope (packages:write is scoped to the build/push job in plan 00-04, not here) |
| T-0-05 | Tampering | merge gate | medium | mitigate | Branch protection makes the CI check a required, admin-non-bypassable merge gate (Task 3) so a failing gate cannot be force-merged |
</threat_model>

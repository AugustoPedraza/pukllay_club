# Phase 01.1 Plan 07: Non-Happy-Path States — Empty, Error, Loading, and 404 Summary

**Aligned the catalog's zero-results/load-error branches, the detail page's loading skeleton, and `/juegos/:id`'s 404 to `empty-loading-error-states.md`'s validated copy and shape — replacing daisyUI's default alert/bg-base-200 treatment, animated shimmer skeletons, and Phoenix's plain-text 404 with one shared `.pk-state`/`.pk-skel` CSS layer and a real branded not-found page.**

## Performance

- **Duration:** ~35 min
- **Tasks:** 3 (all `type="auto"`)
- **Files modified:** 9 (1 created, 8 modified)

## Accomplishments

- Catalog's zero-results state now reads exactly "No se encontraron juegos" / "Probá con otros filtros o términos de búsqueda." with one `Limpiar filtros` action; the load-error state now reads "No pudimos cargar el catálogo" / "Hubo un problema de conexión." with a working `Reintentar` action wired to a new `handle_event("retry", ...)` that re-enters the existing `apply_filters/1` pipeline.
- Both states, plus the new 404 page, share one CSS shape — `.pk-state`/`.pk-state h2`/`.pk-state p` in `app.css`'s `PK CATALOG SURFACES` block — so they cannot visually drift from one another. Both action buttons use `CoreComponents.button/1`'s `"primary"` variant rather than bespoke markup.
- `CarouselRow.skeleton_row/1` and `skeleton_card/1` now use `.pk-skel` (flat, no `@keyframes`, no shimmer) instead of daisyUI's animated `skeleton` class — still sharing `.pk-card-poster`/`.pk-card-caption` with the real card so nothing reflows when real content lands.
- `CatalogLive.Show` gained the same disconnected/connected two-phase mount trick `CatalogLive.Index` already uses: `:loading` skips `Catalog.similar_games/1` on the disconnected pass (a flat skeleton shelf occupies the same footprint instead) and the connected mount runs the real query through a new `safe_similar_games/1`, whose `rescue` degrades a failing "more like this" lookup to no shelf — `carousel_row/1`'s own `:if={@games != []}` guard already renders nothing, so no second error surface was needed.
- `Ecto.NoResultsError` from `Catalog.get_game!/1` now surfaces a branded 404 (`Juego no encontrado` / one link back to the catalog) end-to-end instead of Phoenix's generated plain-text "Not Found" — `render_errors` renders through `{PukllayClubWeb.Layouts, :root}` so the error page inherits the app's real `<head>` (stylesheet, theme script, `lang="es"`), and `PukllayClubWeb.ErrorHTML` now `embed_templates "error_html/*"` while keeping its plain-status-string fallback for every status without its own template (500 deliberately not added).

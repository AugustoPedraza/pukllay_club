<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `handle_event("reserve", ...)` | A free-text visitor name (a person's name — inherently unconstrained, not whitelistable) crosses into the server and back out into a rendered URL. |
| runtime env → application config | The club's WhatsApp number enters the release from the deploy environment, not from source. |
| render → WhatsApp | The visitor is handed a `wa.me` URL carrying their own name in a query parameter. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01.1-02 | Tampering | reservation name field → `wa.me?text=` | high | mitigate | The name is not whitelistable, so the control is containment: it is trimmed and length-capped server-side, rendered through HEEx (which escapes it in the preview), and percent-encoded with `URI.encode_www_form/1` before being concatenated into the query string — server-side, so no client code assembles the URL. Tests 6 and 7 in Task 3 assert the name cannot break out of the `text=` parameter. |
| T-01.1-19 | Information Disclosure | visitor's typed name | high | mitigate | The name is held only in socket assigns for the life of the modal: no `Repo` write, no `Logger` call, no telemetry, no flash. Prohibition recorded in `must_haves.prohibitions` and asserted by grep in Task 2. |
| T-01.1-20 | Spoofing | the reservation destination number | high | mitigate | The number lives only in runtime config; a `:prod` boot with `RESERVATION_WHATSAPP_NUMBER` unset raises rather than rendering a placeholder or an empty `wa.me/` path. It is normalised to digits so a malformed paste cannot silently produce a link to a different account. Asserted by the source-literal grep and the nil-config test. |
| T-01.1-21 | Denial of Service | unbounded name input | low | mitigate | Server-side 60-grapheme cap rejects oversized submissions before any string building; `CoreComponents.input/1` also carries `required`. |
| T-01.1-SC | Tampering | dependency supply chain | low | accept | No package-manager install occurs — `mix.exs`/`mix.lock` untouched. |
</threat_model>

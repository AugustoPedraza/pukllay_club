## D-05 is deliberately superseded by this plan

`01.1-CONTEXT.md`'s **D-05** put the `Sumate` CTA in the header site-wide, and plan 01.1-01
implemented it as a hardcoded non-slot inside `header_inner/1` — an explicit, documented deviation
from `01.1-PATTERNS.md`'s suggested slot, taken because *a slot can be omitted by a caller*, which
would silently reintroduce the per-page-fork risk SHELL-01 exists to prevent.

Sketch 017 Round 3 reopened that decision on the developer's direct, twice-repeated instruction, and
sketch 017's own README flags the reopening as an implementation cost rather than a template edit.
This plan carries it out. The reasoning, recorded here so the prior rationale is superseded and not
silently dropped:

- **Search and the CTA move in opposite directions for the same reason.** Search became cheap enough
  to put on *more* pages (Catálogo **and** Detalle, reopening the 003/011 Catálogo-only rule) exactly
  because it stopped needing a permanent 220px box — a 44px icon costs almost no row. The CTA follows
  the opposite logic: it was never a space problem, it was a *context* problem. "Join the club" asks
  for a commitment before the value case has been made, and the only page that makes that case is
  Quiénes Somos. Asking on Detalle competes with someone mid-way through reading one game's rules.
- **D-05's structural guarantee is replaced by a stronger executable one.** D-05 chose
  "always rendered, no slot" because slot omission is silent. Task 2 replaces that with tests that
  assert the CTA is *absent* on `/` and `/juegos/:id` **and** *present* on both `/club` and
  `/quienes-somos`. That is strictly stronger than "always renders": it also catches accidental
  reintroduction into the header, which the original mechanism could not.

`01.1-PATTERNS.md` is updated in Task 2 to record the supersession at its source.

**3. `.CatalogNav` — extend the one existing hook, never add a second.**
Inside the same colocated `<script :type={Phoenix.LiveView.ColocatedHook} name=".CatalogNav">` block:

- Add `publishHeaderHeight()` reading `this.el.getBoundingClientRect().height` and writing
  `document.documentElement.style.setProperty("--pk-header-h", height + "px")`. Call it at the end
  of `mounted()`, from a `ResizeObserver` on `this.el` (copy `.CarouselScroll`'s `ResizeObserver`
  shape), and from a new `updated()` callback. Disconnect the observer in `destroyed()`.
  This plan owns the publisher because this plan is what changes the header's real height (the
  48px CTA and the 48px toggle both leave the row in Tasks 2 and 3) — `01.1-01-SUMMARY.md`'s open
  item 1 flagged exactly this. Plans 01.1-03 and 01.1-04 are consumers only.
- Add the morph behaviour, all of it guarded on `this.morph` existing so the Quiénes Somos header
  (which renders no search) is unaffected:
  - `openMorph({focus} = {focus: true})` adds `is-open` to the morph, adds `is-search-open` to
    `.pk-nav-inner`, sets the toggle's `aria-expanded` to `"true"` and its `tabindex` to `"-1"`,
    sets the close button's `tabindex` to `"0"`, and focuses the region's `input` when `focus`.
  - `closeMorph()` reverses every one of those and returns focus to the toggle.
  - Listeners: `click` on the toggle opens; `click` on the close button closes; a document-level
    `keydown` closes on `Escape`; a document-level `click` closes when the morph is open and
    `!this.morph.contains(e.target)`. Remove all four in `destroyed()`.
  - `syncMorph()` reads `this.morph.dataset.searchExpanded === "true"` and, if so and not already
    open, calls `openMorph({focus: false})`. Call it at the end of `mounted()` and from `updated()`.
    It only ever opens, never closes — closing is user-driven, so a server round-trip can never
    yank an open box shut.
- All of this behaviour must live in this hook. The app's CSP is `script-src 'self'`, so DOM
  event-handler attributes written directly into markup are silently refused by a real browser
  (`01-REVIEW.md` CR-01 already burned this project once with an inline `<script>` block).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `mount/3` + `handle_params/3` double `stream(reset: true)` before first render**
- **Found during:** Writing this plan's own required URL-param tests (`?weight_bands=`/`?mechanics=` filtering) — both consistently rendered the unfiltered AND filtered result sets concatenated, while the `:total` assign was correctly reduced.
- **Issue:** `mount/3`'s connected branch called `apply_filters/1` (default/empty filters), then `handle_params/3` called it again (real URL filters) — both before the first render. LiveView's stream diff accumulates `stream/4` insert operations across multiple calls issued before any render flushes; the second `reset: true` did not clear the first call's queued entries.
- **Fix:** `mount/3` no longer calls `apply_filters/1` — it now sets the same skeleton placeholder state (`offset: 0, total: 0, load_error: false, stream(:games, [])`) on both the disconnected and connected phases. `handle_params/3` (which Phoenix always invokes right after mount) is now the single authoritative place that calls `apply_filters/1`.
- **Files modified:** `lib/pukllay_club_web/live/catalog_live/index.ex`
- **Verification:** `mix test` (full suite, 331/331) green; the two URL-filter tests that surfaced this now pass correctly.
- **Committed in:** `fdb1025`

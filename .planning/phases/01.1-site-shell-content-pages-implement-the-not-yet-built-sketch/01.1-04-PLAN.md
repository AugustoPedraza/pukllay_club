**Hook `.DetailChrome`** (static string literal in `phx-hook`, per `layouts.ex`'s documented
reason):
- `mounted()` resolves `#detail-cta-bar`, `#detail-title-echo`, `#detail-title-block` and
  `document.querySelector("footer.pk-footer")`, then adds a `pk-has-cta-bar` class to
  `document.body`.
- One passive `window` `scroll` listener runs three things:
  1. **Debounced hide-while-scrolling.** Return immediately if the parked flag is set (the
     debounce must never fight the parked state). Otherwise add `is-hidden` to the CTA bar, clear
     a pending timer, and set a new `setTimeout` of 200ms that removes `is-hidden`.
  2. **Footer park.** `footerReached = footer.getBoundingClientRect().top < window.innerHeight`.
     Toggle `is-parked` on both bars and `pk-cta-parked` on `document.body` from that one flag.
  3. **Title echo.** `scrolledPast = titleBlock.offsetParent !== null &&
     titleBlock.getBoundingClientRect().bottom < headerHeight`, where `headerHeight` is read from
     the `--pk-header-h` custom property on `document.documentElement` (never a literal 64).
     Toggle `is-visible` on the echo bar from `scrolledPast && !footerReached`. The
     `offsetParent !== null` guard is mandatory: a hidden element's rect is all zeros, which
     satisfies the threshold and would show the bar when it should not.
- A delegated `click` listener on `this.el` handles `[data-scroll-top]` with
  `window.scrollTo({top: 0, behavior: "smooth"})`.
- Call the scroll handler once at the end of `mounted()` so both bars are correct on first render
  with no scroll needed.
- `destroyed()` removes the scroll and click listeners, clears the timer, and removes both body
  classes.
Do **not** use `IntersectionObserver` anywhere in this hook — Chrome throttles/suspends its
callbacks whenever `document.visibilityState` is not `visible`, which silently broke exactly this
pattern during sketching.

**CSS**, inside the existing `PK CATALOG SURFACES` block, placed immediately after plan 01.1-03's
`.pk-detail-*` rules:
- Declare the detail layout breakpoint **once** and use it for both concerns, in adjacent rules
  with a comment saying they must flip together: base (mobile-first) is
  `.pk-mobile-cta-bar { display: flex; ... }` and a single-column `.pk-detail-masthead`; a
  `@media (min-width: 48rem)` block turns the masthead into the two-column sticky grid and sets

  block is deliberate — an equal-specificity base rule sitting *after* its media override silently
  wins at every width, which is the exact bug documented twice in the sketch findings. Record in
  the SUMMARY that `48rem`/768px is a new breakpoint for this repo (ux-responsive notes only `sm:`
  and `lg:` are in use) and that the reason is a buy-box beside a reading column needs roughly
  768px to stay legible.
- `.pk-mobile-cta-bar` — `position: fixed; left: 0; right: 0; bottom: 0; z-index: 45;` with
  `background: var(--color-base-200)`, deliberately one step from `var(--color-base-100)` so the
  bar does not fuse with its own outlined child button (verify with computed `backgroundColor`,
  not by eye). Transition `transform` and `opacity` with `var(--duration-base)
  var(--ease-out-soft)`.
- `.pk-mobile-cta-bar.is-hidden { transform: translateY(12%); opacity: 0; pointer-events: none; }`
  — the "paused" state, a nudge, not a slide-away.
- `.pk-mobile-cta-bar.is-parked { transform: translateY(100%); opacity: 0; pointer-events: none; }`
  — the "gone" state. Two distinct classes with two distinct treatments and independent
  lifecycles.
- `body.pk-has-cta-bar { padding-bottom: 9.25rem; transition: padding-bottom var(--duration-base)
  var(--ease-out-soft); }` and, declared **after** it, `body.pk-cta-parked { padding-bottom: 0; }`.
  Scoping the padding to a body class rather than a bare `body` selector keeps every other page
  unaffected; the parked rule must sit later in the file since the two have equal specificity.
- `.pk-title-echo` — `position: sticky; top: var(--pk-header-h, 4.5rem); z-index: 40;` opacity 0 /
  `pointer-events: none` at rest, `.is-visible` opacity 1, `.is-parked` retracted. Sticky rather
  than fixed: it has a natural container.
- `.pk-scroll-top` — a continuous, gentle `translateY` bounce keyframe wrapped in
  `@media (prefers-reduced-motion: no-preference)` so it reads as "there's more above, tap me" for
  as long as the bar is visible, not a one-shot on-appear animation.
**Stacking order across the whole shell (do not pick these numbers independently).** The layers are
already assigned: `.pk-title-echo` 40 and `.pk-mobile-cta-bar` 45 (this plan), `.pk-header-sticky` 50

No literal hex, no arbitrary Tailwind value, no inline `style=`; no `container-type`, `transform`,

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `handle_event("select-image", ...)` | A client-supplied image URL reaches a handler that echoes it into an `img src` — now on two surfaces (inline strip and lightbox). |
| colocated hook → DOM | `.DetailChrome`, `.Lightbox` and `.ShareButton` run client-side against server-rendered elements and `data-*` attributes. |
| render → third-party intent URLs | The share fallback links out to WhatsApp and X with the game's title and canonical URL. |

Claude's-discretion resolutions recorded here for review:
1. **`48rem`/768px is a new breakpoint for this repo.** `ux-responsive` records that only `sm:`
   (640px) and `lg:` (1024px) are in use and that a new one "needs a reason". The reason: a
   320px poster column beside a reading column stops being legible below roughly 768px, and
   `detail-page-mobile-interaction.md` itself specifies the CTA bar at that width. Declared once
   and shared by both the masthead grid and the CTA bar toggle so they cannot drift.
   **Needs developer review.**
2. **The reserved bottom padding is scoped to `body.pk-has-cta-bar`**, added by the hook on mount
   and removed on destroy, rather than to a bare `body` selector — otherwise every page in the app
   would carry 148px of dead space. This is a deliberate departure from the sketch's own CSS.
3. **The lightbox has no client-side index.** It renders the existing `:selected_image` assign, so
   "carousel and lightbox share one state" is structural rather than something two listeners have
   to keep in sync — and the existing whitelist guard covers both surfaces for free.

Unresolved and carried forward: the actual scroll-hide/park/echo timings and the bar's colour
separation can only be confirmed on a real device or a real 390px Chrome viewport — the sketch's
own automation tool capped at ~335px and never reproduced the header-height bug it eventually hit.
These are in 01.1-VALIDATION.md's Manual-Only table.

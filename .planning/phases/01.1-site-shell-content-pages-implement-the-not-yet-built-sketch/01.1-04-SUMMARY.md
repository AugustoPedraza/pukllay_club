# Phase 01.1 Plan 04: Detail Page Mobile Chrome and Interaction Summary

**Gave the game detail page its mobile buy-box: a fixed reservation CTA bar and a sticky title-echo bar driven by one passive scroll listener (never IntersectionObserver), plus a selection-synced lightbox and a native-Web-Share-API-first share control with a fully server-rendered fallback popover — completing SHELL-03's "on both desktop and mobile" half.**

## Performance

- **Tasks:** 3 (all `type="auto"`) — all complete
- **Files modified:** 3 (1 LiveView, 1 CSS, 1 test)

## Accomplishments

- `.DetailChrome` colocated hook: one passive `scroll` listener drives three independent behaviors (debounced hide-while-scrolling, footer-park, title-echo visibility), each guarded correctly (`offsetParent !== null` for the title-echo threshold, never fighting the parked state for the debounce) — zero `IntersectionObserver` usage in this file.
- `.pk-detail-masthead`/`.pk-poster-col` restructured mobile-first: single-column/static poster below a new `48rem` detail layout breakpoint, two-column sticky grid above it — declared once, alongside `.pk-mobile-cta-bar`'s display toggle, so the two concerns can never drift apart. The now-redundant 480px-block overrides from plan 01.1-03 were removed rather than left as dead code.
- `.pk-mobile-cta-bar` (z-index 45, below plan 01.1-09's drawer at 60/61) and `.pk-title-echo` (z-index 40) ship with independent `.is-hidden`/`.is-parked` lifecycles and a reserved `body.pk-has-cta-bar` padding that collapses to 0 in the same transition as `.is-parked`.
- Lightbox renders `@selected_image` directly (the same assign the inline gallery strip renders) — opening it always opens on the currently selected image, and its previous/next controls reuse the existing `select-image` handler and whitelist via `lightbox_neighbor/3`, so there is no second, unguarded image-selection path.
- `share_control/1` — one shared private component rendered once in the buy-box column and once in the mobile CTA bar — calls `navigator.share()` when available and otherwise reveals a fully server-rendered fallback popover (WhatsApp/X intent links built in Elixir with `URI.encode_www_form/1`, copy-link via `navigator.clipboard`). No client-side URL or markup assembly anywhere in the file.
- New `describe "detail page mobile chrome and interaction (SHELL-03)"` block: 7 tests covering every server-observable part of the contract; the three genuinely visual/timing behaviors (scroll-hide debounce, footer park + padding collapse, title-echo fade-in) are explicitly routed to `01.1-VALIDATION.md`'s Manual-Only table and logged as `WINDOWS.md` entries #9–#10 rather than faked as assertions.

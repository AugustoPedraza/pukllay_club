| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1` chip/pill rows) |

## Typography

Inherited verbatim from `ui-design-system`'s measured Catalogue-screen inventory (**already at the
project's 3-tier cap** — heading / body / muted, weight as the sanctioned emphasis lever within the
body tier). Phase 2 introduces **zero new type combos**; every new surface (search state copy,
favorite affordance, auth pages) maps onto these four existing rows. No "Display" tier exists
separately from "Heading" in this app — Bebas Neue at 24px/400 serves both roles, which is why the
row below is shared.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (Inter) — 12px below 480px, matching the app's one documented narrow-viewport density step | 400 | 1.5 |
| Label (emphasis) | 14px (Inter) — 12px below 480px | 600 | 1.5 |
| Heading | 24px (Bebas Neue, `font-display`) | 400 | 1.2 |
| Display | same as Heading — this app has no separate Display tier (see cap note above) | 400 | 1.2 |

Muted/secondary text convention: `text-neutral text-sm` (12px/400) — used for search-state helper
copy ("Ajustando resultados…"), auth-page subtitles, and favorites empty-state body text. Never
`text-base-content/70`.

### Backstop items requiring verification (4)

The four `🧪 backstop` rows above are the real, honest gaps this phase's design does not fully
close in prose — each needs an explicit test or implementation decision, not just inspection,
before Phase 2 can be considered verified:

1. **Search-input re-submission racing** (E2/loading) — stale-job handling while a prior hybrid
   pipeline job is in flight.
2. **Favorites-list load failure** (E3/error) — no defined error UI for a DB error on mount.
3. **Favorite-toggle save failure** (E4/error) — no defined rollback if the optimistic save fails.
4. **Long email wrap in magic-link confirmation** (E5/long-text) — text-wrap contract needs a
   synthetic long-email test case.

## Search Result State Machine **[NEW]**

Not covered by the template's core tables but load-bearing for SEARCH-01 through SEARCH-04 — the
planner and executor need this sequence to implement the async-never-on-hot-path requirement
without inventing a new results surface.

1. **Member types** in the existing `.pk-search-morph` input (unchanged: `phx-change="search"`,
   `phx-debounce="300"`). Every keystroke still does the existing cheap tsvector substring
   narrowing against the flat grid — **this behavior does not change for Phase 2.**
2. **Member submits** (presses Enter, or the search-morph's existing icon becomes an explicit
   submit affordance when text is present — reuse the icon-only, `aria-label`-only convention, no
   new visible "Buscar" button chrome). Submission does two things at once:
   a. Immediately re-renders the flat grid with the current keyword-only (`tsvector`) ranking —
      this is the existing `filter_games/1` path, already fast and already synchronous. The member
      always sees *something* the instant they submit, satisfying SEARCH-04's "never an error"
      baseline even if the async step below never completes.
   b. Enqueues one Oban job (embedding + LLM query-parse against the Phase 1 tag vocabulary,
      SEARCH-02) — never inline in the LiveView `handle_event`, satisfying SEARCH-03.
3. **While the job is in flight**, a small `text-neutral text-sm` line reading "Ajustando
   resultados…" appears directly above the grid (not a full skeleton — the grid is already
   populated with real cards from step 2a). Extend the approved-but-unbuilt "shimmer scoped to
   repopulation" pattern from `carousel-mechanics.md` (sketch 025) to this flat grid: when the
   hybrid-ranked result set arrives, briefly shimmer only the cards whose position is changing
   (not the whole grid, not a full-page skeleton) before settling into the new order. This is a
   distinct, narrower moment from the flat/no-shimmer full-page load (`empty-loading-error-states.md`,
   sketch 009) — do not conflate the two or reuse `.pk-skel`'s flat treatment here.
4. **On success**, the LiveView receives the hybrid-ranked result set (PubSub broadcast or Oban
   completion callback — an implementation detail for `gsd-plan-phase`, not this spec), the grid
   re-orders in place, and the "Ajustando resultados…" line disappears.
5. **On failure/timeout/rate-limit**, the "Ajustando resultados…" line simply disappears and the
   grid stays exactly as it was from step 2a. No toast, no error state, no retry button — this is
   the literal UI expression of SEARCH-04.

## Favorites Interaction **[NEW]**

- **Placement:** an icon-only heart button overlaid on the card poster's top-right corner (not a
  new metadata row — the resting card stays "poster + title only" per `card-interaction.md`; the
  heart sits *on* the image, the same way a corner badge would, not beside the caption). Backed by
  a subtle scrim (`bg-base-100/60` or equivalent existing overlay convention, if one exists in the
  codebase — otherwise a minimal radial gradient) so the icon stays legible over any cover art.
- **States:** `hero-heart` (outline, neutral color) at rest → `hero-heart-solid` (filled,
  `text-primary`, the app's 10% accent) when favorited. Always visible, never hover-only (per
  `ux-responsive`'s "hover is never the sole affordance" rule — touch devices need this reachable
  by tap alone at every viewport).
- **Also present** inside the existing hover-preview/mobile-sheet surface (`GamePreview`), as a
  secondary icon-button alongside the existing outlined "Ver detalles" CTA — same
  `hero-heart`/`hero-heart-solid` swap, same accent-on-active rule.
- **Logged-out tap:** the heart is visible to every visitor (not hidden), but tapping it while
  logged out routes to the login entry point (`/iniciar-sesion` or equivalent) with a flash
  message "Iniciá sesión para guardar favoritos" and the intended game id preserved so the
  favorite can complete automatically after a successful magic-link sign-in. This "validate after
  the attempt, don't disable beforehand" shape matches `ui-design-system`'s Affordance rule
  ("prefer leaving it enabled and validating after the attempt over disabling it beforehand").
- **Toggle is optimistic** (see UI Considerations "loading" row above) — no spinner, no
  round-trip wait before the icon flips.

## Auth Pages **[NEW]**

phx.gen.auth-generated pages, restyled to match the brand (not left at generator defaults):

- **Container:** single centered column, `max-w-sm` (auth forms are inherently narrower than the
  catalog's `max-w-7xl` shell — this is a deliberate, scoped exception, not a violation of the "one
  page container per page" rule, since auth pages are a distinct page family from the catalog
  shell), `rounded-box bg-base-200 p-4` card (existing `p-4` card-body padding convention), on the
  `Layouts.app` shell (shared header/footer, unchanged — auth pages are not a chrome-less special
  case).
- **Heading:** `font-display text-2xl` (the app's one Heading tier) — "Iniciar sesión".
- **Subtitle:** `text-neutral text-sm` (muted tier) — "Te enviamos un enlace para entrar sin
  contraseña."
- **Field:** `CoreComponents.input/1`, type `email`, label "Correo electrónico", placeholder
  "tu@email.com" — no new input component.
- **Submit:** `CoreComponents.button/1` `variant="primary"` (the page's one action) — "Enviar
  enlace de acceso".
- **Post-submit confirmation and error states:** see Copywriting Contract above; both reuse the
  existing `empty-loading-error-states.md` one-heading/one-body/one-button shape.
- **Account entry point (header/drawer):** icon-only control, same bare/monochromatic/
  `sr-only`-labeled convention as the theme toggle (`header-navigation-drawer.md` 014/018) —
  `hero-user` (logged out, label "Iniciar sesión") / `hero-user-circle` (logged in, label "Mi
  cuenta"). Desktop: lives in `.pk-nav-actions` alongside the theme toggle. Mobile: another list
  row inside the existing drawer nav-links section (not the bottom-pinned theme/social block,
  which per 021 is reserved for config/passive-destination items — sign-in is a primary action,
  so it belongs with the drawer's other list-row nav links). Logged-in state opens a minimal menu
  with two items: "Mis favoritos" (→ `/favoritos`) and "Cerrar sesión".

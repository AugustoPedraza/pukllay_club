## Tests

### 1. Recomposed reading-column visual read at 390px and 1440px
expected: |
  Open a fully-enriched game's detail page (e.g. Wingspan Asia, Spirit Island) at both widths.
  The composition should read as title → lightweight accent-coloured hashtags → description →
  one two-column fact grid (Diseñadores/Ilustradores/Mecánicas/Temáticas) → Comunidad BGG, with
  no divider line inside the reading column. The hashtags should read as text, not a filled
  pill. The fact grid should visually pair up into two columns at 1440px and stack to one column
  at 390px. "Comunidad BGG" should read as a sensible group label, not "Avanzado".
result: issue
reported: "I can't see the hashtags below title"
severity: major

### 2. BGG stat rows link to the correct game on real pages
expected: |
  Open 2-3 real game detail pages (e.g. Wingspan, Spirit Island). Valoración / Peso / Ranking
  (under the Comunidad BGG label) each render with a correctly formatted value (X.X/10, X.X/5,
  #N) and link to https://boardgamegeek.com/boardgame/{that game's bgg_id} — not a different
  game or BGG's homepage.
result: pass

### 3. Spanish description language quality
expected: |
  Open three game detail pages (short/long/unusual-title descriptions). Description reads
  naturally in Argentine (Rioplatense) Spanish, proper nouns/mechanic names survive untranslated,
  no stray escape sequences remain. (The expand/collapse mechanism itself is now covered by an
  automated 6-transition round-trip test and does not need a human check — this item is scoped
  to language quality only.)
result: pass

### 4. Description justify, mid-word-cut risk, and toggle ink alignment
expected: |
  Across 3 real games with short/long/unusually-titled descriptions, at BOTH 390px and 1440px, in
  BOTH light and dark theme: (1) the description text is justified at both widths; (2) the
  clipped third line ends on a whole word — if any combination cuts mid-word, the pre-decided CSS
  fallback recorded in 01.3-08-PLAN.md's planner_note should be applied rather than re-tuned or
  re-sketched; (3) the "…" and the chevron read as vertically aligned on their visible ink, not
  merely on their boxes — if not, re-tune `.pk-desc-toggle-icon`'s `translateY` against the real
  Inter rendering; (4) tapping the chevron on a phone-width viewport expands and collapses
  reliably across several round trips.
result: issue
reported: "this fails. See how the chevron isn't inside the text limits (screenshot attached, Honey Buzz description card at 390px: chevron sits outside the right edge of the text column)"
severity: blocker

### 5. Sticky title-echo bar visual read, both themes, at 390px
expected: |
  At 390px, scroll a long game page until the mobile sticky title bar appears, in both light and
  dark theme. The bar should read as a visually distinct surface over the content passing beneath
  it (not blending into the page background), its title should truncate cleanly with an ellipsis
  rather than wrapping, and its left/right content edges should line up with the masthead's. Note:
  the bar's brand-tint/color treatment and `.pk-scroll-top`'s bounce animation were deliberately
  left unchanged this round (see 01.3-09-SUMMARY.md "Open design questions") — this check is only
  about separation, legibility and alignment, not overall brand styling.
result: issue
reported: "Needs a better balance with colors, weight, size and font"
severity: cosmetic

<objective>
Prove the entire D-06 data path end-to-end on one statistic, then build the offline jobs that will
carry the rest.

`01.3-RESEARCH.md` establishes that nothing in this phase is technically novel — every mechanism
already exists in this codebase or in a library the project has committed to. The real risk is
**data-quality assumptions**, and three of them can only be settled by running the path: does BGG's
statistics block actually yield a usable rating and overall rank; does the soft-cast xpath modifier
really absorb BGG's unranked marker; does a narrow re-enrichment changeset write cleanly without
dragging the R2 image pipeline behind it. This plan wires exactly one statistic — Valoración BGG —
from raw XML to a rendered Ficha técnica row, then adds the two offline jobs that populate the rest.

Two data facts found by direct query against `pukllay_club_dev` shape this plan and are not
optional decoration: 368 of 377 games with artist data carry severe duplication in `bgg_payload`,
and 2 games already hold `bgg_weight = 0`. `0.0` is truthy in Elixir, so the UI-SPEC's plain
truthiness render guards would happily print "0.0/5" as if it were a measurement. Both are fixed at
the extraction layer, in one place, so `mix catalog.seed` inherits the fix for free.

Purpose: catch an architectural dead end after one commit instead of after five.
Output: three real columns, a clean extraction layer, one visible row on the detail page, and two
runnable offline jobs ready for the population run in 01.3-02.
</objective>

# Phase 01.3 — UI Design Contract

> Visual and interaction contract for Game Detail Layout & Content Accuracy. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This is a refinement phase on an already-shipped, brand-locked design system
(Phase 1 / 1.1 / 1.2, validated by 37+ sketch rounds — see
`.claude/skills/sketch-findings-pukllay_club/`). Nothing below invents a new visual language.
Sections that restate existing tokens do so because the template requires them; the load-bearing
new content is the **Phase-Specific Layout & Interaction Decisions** section, which resolves D-01
through D-06 from `01.3-CONTEXT.md` into concrete, implementable values — most centrally **D-03/
D-04 (reading-column visual hierarchy)** and **D-05/D-06 (Ilustradores + BGG advanced-stats
block)**, which `01.3-CONTEXT.md` explicitly flagged for this agent rather than blind planning.
D-01/D-02 (Spanish translation + markup cleanup of the `description` field) are content-accuracy
fixes with **no visual decision to make** — they change what text is stored, not how it renders —
and are noted here only for completeness/traceability.

## Spacing Scale

Declared values (all multiples of 4px, matching Tailwind's default scale — this project has never
overridden `--spacing-*`):

| Token | Value | Usage in this phase's scope |
|-------|-------|------------------------------|
| xs | 4px | not touched this phase |
| sm | 8px | **NEW this phase (D-03/D-04):** `.pk-reading-section`'s internal gap — the tight rhythm between a section's own heading (or title) and its immediately-following content (chip row, description, spec grid) |
| md | 16px | `.pk-spec-list`'s row `gap` stays unchanged at `1.5rem` (24px, see `lg` below — not `md`); `.pk-divider`'s own margin stays `0`, spacing supplied entirely by the parent gap |
| lg | 24px | `.pk-spec-list { gap: 1.5rem; }` (existing, unchanged) — spacing between individual Ficha técnica rows, including the new Ilustradores/Peso BGG/Valoración BGG/Ranking BGG rows, which reuse this same grid |
| xl | 32px | **NEW this phase (D-03/D-04), reason documented:** `.pk-text-col`'s own gap, raised from the current flat `1rem` (16px) to `2rem` (32px) — the single biggest lever for the "reads as one continuous flat block" complaint. Previously flagged in 01.2-UI-SPEC as "not currently used anywhere this phase touches; do not introduce without a documented reason" — this is that reason. |
| 2xl | 48px | `.pk-detail-masthead`'s `gap: 3rem` between poster-col and text-col — unchanged by this phase |
| 3xl | 64px | not used |

Exceptions: none beyond the two-tier rhythm above (sm=8px within a section, xl=32px between
sections) — this is a deliberate two-value system, not a third scale.

Resolves `01.3-CONTEXT.md`'s D-01 through D-06. Cross-reference by ID.

### D-03 / D-04 — Reading-column visual hierarchy (the load-bearing new visual decision in this phase)

`01.3-CONTEXT.md` explicitly routed this here rather than deciding blind in plan-phase: "the
problem is not ordering; it's that the sections lack visual distinction... the page as a whole
still reads as too plain/packed." Section order stays exactly as shipped (Título → Descripción →
Mecánicas → Temáticas → Ficha técnica → Juegos similares) — this resolves the visual **HOW**, not
a restructure.

**Root cause, grounded in the shipped CSS (`app.css:3004-3014`):** `.pk-text-col` is a flex column
with a single flat `gap: 1rem` applied uniformly between every child — title, description block,
divider, editorial tags, each heading, each chip row, and the Ficha técnica grid all sit exactly
16px apart regardless of whether they're closely related (a heading and its own content) or
genuinely distinct topics (the end of one section and the start of the next). `.pk-section-heading`
only differs from body text by font-family and size (`1.25rem` display font) plus an ad-hoc
`margin-top: 0.5rem` that fights the flex gap rather than replacing it. This uniform spacing is
what produces the "one continuous flat block" complaint — nothing currently signals "new topic
starts here" more strongly than "next line of the same paragraph."

**Fix — two-tier spacing, one new wrapper class, one heading-style addition:**

1. **Introduce `.pk-reading-section`** — a plain, chrome-free `display: flex; flex-direction:
   column; gap: 8px;` wrapper (no border, no background, no shadow — purely a spacing control, not
   a new bordered "card" pattern). This is a deliberate minimal-diff choice: `detail-page-layout.md`
   (sketch 037) already found that a shared bordered/tinted container is *not* the right fix for
   "these elements feel disconnected" on this page — proximity + rhythm won that comparison. This
   phase applies the same principle at the section level, not the container level.
2. **Wrap four groups in it:** (title `<h1>` + description block), (Mecánicas `<h2>` + chip row),
   (Temáticas `<h2>` + chip row), (Ficha técnica `<h2>` + `<dl>`). Each group's own heading-to-
   content distance shrinks from 16px to 8px — tighter, correctly signaling "these belong together."
3. **Raise `.pk-text-col`'s own gap from `1rem` (16px) to `2rem` (32px).** The existing `.pk-divider`
   and the headless editorial-tags row stay unwrapped, flat children of `.pk-text-col` — they simply
   inherit the new, more generous 32px rhythm on both sides, reinforcing the divider's own role as a
   deliberate boundary rather than shrinking it back down.
4. **`.pk-section-heading` gains `text-transform: uppercase; letter-spacing: 0.04em;`** and drops
   its old `margin-top: 0.5rem` (spacing is now fully owned by the wrapper/gap system above, not a
   heading-level override). Font-family and font-size are unchanged — this stays within the screen's
   existing type-inventory cap (see Typography above).

```css
.pk-text-col {
  display: flex;
  flex-direction: column;
  gap: 2rem; /* was 1rem — see D-03/D-04 */
}

.pk-reading-section {
  display: flex;
  flex-direction: column;
  gap: 0.5rem; /* 8px — tight heading-to-content pairing */
}

.pk-section-heading {
  font-family: var(--font-display);
  font-size: 1.25rem; /* unchanged */
  text-transform: uppercase;
```

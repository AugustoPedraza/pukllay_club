<planner_note>
**The JS in sketch 042's reference file does not get ported.** `description-truncation.md`
documents a JS `toggleDesc()` that physically relocates the button between the paragraph and a
trailing sibling position, and warns at length about branching on the button's *current parent*
instead of the *target state*. That whole bug class exists because a static HTML mockup has no
server-side state to render from. This app already has `@description_expanded` and a
`toggle-description` handler; rendering two mutually exclusive `:if` branches off that assign
gives the identical DOM outcome with no relocation logic, no parent inspection, and no possible
one-way-only failure. Do not add a colocated hook for this. Say so in the template comment so a
future reader who finds the sketch's JS does not "restore" it.

**Pre-decided fallback, so a UAT failure does not cost another sketch round.**
`description-truncation.md` records that this `max-height` + float technique has no native
clean-cut guarantee and was observed cutting mid-word when composed at a different frame width
(sketch 043). If Task 3's human check finds mid-word cuts on real Spanish descriptions at either
real width, the answer is already chosen — do NOT re-sketch. Revert `.pk-desc.is-clamped` to
`display: -webkit-box; -webkit-box-orient: vertical; -webkit-line-clamp: 3; overflow: hidden;
text-overflow: ellipsis;` and move `.pk-desc-toggle` out of the paragraph into the always-trailing
sibling position (the `is-expanded` branch's position, used for both states), dropping the float,
the `::before` offset tuning and the ellipsis span. That variant was built and rejected on
aesthetics alone in sketch 042 — it is a known-good landing spot, not a new design. Record which
variant shipped in the SUMMARY.
</planner_note>

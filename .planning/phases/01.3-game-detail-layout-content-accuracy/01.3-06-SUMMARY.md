  predicates (`fragment("? && ?", ..., type(^values, {:array, :string}))`), wired into
  `base_filtered_query/2`'s shared pipeline so `filter_games/1` and `count_games/1` both pick them
  up automatically.
- GIN indexes on `games.designers`/`games.artists` (migration `20260831120000`), reversibility
  verified via a live rollback + re-migrate round-trip.
- `CatalogFilters.parse_name_list_param/1`: the module's first open-text (non-Vocabulary-whitelist)
  list param — bounded by `Enum.take(20)` (applied before any per-element work), non-binary
  filtering (nested-array safety), `String.slice(0, 120)`, and empty-string rejection. `from_params/1`
  grew from nine to eleven keys; `to_query/1` needed no new clause.
- `CatalogLive.Index`: `:designers`/`:artists` socket assigns, `filter_opts/1` and
  `active_filter_count/1` extended, two literal `facet_assign_key/1` clauses routing chip removal
  through the existing `toggle-facet` dispatcher, and `creator_chips/3` rendering
  `"Diseñador: <name>"` / `"Ilustrador: <name>"` removable chips.
- Full test coverage across all three layers: exact-match + facet-composition query tests
  (`catalog_test.exs`), bound/hostile-input tests including a `javascript:` value through
  `catalog_path/1` (`catalog_filters_test.exs`), and render/removal/surface-switching tests
  (`catalog_live_test.exs`).

## Decisions Made

- **Open-text bound-and-parameterize contract, not a Vocabulary whitelist**: designers/artists are
  free-text BGG-sourced strings with no closed set. Element count (20) and per-element length (120)
  bounds replace membership validation for these two keys only — documented explicitly in the
  moduledoc so it's not mistaken for an oversight later.
- **`filters_active?/1` split into two functions** (Rule 1 + quality-gate fix): adding the two new
  facet checks pushed Credo's cyclomatic-complexity check from 9 to 10 clauses in one function;
  split into `filters_active?/1` + `any_facet_active?/1` rather than suppressing the check.
- **`creator_chips/3` kept as a separately named function** even though its body is byte-for-byte
  the same shape as `facet_chips/3` — call-site clarity (a reader sees `creator_chips` and knows
  immediately which UAT gap it closes) outweighs the small duplication.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `filters_active?/1` did not include `:designers`/`:artists`**
- **Found during:** Task 3, while writing the LiveView test for `/?designers=<name>`
- **Issue:** `filters_active?/1` (and therefore `browsing_results?/1`, the two-surface D-01/D-02
  gate) only checked `q`/`mechanics`/`themes`/`weight_bands`/`tags`/`players`/`max_playtime`/
  `min_age`. A `designers`-only or `artists`-only URL would leave the member on the unfiltered
  carousel surface instead of switching to the narrowed grid — the exact broken round-trip this
  plan exists to close, undetected by any acceptance-criteria grep since the plan's read_first list
  didn't call out `filters_active?/1` by name.
- **Fix:** Added `assigns.designers != []` / `assigns.artists != []` clauses.
- **Files modified:** `lib/pukllay_club_web/live/catalog_live/index.ex`
- **Commit:** `d02f952`

**2. [Rule 1 - Bug] Credo cyclomatic-complexity failure after the `filters_active?/1` fix above**
- **Found during:** Task 3, `mix quality` run
- **Issue:** The added clauses pushed `filters_active?/1` to cyclomatic complexity 10 (Credo's
  `--strict` threshold is 9), failing `mix credo --strict` with exit code 8.
- **Fix:** Split into `filters_active?/1` (q + facet-group + three scalars) and a new
  `any_facet_active?/1` (the six facet checks). Not introduced as a new reusable abstraction —
  purely a complexity-budget split.
- **Files modified:** `lib/pukllay_club_web/live/catalog_live/index.ex`
- **Commit:** `d02f952`

**3. [Rule 1 - Bug] Pre-existing `to_query/1`/`from_params/1` idempotence test broke on the shape change**
- **Found during:** Task 2, running `catalog_filters_test.exs`
- **Issue:** `from_params/1`'s return shape grew from nine to eleven keys (additive by design), but
  the pre-existing round-trip test's `filters` literal only had nine keys, so
  `round_tripped == filters` failed structurally (comparing an 11-key map to a 9-key map).
- **Fix:** Added `designers: ["Uwe Rosenberg"], artists: []` to the test's `filters` literal so it
  reflects the current full shape.
- **Files modified:** `test/pukllay_club_web/catalog_filters_test.exs`
- **Commit:** `b783029`

**4. [Rule 2 - Missing functionality] `clear-filters` handler did not reset `:designers`/`:artists`**
- **Found during:** Task 3, wiring assigns
- **Issue:** The plan's Task 3 action only names `mount/3` and `handle_params/3` for the new
  assigns, but the existing `clear-filters` event handler (the modal's "Limpiar filtros" action and
  the empty-state banner) independently resets each filter assign to its default. Leaving
  `:designers`/`:artists` out would mean "Limpiar filtros" silently leaves a creator filter active.
- **Fix:** Added `|> assign(:designers, []) |> assign(:artists, [])` to `clear-filters`'s assign
  chain, matching the pattern of every other facet assign already reset there.
- **Files modified:** `lib/pukllay_club_web/live/catalog_live/index.ex`
- **Commit:** `d02f952`

None of the above are architectural — all four are additive fixes within the plan's own stated
scope (correctness of the feature this plan ships), not new surface.

<objective>
Close UAT gap **G-01.3-6**: on real WebKit/Mobile-Safari at 390px, the description's expand
chevron renders on its own line *below* the clamped third line instead of trailing it.

Root cause (`.planning/debug/chevron-line-break-regression.md`): `.pk-desc-shell` is a
column-direction flex container, so its main axis is vertical and every child — the clamped
`<p>` and the sibling `<button>` — gets its own row. `align-self: flex-end` only acts on the
cross (horizontal) axis, so it can push the toggle flush right but can never pull it up into
the paragraph's last line box. This is engine-independent: it is a plain consequence of the
flex-column mechanism 01.3-10 introduced when it fixed G-01.3-4.

Purpose: re-establish the *vertical* trailing placement that 01.3-10's fix dropped, without
reintroducing the float-in-a-justified-paragraph technique that caused G-01.3-4 (explicitly
forbidden, and already pinned as un-reintroducible by two existing tests). Also close the
coverage gap that let this ship past CI: every existing `.pk-desc*` test is a DOM-structure or
literal-CSS-source check, and none of them reasons about where the control actually lands.

Output: a collapsed-state-only absolute overlay anchored on the paragraph's own box, a reserved
horizontal gutter so text never runs under the tap target, and a derived geometric-contract
test block that fails against today's CSS.
</objective>

<planner_note>
**Verified facts this plan is built on** (checked against the working tree, not assumed):

- `.pk-desc-shell` (app.css:3096-3099) declares only `display: flex; flex-direction: column`.
  No `position`, no `min-height`.
- `.pk-desc` (3111-3118) declares `line-height: 1.5` and no `font-size`. Neither
  `.pk-desc-shell`, `.pk-reading-section` (3075-3079) nor `.pk-text-col` (3038-3041) declares a
  `font-size` either, so the description computes at the 16px document base — a **3-line clamp
  is a 72px box and each line band is 24px**. This is the basis every number below is derived
  from, and Task 2 pins it so it cannot drift silently.
- `.pk-desc-toggle` (3159-3174) declares `align-self: flex-end`, `display: inline-flex`,
  `align-items: center`, `justify-content: center`, `padding: 0`. Its 44px box comes from the
  markup utilities `min-h-11 min-w-11` in `show.ex:557`, **not** from CSS (deliberate — see that
  rule's own comment).
- `.pk-desc-toggle-icon` is 16px square (3194-3197).
- `is-expanded` is emitted on the shell by `show.ex:547`, so `:not(.is-expanded)` is a real,
  already-rendered hook — no markup change is needed and none is made. The DOM structure (button
  is `#game-description`'s adjacent sibling, never a descendant) is G-01.3-4's structural
  guarantee and **must not change**; two existing tests enforce it.

**Derived geometry the fix targets** (collapsed state, 3-line description):

- Paragraph box: 3 x 24px = 72px. Last line band: 48px..72px from the shell's top.
- Toggle anchored `bottom: 0` with a 44px box: its border-box bottom sits at 72px.
- With `align-items: flex-end` + `padding-bottom: 0.25rem` (4px), the 16px icon spans 52px..68px
  — centred in the 48..72 band, since (24 - 16) / 2 = 4. That is the whole fix in one number.
- `0.25rem` is Tailwind's `space-1` step, already this codebase's spacing unit; no new scale
  value is invented. It is written as a literal, **not** as a `calc()` on a line-height multiple
  (that form is forbidden by the existing test at catalog_show_test.exs:817).

**Why the horizontal reservation is the full 44px, not the 16px icon width.** The diagnosis
suggested tuning against the icon rather than the touch target. Rejected: the toggle is an
*interactive* 44px box, and 01.3-10 deliberately deleted an invisible offset overlay precisely
because it "hung over the paragraph above and the fact grid below, an accidental tap-hijack
surface, not a hit area" (its test at catalog_show_test.exs:860-879 exists to keep that gone).
Reserving less than the tap box would put live description text under a tap target and under the
toggle's own hover/active background wash. So: `padding-right: 2.75rem`, exactly `min-w-11`.

**Pre-decided fallback (apply rather than re-tune, if the device check flags it).** The 44px
gutter narrows the justified column on lines 1-2 as well as line 3 (CSS padding cannot be scoped
to the last line). At the ~640px+ desktop reading column that is ~6% and invisible; at 390px it
is ~12% and may read as an over-indented right margin. If the human check reports that, do **not**
hand-tune a middle value. Apply this pair together, as one change:
(a) drop `padding-right` to `1.75rem` (28px = the 16px icon plus a 12px gap), and
(b) in the same `:not(.is-expanded)` scope, neutralise the toggle's `:hover`/`:focus-visible`/
`:active` **background** fills (keep the colour and transform changes) so no surface washes over
the text that now sits under the box's transparent left half.
Both halves are required — (a) without (b) reintroduces exactly the wash/tap-hijack objection
that made 44px the default. Record the choice in the SUMMARY either way.

**Known, accepted behaviour for short descriptions.** The toggle renders whenever a description
exists, including one that does not overflow three lines. With the overlay, a one-line (24px)
paragraph is shorter than the 44px control, which would otherwise hang 20px *upward* over the
hashtag row — the tap-hijack failure again. The `min-height: 2.75rem` floor on the collapsed
shell contains it downward instead. Cost: on a one-line description the chevron sits ~20px below
the text rather than beside it. Accepted for this gap; conditioning the toggle's presence on
actual overflow needs measurement the server does not have and is out of scope here.
</planner_note>

<objective>
Close UAT gap **G-01.3-5** (cosmetic): the mobile sticky title-echo bar's title text has no
deliberate typography at all.

Per `.planning/debug/sticky-bar-color-balance.md`, `.pk-title-echo-name` declares only its four
truncation properties — no font-family, no font-weight, no font-size, no color, and none in its
ancestors either. It inherits ambient body text by omission, then sits beside `.pk-scroll-top`, a
44px solid-brand-filled circle. Plain undifferentiated text next to a heavy saturated button is the
concrete mechanism behind "Needs a better balance with colors, weight, size and font".

Purpose: two other surfaces on this same page render this same string and each made an explicit,
role-appropriate choice — the H1 uses the brand display face at `text-3xl`, the breadcrumb echo uses
0.875rem muted Inter. The sticky bar's title, which is a reduced restatement of the H1 as it scrolls
away, made none. Give it one.

Output: a single CSS rule change plus the regression pins that keep it from silently reverting, with
the separately-deferred brand-tint question left exactly as `01.3-09-SUMMARY.md` left it.
</objective>

<planner_note>
**Scope is one CSS rule. This plan deliberately does not re-open what 01.3-09 deferred.**
`01.3-09-SUMMARY.md`'s "Open design questions" records a developer `accept-mechanical` decision that
left two things explicitly unresolved: whether the bar should carry a brand tint instead of a
neutral `base-200` step, and whether `.pk-scroll-top`'s solid primary fill and infinite bounce are
themselves the source of the imbalance. Those stay open. The debug session establishes that this gap
is a genuinely different, previously-unaddressed defect that merely shares vocabulary with them —
01.3-09's own Task 1 action text names `.pk-title-echo-name` as deliberately unchanged and out of
its scope. Do not "while I'm here" the bar's fill or the button.

**The typography choice is not a fresh design decision, and must not be treated as one.** D-04
routes open-ended visual calls on this page through the UI system rather than deciding them blind
during planning. Accordingly this plan picks from what the system already declares rather than
inventing: `ui-design-system` states `font-display` (Bebas Neue) is for all headings/titles and that
a title must not be left on the plain sans default; `.pk-section-heading` already establishes
1.25rem as this stylesheet's display-label step below the H1. The rule below is those two existing
decisions applied to a surface that was skipped, which is exactly what the gap says is missing.

**Why the size lands at 1.25rem specifically.** The H1 it echoes is `text-3xl` (1.875rem) in the
same face. The bar's own height is already dictated by the 44px button plus `0.5rem` padding, so a
1.25rem title changes no layout: it fits inside the height the bar already has. A step down from the
H1, a clear step up from 1rem body text, and no reflow.
</planner_note>

    Add five declarations to `.pk-title-echo-name`, keeping all four existing truncation properties
    exactly where they are:

    `font-family: var(--font-display);` — the brand display face, matching the H1 this bar echoes.
    `ui-design-system` states titles use this face and that a title must not be left on the plain
    sans default; this span is a title that was left on it. Bebas Neue is also condensed, which buys
    real horizontal room for a long game name in a 390px bar that has already given 44px to the
    button — a functional gain, not only a stylistic one.

    `font-size: 1.25rem;` — the same display step `.pk-section-heading` already declares in this
    file, one step below the H1's `text-3xl`. Reuse that number; do not introduce a sixth size.

    `font-weight: 400;` — declared explicitly, not left implicit. Only weight 400 of Bebas Neue is
    self-hosted (see the `@font-face` blocks in `read_first`), so any heavier value here would be
    synthesized by the browser into a faux bold that no build step flags. Writing the constraint at
    the site is how a future "make it bolder" edit gets caught by Task 2's test instead of shipping.

    `line-height: 1.3;` — this rule clips its own overflow, and Spanish game names carry accented
    capitals. Give the caps headroom rather than letting a tight line box shave the accent marks.

    `color: var(--color-base-content);` — the value this span already resolves to by inheritance,
    now stated as a decision. Making it explicit is the point: it is what the existing two-theme
    4.5:1 contrast tests in this same describe block have been measuring all along, and pinning it
    here means a future ambient-text retune cannot silently drift the bar's title out from under
    those assertions.

    Rewrite the rule's comment. Its current text is entirely about the G-01.2-24 truncation fix and
    ends by asserting that "no colour on this bar changes here or anywhere else in this fix" —
    accurate for that round, misleading now. Keep the four-properties-required-together explanation
    verbatim (it is still true and still load-bearing), and add why the typography arrived: the span
    had no font decision at all, the H1 and the breadcrumb echo of this same string both made one,
    and this is that missing decision, sized against the H1 rather than against the button beside it.
    Note in the comment that the bar's own fill, its border, and `.pk-scroll-top` are deliberately
    untouched here and remain the open question 01.3-09 recorded. When writing the comment, never let
    a token-family wildcard end with a star immediately before a slash —
    `stylesheet_integrity_test.exs` fails the build on a comment that closes early that way.

    Change nothing else in this file. Not `.pk-title-echo`'s background or border, not
    `.pk-title-echo-inner`, not `.pk-scroll-top`, not the bounce keyframes.

```elixir

defp retry_or_give_up(ids, credentials, attempts_left, _reason) do
  backoff_ms = @base_backoff_ms * (@max_attempts - attempts_left + 1)
  Process.sleep(backoff_ms)
  do_request(ids, credentials, attempts_left - 1)
end
```

defmodule PukllayClub.Catalog.Seed.DescriptionNormalizer do
  @moduledoc """
  [Document: decodes the N confirmed named HTML entities found in stored
  descriptions — see 01.3-RESEARCH.md Pitfall 1 for the exact entity list
  and evidence query. Does NOT handle &#10;/BBCode — confirmed absent from
  real data.]

  @entities %{
    "&mdash;" => "—", "&ndash;" => "–", "&rsquo;" => "’",
    # ... remaining ~30 entries from RESEARCH.md Pitfall 1's confirmed list

  @spec clean(String.t() | nil) :: String.t() | nil

## Shared Patterns

### Seed-time normalization module convention
**Source:** `lib/pukllay_club/catalog/seed/hashtag_normalizer.ex`
**Apply to:** `description_normalizer.ex` (D-02)
Plain module (no struct/GenServer), pure functions, `@moduledoc` cites the exact research evidence backing every hardcoded value, `@spec` on every public function, private helpers grouped at the bottom.

### Mix.Task dry-run + `Mix.shell()` logging convention
**Source:** `lib/mix/tasks/catalog.seed.ex` (lines 226-243, 305-314)
**Apply to:** `catalog.translate_descriptions.ex`, `catalog.enrich_bgg_stats.ex`
`Mix.shell().info/1` for progress/dry-run output, `Mix.shell().error/1` for per-item recoverable failures (never raise mid-batch — one bad item must not crash the whole run), continue processing remaining items.

### Credentials resolution + redaction
**Source:** `lib/pukllay_club/catalog/seed/credentials.ex`
**Apply to:** new `gemini_api_key` field
Env var first, then `config :pukllay_club, PukllayClub.Catalog.Seed`, `nil`/`""` both treated as missing; any new secret field must be added to `@secret_fields` so `redacted/1` masks it in logs.

### Narrow Ecto changeset update (avoid full-row upsert for offline enrichment tasks)
**Source:** RESEARCH.md Pattern 2, mirrored from `catalog.seed.ex`'s upsert shape but deliberately narrower
**Apply to:** `catalog.enrich_bgg_stats.ex`, `catalog.translate_descriptions.ex`
Use `Ecto.Changeset.cast/3` on only the fields being touched (`bgg_weight`/`bgg_rating`/`bgg_rank`/`bgg_payload` for one task, `description` for the other) + `Repo.update/1` directly — do not route through `Catalog.upsert_game!/1`, which expects/overwrites the full row shape and would re-trigger unrelated fields.

### Artists dedup — apply everywhere `bgg_payload["artists"]` is read
**Source:** RESEARCH.md Pitfall 2 / Pattern 3
**Apply to:** D-05's one-off backfill task AND D-06's re-enrichment task (if it also rewrites `bgg_payload`)
```elixir
artists =
  game.bgg_payload["artists"]
  |> List.wrap()
  |> Enum.uniq()
```
368/377 games with artist data have severe raw duplication (worst case Spirit Island: 367 raw entries → 15 unique). Never copy `bgg_payload["artists"]` verbatim into the new `artists` column.

### Conditional-render spec-row convention (ground every field in the real schema)
**Source:** `show.ex`'s existing `pk-spec-row`/`pk-spec-row--wide` rows + `ficha_tecnica?/1`
**Apply to:** all new Ficha técnica rows (Ilustradores, Peso BGG, Valoración BGG, Ranking BGG) and their group guard (`advanced_stats?/1`)
Every field-backed row is `:if={@game.field}` / `:if={@game.field != []}`; group-level guards are an `or`-chain of the same conditions, never render a bare heading over zero rows.

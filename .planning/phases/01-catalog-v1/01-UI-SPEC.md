# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Visual source of truth:** "PUKLLAY CLUB — Manual de Identidad Visual" (Gustavo Nina, brand
identity PDF), extracted and locked below — supersedes the stock daisyUI orange/slate theme
currently in `assets/css/app.css` and the previously-planned Google Stitch export (D-11), which
was never produced. `assets/css/app.css`'s existing `light`/`dark` `@plugin
"daisyui/packages/bundle/daisyui-theme"` blocks must be overridden to the values in this document,
not treated as authoritative.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Phoenix LiveView + Tailwind v4 + daisyUI is not a shadcn-compatible stack (shadcn requires React/Next.js/Vite); shadcn gate not applicable |
| Preset | not applicable |
| Component library | daisyUI v5.5.20 (existing `mix.exs` dependency, Tailwind plugin, `themes: false` + two named `@plugin` theme blocks) |
| Icon library | Heroicons v2.2.0 (existing `mix.exs` dependency, sparse/optimized install, already wired via `@plugin "../vendor/heroicons"`) |
| Font | **Bebas Neue** (display/brand — logo wordmark, page-level headings) + **Inter** (UI/body — everything else). Both are Google Fonts, OFL-licensed, safe to self-host. See Typography section for the licensing rationale behind substituting Inter for the manual's "Segoe UI Semibold." |

**Logo usage rules (from the brand manual — apply wherever the isologo/wordmark appears in-app, e.g. site header/footer):**
- Isologo: abstract Andean llama silhouette built from a hexagon (board-game tile reference) fused with a meeple-profile silhouette. Wordmark "PUKLLAY CLUB" set in Bebas Neue, all caps. Tagline "JUEGOS DE MESA MODERNOS" set smaller/lighter, uppercase, letter-spaced.
- Two lockups available: horizontal (isologo + wordmark + tagline) and circular badge/seal (isologo centered, tagline running around the circle). Use horizontal in the site header; circular badge is optional (e.g. footer/favicon treatment), not required for Phase 1.
- Minimum size: never render the logo lockup below ~20% of its reference/original size (brand manual's reduction-test floor) — treat as a "don't shrink past legibility" rule, not a literal CSS token.
- Prohibited: do not flatten/squash, stretch, mirror, or recolor the logo to an off-brand hue (the manual's own example of "wrong" is rendering it in orange — notably the exact hue the stock daisyUI theme currently uses, reinforcing why that theme must be overridden).
- Optional decorative texture: the manual includes a monochrome-purple abstract doodle/line-art pattern used on marketing/merch assets. Usable as a subtle background texture on a marketing/hero section if one exists, but do **not** apply it inside the catalog grid/card UI itself, and do not block Phase 1 on recreating it — no source asset file exists, only the PDF rendering, so treat as out of scope unless a marketing/landing surface is added later.

## Visual Hierarchy

Top-to-bottom priority on the browse screen (per D-08/D-09/D-15):

1. **Header** — horizontal logo lockup (isologo + wordmark + tagline), minimal chrome.
2. **Search bar** — one search box at the top of the browse content, above the carousels. Primary
   entry point for keyword search (title/designer/publisher); narrows whatever is below it,
   including the carousels' underlying data, without leaving the page (D-15).
3. **Curated carousel rows** — Club Favorite / Beginner-Friendly first (highest editorial trust
   signal for a new/casual player), then the 6 editorial-hashtag rows, then Recently Added. These
   are the primary visual anchor and first full-bleed image-forward content a member sees —
   image-forward cards, not the grid, carry the initial visual weight (D-08/D-09).
4. **Filter-drawer trigger** — a persistent but secondary button (not a sidebar) that opens the
   slide-over filter panel on demand; kept visually lighter than the search bar and carousels so it
   doesn't compete with them for attention (D-13).
5. **Full grid** — below the carousels, the exhaustive ~400-game grid. Lowest visual priority of
   the primary elements (users reach it after search/carousels/filters have already narrowed
   intent), but still the functional backbone of the browse experience.

Accent color (`#3D096D` / dark-mode `#A97FD1`) reinforces this order: reserved for the search
focus ring, the filter-drawer trigger, and primary CTAs — never used decoratively on the grid
itself, so it doesn't compete with the carousels' images for the eye's first pass (see Color
section for the full reservation list).

Exceptions: **44px minimum touch target** for the mobile filter-drawer trigger button (D-13) and

exceptions.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | Inter Regular (400) | 1.5 |
| Label | 14px | Inter Regular (400) | 1.5 |
| Heading | 20px | Inter Semibold (600) | 1.2 |
| Display | 28px | Bebas Neue (single weight — see exception note) | 1.2 |

**Typeface decision — "Segoe UI Semibold" substitution:** the brand manual specifies Segoe UI
Semibold as its tagline/secondary face, but Segoe UI is a proprietary Microsoft font with no
free web-embeddable license and no Google Fonts availability — it only renders natively on
Windows. Phase 1 carries a large volume of running Spanish UI text (game titles, descriptions,
filter labels, weight-band descriptors, mechanic/theme chips), so consistent cross-platform
rendering matters more than an exact system-font match. **Decision: use Inter** (OFL-licensed,
self-hosted, excellent Spanish accented-glyph coverage and small-size legibility) as the
project's UI/body face everywhere Segoe UI would have appeared, rather than a `-apple-system,
"Segoe UI", ...` system stack that would only render as intended for Windows visitors. Inter
Semibold (600) is the closest practical visual match to "Segoe UI Semibold" for the smaller
number of Windows users; everyone else gets a deliberately-chosen, on-brand-adjacent face
instead of an arbitrary OS default.

**Weight-count exception:** the type system uses exactly 2 weights (Inter 400/600) for Body,
Label, and Heading. Display is a documented exception — Bebas Neue is a single-weight condensed
display face per the brand manual and is used only for large, low-density text (logo wordmark,
page-level/section headings such as a "Catálogo" hero title or carousel row titles), never for
dense body/UI copy, per the manual's own caution against using it for paragraph text.

## Color

Locked from the brand manual's 3 defined hues (dark purple, white, violet) — no other hues are
brand-defined; supporting neutrals and semantic colors below are derived, harmonized to the
violet family rather than introducing an unrelated hue.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (light) / `#170A26` (dark) | Page background, primary surface |
| Secondary (30%) | `#F3ECFA` light-lavender (light) / `#22103A` dark-violet (dark) | Cards, nav header, carousel row backgrounds, filter drawer panel |
| Accent (10%) | `#3D096D` brand dark purple (light) / `#A97FD1` lightened violet (dark) | Primary CTA buttons ("Ver detalles"), filter-drawer trigger button, selected/active tag-pill state, active nav/link state, focus rings |
| Destructive | not applicable — Phase 1 has no destructive actions (no auth, no admin, no delete/rental flows; those land in Phase 2/4) | n/a |

Accent reserved for: primary CTA button on game cards ("Ver detalles"), the filter-drawer trigger
button, the currently-selected state of mechanic/theme tag pills, active/focused search input
border, and link/focus-ring states. **Not** used for the editorial hashtag chips (see below) or
for decorative purposes — this keeps the ~400-card grid from turning into a wall of purple.

**Editorial hashtag chip treatment (single consistent style, all 6 hashtags — confirmed, no
per-hashtag colors):** light-lavender background `#EDE1F7` with dark-purple text `#3D096D`
(light theme); deep-violet background `#3D2A56` with light-lavender text `#E4D3F5` (dark theme).
Applies uniformly to all 6: `#DescubreElHobby`, `#IngenioEstratega`, `#NivelExperto`,
`#CreaConexiones`, `#EquipoGanador`, `#DuelosMemorables`.

## Copywriting Contract

Phase 1 ships no destructive actions (no auth/admin/delete flows in this phase — those land in
Phase 2 and Phase 4), so that row is n/a. Drafted in a warm, teach-don't-assume, welcoming-club
tone per confirmed direction; user may adjust wording later.

| Element | Copy |
|---------|------|
| Primary CTA | "Ver detalles" (on each game card, links to the game detail page) |
| Filter-drawer trigger label | "Filtros" (icon + label button that opens the slide-over per D-13) |
| Search input placeholder | "Busca por título, autor o editorial…" |
| Empty state heading | "No encontramos juegos con esos filtros" |
| Empty state body | "Prueba a quitar algún filtro o ajustar tu búsqueda — seguro hay algo en nuestra colección que te va a gustar." + a "Limpiar filtros" (clear filters) action |
| Error state | "No pudimos cargar el catálogo en este momento. Intenta recargar la página en unos segundos." (problem + concrete next step: reload) |
| Broken/missing game image fallback | Alt text keeps the game's title; visual fallback is a simple brand-violet meeple/dice placeholder illustration, not a broken-image icon or blank box |
| Destructive confirmation | not applicable — no destructive actions in Phase 1 |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 10 covered, 2 backstop, 1 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Catalog grid / search results (list-collection) | ✅ covered | Zero-result state renders the "Empty state heading/body" copy from the Copywriting Contract, with a "Limpiar filtros" action |
| empty | Game gallery images (media) | ✅ covered | Per D-04, gallery photos beyond the cover are best-effort; a game with fewer gallery images than the gallery UI slots simply shows fewer thumbnails — no placeholder padding, no broken-slot look |
| loading | Catalog grid initial load (list-collection) | 🧪 backstop | LiveView renders skeleton card placeholders while the ~400-game initial query streams in; no visual mock exists for the skeleton treatment, flagged for explicit verification at build time rather than assumed |
| loading | Carousel rows (list-collection) | 🧪 backstop | Same skeleton-card treatment as the grid, applied per carousel row |
| error | Catalog grid load failure (list-collection) | ✅ covered | Renders the "Error state" copy from the Copywriting Contract as an inline banner above the grid |
| error | Cover/gallery image load failure (media) | ✅ covered | Falls back to the brand-violet meeple/dice placeholder illustration described in the Copywriting Contract's "Broken/missing game image fallback" row, alt text retains the game title |
| populated | Catalog grid at ~400 games (list-collection) | ✅ covered | LiveView stream-backed grid, paginated via a "Cargar más" (load more) button below the fold rather than infinite scroll — simpler to implement correctly and avoids mobile scroll-jank; resolved as Claude's discretion per D-08/CATALOG-01 |
| populated | Carousel rows at typical volume (list-collection) | ✅ covered | Fixed hardcoded rows per D-09 (Club Favorite/Beginner-Friendly, one per editorial hashtag, Recently Added), horizontally scrollable card rail |
| partial | Game card with missing optional enriched field (e.g. min age not returned by BGG for a given game) (list-collection) | ⚠ unresolved | BGG enrichment completeness for the actual ~400-game dataset isn't known until the D-01 seed task runs; default behavior should be "omit the missing chip/row" rather than showing a blank placeholder, but the exact per-field fallback list needs planner confirmation once real seed output is available — treated as an explicit planner assumption, not silently resolved |
| overflow | Game title on card (static-content within list-collection) | ✅ covered | Truncate to 2 lines with ellipsis on the card; full title always shown on the detail page |
| overflow | Mechanic/theme chip row on card (list-collection) | ✅ covered | Cap visible chips at 3–4 per card with a "+N" overflow indicator; full chip list shown on the detail page |
| zero-one-many | Filter results count (list-collection) | ✅ covered | Singular/plural Spanish count copy ("1 juego encontrado" / "12 juegos encontrados"); zero routes to the empty state above |
| long-text | Weight-band descriptor one-liner (static-content) | ✅ covered | Editorial copy (D-05, Claude-drafted/user-reviewed) is authored to a fixed short-line budget by design — no dynamic overflow risk |
| long-text | Filter drawer facet labels (interactive-control) | ✅ covered | Mechanic/theme glossary terms (D-07) are curated as short 1–3 word labels; no truncation handling needed by design |

# Plan 01-01 — Prerequisites: BGG application token, R2 catalog bucket, seed dependencies

**Phase goal (verbatim from ROADMAP.md):** Members can browse, filter, sort, and search a public
catalog of ~400 games, with UX that teaches complexity instead of assuming hobbyist vocabulary.

> **MVP-mode note:** this plan is the phase's external-prerequisite gate, not a feature slice. It
> exists because 01-RESEARCH.md discovered a hard blocking dependency (BGG's July-2025 auth
> requirement) that no amount of code can work around, and because R2 bucket creation is a
> human-only account action. The tracer slice is `01-03-PLAN.md`, which leads with
> `type="tracer"` and cannot start until this plan's checkpoint clears.

<objective>
Clear every external, human-only prerequisite that blocks the D-01/D-02/D-03 seed pipeline, and land
the five new hex dependencies plus a single credential-resolution seam.

Purpose: 01-RESEARCH.md Pitfall 1 confirmed live that `GET /xmlapi2/thing` now returns
`401 WWW-Authenticate: Bearer realm="xml api"` without a registered application. Discovering that
mid-build wastes an executor's whole context. R2 bucket creation + public-read enablement is
likewise a dashboard-only action. Both are settled here, once, before any BGG-calling or
R2-writing code exists.

Output: a compiling project with `sweet_xml`/`image`/`ex_aws`/`ex_aws_s3`/`nimble_csv` available, a
gitignored `config/dev.secret.exs` holding real credentials, a committed
`config/dev.secret.exs.example` template, and `PukllayClub.Catalog.Seed.Credentials` as the one
place any seed code reads a secret from.
</objective>

  1. Go to `boardgamegeek.com/applications/create` while logged in to a BGG account. Register a
     non-commercial application (suggested name: `PukllayClub catalog seed`; purpose: one-time
     enrichment of a ~434-game club library). Copy the issued API token.
  2. Sanity-check the token from a terminal:
     `curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $BGG_API_TOKEN" \

     Copy the access key id and secret.

     `config/dev.secret.exs`. Do NOT paste any of them into a git-tracked file, a commit message, or
     a PLAN/SUMMARY document.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer machine → BGG XML API | A long-lived Bearer token crosses this boundary on every enrichment request. |
| developer machine → Cloudflare R2 | Long-lived S3 access-key credentials with object write scope cross this boundary. |
| repository working tree → git remote (public repo) | The repo is PUBLIC as of Phase 0 D-19. Anything committed is world-readable and effectively unrevokable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `config/dev.secret.exs` | critical | mitigate | Task 2 adds `/config/dev.secret.exs` to `.gitignore` before the file is created; Task 2's acceptance criteria assert both `git check-ignore` success and `git ls-files` emptiness. The repo is public (Phase 0 D-19), so a leaked BGG token or R2 write key is immediately exploitable. |
| T-01-02 | Information Disclosure | `Credentials` struct in logs / crash reports | high | mitigate | `@derive {Inspect, only: [...]}` on the struct plus a `redacted/1` accessor; Task 3 asserts `inspect/1` output excludes the token.

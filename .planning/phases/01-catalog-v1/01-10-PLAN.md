<objective>
Implement sketch 002 (card-hierarchy, winning variant D) in the real Phoenix/LiveView catalog:
strip the resting card down to poster + single-line title, and move every secondary fact
(players, tiempo, a 3-dot difficulty indicator paired with the weight-band label, one editorial
tag, the CTA) behind an interaction — a 300ms hover-intent desktop preview rendered through a
`position: fixed` portal outside the scrolling rail, and a full-screen bottom sheet on touch.

Purpose: the shipped card crams title + weight badge + up to 2 editorial tags + up to 4 mechanic
chips into one dense stack, and never shows player count or playtime — the two most
decision-critical facts for "will this work tonight". The sketch converged on a poster-forward
resting card with everything else behind interaction. The desktop preview must live outside the
rail because `overflow-x: auto` implicitly makes the cross axis `auto` too, so any panel nested
inside the rail is silently clipped — that is the root cause of the "broken on mobile" expand
found during sketching, not a styling mistake.

Output: `PukllayClubWeb.GamePreview` (shared markup + `.GamePreview` colocated hook), a rewritten
minimal `GameCard`, `Vocabulary.weight_band_level/1`, and the `pk-*` shared CSS layer that both
preview surfaces use verbatim.

## Why the shared CSS lives in `assets/css/app.css`

`Phoenix.LiveView.ColocatedCSS` exists in this LiveView version but requires a new behaviour
module and colocates CSS *per component* — the opposite of what this design needs, since the
whole point is that `GamePreview` and `GameCard` share one declaration per field. One clearly
delimited block in `app.css` is the single source of truth. Colocated *hooks* stay colocated,
matching `carousel_row.ex`'s existing `.CarouselScroll` pattern.

`preview_host/1` renders, in order: an outer `<div id="game-preview" phx-hook=".GamePreview">`

duplicates the card link that is already in the tab order, so exposing it would create a second
focus path to the same destination.

Colocate the `.GamePreview` hook in the same module using the `carousel_row.ex` shape. In
`mounted()`: read the numeric options off `this.el.dataset`; compute
`this.finePointer = window.matchMedia("(hover: hover) and (pointer: fine)").matches`; cache the
portal element; attach delegated `mouseover` and `mouseout` listeners on `document` (these bubble,
unlike mouseenter/mouseleave) that resolve `event.target.closest("[data-game-card]")` and ignore
the event when `event.relatedTarget` is inside the same card. On card enter with a fine pointer,
clear both timers and start a show timer at the configured delay — this delay is what stops a
pointer sweeping across a row from firing a preview per card. On card leave, clear the show timer
and start a hide timer.

`showPortal(card)` must position from `card.getBoundingClientRect()` using a fixed portal width
read from the dataset, never a multiple of the card's own width: `grow = width - rect.width`,
`left = Math.max(edgeGap, Math.min(rect.left - grow / 2, window.innerWidth - width - edgeGap))`,

the portal element, then `replaceChildren(card.querySelector("template[data-game-preview]")

server-rendered nodes — the hook must never assemble markup from string concatenation or from
`dataset` values, which is how the throwaway sketch did it and is a live DOM-injection path.
Attach `mouseenter`/`mouseleave` handlers on the portal so moving the pointer onto the preview
cancels the hide.

immediately on any `scroll` event (capture phase, passive) and on `keydown` Escape, because a
`position: fixed` panel positioned from a rect goes stale the moment anything scrolls. In
`destroyed()`, clear both timers and remove every document/window listener.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> LiveView event channel | `phx-click`/`phx-change` payloads are attacker-controlled strings |
| Postgres -> rendered HEEx | `games.description`, `name` and `tags` originate from a third-party API (BGG) and a club CSV, not from this app |
| server-rendered DOM -> client hook | the `.GamePreview` hook reads nodes out of the document and writes them into a fixed-position surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-31 | Tampering | `.GamePreview` hook portal/sheet population | high | mitigate | The hook populates both surfaces exclusively by `cloneNode(true)` of server-rendered `<template>` content via `replaceChildren`; it never assembles markup from strings or from `dataset` values. Enforced by Task 1's action and reviewed at code review. |
| T-01-32 | Information disclosure | `games.description` rendered into `.pk-preview-text` | medium | mitigate | Rendered through normal HEEx interpolation, which HTML-escapes; `raw/1` is never used on any game field. BGG descriptions legitimately contain markup-looking text and must render escaped. |
| T-01-33 | Elevation of privilege | cloned `<.link navigate>` CTA inside the portal | low | mitigate | The preview host is rendered inside the LiveView root so LiveView's delegated navigation resolves an owning view; the CTA target is server-generated from the game struct via `~p"/juegos/#{game}"`, never from a client-supplied value. |
| T-01-34 | Denial of service | hover-intent timers, document listeners, body scroll-lock | low | mitigate | `destroyed()` clears both timers, removes every document/window listener and drops the body scroll-lock class, so repeated live navigation cannot accumulate handlers or leave the page unscrollable. |
| T-01-35 | Spoofing | fixed-position portal overlaying page chrome | low | accept | Same-origin content only; `frame-ancestors 'none'` already blocks the clickjacking case, and the portal auto-hides on scroll and Escape. |
| T-01-36 | Tampering | Content-Security-Policy compliance of the new hook | medium | mitigate | The hook is a colocated hook extracted to a bundled asset at compile time, so no inline `<script>` body reaches the page; the existing landing-render test that refutes an inline hook body covers the new hook as well. |

No package-manager installs occur in this plan set, so no package-legitimacy gate applies.

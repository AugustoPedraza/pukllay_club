<objective>
Close two UAT gaps that share the same screen region — the stack of carousel
rows above the browse grid.

- G-01-4 (major): all ~8 sections look identical. `CarouselRow.carousel_row/1`
  renders one hardcoded, unvaried heading for every row regardless of whether
  it is the curated hero row, a per-hashtag row, a per-weight-band row or the
  recency row; and the main grid — the largest section on the page — has no
  heading at all, only a muted result-count line. The diagnosis explicitly
  ruled out inter-section spacing as the deficiency.
- G-01-3 (major, expected to reclassify): the reported "~20 columns forcing
  horizontal scroll" was traced to the by-design `CarouselRow` rail (daisyUI
  `.carousel`, capped at exactly 20 items) being mistaken for the responsive
  `#games` grid, which was verified correct. The contributing factor is real
  and fixable: daisyUI's `.carousel` sets `scrollbar-width: none`, removing
  the only native cue that the rail scrolls at all.

Purpose: a new player scanning this page has no way to learn what the shelves
mean or that they scroll. Both are direct hits on CLAUDE.md's "teach the
complexity of board games rather than assume familiarity" principle.

Output: differentiated, self-explaining section headers; a titled main grid;
and persistent, discoverable carousel scroll controls.
</objective>

  controls". Read the flip condition carefully: B9's 5-frame cap is written
  for a hero/banner carousel where one frame must stand for the whole, and it
  flips off when "every single frame alone still gives an accurate

  Record that reasoning in the SUMMARY rather than silently ignoring the row.
- `Skill(skill="ux-responsive")` — hover is never the sole affordance; touch
  devices have no hover state, so the controls added here must be persistent,
  not revealed on hover. Only `sm:` and `lg:` are in use in this repo; do not
  introduce `md:`/`xl:`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server-rendered markup -> browser JS | A new client-side hook now runs on every landing-page render and manipulates DOM classes and scroll position |
| Vocabulary copy -> rendered section subtitles | Section subtitles are hardcoded server-side strings and vocabulary constants; no request-supplied value reaches a heading |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-50 | Tampering | `CarouselRow` colocated hook | medium | mitigate | The hook is forbidden from `innerHTML`, `eval` and `new Function`; it only reads `dataset`/`scrollWidth`/`clientWidth` and calls `scrollBy` plus `classList.toggle`. No DOM is built from any string. |
| T-01-51 | Elevation of Privilege | app CSP `script-src` | medium | mitigate | Colocated hooks are extracted at compile time into `_build/*/phoenix-colocated` and bundled by esbuild into `priv/static/assets/js/app.js`, so nothing is emitted as an inline `<script>` that `script-src` would refuse. Verified by an automated grep of the bundled output plus a test asserting the rendered HTML carries no inline script tag. |
| T-01-52 | Denial of Service | `ResizeObserver` in the hook | low | mitigate | One observer per rail, disconnected in `destroyed`; the sync callback does two layout reads and one class toggle, with no allocation loop and no timer. |
| T-01-53 | Information Disclosure | section subtitles | low | accept | Subtitle copy is compile-time constant editorial text drawn from `Vocabulary`; no user-, request-, or DB-supplied value is interpolated into a heading, so there is nothing to disclose. |

No package-manager installs occur in this plan (no `mix deps` change, no npm/pip/cargo
install — the hook rides existing esbuild wiring), so no `T-01-SC` supply-chain row and
no package-legitimacy checkpoint applies.
</threat_model>

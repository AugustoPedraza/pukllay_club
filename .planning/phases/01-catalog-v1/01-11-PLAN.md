<objective>
Implement sketch 001 (shelf-structure, winning variant D)'s layout half: turn the catalogue's
eight carousel rows into full-bleed Netflix-style shelves with always-visible gradient edge-fades,
one shared gutter token that guarantees nav-to-row alignment, a trailing "Ver todo" tile per
shelf, and narrow-viewport density tuned so the next card visibly peeks in.

Purpose: this is the concrete fix for the acknowledged G-01-4 gap carried out of Phase 01's UAT —
the rows currently read as one vertical list with no visible affordance that there are multiple
carousels. The production rail relies on daisyUI's `.carousel`, which hides the scrollbar and
leaves no passive scroll cue; the persistent prev/next controls added in 01-08 help on a pointer
device but are not a passive, always-visible signal, and are invisible as a *cue* on touch.
Edge-fade plus a deliberately peeking next card is the cue the sketch converged on.

Output: a `--pk-gutter` design token with exactly one padding declaration behind it, a
`.pk-shelf`/`.pk-rail-wrap`/`.pk-rail` layer, a `fullbleed` mode for `Layouts.app`, a `Ver todo`
tile wired to real filter state, and narrow-viewport density plus touch-scroll hardening.

## Decisions locked by this plan

- **The persistent prev/next rail controls from 01-08 stay.** The sketch finding rejects
  *hover-only* prev/next as the primary scroll cue, and this plan makes edge-fade the primary,
  always-visible cue. The existing controls are persistent (not hover-revealed) and were shipped
  to close G-01-3; removing them would regress that gap and would violate the design system's
  "hover is never the sole affordance" rule. Edge-fade is added alongside them, not instead.
- **Row headings already render as plain Spanish** ("Duelos memorables", not
  "#DuelosMemorables") because `PukllayClub.Catalog.list_carousel_rows/0` supplies humanised
  titles. This plan adds a regression test pinning that behaviour rather than re-implementing a
  transform that already exists; the underlying hashtag data and the chip labels elsewhere are
  untouched.
- **Touch diagonal-swipe ambiguity** (carried forward from the sketch wrap-up as needing device
  testing) is mitigated with `overscroll-behavior-x: contain` on the rail, so a horizontal
  overscroll cannot chain into the page or a browser back-swipe, plus `touch-action: manipulation`
  so a tap on a card opens the sheet without the double-tap-zoom delay. Both axes stay pannable —
  restricting the rail to `pan-x` would intersect with the page's own pan and make a vertical
  swipe that starts on a card unable to scroll the page, which is a worse regression than the
  ambiguity it fixes. A real-device check is part of Task 3's verification.
- **Full-bleed rails, capped content sections.** Rails break out to the viewport edge; the
  toolbar, main grid heading, grid and load-more stay inside `mx-auto w-full max-w-7xl` so line
  and card lengths stay sane on wide displays. This deviates from the design system's
  one-container-per-page rule, and the deviation is the whole point of the sketch's full-bleed
  decision.

## Gutter alignment is one declaration, not two matching values

The single most load-bearing finding across both sketches: when two surfaces must line up, give
them one shared declaration. The nav-versus-row misalignment found during sketching was caused by
the nav and the row content each choosing their own spacing token. So this plan introduces:

- `--pk-gutter` on `:root`, with a single narrow-viewport override.
- One class, `.pk-gutter`, that is the only place `padding-left`/`padding-right` reads that token.
- Every aligned surface (the header, each row header, each rail wrap, each capped page section)
  gets that same class. No surface re-declares the padding.

Colour and spacing values translate through the sketch-token map in `01-10-PLAN.md`; do not copy
literal colours out of the sketch CSS.

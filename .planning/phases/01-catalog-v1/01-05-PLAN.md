# Plan 01-05 — Browse: carousels, live filtering, sort, and Spanish keyword search

**Phase goal (verbatim from ROADMAP.md):** Members can browse, filter, sort, and search a public
catalog of ~400 games, with UX that teaches complexity instead of assuming hobbyist vocabulary.

> **Expansion of the 01-03 tracer.** The tracer proved a public LiveView rendering seeded rows from
> the `Catalog` context. This plan grows that same page into the real browse experience: the
> curated carousels above, the filter drawer beside, the search box on top, and pagination below —
> all reading through the same context boundary the tracer established.

<objective>
Turn the tracer's minimal grid into the browse surface described by D-08/D-09/D-12/D-13/D-14/D-15
and the approved UI design contract, on top of the fully seeded 434-game catalog.

Purpose: CATALOG-02, CATALOG-03, and CATALOG-04 all apply to the *same* result set at the same time
— 01-RESEARCH.md Pattern 3 is explicit that these must compose into one Ecto query rather than
branching into "search mode" versus "filter mode". Getting that composition right once, in the
context, is what keeps the LiveView thin and what makes D-15's "search narrows whatever the filters
show" behavior fall out for free instead of being special-cased.

Output: a `Vocabulary` module, a fully composed `filter_games/1`, a live-updating filter drawer with
OR-within-facet tag pills, sort controls, a load-more grid, curated carousel rows, and the empty /
error / loading states the UI contract requires.
</objective>

  **Catalog query.** Extend `PukllayClub.Catalog` with `filter_games/1` accepting a map or keyword
  list with `:q`, `:mechanics` (Spanish labels), `:themes` (Spanish labels), `:weight_bands`,
  `:tags`, `:players`, `:max_playtime`, `:min_age`, `:sort`, `:limit`, `:offset`. Compose it as a
  pipeline of `maybe_*` private functions over a base `Game` query, per 01-RESEARCH.md Pattern 3 —
  one query, never a branch between search mode and filter mode.

  - Search: `fragment("? @@ websearch_to_tsquery('spanish_unaccent', ?)", g.search_vector, ^term)`.
    Use `websearch_to_tsquery`, not `to_tsquery` — it tolerates stray quotes, hyphens, and the word
    `OR` from a public search box without raising. The configuration name must match the
    `spanish_unaccent` config created in 01-04 so accent folding applies.
  - Facets: translate the incoming Spanish labels to raw BGG values via
    `Vocabulary.mechanic_terms_for/1` / `theme_terms_for/1`, then
    `fragment("? && ?", g.mechanics, ^raw_values)`. The overlap operator `&&` is OR-within-facet
    (D-14); `@>` would mean AND-contains and is the wrong operator here. Mechanics and themes are
    separate `where` clauses, which yields AND-across-facets.
  - Player count: a single `:players` integer matches when `min_players <= n and max_players >= n`.
  - Playtime: `:max_playtime` matches when `playing_time <= n` (falling back to `max_playtime` when
    `playing_time` is null via `coalesce`).
  - Min age: `:min_age` matches when `min_age <= n` — the member states the youngest player at the
    table, so the filter selects games suitable at or below that age.
  - Sort: support `:name_asc` (default), `:playtime_asc`, `:playtime_desc`, `:complexity_asc`,
    `:complexity_desc`, `:year_desc`. Order complexity by
    `fragment("array_position(ARRAY['descubre_el_hobby','ingenio_estratega','nivel_experto'], ?)", g.weight_band)`
    with `bgg_weight` as a secondary key. Every sort must place nulls last so the 26 band-less games
    do not lead the list. Reject an unknown sort atom by falling back to `:name_asc` rather than
    raising — a crafted query parameter must not crash a public page.
  - Pagination: always apply `limit` (default 24) and `offset`. Never return an unbounded result set.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous browser → LiveView events | Search text, facet values, sort keys, and scalar filter values all arrive from an unauthenticated public client. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-20 | Tampering | SQL injection through search and facet parameters in `filter_games/1` | high | mitigate | Every user value is a pinned `^` parameter inside `fragment/2`; no query text is built by interpolation. Facet values are additionally translated through `Vocabulary.mechanic_terms_for/1`, so an arbitrary client-supplied string maps to a known glossary term or to nothing at all — it never reaches the query as free text. |
| T-01-21 | Denial of Service | Malformed search input raising inside `to_tsquery` | medium | mitigate | `websearch_to_tsquery` is used instead of `to_tsquery`; it tolerates stray quotes, hyphens, and boolean words without raising. Task 1's acceptance criteria drive it with adversarial literal input. |
| T-01-22 | Denial of Service | Unbounded result set or a crafted deep `offset` scanning the whole table | medium | mitigate | `filter_games/1` always applies a `LIMIT` (default 24) — there is no unbounded branch. GIN indexes on `search_vector`, `mechanics`, `themes`, and `tags` from 01-04 bound query cost, and the table is ~434 rows. |
| T-01-23 | Denial of Service | Crafted `sort` parameter reaching `order_by` | medium | mitigate | Sort keys are matched against a closed set of atoms and fall back to `:name_asc` on anything unrecognized; no client string is ever converted to an atom or spliced into `order_by`. |
| T-01-24 | Information Disclosure | An unhandled query exception rendering an Elixir stacktrace to a public visitor | low | mitigate | The catalog reads are wrapped so a failure renders the contracted Spanish error banner; production error pages are already the generated `ErrorHTML` from Phase 0, which does not leak stacktraces. |
| T-01-25 | Elevation of Privilege | Catalog routes acquiring an auth requirement | low | accept | The catalog is intentionally fully public (CATALOG-08); the `:browser` pipeline is reused unmodified with no auth plug. |
| T-01-SC | Tampering | package-manager installs | n/a | mitigate | No new package installs in this plan; the audited set from 01-01 is unchanged. |

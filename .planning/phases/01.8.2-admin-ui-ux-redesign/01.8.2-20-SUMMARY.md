# Phase 01.8.2 Plan 20: The Draft Sheet, Row Routing, and the Publish Gate Summary

**D-30's draft flow, end to end: a draft is edited in a classic-form bottom sheet opened from the
list (no chevron), a published or retired row opens the full editor page (chevron), and
`Catalog.publish_game/1` refuses a nivel-less non-expansion draft with `{:error, :nivel_required}`
while the draft sheet's `Publicar` stays live at all times and explains a blocked publish with a
persistent inline line — the shape resolved by this plan's own Task 1 checkpoint, measured against
sketch 078's real geometry rather than assumed.**

## Accomplishments

- **Task 1 (checkpoint:decision, resumed with the developer's answer):** open item 6 — how the
  live `Publicar` explains itself on tap — is drawn. The developer chose **(b) a persistent inline
  line under the gate**, against the measurement the prior executor took in real headless Chrome
  (`playwright-core`) against `.planning/sketches/078-admin-publish-gate/index.html`: the nivel row
  was already fully on screen at BOTH 390×844 and 360×640 when `Publicar` rests at the sheet's
  natural, non-sticky foot position — making (c) scroll-to-nivel solve a problem this geometry
  doesn't have, and (a) a snackbar detach the explanation from the field before the fix is made.
  Recorded verbatim in `01.8.2-UI-SPEC.md`'s new "Live-gate explanation (open item 6)" section as
  the reusable rule for any future live-gate control, including the caveat about longer
  descriptions the developer explicitly declined to resolve with a conditional scroll branch.
- **Task 2:** the draft sheet and row routing. `game_live/index.ex` gained a classic-form draft
  sheet (cover · nombre · descripción · expansión · nivel, one 52px filled full-width CTA — D-30's
  documented S3 Contorno exception, same shape as D-27's top app bar) opened either by tapping a
  draft row (`"open-draft-sheet"`, no chevron per D-19i) or via a `?draft=<id>` URL param
  `handle_params/3` now recognizes. `game_live/form.ex`'s `mount/3` redirects a draft's direct
  editor URL straight back to that same `?draft=` param — checked BEFORE the editor's own
  `put_section_names/1`/`Shelves.list_shelves/0`/`Shelves.count_for_game/1` calls, so the redirect
  costs exactly the one lookup already needed to decide. Publishing reuses 076's `.fresh` highlight
  and `admin_list.js`'s existing `scrollFreshIntoView` **unmodified** — the row moves from
  Borradores into Juegos del club, which never collapses (D-19g-bis decision 15), so the freshly
  published row is always on screen to scroll to.
- **Task 3:** the publish gate. `Game.needs_nivel_to_publish?/1` is the one shared predicate (false
  for any expansion; true for a non-expansion draft with no `weight_band`) — `Catalog.publish_game/1`
  checks it before the status transition and returns `{:error, :nivel_required}` instead of
  publishing, so every caller is gated, not just the button (D-37's own stated reason: 078 proved a
  drawn-only gate is pure paint). No `validate_required` was added anywhere — a nivel-less draft
  still saves fine. The draft sheet's `Publicar` never renders `disabled` and is never
  opacity-dimmed (D-24); tapping it with no nivel renders Task 1's chosen inline line, stating the
  consequence ("Sin nivel, {nombre} no va a aparecer en ninguna fila del inicio") rather than a
  required-field message, and leaves the game in `:draft`. The nivel picker offers exactly the
  three real `Vocabulary.weight_bands()`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Two D-03 failed-enrichment-retry tests had a fixture status the new editor
guard makes unreachable**
- **Found during:** Task 2 (running the full `game_live_test.exs` suite after wiring the editor
  guard)
- **Issue:** `test/pukllay_club_web/live/admin/game_live_test.exs`'s "failed enrichment retry
  (D-03)" describe block used `game_fixture(%{status: :draft, enrichment_status: "failed"})` and
  then called `live(conn, ~p"/admin/juegos/#{game.id}/editar")` directly — Task 2's own guard now
  redirects any `:draft` game away from that route before it ever renders, so both tests failed
  with a `live_redirect` `MatchError`. A third test, "a draft game opens in the editor even though
  its public URL 404s", asserted the exact behavior Task 2's own acceptance criteria overturn.
- **Fix:** The two enrichment-retry fixtures moved to `status: :published` — `retry_enrichment/1`
  gates only on `enrichment_status`, never on `status`, so a published game with a stale `"failed"`
  enrichment_status is a real, still-reachable state (staff could publish despite a failed BGG
  fetch), and the editor's `failed?/1` + Reintentar affordance stays exercised against that real
  path rather than being silently orphaned. The third test was replaced with one asserting the
  redirect this plan's guard performs — see `GameLive.Form — D-30 draft editor guard`.
- **Files modified:** `test/pukllay_club_web/live/admin/game_live_test.exs`
- **Verification:** `mix test test/pukllay_club_web/live/admin/game_live_test.exs` — 80 tests, 0
  failures

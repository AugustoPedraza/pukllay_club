## Accomplishments

- The 56px top app bar (`‹ · título · ⋮`) replaces the old `.hdr`/`.pbar`/`<.header>` stack; the title is invisible-but-`flex:1` at rest and fades in past `scrollTop > 46` via a new `EditorShell` JS hook (mirrors `AdminList`'s non-colocated, window-scroll pattern). Leaving a clean editor navigates silently; leaving a dirty one opens D-19f's centred discard dialog — `Descartar` is deleted outright, never relocated (grep-verified 0 occurrences).
- The D-29 franja is fixed directly under the top bar (`top: 56px`, 39px tall) and states the consequence, never the name: `Publicado · Así se ve en la web.` / `Retirado · No se ve en la web ni está en el estante.` — a draft renders neither string, and the prohibited `Se está viendo así en la web` appears nowhere in the codebase (grep-verified).
- The write model — *«la hoja PREPARA, el pie escribe»* — is `@draft`/`@saved` (both plain maps of `Game.admin_changeset/2`'s five cast fields), `dirty?/2` derived by comparison, and a generic `"draft-change"` event plan 01.8.2-19's field sheets will call. `status` sits outside the draft entirely: the ⋮ menu's `Catalog.retire_game/1`/`restore_game/1` commit on their own.
- `AdminComponents.save_bar/1`'s FIRST live call site: `Guardar` is disabled exactly when clean, enabled with `● Sin guardar` when dirty, persists through the unchanged five-field cast allowlist, and leaves the editor clean again. `test/visual/admin_shell.mjs`'s new `measureSaveBarLive` proved this live — 77px bar height, 88.7×44px natural-width button at 61.7% ink fill, and (D-28's own named failure mode) the body's last block sits 16.2px clear above the bar, not hidden under it, at both 375 and 360.
- The body renders D-26's exact order (pills → tapa → título Bebas 30/36 → chip de sección → descripción → five BGG facts → divider → Copias/Estante/Es una expansión) with the `--val` tint + 14px pencil on all seven editable blocks; the cover's pencil is a non-interactive corner badge by design (redrawing the cover would revert 01.3.1/D-07); the section chip carries no tint (D-33). No bottom tab bar on this route (D-30, the `suppress_tab_bar` exception).
- `test/visual/admin_components.mjs`'s real-browser 44px-hit-target sweep, extended to the editor via a dedicated (non-`PAGES`) block, found and closed two real defects ExUnit could not see: a 32px nivel pill and a 36px título button, both fixed with the same bleeding-`::after` hit-box technique the public ficha's own description toggle already uses.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `bottom_collapse` added to the `<Layouts.app>` call**
- **Found during:** Task 1 (running the full `mix test` suite after the initial implementation)
- **Issue:** `test/pukllay_club_web/components/layouts_test.exs`'s pre-existing D-02 guard requires every `<Layouts.app>` call site under `lib/` to pass `boundary_collapse` or `bottom_collapse`; the new call site had neither, failing that test.
- **Fix:** Added `bottom_collapse` (harmless — `editor.css`'s `body:has(.pk-game-editor) main { padding: 0; }` already unconditionally zeroes `<main>`'s padding regardless of which Tailwind classes render).
- **Files modified:** `lib/pukllay_club_web/live/admin/game_live/form.ex`
- **Verification:** `mix test` — 1714 tests, 0 failures
- **Committed in:** `98d773d`

**2. [Rule 1 - Bug] Two real 44px hit-target floor violations, found by `admin_components.mjs`**
- **Found during:** Task 3 (running the extended visual harness against the live editor)
- **Issue:** The nivel pill's drawn box (32px) and the título button's drawn box (36px, its exact line-height) both fell under the 44px A8 hit-target floor — real, measured defects a static ExUnit render cannot see.
- **Fix:** Added a bleeding `::after` pseudo-element on each (6px/4px top+bottom respectively) — the identical technique the public ficha's own description-clamp toggle button already uses in this codebase, not a novel pattern.
- **Files modified:** `assets/css/admin/editor.css`
- **Verification:** `node test/visual/admin_components.mjs` — re-run clean, `admin_components.mjs: ALL CHECKS PASSED`
- **Committed in:** `98d773d` (found and fixed before any commit was made, folded into the shell commit)

**3. [Rule 1 - Bug] `admin_shell.mjs`'s new save-bar measurement compared against the wrong background baseline, and measured body clearance without scrolling**
- **Found during:** Task 2 (first run of the new `measureSaveBarLive` check)
- **Issue:** (a) Comparing button/bar background against `document.body`'s own computed style, which is transparent in this app (the real page ground, `--color-base-100`, is never painted directly on `<body>`); (b) measuring the last body block's position without first scrolling to the document's real bottom — a `position: fixed` bar's own top is always viewport-relative, so an un-scrolled body rect trivially reports "clear" regardless of the real clearance.
- **Fix:** (a) Resolve `--color-base-100` via a throwaway swatch element instead; (b) `window.scrollTo(0, document.body.scrollHeight)` before measuring.
- **Files modified:** `test/visual/admin_shell.mjs`
- **Verification:** re-run clean, `admin_shell.mjs: ALL CHECKS PASSED` with a real, non-trivial measured clearance of 16.2px
- **Committed in:** `6eba1f8`

- **D-00c:** *(revised 2026-09-16, estante UI restart decision 35 — was "a placed box goes to the far right end")*
  Placing a box: choose the estante; if it is **empty** the box goes in directly as its first box; otherwise staff
  **choose the spot** — before the first box, between any two, or after the last. It happens in a **full-height
  "¿Dónde va?" sheet that opens the moment staff find a game with no spot** (restart decisions 36–39): its search finds
  an estante or a game already on one and then keeps the chosen estante's name; picking a game opens its estante with
  that game lifted and a "+" on each side. Done → "Juego ubicado" snackbar with Deshacer, and the placed cover drops
  into its spot (no motion under reduced-motion). No separate Ubicar button.

  then leaves the old spot and takes the new one together ("Juego movido" + Deshacer; cancel changes nothing).
  **Quitar del estante** confirms first in a centred dialog (restart decision 41).

### In-shelf position & copies (reverses 01.8.1 D-11)
- **D-01:** Every physical **copy** has its own location: estante + left-to-right position. A copies
  table is introduced in this phase; place / move / undo / reorder act on a copy, not a game. —
  **Reversibility:** one-way — new table + FK graph that Phase 4 rentals will build on; undoing
  means a migration collapsing copies back into `games.units`.
- **D-02:** Copy rows are the source of truth; `units` becomes the count of a game's copies.
  **Sharpened 2026-09-22 by D-31** — "becomes the count" means the **column is dropped**, not cached.
  Raising **Copias** in the editor adds unplaced copies (they appear in Sin ubicar). Lowering it
  removes an unplaced copy first; if every copy is placed, the editor asks which copy to remove.
- **D-03:** Copies are distinguished by a stable number, shown only when a game has more than one:
  `copia N de M` on the meta line and in the accessible name (`"Dixit, copia 2 de 3, caja 29 de 59"`).
  Numbers do not renumber when a copy is placed or moved. No staff-named copies.
- **D-04:** "caja N de M" and the zone bar count **copies (boxes)** on the estante.

### Migration — start empty
- **D-05:** **Clear everything.** When position lands, all estantes AND all shelf assignments are
  deleted; every copy starts in `Sin ubicar`, even though games are physically on shelves. No
  backfill from name order, no "orden sin revisar" state. Staff recreate estantes with
  **Nuevo estante** and walk each shelf left to right — placement-at-far-right records the real
  order as a side effect. — **Reversibility:** one-way — destroys production shelf data; recovery
  only from a backup.
- **D-06:** The migration logs counts of estantes and assignments it removes. The rollout plan takes
  a `pg_dump` immediately before deploy and records those counts (plan 01.8.1-14 baseline pattern).
- **D-07:** Because of D-05, the migration and the new Estantes page ship in the **same deploy** —
  production must never have cleared shelves without the screen to rebuild them.

### Estantes page behaviour
- **D-08:** *(rewritten 2026-09-17 — estante UI restart, sketch 069, decisions 1–68 in
  `.planning/notes/estante-ui-restart.md`; replaces master/detail, 066 R2-A and the zone bar)* Three pages:
  - **Estantes** (`/admin/estantes`) — one job: find a box. Header: title + **Pendientes** icon with a count badge
    (D-19g) + gear (Administrar estantes). Idle: the prompt **"¿Qué juego buscás?"** and the search field
    ("Buscá un juego") centred at the optical centre (2:3), nothing else. Focusing the empty field shows **Últimas
    búsquedas** (3) in the dropdown; typing shows suggestions (cover · name · estante or ● Sin lugar); no match →
    **"Crear «texto»"** → the Juegos new-game editor with the name filled in → "¿Dónde va?" (D-00c).
    Picking a game: the field **keeps its name with ✕** (✕ = back to idle; focusing selects the name so typing
    replaces it); the page rises (title → field 16, field → answer 32) and shows the estante as context (18px estante
    icon + name, 14/600 muted) over the **rail**: the whole estante as a swipeable row of 96px covers opened at the game,
    which is **lifted** (−12px + shadow). A **"+" on each side of the selected cover** opens the full-height
    **"¿Qué juego va acá?"** sheet (Sin ubicar games first; a search over every game — a shelved one is moved; no match
    → Crear, which places the new game straight into that spot). Tapping another cover moves the selection; tapping the
    selected cover opens its options sheet (Ver ficha · Mover · Quitar del estante, D-19e). A game with no spot opens
    "¿Dónde va?" at once.
  - **Pendientes** (`‹ Estantes`) — the work queues: **Afuera** (Phase 4 checkout data; the section exists empty until
    then) and **Sin ubicar**, each a heading with count + one hint line + all rows. Afuera row → Estantes with the game
    lifted in its spot; Sin ubicar row → "¿Dónde va?".
  - **Administrar estantes** (gear, `‹ Estantes`) — estante rows (estante icon · name · "N juegos"; **no chevron**, no
    page per estante). Header: ⇅ **Ordenar** + **"+" Nuevo estante** icons. Row → options sheet **Editar** / **Eliminar**
    (D-10). Nuevo estante and Editar share one **name sheet** (field pre-filled and selected — "Estante 10" or the
    current name — hint "Un nombre que se reconozca en el salón.", Crear estante / Guardar; errors for empty and
    duplicate names). **Ordenar** is a mode: header "Ordenar estantes" + Listo, rows with a ≡ drag handle; tapping ≡
    shows ↑/↓ on that row (non-drag path, WCAG 2.5.7); Listo → "Orden guardado" + Deshacer. The order is used everywhere
    estantes are listed.
  **Why:** real-world priority — the frequent job is locating a box (put back / pick up); managing estantes is rare. The
  developer asked for search first and management as a secondary page, then rejected lists under the search (they
  competed with it) in favour of Pendientes behind a badge. **Routes:** no `/admin/estantes/:id`; Pendientes and
  Administrar estantes get their own routes under `/admin/estantes`.
- **D-09:** **First run** (0 estantes, all copies Sin ubicar): an honest empty state on **Administrar estantes** — one
  line of purpose (e.g. "Creá los estantes en el orden en que los recorrés") and **Nuevo estante** as the one action
  (the name sheet, D-08). No wizard/checklist, no seeded room layout. Estantes itself stays search-first; its
  Pendientes badge shows every copy Sin ubicar.
- **D-10:** **Deleting a non-empty estante:** destructive row in the estante options sheet →
  confirmation dialog (D-19f) "¿Eliminar {estante}?" stating the consequence ("Sus N juegos quedan sin lugar hasta que
  los vuelvas a ubicar.") → delete → stays on Administrar estantes; copies return to Sin ubicar; an undo snackbar
  ("Estante eliminado" + Deshacer) restores the estante and its copies' positions.
- **D-11:** **Concurrent staff:** position writes are serialized per estante (transaction +
  advisory lock, as plan 01.8.1-15 did per BGG id) so positions never collide or gap. Every open
  Estantes page, Pendientes page and Administrar estantes page updates live over PubSub (Pendientes badge and
  lists, estante counts and order, the rail). If a copy you
  are acting on changed underneath you, a quiet snackbar says so.

  - **D-19o:** *(added 2026-09-18, Juegos redesign decision 32, sketch 071)* **every pressable surface has a press
    state, and it is one token.** Suppress the platform tap highlight at `:root` — `-webkit-tap-highlight-color:
    transparent` — and paint `:active` with **`--color-surface-2`** on every pressable surface. The property
    **inherits**, so suppressing it once at the root covers surfaces added later; leaving it unset hands every
    control the platform default (`rgba(51,181,229,0.4)`, Android's Holo cyan), a colour in no PukllayClub palette.
    - **The rule is "a `:hover` implies an `:active`", not "these surfaces need one".** Touch has **no hover**, so
      a hover-only control is *invisible to press on the primary platform* — and this project is mobile-first.
      Sketch 071 shipped 8 `:hover` rules, 6 `:focus-visible` and 0 `:active` before anyone measured it.
    - **One token, not a ramp.** Rejected: press = the hover fill (#F1ECFD, the lightest option — a press is a
      *momentary* state where hover is *sustained*, and needs more contrast to register in the ~100ms it exists);
      and press = one step past hover everywhere (needs a fabricated third colour wherever hover is already
      surface-2). **Accepted cost:** where a surface's hover is already surface-2 — a pinned collapsible caption —
      a *pointer* reads press == hover. Touch never reaches that collision.
    - Where the fill is a **transition**ed pseudo-element, set `transition-duration: 0s` on the way **in**: a band
      that fades over 120ms is slower than a quick tap and would show only partly faded, or not at all.
    - **Verify with a mouse press, and say so.** CDP touch emulation does **not** set `:active` (controlled for:
      an injected rule painted under `mouse.down()` and not under `Input.dispatchTouchEvent`), so a touch-driven
      assertion passes vacuously. Real-tap behaviour is confirmed on a device.

  - **D-19n:** *(added 2026-09-18, Juegos redesign decisions 6–7 and 9, sketch 071)* **a long list keeps its context
    in two pinned tiers.** Measured on Pendientes at scrollTop 1500 (375×667): the page title, the back link **and**
    the section heading are all off screen at once, leaving 11 rows with nothing to orient them and the back link
    1,500px away; a Sin datos section is 3,307px tall and the full Juegos catalog 27,664px (~45 screens).
    Both design systems pair two mechanisms and so does this admin:
    - a **44px page bar** (`‹ back` + the page title at 17/600) pins at the top of the scroller once the title row
      has gone behind it. It is an **absolute overlay, not a sticky child** — at rest it must cost zero layout
      (verified byte-for-byte: phead 69, field 129, heading 209, first cover 244.5, row 64, all unchanged).
      `inert` toggles between the in-page back link and the bar's, so **exactly one back control is ever focusable**.
    - the **section heading** pins under it, full-bleed and opaque so full-bleed rows cannot slide past its edges.
      The "stacked" push is free from `position: sticky`: each heading is confined to its own section, so an
      arriving section evicts the previous heading.
    - on a page whose one job is a **search**, the search itself pins instead of a title bar — a bar there would
      only repeat the word the pinned heading already says. It is the *same* input pinning, never a copy, so there
      is no second field to keep in sync. It **hides on scroll-down and returns on scroll-up** (+1 visible row on
      every viewport), never while focused or within 140px of the top. Measured and rejected: collapsing it to a
      44px icon saves 16px — a quarter of a row — gaining **0** rows at 375×667 *and* costing a tap.
    - a new screen always starts at scrollTop 0, so the bar never appears on a page nobody scrolled.
  - **D-19g-bis:** *(**the group list is replaced 2026-09-22 by D-25** — `Sin datos 49 · Borradores 1 ·
    Juegos del club 385` stops partitioning once 075 turns the 49 into drafts, and it never had a home for a
    retired game. Groups are now **by `status`**. Everything below about *how a section behaves* — one list,

    work *queues*; a catalog groups its own rows.** A queue is a set of items in a genuinely different state
    (Estantes' **Afuera**, **Sin ubicar** — the game has no shelf), and those still go behind a header badge on
    their own page: **Estantes is unchanged.** But on **Juegos** the incomplete games are not a queue — "sin datos"
    is an *attribute of a catalog row*, not a separate work item — so Juegos is **one list of collapsible groups**
    (`Sin datos 49` · `Borradores 1` · `Juegos del club 385`) with no Pendientes page and no badge. Rules for such
    groups: they **partition** the list (49 + 1 + 385 = 435, never a game in two); work groups are **collapsed by
    default** and sit on top, so both counts are on screen at rest without burying the catalog; the header is a
    real **44px** control; opening a group **keeps the tapped heading where the finger left it**; and **a row never
    repeats its group's state** — the group names the state, the row names the thing.
    **ONE LIST, one section anatomy** *(added 2026-09-18, decision 17 — supersedes the band rules that decisions
    10, 11, 13, 14 and 15 built up)*: a page like this is **one continuous list whose sections hold different
    content**, not a block of work groups placed beside a catalog. **Every section header is the same caption** —
    a `<span>`, never a control: no caret, no `aria-expanded`, no 44px target, no tonal band, nothing collapses.
    It wears decision 16's **Label (group)** rank, **13/600 muted on the 16 container keyline**, is full-bleed and
    sticky, and gains a `--color-surface` fill **only while pinned**, the one moment it must terminate itself over
    rows sliding under it. **Sections butt together with no gap.** This is the iOS plain-table / Contacts model the
    BENCHMARK already records.
    **Why the earlier rules are gone, not merely changed:** decisions 10 (band + leading caret so a header would
    not read as a row), 11 (two units, gaps 24/0/32/0), 13 (the caret takes the cover's 40px slot) and 14 (the tint
    marks the work block) all existed *only* because there were **two kinds of header**. A caption is not a
    control, so it cannot be mistaken for a row; there are no blocks, so there is nothing to space; there is no
    caret to place; and nothing is tinted at rest. Decision 15's empty-page defect cannot occur because no section
    collapses. Two text left edges, **16 / 68**, still hold.
    **Accepted cost:** with sections ordered exceptions-first, the body section is as far down as its predecessors
    are long (measured here: the catalog sits 50 rows / 3,270px down). That is the price of putting the work where
    it cannot be missed, and it is a deliberate ordering choice, not a defect.
    **Exception sections close at rest** *(added 2026-09-18, decision 18)*: ordering exceptions-first buries the
    body section behind them (measured: 3,270px), so the exception sections are **collapsible and collapsed by
    default**, which brings the body back to 206px. This does not reintroduce two kinds of header: **anatomy stays
    one** (fill, rank, colour, height, keyline identical) and the **caret is affordance, not a second kind** —
    only a collapsible section carries one, which is what tells you it collapses. The caret sits **inline after
    the count**: never *leading* (that puts a hole back in the container keyline) and never at the row-chevron
    slot (D-19i reserves trailing for "opens a page"). A caption is below the 44px touch floor, so a collapsible
    one stretches its **hit box** with a pseudo-element rather than padding the visible row — the touch floor is
    met without loosening the list's rhythm. The **body section never collapses** (decision 15 holds).
    **A section label carries D-19j's rank, 15/600 at full strength** *(added 2026-09-18, decision 20 —
    supersedes decision 16's 13/600 muted)*: audited, the ladder had inverted — the label organising a list was
    **2px smaller and 2.8x lower contrast than a single row inside it**, and **byte-identical to a row's second
    line** (both 13 / muted), so a section name carried the weight of row metadata. D-19j puts a list section at
    **15/600, above** row names; that is the rank. A section and a row may share size and colour, because they
    separate on **weight (600/400), keyline (16/68) and the cover a row has and a section does not** — decision
    10's confusion was a 44px *control* with a trailing icon in the row-chevron slot, which no longer exists.
    Two guards: a section is **never smaller** than the rows it heads, and **never identical** to a row's second
    line. Note that the BENCHMARK's `Label (group) 13/600` is a **form** section label (sketch 065) and does not
    govern a list section header — conflating them is what caused this.
    **A section label gets air above it and none below** *(added 2026-09-18, decision 21)*: measured text-to-text,
    a list of collapsed sections read **15px above a label against 17px below** — *inverted proximity*, so each
    label attached to the label above rather than to the rows it heads, and several strong labels read as one
    block. A label sits **closer to its own rows than to the label before it, by at least 2:1** (built here as
    26px above / 0 below, measuring 27 against 9 = 3.0:1). **Proximity is a ratio — the two ends must move in
    opposite directions**: welding the label to its rows *alone* failed, because a header's bottom padding also
    feeds the gap to the next header, so both ends tightened together. The **first** section takes less leading
    air than the rest, because whatever precedes it (here a 48px search field) already separates it — that is
    spacing, not a second anatomy.
    **Measure ink, not boxes, when the element draws nothing.** A transparent header's box edge is invisible, so
    box gaps report padding changes as no change at all. Every spacing number for a transparent element is
    text-to-text.
    **Two process rules this earned:** *(1) when consecutive rounds keep re-touching one seam, the seam is not the
    problem — the structure that creates it is.* Four passes at the same 20px of screen should have prompted a
    premise check, not a fifth pass. *(2) when a decision is superseded, re-check what was justified by the thing
    it removed.* Twice a rule outlived its reason: hints deleted for a premise later changed, and a rank lowered to
    separate it from controls later deleted. A supersession note should list what becomes **re-openable**, not
    only what is now true.
  - **D-19m:** *(added 2026-09-17, Web redesign decisions 14–16, sketch 070)* **a kind is a quiet tag, a status is a dot**
    (D-19h): the tag is 18px, 11px regular, lowercase, on a hairline `--color-border`, muted text — it never competes
    with the row name (6.2:1 against the name's 17.2:1). **A count is a neutral pill on the tile's bottom-right corner**,
    page-filled with a 1px `--stroke`, 11/600 muted, and is in the tile's accessible name — never the top-right filled
    primary badge, which means pending work (D-19g).

### The game editor (sketches 072–080, decided 2026-09-22)

The whole editor follows one write model — **«la hoja PREPARA, el pie escribe»**: the page holds a draft
`G`, sheets write into it, `SAVED` is the last commit, and `Guardar` copies one onto the other. `status`
sits **outside** the draft — the ⋮ changes it and it commits on its own.

- **D-23 — one anatomy for an editable value** *(072 d33/d34/d35)*: a stored value shown at rest and
  changed elsewhere is a **row that opens a sheet** — line 1 label (prominent), line 2 value (subordinate,
  carrying the `--val` tint). **No glyph at all**: not `›` (D-19i reserves that for "opens a page") and not
  the `⌄` that briefly replaced it. Explicitly out of scope: search, filters, switches, steppers, and
  fields already *inside* a sheet. The tint marks **the datum you are about to change**, never "this row
  is tappable" — 071's 435 game rows are tappable and untinted. A picker's chosen option gets a **tick,
  not a tint**. Distinguishability here is judged as **CIE76 ΔE with a bar at 20**, never a contrast
  ratio — contrast cannot see hue (the rejected pair scored 1.17 against the accepted 1.21, but 10.1
  against 29.6 as ΔE).
- **D-24 — disabled means "nothing to write", and nothing else** *(settles 064's eight ungoverned
  exceptions)*: a control may ship disabled **only** when it is a save/commit control reflecting an empty
  diff (D-28's `Guardar`, 076's `Agregar`). A gate on **missing data** must stay **live and explain on
  tap**. Always rendered with the **muted stops, never opacity** — opacity dims the label, which is the
  only thing saying what happens when it revives.
  **Consequence, accepted: 078's P2 is redrawn.** `Publicar` was chosen as "born dead, revives on choosing
  a nivel, never an error message"; it now stays live and explains on tap. The `Nivel · hace falta para
  publicar` mark on the label survives as a hint but **stops being load-bearing**, because the tap now
  carries the explanation. This resolves d42 (0 allowed) vs d44 (1) vs d50 (4) as a rule rather than a
  tally.
- **D-25 — Juegos groups by `status`** *(replaces D-19g-bis's group list)*: **Borradores · Juegos del club ·
  Retirados** (a group with 0 rows is not rendered). `status` is durable and mutually exclusive, so the
  partition is guaranteed by the schema instead of by predicate ordering, and a **retired game finally has
  a home** — today it would land in "Juegos del club", whose name asserts exactly what the state denies,
  unmarked. "Sin datos" stops being a group and becomes a **row attribute inside Borradores**, which is
  what D-19g-bis itself said it was before making it a group anyway.
  *Measured on the dev catalog 2026-09-22 (435 rows): after D-33's unpublish the shape is Borradores ~50 ·
  Juegos del club ~385 · Retirados 0.*
- **D-26 — the editor body mirrors the public ficha** *(079 E3)*: pills → tapa → título **Bebas 30/36, no
  label** → chip de sección → descripción → `AÑO / DISEÑADORES / ILUSTRADORES / MECÁNICAS / TEMÁTICAS` →
  divider → `COPIAS / ESTANTE / ES UNA EXPANSIÓN`. **Overrides D-19j for this page only.** The editable
  affordance is `--val` tint **+ a 14px pencil** on all 7 editable blocks — the synthesis is required
  because neither half reaches everything: the tint cannot mark the cover (an image → pencil as a corner
  badge, where the ficha already puts its share control) and the pencil cannot mark the description (the
  3-line clamp clips it → anchored in the 44px column the clamp already reserves). **The pencil is hereby
  a second system glyph**, recorded rather than left as drift; D-19i governs chevrons, not pencils.
- **D-27 — one 56px top app bar**: `‹ · título · ⋮`, replacing `.hdr` + `.pbar` + `.back` (which cost 97px
  before the game's name and drew the back affordance **twice**). The **title is absent at rest and fades
  in on scroll** (D-19n applied to a bar already present), keeping `flex: 1` while invisible so nothing
  slides. **The ⋮ is the bar's only control** — 074's swapping CTA slot (d44) is **deleted**; `Guardar`
  lives at the foot (D-28). `Descartar` is **deleted, not relocated**: the back-confirm *is* `Descartar`,
  drawn as D-19f's centred dialog; a clean editor leaves silently. Button weight is judged on **painted
  area, not contrast** (W1 3903px² / W2 285 / W3 0), and "filled is loudest" is a **light-theme fact** —
  dark `--color-primary` on the bar is 2.33:1 against 14.16:1 in light. **064's "no disabled buttons /
  S3 Contorno" is overturned for the top app bar only** (d47) and upheld everywhere else.
- **D-28 — the fixed foot save bar**: `Guardar` is **fixed at the foot, always present (77px)**, enabled
  only when there is something to save — replacing **880px of scroll** (079's CTA sat at y=1453). The bar
  is a **divisor**: full width, opaque, **page-coloured**, so the only thing it draws is its **1px line**
  (measured at scrollTop 700, body ink inside the button's band: divisor 0px · tonal band 0px · vela 255px
  · no band 1456px). The button is **064's A1 exactly** — outline, 44px, radius 8, 14/600, **natural
  width**, right-aligned on the keel (ink fill 61.7% at natural width vs 15.8% full-width; 064's own table
  already said Principal in a save bar is "A1, last" and full-width "never"). Geometry copies the public
  `.pk-mobile-cta-bar` (`app.css:5375`), not 078's 52px sheet `.cta`. **The body reserves the bar's height
  measured from the real bar, never estimated** (65px at 375, 64.7 at 360) — an estimate hides the last
  block under a few pixels and no check notices. A disabled button takes the **page ground, not the bar's
  surface** (`--color-surface` gave 1:1).
  **The bar's left half is `.ebar.inline`'s status line + dot** and carries **only the transient save
  state** (● Sin guardar). This restores D-00a's save-bar anatomy and **reverses 080 r4's body note**,
  which is deleted.
- **D-29 — durable status keeps 079's franja**: a **39px franja under the top bar at y=56** states the
  **consequence, not the name** — `● Publicado · Así se ve en la web.` / `● Retirado · No se ve en la web
  ni está en el estante.` It exists because mirroring the public ficha **erased `status`**: a published and
  a retired game rendered byte-identical pages (the same 92,885-byte PNG). Dot + text per D-19h.
  **Together with D-28 this closes 080's open item 4** — `status` and `Sin guardar` now have separate
  homes, so both show at once instead of one hiding the other.
- **D-30 — a draft is a sheet, not a page** *(078 P2)*: a draft is edited in a **bottom sheet opened from
  the list** — cover · nombre · descripción · expansión · nivel, **one 52px filled full-width CTA**, ✕ to
  cancel, **nothing written until `Publicar`**. On publish: close, return to the list, scroll and highlight
  the row (076's `.fresh` + `scrollNewIntoView`, reused not invented). **Row routing:** a **draft row opens
  the sheet** (no chevron, D-19i); a **published row opens the editor** (chevron). The **editor page
  therefore exists only for an already-published game**, and is **full-screen with no bottom tab bar**
  (exception to D-13b). The publish gate has **exactly one condition — `nivel` — and none for an
  expansion**; `nivel` maps 1:1 onto `sections.rule_value`, so the gate states a **consequence, not a
  rule**, and the vocabulary is the **three bands in `vocabulary.ex:24-40`**, not the four invented in 075.
  **Required means required to publish, never to save.**
  **Two sheet patterns, never mixed** *(079)*: the **draft sheet** is a classic form with one CTA; the
  **editor field sheet** is `.opt` + tick where **choosing IS the commit and closes**. Text fields get
  **their own wide `Guardar`** inside the sheet; choice fields do not; closing with ✕ writes nothing.
  *(This is 073 d41 — "exactly one Guardar in the editor" — knowingly amended: 079 found that closing a
  text sheet with ✕ silently discarded what you had typed.)*
- **D-31 — `games.units` is dropped**: copy rows are the only source of truth and the count is
  `count(copies)` wherever it is shown; the **Copias** stepper creates and removes copy rows directly. The
  migration creates **one copy row per existing unit before dropping the column**. This deletes 078's whole
  bug class rather than patching it — `units` has no DB default, is never cast by `enrichment_changeset`,
  and `admin_changeset` lets a blank through, so every game the new draft flow creates would otherwise
  carry `copias = nil` forever. *(Measured 2026-09-22: `units` is NULL on exactly **1** of 435 rows — the
  one existing draft — so this is a **forward-looking** defect, not 434 broken rows as the sketch note
  implied.)*
- **D-32 — the editor's ESTANTE block opens the real «¿Dónde va?» sheet**: it keeps D-23's anatomy (a row
  showing the current value, opening a sheet) but the sheet is **D-00c's position-aware one**, not a plain
  list of estantes — same sheet, same single transaction, same `Juego ubicado/movido` + Deshacer. For a
  game with more than one copy it acts on **the copy you came from**. This prevents the editor from
  reintroducing "the box goes to the far right", which D-00c explicitly reversed.

## Phase Boundary

Rebuild the staff admin shipped in 01.8.1 to the design validated in sketches 059–065, end to end:
all nine admin LiveViews, the admin shell (tab bar, sectioned drawer, no admin footer), one save
bar, one action system (A1–A4), one sheet, Juegos rows, and **Estantes as a search-first page** with a
Pendientes page and an Administrar estantes page (D-08, sketch 069) — no page per estante — with the Asignar screen deleted. Underneath it, the shelf data model gains a real **per-copy, left-to-right
position** (reversing 01.8.1 D-11), introduced as a copies table and a clean-slate migration.

Also in scope because it lives in the shared `layouts.ex` chrome: the broken drawer (G-01.8.1-1b)
and footer (G-01.8.1-1a) on the **public** site, and staff chrome (drawer + tab bar) on public pages.

Not in scope: restyling public catalog content (cards, rails, filters, game page), checkout/rental
state (Phase 4), fixing production add-by-BGG enrichment (G-01.8.1-14-enrichment-stuck — debug run
after this phase deploys).

The full gap analysis, per-file fate, and ~18–22-slice decomposition with ordering constraints is
in `.planning/notes/admin-redesign-scope.md` — this CONTEXT records the decisions made on top of it.

## Implementation Decisions

### Carried forward (not re-asked)
- **D-00a:** Sketches 059–065 are the design source of truth for the admin (shell, S3 Contorno
  outline-only actions, A1 outlined / A2 text / A3 icon / A4 sheet row, one save bar `.ebar.inline`
  with one-word **Guardar**, R6 sheet shell, 061/065 row anatomy, Juegos pills with Publicado
  unmarked, Ordenar→Listo mode, zone bar with `ZONE_NAV_MIN = 30`, **Copias**, Admin/Web/Perfil
  renames, `Mostrar más · N de M`, 22px/600 Inter titles with Bebas only for the editor's game name).
  Where `01.8.1-UI-SPEC.md` disagrees, the scope note's stale-rows table says what supersedes it.
  **Exception (2026-09-16, revised 2026-09-17):** everything 065 R8 and 066 drew for the estante screens (ONE Estantes
  page, then master/detail, zone bar, Agregar juegos mode, per-estante Ordenar) is replaced by sketch 069 — see D-08.
  R8 results that carry over: search answers "where is it", game order is shelf order, neighbours are one tap away,
  Asignar stays deleted.
- **D-00b:** No footer on `/admin`; Salir moves into the drawer / account sheet (059/060-B).
- **D-00c:** *(revised 2026-09-16, estante UI restart decision 35 — was "a placed box goes to the far right end")*
  Placing a box: choose the estante; if it is **empty** the box goes in directly as its first box; otherwise staff
  **choose the spot** — before the first box, between any two, or after the last. It happens in a **full-height
  "¿Dónde va?" sheet that opens the moment staff find a game with no spot** (restart decisions 36–39): its search finds
  an estante or a game already on one and then keeps the chosen estante's name; picking a game opens its estante with
  that game lifted and a "+" on each side. Done → "Juego ubicado" snackbar with Deshacer, and the placed cover drops
  into its spot (no motion under reduced-motion). No separate Ubicar button.
  **Moving** a box opens the same sheet and is one transaction: the box keeps its spot until the new one is chosen,
  then leaves the old spot and takes the new one together ("Juego movido" + Deshacer; cancel changes nothing).
  **Quitar del estante** confirms first in a centred dialog (restart decision 41).

### In-shelf position & copies (reverses 01.8.1 D-11)
- **D-01:** Every physical **copy** has its own location: estante + left-to-right position. A copies
  table is introduced in this phase; place / move / undo / reorder act on a copy, not a game. —
  **Reversibility:** one-way — new table + FK graph that Phase 4 rentals will build on; undoing
  means a migration collapsing copies back into `games.units`.
- **D-02:** Copy rows are the source of truth; `units` becomes the count of a game's copies.
  Raising **Copias** in the editor adds unplaced copies (they appear in Sin ubicar). Lowering it
  removes an unplaced copy first; if every copy is placed, the editor asks which copy to remove.
- **D-03:** Copies are distinguished by a stable number, shown only when a game has more than one:
  `copia N de M` on the meta line and in the accessible name (`"Dixit, copia 2 de 3, caja 29 de 59"`).
  Numbers do not renumber when a copy is placed or moved. No staff-named copies.
- **D-04:** "caja N de M" and the zone bar count **copies (boxes)** on the estante.

### Migration — start empty
- **D-05:** **Clear everything.** When position lands, all estantes AND all shelf assignments are
  deleted; every copy starts in `Sin ubicar`, even though games are physically on shelves. No
  backfill from name order, no "orden sin revisar" state. Staff recreate estantes with
  **Nuevo estante** and walk each shelf left to right — placement-at-far-right records the real
  order as a side effect. — **Reversibility:** one-way — destroys production shelf data; recovery
  only from a backup.
- **D-06:** The migration logs counts of estantes and assignments it removes. The rollout plan takes
  a `pg_dump` immediately before deploy and records those counts (plan 01.8.1-14 baseline pattern).
- **D-07:** Because of D-05, the migration and the new Estantes page ship in the **same deploy** —
  production must never have cleared shelves without the screen to rebuild them.

### Estantes page behaviour
- **D-08:** *(rewritten 2026-09-17 — estante UI restart, sketch 069, decisions 1–68 in
  `.planning/notes/estante-ui-restart.md`; replaces master/detail, 066 R2-A and the zone bar)* Three pages:
  - **Estantes** (`/admin/estantes`) — one job: find a box. Header: title + **Pendientes** icon with a count badge
    (D-19g) + gear (Administrar estantes). Idle: the prompt **"¿Qué juego buscás?"** and the search field
    ("Buscá un juego") centred at the optical centre (2:3), nothing else. Focusing the empty field shows **Últimas
    búsquedas** (3) in the dropdown; typing shows suggestions (cover · name · estante or ● Sin lugar); no match →
    **"Crear «texto»"** → the Juegos new-game editor with the name filled in → "¿Dónde va?" (D-00c).
    Picking a game: the field **keeps its name with ✕** (✕ = back to idle; focusing selects the name so typing
    replaces it); the page rises (title → field 16, field → answer 32) and shows the estante as context (18px estante
    icon + name, 14/600 muted) over the **rail**: the whole estante as a swipeable row of 96px covers opened at the game,
    which is **lifted** (−12px + shadow). A **"+" on each side of the selected cover** opens the full-height
    **"¿Qué juego va acá?"** sheet (Sin ubicar games first; a search over every game — a shelved one is moved; no match
    → Crear, which places the new game straight into that spot). Tapping another cover moves the selection; tapping the
    selected cover opens its options sheet (Ver ficha · Mover · Quitar del estante, D-19e). A game with no spot opens
    "¿Dónde va?" at once.
  - **Pendientes** (`‹ Estantes`) — the work queues: **Afuera** (Phase 4 checkout data; the section exists empty until
    then) and **Sin ubicar**, each a heading with count + one hint line + all rows. Afuera row → Estantes with the game
    lifted in its spot; Sin ubicar row → "¿Dónde va?".
  - **Administrar estantes** (gear, `‹ Estantes`) — estante rows (estante icon · name · "N juegos"; **no chevron**, no
    page per estante). Header: ⇅ **Ordenar** + **"+" Nuevo estante** icons. Row → options sheet **Editar** / **Eliminar**
    (D-10). Nuevo estante and Editar share one **name sheet** (field pre-filled and selected — "Estante 10" or the
    current name — hint "Un nombre que se reconozca en el salón.", Crear estante / Guardar; errors for empty and
    duplicate names). **Ordenar** is a mode: header "Ordenar estantes" + Listo, rows with a ≡ drag handle; tapping ≡
    shows ↑/↓ on that row (non-drag path, WCAG 2.5.7); Listo → "Orden guardado" + Deshacer. The order is used everywhere
    estantes are listed.
  **Why:** real-world priority — the frequent job is locating a box (put back / pick up); managing estantes is rare. The
  developer asked for search first and management as a secondary page, then rejected lists under the search (they
  competed with it) in favour of Pendientes behind a badge. **Routes:** no `/admin/estantes/:id`; Pendientes and
  Administrar estantes get their own routes under `/admin/estantes`.
- **D-09:** **First run** (0 estantes, all copies Sin ubicar): an honest empty state on **Administrar estantes** — one
  line of purpose (e.g. "Creá los estantes en el orden en que los recorrés") and **Nuevo estante** as the one action
  (the name sheet, D-08). No wizard/checklist, no seeded room layout. Estantes itself stays search-first; its
  Pendientes badge shows every copy Sin ubicar.
- **D-10:** **Deleting a non-empty estante:** destructive row in the estante options sheet →
  confirmation dialog (D-19f) "¿Eliminar {estante}?" stating the consequence ("Sus N juegos quedan sin lugar hasta que
  los vuelvas a ubicar.") → delete → stays on Administrar estantes; copies return to Sin ubicar; an undo snackbar
  ("Estante eliminado" + Deshacer) restores the estante and its copies' positions.
- **D-11:** **Concurrent staff:** position writes are serialized per estante (transaction +
  advisory lock, as plan 01.8.1-15 did per BGG id) so positions never collide or gap. Every open
  Estantes page, Pendientes page and Administrar estantes page updates live over PubSub (Pendientes badge and
  lists, estante counts and order, the rail). If a copy you
  are acting on changed underneath you, a quiet snackbar says so.

### Consistency system

- **D-18:** Consistency is held in code by **one admin component module** (field, section panel,
  row, pill, A1–A4 actions, sheet, save bar, back row) so screens cannot hand-roll them, plus the
  sketch harness's measurable rules ported to tests (`audit-admin.js` A1–A9, D1–D3, K1, 44px hit
  boxes). Rules a LiveView test cannot measure go to the UAT phone checklist.
- **D-19:** **Mobile-standards benchmark pass before planning:** compare each component the sketches
  settled (field, label, section, button roles, sheet, tab bar, row, toast, save bar, drawer)
  against iOS HIG and Material 3; produce a deviations table. Where sketches match, nothing changes.
  Each real deviation is brought to the user **one at a time** (keep vs align).
  **Resolved 2026-09-16** (`01.8.2-BENCHMARK.md`), all four aligned:
  - **D-19a:** the save bar **pins above the tab bar while dirty**; clean, it stays in the page.
  - **D-19b:** a snackbar with an action stays **10 s** (closes early when replaced or on ✕);
    plain snackbars keep 4 s.
  - **D-19c:** **one feedback component**: the top toast is deleted and its messages use the bottom snackbar.
  - **D-19d:** the **drawer and hamburger move to the left, site-wide** (public + admin), with D-12.
  - **D-19e:** *(added 2026-09-16, estante UI restart decision 29)* **every admin bottom sheet closes with a
    44px ✕ at the right of its header**; tap outside, drag down and Esc still close it. **No Cancelar row** —
    replaces 065 round 7's "commit first, Cancelar last with ‹", which read as a back link and as one more
    option. Applies to option sheets, choose-a-destination sheets and form sheets (commit row stays first).
    Public catalog sheets already carry a 44px close and stay as they are (D-16).
  - **D-19f:** *(added 2026-09-16, estante UI restart decisions 41–42)* **every destructive action in the admin
    confirms in a centred dialog, never in a sheet**: a 312px M3 basic dialog (16px radius) with an 18/600 question
    naming the thing ("¿Quitar {juego} del estante?"), one 14px muted line with the consequence, and two text
    actions right-aligned — **Cancelar** (focused by default) and the verb in Peligro red. Scrim tap and Esc cancel.
    A confirmed change still gets the Deshacer snackbar when it can be undone. Covers Quitar del estante, deleting
    an estante (D-10), Quitar del staff, Retirar a game, and any later destructive action. Replaces "in-sheet
    confirms" here and 064's "Peligro … always confirms in a sheet".
    **Anatomy, same scope** (restart decisions 30–31): the header is not a row — optional 56×60 cover, title
    18/600, subtitle 14px, ✕ at the right, then a full-width 1px divider and 8px before the rows. A row whose
    result is not obvious is two lines: short verb + one 13px grey line saying what happens (64px); single-line
    rows stay 48px.
    A sheet taller than 85% scrolls its rows under a pinned grabber + header, so the ✕ never scrolls away.
  - **D-19g:** *(added 2026-09-17, estante UI restart decision 59)* **pending work lives behind a header icon with a
    count badge, never as lists on a task page.** When a page has one main job (Estantes: search a box) and there are
    queues of things to do (Afuera, Sin ubicar), the page shows only its job; the queues go on their own page
    ("Pendientes", `‹ back`), opened from a 44px A3 icon in the page header, left of any other header icon, carrying an
    18px count badge (primary fill, "99+" above 99, no badge at 0; the count is in the accessible name). Use the same
    pattern anywhere else in the admin that needs "things waiting for you".
  - **D-19h:** *(added 2026-09-17, restart decision 22)* **a status is a dot + text, never a pill** — an 8px dot in the
    status colour before the word (● Sin lugar, ● Borrador, ● Retirado, ● Afuera). Every status indicator in the admin.
    Tag and filter chips are not statuses and are not affected. Supersedes D-00a's "Juegos pills".
  - **D-19i:** *(added 2026-09-17, restart decisions 25, 45)* **a chevron means "this row opens another page"**. Rows
    that act in place (show an answer, open a sheet) have none.
  - **D-19j:** *(added 2026-09-17, restart decisions 54, 57–58, 61)* **a page with one main job shows only that job**,
    and its rhythm follows ranks, not habit: page title 22/600 › prompt 17/600 › the main control (48px field) ›
    section/context 15/600 or 14/600 muted › row names 14–15 › chips/subs 12–13. Secondary lists move behind an entry
    (D-19g) instead of sitting under the main control; switching what is below never moves the main control.
  - **D-19k:** *(added 2026-09-17, Web redesign decision 10, sketch 070)* **taking an item out of a list staff curate is
    not destructive**: it happens at once with a Deshacer snackbar (10 s), no dialog, and the row is not Peligro red
    ("Quitar de la fila" on a home row). D-19f's dialog stays for actions that lose state staff would have to rebuild —
    Quitar del estante (the spot), Eliminar estante, Quitar del staff, Retirar a game.
  - **D-19l:** *(added 2026-09-17, Web redesign decision 18, sketch 070)* **a page with one main job may list its
    siblings under that job** — the job stays at the top and fully usable, and the list below is navigation, not a second
    control (Web: the destacada's rail, then "Otras filas"). It is the counterpart to D-19g: queues of pending work still
    go behind a header badge, but a short, stable list of the same kind of thing (home rows, not tasks) earns its place
    on the page when the main control alone leaves half the screen blank — measured on Web: 250px of content against
    272–449px of blank at 375×667…390×844. Amends D-19j, which reads as "nothing below the main control".
  - **D-19n:** *(added 2026-09-18, Juegos redesign decisions 6–7 and 9, sketch 071)* **a long list keeps its context
    in two pinned tiers.** Measured on Pendientes at scrollTop 1500 (375×667): the page title, the back link **and**
    the section heading are all off screen at once, leaving 11 rows with nothing to orient them and the back link
    1,500px away; a Sin datos section is 3,307px tall and the full Juegos catalog 27,664px (~45 screens).
    Both design systems pair two mechanisms and so does this admin:
    - a **44px page bar** (`‹ back` + the page title at 17/600) pins at the top of the scroller once the title row
      has gone behind it. It is an **absolute overlay, not a sticky child** — at rest it must cost zero layout
      (verified byte-for-byte: phead 69, field 129, heading 209, first cover 244.5, row 64, all unchanged).
      `inert` toggles between the in-page back link and the bar's, so **exactly one back control is ever focusable**.
    - the **section heading** pins under it, full-bleed and opaque so full-bleed rows cannot slide past its edges.
      The "stacked" push is free from `position: sticky`: each heading is confined to its own section, so an
      arriving section evicts the previous heading.
    - on a page whose one job is a **search**, the search itself pins instead of a title bar — a bar there would
      only repeat the word the pinned heading already says. It is the *same* input pinning, never a copy, so there
      is no second field to keep in sync. It **hides on scroll-down and returns on scroll-up** (+1 visible row on
      every viewport), never while focused or within 140px of the top. Measured and rejected: collapsing it to a
      44px icon saves 16px — a quarter of a row — gaining **0** rows at 375×667 *and* costing a tap.
    - a new screen always starts at scrollTop 0, so the bar never appears on a page nobody scrolled.
  - **D-19g-bis:** *(added 2026-09-18, Juegos redesign decision 8, sketch 071 — amends D-19g)* **D-19g governs real
    work *queues*; a catalog groups its own rows.** A queue is a set of items in a genuinely different state
    (Estantes' **Afuera**, **Sin ubicar** — the game has no shelf), and those still go behind a header badge on
    their own page: **Estantes is unchanged.** But on **Juegos** the incomplete games are not a queue — "sin datos"
    is an *attribute of a catalog row*, not a separate work item — so Juegos is **one list of collapsible groups**
    (`Sin datos 49` · `Borradores 1` · `Juegos del club 385`) with no Pendientes page and no badge. Rules for such
    groups: they **partition** the list (49 + 1 + 385 = 435, never a game in two); work groups are **collapsed by
    default** and sit on top, so both counts are on screen at rest without burying the catalog; the header is a
    real **44px** control; opening a group **keeps the tapped heading where the finger left it**; and **a row never
    repeats its group's state** — the group names the state, the row names the thing.
    **A group header must not read as a row** *(added 2026-09-18, decision 10 — applies to every `.lhead` in the
    admin, 069's Pendientes and 070's Otras filas included)*: measured, the two shared **four attributes exactly** —
    15px, `rgb(35,19,57)`, transparent background, and a 20px trailing icon at x=339 — leaving only weight to
    separate them, and the app ships Inter in **400/600 only**. So a group header carries a **full-bleed tonal band**
    (`--color-surface`, which also makes its pinned opacity natural) and its **caret is leading**, a right-pointing
    disclosure triangle rotating 90° — never a trailing "›", which D-19i reserves for navigation.
    Contrast on the band: 14.84:1 light / 12.25:1 dark.
    **A page carries two text left edges, not three** *(added 2026-09-18, decision 13 — supersedes decision 10's
    indent)*: outdenting header text to 44 against a row's 68 gave the page a **16 / 44 / 68** ladder in which the
    text aligned with nothing. A row's text cannot leave 68 (its 40px cover holds it there), so the **band** moves:
    the caret takes the same **40px leading slot** the cover occupies (20px caret + 24px margin + the 8px gap), which
    puts header text at **68**, the row-text column, and leaves the caret **left-aligned at 16** with the page title,
    the search field and the covers. Two edges, **16 and 68** — the iOS/Material keyline pair. Group hint lines stay
    at 16. Rejected: header text at 16 with a trailing caret — it aligned with the page title but left the carets
    ragged (measured x=126 / 127 / 182), floated the band 52px left of its own rows against the welding rule below,
    and put the caret back on the trailing side. The header/row separation now rests on the band, the icon slot
    (16 vs 339), height (44 vs 64), weight and full-bleed — **not** on indent.
    **Bands must not repeat into a stripe** *(added 2026-09-18, decision 11)*: three equal bands with equal air
    measured 44/16/44/16/44 and read as "rayado". Groups of the **same kind** join into one contiguous block, split
    by a hairline and with **no gap**; a different kind is separated by 32; and **a band is always welded to its own
    rows** (0), collapsed or expanded, so the component never shows two attachments at once. Measured visible gaps
    on Juegos: **24 / 0 / 32 / 0** — no two alike. Gaps are back-solved from **visible edges**, since a filled band's
    box is what the eye reads, not its text.
  - **D-19m:** *(added 2026-09-17, Web redesign decisions 14–16, sketch 070)* **a kind is a quiet tag, a status is a dot**
    (D-19h): the tag is 18px, 11px regular, lowercase, on a hairline `--color-border`, muted text — it never competes
    with the row name (6.2:1 against the name's 17.2:1). **A count is a neutral pill on the tile's bottom-right corner**,
    page-filled with a 1px `--stroke`, 11/600 muted, and is in the tile's accessible name — never the top-right filled
    primary badge, which means pending work (D-19g).

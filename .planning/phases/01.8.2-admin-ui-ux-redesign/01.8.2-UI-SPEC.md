## Component contract

Every admin component below is drawn from `01.8.2-BENCHMARK.md`'s measured table and the
`sketch-findings-pukllay_club/references/admin-*.md` files. Geometry is the sketches' measured
values, not estimates.

### Field

44px tall, label above (12px/600 muted), 1px `--stroke` border (≥3:1), 8px radius, 16px input
text (no iOS zoom-on-focus). Text fields share the Secundaria button stroke token — a field and a
button can never visually drift apart.

### Section panel

Tonal fill (`--color-surface`), no border, 12px radius, 16px padding.

### Row

44px hit-box floor, measured on the hit box, not the drawn box. Two shapes:
- **Single-line row** (a setting, an action): 48px.
- **Two-line row** (a game row, a sheet row whose result isn't obvious): 60–64px — short label +
  one 13–14px muted second line.
A row that opens another page carries a trailing chevron (D-19i) and nothing else does. A row
that opens a sheet carries no glyph at all, unless it is an editable value in the game editor
(D-23), which carries a `--val` tint on its value line — the tint marks the datum you're about to
change, never "this row is tappable."

### Status dot

8px dot in the status colour, immediately before the word — never a pill (D-19h): `● Publicado`,
`● Borrador`, `● Retirado`, `● Sin lugar`, `● Afuera`.

### Sheet shell

18px top radius, 36×4px grabber, 38% scrim, max 85% viewport height (scrolls its rows under a
pinned grabber + header past that). Header: optional 56×60 cover + 18px/600 title + 14px subtitle
+ a **44px ✕ at the right** (D-19e) — the only way a sheet's header closes; no Cancelar row. Full
width 1px divider, 8px before the first row. Two-line option rows are 64px, single-line rows 48px.

### Centred (destructive) dialog

312px wide, 16px radius (D-19f). Header is not a row: optional 56×60 cover, 18px/600 title, 14px
subtitle, then a full-width 1px divider and 8px before the rows. An 18px/600 question naming the
thing, one 14px muted consequence line, two right-aligned text actions — **Cancelar** (focused by
default) and the verb in Peligro red. Scrim tap and Esc cancel. A confirmed change that can be
undone still gets the Deshacer snackbar.

### Snackbar

Bottom-anchored, inverse surface, 13px text. **10s with an action** (Deshacer / Reintentar /
Editar), closing early on ✕ or on replacement by the next snackbar; **4s without an action**
(D-19b/D-19c). One feedback component in the whole admin — the top toast is deleted.

### Save bar

Fixed at the foot, always present, 77px, page-coloured, drawing only its 1px top divisor line
(D-28). Enabled only when there is something to save. The button is A1 exactly — outline, 44px,
radius 8, 14px/600, natural width, right-aligned on the keel. The bar's left half carries the
transient save-state line: `● Sin guardar` (in `--color-warning`, D-34's resolution of the
sketch's non-existent `--color-accent-text`) or nothing when clean. The body reserves the bar's
real measured height, never an estimate.

### Back row / page bar

`‹` + 22px/600 title at rest, in the page flow. On a long list, a **44px page bar** (`‹ back` +
17px/600 title) pins at the top once the title row scrolls past it — an absolute overlay, not a
sticky child, costing zero layout at rest (D-19n). `inert` toggles between the in-page back link
and the bar's own, so exactly one back control is ever focusable.

### The game editor's top app bar

The one documented exception to outline-only: a fixed 56px bar, `‹ · título · ⋮`, where the ⋮ is
the bar's only control (D-27). `Guardar` lives at the foot (see Save bar above), not in this bar.

### Tab bar

Fixed at the screen's bottom, 67px, for a signed-in staff member (D-13b). Five destinations —
Admin, Juegos, Estantes, Web, Perfil (avatar tab) — the active one carrying a 56×30 pill
indicator behind its icon, 11px/600 labels. A destination with pending work shows an 18px
primary-filled count badge (`99+` above 99, absent at 0, count in the accessible name — D-19g's
shape, never D-19m's neutral count pill). Renders on every page a signed-in staff member visits,
admin and public alike, with one measured exception below (D-14).

**D-14 — the tab bar suppresses on the game detail page (`suppress`, decided 2026-09-23).**
Measured in real headless Chrome (real magic-link login, `getBoundingClientRect()`/z-index) at
390×844 and 360×640:

- **Catalog index page (`/`): no collision.** `.pk-filter-trigger` sits at y 9.5–53.5 at both
  viewports; the tab bar at y 777–844 (390×844) / y 573–640 (360×640).
  `filterTriggerCoveredByTabBar: false` at both. **This corrects an earlier framing** (this
  document's own history and `01.8.2-CONTEXT.md`'s D-14 note both described a second
  `pk-bottom-collapse` bar the tab bar would stack against on this page — measurement found no
  such fixed-bottom element exists here; `bottom_collapse` is a padding mechanism, not a second
  bar). The index page does not suppress and needs no exception.
- **Game detail page (`/juegos/:id`): full occlusion, not partial.** Both `.pk-admin-tab-bar`
  and `.pk-mobile-cta-bar` are `position: fixed; bottom: 0` with no coordination between them —
  they overlap rather than stack. Tab bar z-index 70 (top 777 / bottom 844 at 390×844, top 573 /
  bottom 640 at 360×640); CTA bar z-index 45 (top 775 / bottom 844, top 571 / bottom 640). The
  reserve button itself (top 788 / bottom 832 at 390×844; top 584 / bottom 628 at 360×640) sat
  **entirely inside** the tab bar's band at both viewports (`overlapPx: 67` at both,
  `ctaBtnFullyCoveredByTabBar: true` at both).
- Visible content heights computed from these numbers: collide-as-overlap 711px (390×844) /
  507px (360×640); collide-as-stack 644px / 440px; merge-or-suppress 713px / 509px.
- The catalog's filter control's reachability is unaffected under any option (1 tap, unchanged)
  since it was never bottom-anchored.

**Chosen: suppress.** The tab bar hides specifically on the one page that already owns the
bottom of the screen with its own fixed surface (the game detail page's `.pk-mobile-cta-bar`)
and shows everywhere else, including the catalog index (which the measurement proved has no
collision at all) and every admin page. This keeps D-13b's promise everywhere the bar does not
fight an already-shipped, already-tuned fixed bar, without inventing a merged-bar interaction
pattern for a single page. **Rejected:** collide (both bars render, ~130px lost on a 390×844
viewport, and the reserve CTA stays unreachable underneath the tab bar); merge (no second
bottom-fixed surface exists on the detail page to fold the tab bar into — merge only ever
applied as a name, not a real mechanism, once the CTA bar turned out to be the sole owner of
that band).

**Implementation contract:** the suppression signal is a structural, call-site-scoped boolean
attr (`Layouts.app/1`'s `suppress_tab_bar`, mirroring `admin_chrome`'s pattern) passed
explicitly by `CatalogLive.Show`'s own `<Layouts.app>` call — never a URL-string admin-path
match anywhere in `layouts.ex` (T-01.8.2-45). `tab_bar/1`'s own `staff_session?/1` gate is
unchanged and stays the sole authority for every other page.

## Copywriting contract

Argentine/Rioplatense Spanish (voseo) throughout — "Vas a poder", "Probá", "Tenés", never
"Puedes"/"Tienes". Every string below is current; where Task 1's open items are resolved, the
developer's decided wording is recorded verbatim and is **not** an open item.

### Decided in this plan (open item 5, Task 1 — developer's own words)

| # | Question | Decision |
|---|----------|----------|
| 1 | "agregado" vs "ya tiene sus datos" — creation vs arrival | **Split into two distinct phrases.** Creation (the row now exists, still unpublished): **«Borrador creado»**. Arrival (BGG enrichment finished, the game now has its data): **«Agregado al club»**. The chosen snackbar form for the arrival event: `Catan: agregado al club`. «Agregado» means **arrival only, never creation** — every creation-path string in this contract uses «Borrador creado» or an equivalent creation phrasing, never «agregado». |
| 2 | `Ver` vs `Editar` on the enrichment-completion toast | **`Editar`.** The staff member's job after enrichment is to correct/complete the data, not just look at it. The toast reads: message `Catan: agregado al club` + action `[ Editar ]` — using the decided arrival phrasing from #1, not the older "ya tiene sus datos" wording. |
| 3 | `Guardar` vs `Guardar cambios` | **`Guardar`** (one word). Confirms D-00a / sketch 065 R7 #3. **`01.8.1-UI-SPEC.md`'s shipped `Guardar cambios` (line 144) is SUPERSEDED** — see the supersession banner on that file. |

None of the three is deferred; there is no `OPEN — carried to UAT (D-21)` row for open item 5.

### Pre-resolved, not a developer question (the `+` sheet hint)

The `+` sheet's hint used tuteo (`hasta que lo publiques`) against the admin's voseo everywhere
else — a defect against this project's Rioplatense/voseo standard, fixed here:

> **Was (tuteo, defect):** "Traemos toda la info de BGG. Queda como borrador hasta que lo
> publiques."
> **Now (voseo-safe):** "Traemos toda la info de BGG. Queda como borrador hasta publicarlo."

The rewrite sidesteps the standard-vs-colloquial-voseo subjunctive ambiguity entirely (this
project's existing voseo copy — "Vas a poder", "Probá", "Tenés" — is all indicative/imperative;
there's no precedent here for a voseo-conjugated subjunctive) by using the person-neutral
infinitive `publicarlo` instead of conjugating the verb at all. No tuteo form survives.

### Prohibition — never render this on a draft

**«Se está viendo así en la web» must never be specified for a draft.** A draft is not on the
web — this is the single easiest thing for a build to get wrong here, per
`sketch-findings-pukllay_club/SKILL.md`'s own flag on this exact string, and 073 d38's rejected
accusation copy. The only durable-status copy that may ever appear is D-29's two consequence
lines, recorded verbatim above under "Durable status franja": `● Publicado · Así se ve en la
web.` and `● Retirado · No se ve en la web ni está en el estante.` A draft's status franja does
not exist — a draft has no "how it looks on the web" line, because it has none.

## UI-considerations matrix

One row per admin surface. Categories not listed resolve as **backstop** — consistent with the
explicit truths below, confirmed by a held-out UI-state test at verify time.

| Surface | Empty | Loading | Error | Zero-one-many |
|---|---|---|---|---|
| **Dashboard** | Cannot occur (fixed card set always renders) | Skeleton cards matching the real 2-col/3-col grid | A card's own data query failing shows that card's count omitted, not a page-level error | N/A — fixed card count |
| **Juegos list** | A status group with 0 rows is not rendered (D-25) — never an empty-state illustration for a whole group | Flat skeleton rows matching real row height, no shimmer | A load-more failure shows an inline retry row, not a page error | 1 group renders identically to 50; the catalog's own body section never collapses |
| **Editor** | Cannot occur (only reachable for an already-published game, D-30) | Skeleton mirrors the ficha layout (cover, title, fact grid) while the game's own data loads | A field-sheet save failure keeps the sheet open with an inline error, never silently discards the edit (D-38's save-first-then-link lesson) | Every editable block always renders, even when its value is empty (shows a placeholder row, not a missing block) |
| **Estantes** | The idle prompt (`¿Qué juego buscás?`) IS the empty state — nothing to search yet is not an error | Type-ahead suggestions load under existing debounce; no extra skeleton | A failed place/move save reverts the copy to its prior position and shows an error snackbar | A rail with 1 box behaves identically to a rail with 50 — the "+" on each side of the selected cover always renders |
| **Pendientes** | Both queues (Afuera, Sin ubicar) render their heading + hint even at 0 rows, until Afuera has real data (Phase 4) — Sin ubicar at 0 is the honest success state, not a defect | Flat skeleton rows per queue | A queue's own query failing shows that queue's section with an inline retry, not the whole page | Each queue heading always shows its count, including 0 |
| **Administrar estantes** | First-run (0 estantes): one line of purpose + `Nuevo estante` as the one action (D-09) — no wizard, no seeded layout | Flat skeleton rows | Create/rename/delete failures surface inline on the name sheet, never silently discarded | Reorder mode (`Ordenar`) works identically for 1 estante or 20 — Listo always available |
| **Staff** | Owner alone shows the existing 01.8.1 empty-state copy (surviving, unchanged) | Flat skeleton rows | Invite-email failure uses the existing 01.8.1 error copy (surviving) | N/A — staff list is always small |
| **Web / secciones** | A section with no visible games stays hidden entirely, no fallback (D-24, surviving from 01.8.1) | Existing carousel skeleton (public surface, E7, unaffected by this phase) | Unaffected — E7 is public-surface, untouched | Featured stays pinned first regardless of count below it |
| **Niveles (band audit)** | "Todo en orden — no hay discrepancias de nivel." positive empty state, no CTA (surviving from 01.8.1) | Flat skeleton rows | A mismatch row's own re-check failing keeps the row in its prior state with a retry action | Each mismatch row carries `Corregir` / `Mantener`, regardless of how many rows |
| **Shared chrome (drawer, tab bar, sheets, snackbar, dialogs)** | N/A — chrome always renders once a staff session exists | Drawer/tab-bar render immediately from session state, no loading state | A PubSub disconnect during a live update shows the existing quiet "changed underneath you" snackbar (D-11), never a silent stale render | The Pendientes badge shows no badge at 0, a real count 1–99, and "99+" above 99 (D-19g) |

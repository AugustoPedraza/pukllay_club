## Accomplishments

- `publish_game/1` and `retire_game/1` now refuse a transition from an origin status they aren't defined for (`{:error, :not_publishable}` / `{:error, :not_retirable}`), closing the gap sketch 078 proved was pure paint — a retired game can no longer be published directly, bypassing `restore_game/1`'s guard.

## Re-measured Distribution (D-36 Task 3, dev database, 2026-09-23)

| status | enrichment_status | is_expansion | bgg_id IS NULL | count |
|---|---|---|---|---|
| draft | enriched | false | false | 1 |
| published | bgg_missing | false | false | 8 |
| published | enriched | false | false | 385 |
| published | no_bgg_id | false | true | 15 |
| published | no_bgg_id | true | true | 26 |
| **total** | | | | **435** |

**This is unchanged from CONTEXT's 2026-09-22 recorded shape** (`draft 1 · published/bgg_missing 8 · published/enriched 385 · published/no_bgg_id 15 · published/no_bgg_id-expansión 26 = 435`). The D-35 publisher-dedup backfill (quick tasks 260922-tum/260922-veq, confirmed in production 2026-09-23) only corrects values *inside* already-`"enriched"` rows — it cannot move a row across `status`/`enrichment_status`/`bgg_id`/`is_expansion`, so this axis was never going to show its effect.

**Content cross-check:** exactly 49 published games have both a blank/nil `description` and a nil `cover_url` — precisely the union of the 8 `bgg_missing` + 15 `no_bgg_id` base + 26 `no_bgg_id` expansions, and no other row. This confirms the enrichment_status-based grouping and a real-content predicate agree completely, so the migration's `still_empty_query/0` is keyed on content (`status == "published" AND (description IS NULL OR '') AND cover_url IS NULL`) rather than the status label. No live re-enrichment retry of the 8 `bgg_missing` games has actually run since credentials were confirmed (quick task 260922-veq's own report left that repair "pending a human-authorized production run") — the measurement shows they did not "re-enrich clean," so per D-36's own rule they are genuinely still empty and were unpublished along with the rest.

**D-36's expansion leniency does not apply here:** the plan text says an expansion is "excluded from the blanket rule unless the measurement says otherwise." All 26 `no_bgg_id` expansions are exactly as empty as the 15 broken base games (no description, no cover, no `weight_band`) — the measurement says otherwise, so all 26 are included in the 49-row unpublish set.

Migration verified round-tripping cleanly: `mix ecto.migrate && mix ecto.rollback --step 1 && mix ecto.migrate` exits 0 and reproduces the identical 49-id set on each `up/0`.

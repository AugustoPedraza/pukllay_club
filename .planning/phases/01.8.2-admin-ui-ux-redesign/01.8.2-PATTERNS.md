## Pattern Assignments

### `lib/pukllay_club/catalog/copy.ex` (model, CRUD)

**Analog:** `lib/pukllay_club/catalog/shelf.ex` (full file, 34 lines — read above)

**Full pattern to copy** (imports + schema + changeset, lines 1-33):
```elixir
defmodule PukllayClub.Catalog.Shelf do
  @moduledoc """..."""
  use Ecto.Schema
  import Ecto.Changeset

  schema "shelves" do
    field :name, :string
    field :position, :integer
    has_many :games, PukllayClub.Catalog.Game
    timestamps()
  end

  def changeset(shelf, attrs) do
    shelf
    |> cast(attrs, [:name, :position])
    |> validate_required([:name])
    |> validate_length(:name, max: 40)
    |> unique_constraint(:name)
  end
end
```
**Applied to `Copy`:** `belongs_to :game, PukllayClub.Catalog.Game`, `belongs_to :shelf, PukllayClub.Catalog.Shelf` (nullable — unplaced), `field :position, :integer` (nullable — unplaced has no position), `field :number, :integer` (D-03's stable "copia N de M," never renumbered). Mirror the `@moduledoc` convention: state which D-numbers this schema implements and what invariant the DB enforces vs. what application code must (this repo's every schema file explains its "why," not just its fields — see both `game.ex:1-12` and `shelf.ex:1-7` above).

### `lib/pukllay_club_web/components/admin_components.ex` (component, transform)

**Analog:** `lib/pukllay_club_web/components/core_components.ex` — `button/1` (core_components.ex:105-135, quoted above):
```elixir
def button(%{rest: rest} = assigns) do
  variants = %{"primary" => "btn-primary", "secondary" => "btn-outline btn-primary pk-btn-secondary", nil => "btn-primary btn-soft"}
  assigns = assign_new(assigns, :class, fn -> ["btn", Map.fetch!(variants, assigns[:variant])] end)
  if rest[:href] || rest[:navigate] || rest[:patch] do
    ~H"""<.link class={@class} {@rest}>{render_slot(@inner_block)}</.link>"""
  else
    ~H"""<button class={@class} {@rest}>{render_slot(@inner_block)}</button>"""
  end
end
```
Pattern to copy for the new **A1-A4 action component**: a variant-keyed class map plus branch-on-`href`/`navigate`/`patch` to decide `<.link>` vs `<button>` — this is the direct precedent for rendering the four S3-Contorno action tiers as one component with a `variant` attr, rather than four separate components. **Do not reuse the `variants` map's actual classes** (`btn-primary`/`btn-outline` are daisyUI-filled conventions D-16/D-17 explicitly reject for `/admin` — only the *code shape* transfers, not the CSS classes).

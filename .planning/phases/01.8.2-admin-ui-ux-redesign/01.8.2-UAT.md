## Group (c) — this phase's new truths

### c1. The start-empty migration
expected: After deploy, `/admin/estantes` shows zero estantes and every copy `Sin ubicar` (D-05).
Confirmed by the post-deploy smoke (Task 3) against the recorded pre-deploy baseline, and
re-confirmed here as a UI-level truth: Administrar estantes shows D-09's first-run empty state
with `Nuevo estante` as the one action.

### c2. Place / move / undo with position and copies
expected: Creating an estante via `Nuevo estante`, then placing a copy via search → "+" on the
rail, produces a real left-to-right position; a Deshacer snackbar reverses the placement; a second
copy of the same game shows `copia N de M` once the game has more than one copy (D-01..D-04).

### c3. Search → rail → "+" / options (D-08)
expected: Typing a game name on Estantes surfaces suggestions (cover · name · estante or `● Sin
lugar`); picking one opens the rail at that game (lifted −12px + shadow); tapping the selected
cover opens its options sheet (Ver ficha · Mover · Quitar del estante).

### c4. Pendientes (D-08, D-19g)
expected: The header's Pendientes icon shows a count badge; opening it shows Afuera (empty until
Phase 4) and Sin ubicar as two queues, each row routing back to Estantes (Afuera) or "¿Dónde va?"
(Sin ubicar).

### c5. Administrar estantes: create / rename / order / delete (D-08, D-09, D-10)
expected: Nuevo estante and Editar share one name sheet (pre-filled and selected); Ordenar mode
shows drag handles + tap-reveal ↑/↓; deleting a non-empty estante confirms in a centred dialog
(D-19f) naming the consequence, then offers Deshacer.

### c6. Crear from search (D-08)
expected: Typing a name with no match offers `Crear «texto»`, opening the new-game editor with the
name filled in, then immediately into "¿Dónde va?" to place the new copy.

### c7. Two staff acting concurrently (D-11)
expected: With two sessions open (two browser profiles or a phone + desktop), a position change
made in one session appears live in the other's open Estantes/Pendientes/Administrar page via
PubSub, without a manual refresh; a conflicting concurrent write is serialized (no collision, no
gap) and shows a quiet "changed underneath you" snackbar to the loser.

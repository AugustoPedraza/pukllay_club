## Accomplishments

- `sheet/1` renders D-19e's shell exactly: pinned grabber + header (optional
  56×60 cover, 18/600 title, 14px subtitle, a 44px ✕), a full-width divider,
  then rows scrolling under the pinned chrome, capped at 85vh — with **no**
  `Cancelar` row anywhere, verified by a negative test.
- `dialog/1` renders D-19f's centred 312px M3 dialog with `Cancelar` first in
  DOM order and carrying initial focus (`autofocus`), the verb in the Peligro
  role, and is never nested inside `sheet/1` markup (T-01.8.2-30's mitigation,
  asserted directly).
- `assets/js/hooks/admin_sheet.js` funnels Esc, scrim tap and pointer
  drag-down through the SAME `phx-click` control a pointer tap on the close
  button would hit, adds a focus trap and focus return via a `MutationObserver`
  on the one stylesheet-owned open/close class, and checks visibility only via
  `offsetParent` — never `JS.show`/`JS.hide` (T-01.8.2-32) and never `.hidden`.
- `snackbar/1` replaces the admin's top toast outright: an action snackbar
  carries a 44px ✕ and a `data-timeout="10000"`; a plain one carries neither
  a close control nor a timeout above 4000ms. `Layouts.admin_flash/1` now
  routes every `@admin_chrome` flash (including `Sesión cerrada.`) through it;
  Scope B keeps `flash_group/1` unchanged.
- `save_bar/1` is D-28's fixed 77px foot bar, page-coloured so it draws only
  its 1px top line, with the A1 action natural-width and right-aligned,
  disabled only when clean; the `--pk-save-bar-h` custom property is the one
  source both the bar's own height and the body's `calc()`-derived clearance
  read from. `back_row/1` and `page_bar/1` complete D-19n's two-tier pinned
  context, with `inert` guaranteeing exactly one focusable back control.

## Decisions Made

- `admin_sheet.js` is a hand-authored, non-colocated hook (registered in
  `app.js`), not a `Phoenix.LiveView.ColocatedHook` block embedded in
  `admin_components.ex` — `sheet/1` and `dialog/1` both need the identical
  behavior, and a colocated block would have had to be duplicated verbatim
  into two templates in the same module.
- The snackbar's D-19b durations render as string literals (`"10000"`/
  `"4000"`), not integers — `mix format`/Styler rewrites a bare integer
  `>= 10_000` with an underscore separator, which would have silently
  defeated this plan's own literal `grep -n "10000\|4000"` `<verify>`.
- The snackbar's "inverse surface" is the theme's own base pair, swapped
  (`background: --color-base-content`, `color: --color-base-100`) — no new
  token invented, consistent with how plan 07 resolved its own token gap.
- `--pk-save-bar-h` (77px) is declared once; `.pk-admin-save-bar`'s
  `min-height` and `.pk-admin-has-save-bar`'s body clearance both `calc()`
  off that one property, making D-28's "never an estimate" requirement a
  structural guarantee.
- `page_bar/1`'s at-rest/visible toggle uses `visibility`, not `opacity` —
  `opacity` would have violated the existing "components.css never declares
  a bare opacity property" test from plan 07, and `visibility` doesn't
  affect box generation for an absolutely-positioned element, so zero
  layout cost at rest holds either way.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Edited `lib/pukllay_club_web/components/layouts.ex`, not in this plan's declared `files_modified`**
- **Found during:** Task 2 (the one snackbar, replacing the top toast)
- **Issue:** D-19c requires the admin's top toast be deleted and its messages
  route through the new snackbar. The top toast is rendered by
  `Layouts.app/1`'s single, unconditional `<.flash_group flash={@flash} />`
  call — there is no way to satisfy D-19c's acceptance criteria ("no
  top-positioned admin toast markup remains anywhere under
  `lib/pukllay_club_web/`") without touching that call site, and `layouts.ex`
  was not listed in the plan's `files_modified` frontmatter or Task 2's
  `<files>`.
- **Fix:** Added a private `admin_flash/1` to `Layouts` and branched the
  `app/1` call site: `@admin_chrome` pages render `admin_flash/1`
  (snackbar-routed), everyone else keeps `flash_group/1` unchanged.
- **Files modified:** `lib/pukllay_club_web/components/layouts.ex`
- **Verification:** `test/pukllay_club_web/components/layouts_test.exs`'s new
  "app/1 admin flash routing" tests (4 tests) confirm `admin_chrome: true`
  renders the snackbar and never `toast-top`, while `admin_chrome: false`
  (the default) still renders the top toast unchanged.
- **Committed in:** `dd8c17a` (Task 2 commit)

**2. [Rule 1 - Bug] `<CoreComponents.icon>`'s `aria-hidden="true"` attribute was silently discarded**
- **Found during:** Task 3 (`back_row/1` and `page_bar/1`)
- **Issue:** `CoreComponents.icon/1` declares only `:name` and `:class` — no
  `:rest` global attr — so passing `aria-hidden="true"` produced an
  "undefined attribute" compile warning, which would have failed Task 3's
  own `mix compile --warnings-as-errors` `<verify>`.
- **Fix:** Dropped `aria-hidden="true"` from both call sites, matching the
  existing precedent already in `sheet/1`'s own close-icon usage (no
  `aria-hidden` there either — the icon is decorative by convention, not by
  an explicit attribute this component doesn't accept).
- **Files modified:** `lib/pukllay_club_web/components/admin_components.ex`
- **Verification:** `mix compile --warnings-as-errors` exits 0, no warnings.
- **Committed in:** `46ecaaa` (Task 3 commit)

**3. [Rule 1 - Bug] `page_bar/1`'s at-rest/visible toggle initially used `opacity`, violating an existing invariant**
- **Found during:** Task 3 (`page_bar/1`)
- **Issue:** The first draft toggled `opacity: 0`/`opacity: 1` for the page
  bar's hidden/visible states. Plan 07's own regression test
  ("components.css never declares a bare opacity property") failed against
  this — D-24's opacity prohibition was written for disabled controls but
  the test itself is unconditional over the whole stylesheet.
- **Fix:** Switched to `visibility: hidden`/`visibility: visible` +
  `pointer-events`, which does not affect box generation for the
  already-`position: absolute` element, so "zero layout cost at rest" still
  holds.
- **Files modified:** `assets/css/admin/components.css`
- **Verification:** `mix test test/pukllay_club_web/components/admin_components_test.exs` — the pre-existing opacity-prohibition test and the new page-bar tests both pass.
- **Committed in:** `46ecaaa` (Task 3 commit)

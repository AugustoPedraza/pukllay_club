# Phase 01.8.2 Plan 07: Admin component module, part one (atoms) Summary

**`PukllayClubWeb.AdminComponents` ships the A1-A4 outline-only action system plus every field/row/status/tag atom the admin composes from, each geometry rule taken verbatim from `01.8.2-BENCHMARK.md` and every glyph/disabled/pill rule enforced by a negative test rather than left to convention.**

## Accomplishments

- `action/1` renders the four D-00a/064 "S3 Contorno" anatomies (A1 outlined, A2 text, A3 icon, A4
  sheet row) across four roles (Principal/Secundaria/Terciaria/Peligro) — no filled or ghost daisyUI
  class anywhere, confirmed by a grep verify over the compiled module and its stylesheet.
- `disabled` is unreachable except through `commit={true}` (D-24); passing it without `commit` raises
  at render time naming D-24, and the legitimate disabled state paints with muted colour stops, never
  `opacity`.
- `field/1`, `section_panel/1`, `form_label/1` and `list_section_label/1` land the field/panel/label
  atoms, keeping the *form* label ranks (12px/600 field, 13px/600 group) visibly distinct from the
  *list* section rank (15px/600) — a distinction two tests enforce directly against the CSS source.
- `list_row/1`, `editable_row/1`, `status_dot/1`, `kind_tag/1`, `count_pill/1` land the row/status/tag
  atoms: a chevron only when `opens_page={true}` (D-19i), no glyph at all on an editable value (D-23),
  and a status that is always a dot + word, never a pill (D-19h) — the last two enforced by explicit
  negative tests against rendered markup.

## Decisions Made

- Resolved `01.8.2-TOKENS.md`'s flagged dark-mode Principal-ink gap with `--pk-ramp-400` (the same
  stop `--val` already resolves to, already measured 6.52:1 in that same document) rather than
  inventing a new alias or reviving the discarded `--color-accent-text`.
- Wired `components.css` through a nested `@import` inside `admin/tokens.css` rather than `app.css`,
  since Task 3's own `<verify>` requires `git status --porcelain -- assets/css/app.css` to print
  nothing.
- `status_dot/1`'s five per-status colours are a documented design choice (draft=neutral,
  published=success, retired=error, sin_lugar=warning, afuera=neutral) — no read_first source for
  this plan pins exact colours beyond "dot + word, never a pill."
- The two D-19g-bis decision 20 comparison tests (list-section-label size >= row-name size; pair
  differs from row-meta pair) are grounded in `01.8.2-BENCHMARK.md`'s documented 14px/13px figures
  rather than Task 3's then-unwritten CSS, since Task 2 lands before Task 3 in the same plan.

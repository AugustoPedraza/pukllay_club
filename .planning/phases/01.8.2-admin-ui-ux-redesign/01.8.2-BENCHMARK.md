# Phase 01.8.2: Mobile-standards benchmark (D-19)

**Run:** 2026-09-16 · **Source measured:** `.planning/sketches/065-admin-composition/index.html`
(the composed 059–065 system), headless Chrome, phone view (device frame 366×740 inside a 390×844
viewport), light theme. Values are computed styles and bounding boxes, not the READMEs' prose.

**Standards:** Apple HIG (iOS 18/26) and Material 3 (incl. Expressive). The standards' numbers below
are from knowledge, not re-fetched this session.

**Rule used:** a component **matches** if it agrees with **at least one** of the two platforms (the
admin is a web app used on both, so matching either is a recognised mobile pattern). It is a
**deviation** only when it agrees with neither. Matches change nothing.

## Deviations — resolve one at a time

Ordered by consequence.

| # | Deviation | Consequence if kept | Align would mean | Decision |
|---|---|---|---|---|
| D-1 | Save bar scrolls with the page (063 R6 dropped the sticky bar) | Edit the name at the top of the editor, then scroll to the bottom to find Guardar. The leave-guard stops lost work, but not the hunt. 063 recorded this trade-off. | Guardar reachable without scrolling while there are changes (pinned bar above the tab bar, or in the top row) | **ALIGN** — pin while dirty: with unsaved changes the same bar pins above the tab bar; clean, it stays in the page. Check the fit with the keyboard open before building. |
| D-2 | Undo snackbar hides after 4 s | Undo is the safety net for place / move / quitar and for deleting a whole estante (D-10). 4 s is the M3 minimum and short for WCAG 2.2.1 timing. | Snackbars with an action stay longer (≥10 s) or until dismissed; plain ones keep 4 s | **ALIGN** — a snackbar with an action (Deshacer / Reintentar) stays 10 s and closes early when the next snackbar replaces it or on ✕. Plain messages keep 4 s. The ✕ is new (today's snackbar has none); it is an A3 icon button (M3 allows an optional close icon). |
| D-3 | Two feedback components (top toast + bottom snackbar) | Two positions for "something happened"; the top pill sits over the page head | One component: the bottom snackbar, with or without an action | **ALIGN** — the top toast is deleted; its messages (e.g. "Cerraste sesión") use the bottom snackbar without an action (4 s per D-2). One feedback component in the admin module and the shared chrome (D-16). |
| D-4 | Drawer opens from the right | Opposite of M3; but the **shipped public drawer also opens from the right** (`app.css` `.pk-drawer { right: 0 }`), so it is consistent across the site | Drawer from the left for public and admin | **ALIGN** — site-wide: the drawer and its hamburger move to the left on public and admin (the header layout changes with it). Lands with D-12's shared-chrome work. |

## Outcome

All four deviations **aligned** (2026-09-16). The already-decided one (outlined Principal, 064 S3) stands.
Sketches 066 and 067 are drawn with these in place: pinned save bar while dirty, one bottom
snackbar (10 s with an action, ✕ to close), and a left drawer with a left hamburger.

## Noticed on the way (not standards deviations)

- **Drawer section labels** are 11px UPPERCASE ("ADMIN", "SITIO") while page group labels are 13px
  sentence case ("Ajustes"). Two looks for one "labelled group" role — an internal consistency item
  for the component module (D-18), not a platform question.
- **Estantes tab badge after D-05:** the badge counts unplaced copies, so right after the start-empty
  migration it shows ~400 on every page. Badges are for pending work (matches both platforms), but a
  400 badge is noise until staff have walked the shelves — a planning note, not a design deviation.

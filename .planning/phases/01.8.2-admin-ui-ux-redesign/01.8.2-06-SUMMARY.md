## Decisions Made

- **D-05 clear-slate confirmed as specified** — no backfill, no audit table, `down/0` raises.
  See Task 1 above for the full verbatim confirmation.
- **`PukllayClub.Repo` used directly instead of the `repo()` migration-DSL helper.**
  `Ecto.Migration.Runner.repo/0` reads an `Agent` process the migration Runner starts, which only
  resolves inside an active `Ecto.Migrator` run. The plan's Task 2 explicitly requires the test to
  invoke `up/0`/`down/0` directly (not through `mix ecto.migrate`), which is only possible if the
  migration itself doesn't depend on Runner-only DSL functions. This is safe specifically because
  the migration does no DDL (no `alter table`, no `create table`) — only `PukllayClub.Repo.query!`
  calls, which work identically under `mix ecto.migrate` and under a direct test call. Documented
  in the migration's own moduledoc as the convention for later data-only migrations to follow.
- **Migration counts map: `estantes_removed` = pre-clear `shelves` count, `assignments_removed` =
  pre-clear `games.shelf_id IS NOT NULL` count (the legacy game-level assignment), `copies_unplaced`
  = pre-clear `copies.shelf_id IS NOT NULL` count (copies that had a shelf and become unplaced).**
  This mapping matches the measured dev counts exactly (assignments_removed=1, copies_unplaced=0)
  and keeps the two distinct legacy-vs-copy-level assignment concepts separately auditable.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `ExUnit.CaptureLog` did not capture the migration's `Logger.info` line under the initially-chosen `Logger.put_process_level/2` approach**
- **Found during:** Task 2 (writing and first-running the migration test)
- **Issue:** The plan's `<action>` says to capture the migration's logged JSON line with
  `ExUnit.CaptureLog`. `config/test.exs` sets the *global* Logger level to `:warning`. The
  initially-chosen approach — `Logger.put_process_level(self(), :info)` inside the test's
  `setup` block, a per-process override — compiled and ran, but the captured log was empty:
  `Logger.info/1` calls were being dropped before `ExUnit.CaptureLog` ever saw them. A standalone
  probe test confirmed neither `Logger.put_process_level/2` nor `capture_log/2`'s own `level:`
  option can raise visibility above the global primary level configured via `config :logger,
  level: :warning` — both can only lower it, never raise it, on this project's Elixir 1.19.5/OTP
  28 pair.
- **Fix:** Replaced the per-process override with a temporary **global**
  `Logger.configure(level: :info)` in the test file's `setup` block, restored via `on_exit`.
  Verified empirically (two standalone probe tests, one per approach) that only the global
  `Logger.configure/1` call actually works. `async: false` on the test module (already required
  by the plan's read_first pattern) keeps this global mutation from racing other tests in the
  same file; the `on_exit` restore keeps it from leaking into concurrently-running async test
  files in other modules.
- **Files modified:** `test/pukllay_club/repo/clear_estantes_migration_test.exs`
- **Verification:** all 9 tests pass, including the three that assert on the decoded JSON log
  payload (`estantes_removed`, `assignments_removed`, `copies_unplaced`, `at`)
- **Committed in:** `ca0c2f7` (Task 2 commit)

**2. [Rule 3 - Blocking] The migration module was undefined when the test tried to call `up/0`/`down/0` directly**
- **Found during:** Task 2 (first test run)
- **Issue:** The plan's `<action>` explicitly requires invoking the migration module's `up/0`
  directly, "not through `mix ecto.migrate`." Files under `priv/repo/migrations/` are not part of
  `mix compile`'s `elixirc_paths` — they are loaded ad hoc by `Ecto.Migrator` at migrate time, so
  the module simply did not exist in the compiled application when the test referenced it
  (`UndefinedFunctionError`, module not available).
- **Fix:** Added `Code.require_file("priv/repo/migrations/20260923140000_clear_estantes_and_assignments.exs", File.cwd!())`
  at the top of the test file, before the test module definition, so the migration source loads
  and its module becomes callable. Documented as part of the established migration-behaviour-test
  convention in the test file's moduledoc.
- **Files modified:** `test/pukllay_club/repo/clear_estantes_migration_test.exs`
- **Verification:** all 9 tests pass
- **Committed in:** `ca0c2f7` (Task 2 commit)

## The deliberate `desc: id` tiebreak

`automatic_order_by(:recent)` orders `[desc: inserted_at, asc: id]`. `recent_games_for_row/2` uses `desc: id` instead. `timestamps()` is second-precision and several games are routinely added inside one second, and a higher id is the later insert, so `desc: id` is the only deterministic "newest first" tiebreak. This is recorded in the function's `@doc`, and the tie-break test (three games sharing one `inserted_at`, asserted `[third, second, first]`) pins it.

## Decisions Made

- Followed the plan's locked decisions: no thumbnail requirement, drafts included, `desc: id` tiebreak, no index, slice-then-trim, single `escape_ilike/1`.
- The telemetry-based "no query issued" test attaches to `[:pukllay_club, :repo, :query]` in an `async: true` test. The handler `send`s only to the test's own pid and the event is detached in `after`, but a concurrent async test's Repo query would also fire the same global event; the handler sends to the attaching pid regardless of which process queried, so it uses a unique `make_ref()` and `refute_received`. It passed on repeated full-suite runs, but it is the one test here that is timing-adjacent rather than purely deterministic — noted for plan review.

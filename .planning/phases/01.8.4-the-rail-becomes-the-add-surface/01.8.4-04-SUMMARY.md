## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The slot column rendered 24px wide, so the hit pitch was 48px, not 44px**
- **Found during:** Task 3 (validating `checkSlotHitBox` against the real stylesheet in headless Chrome)
- **Issue:** Plan 01 shipped `.pk-admin-web-slot` as `display: grid` with `flex: 0 0 20px` and no `min-width: 0`. The slot's 24px "+" circle set the flex item's automatic minimum, so the column rendered 24px wide. Every declaration the source gate reads (`flex: 0 0 20px`, `margin: 0 12px`) was correct, yet the covers sat 48px apart and the hit layers overlapped the neighbours. The probe's +-23px check failed on every interior slot against the unfixed CSS and passed after the fix, so it is non-vacuous.
- **Fix:** `display: flex; justify-content: center; align-items: flex-start; min-width: 0` on the slot (sketch 070's own declarations) and `flex-shrink: 0` on the glyph; the empty tile centres its glyph with `align-items: center`. Measured afterwards: slot 20px wide, 140px between slot lefts (20 + 24 + 96), glyph centred in the empty tile (dx = 0, dy = 0), empty tile 96x100.
- **Files modified:** `assets/css/admin/screens.css`
- **Verification:** headless-Chrome probe on a static harness using the real `screens.css`; plus a new gate test (`the slot may not shrink its column below the glyph...`), which went RED when `min-width: 0` was removed from the slot rule.
- **Committed in:** `999bd898`

## Notes the plan asked for

- **`motion_rhythm_test.exs` helpers.** Not reusable for containment. `rules/1` returns every innermost `{selector, body}` pair but discards which at-rule each came from, so it cannot say a rule sits inside `no-preference`; `declares?/3` is a fine property matcher but works on a body that `rules/1` has already flattened. A brace-matched `at_rule_body/2` was written instead, and containment is proven by removing that block from the source and requiring the trigger and the keyframes to disappear with it.
- **`AdminRail` same-game-twice caveat.** The hook guards on `lastScrolledId`, so placing the same game twice in a row re-animates the cover but does not re-scroll it into view. A hook-level behaviour shared with Estantes; recorded, not fixed.
- **Probe output.** `test/visual/admin_components.mjs` was NOT run against `/admin/secciones`: it needs a booted dev server and a real staff magic-link session, and makes writes to the dev database (it invites and removes a throwaway staff account). It is routed to the end-of-phase device pass and logged as an `unrun-verify` window. What was run: the exact `slotHitBoxes` and `checkSlotHitBox` source, extracted from the file and executed in headless Chrome against a static page using the real `screens.css`. On the fixed CSS it reported no failures for a populated rail and skipped the empty rail; on the unfixed CSS it reported the +-23px overlaps. That harness lived in the scratchpad and is not committed.
- **`mix quality`** ran green: hex.audit, deps.audit, deps.unlock --check-unused, format --check-formatted, credo --strict, sobelow and 2023 tests, 0 failures.

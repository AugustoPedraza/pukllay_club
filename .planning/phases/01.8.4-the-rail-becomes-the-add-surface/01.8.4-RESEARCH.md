## Summary

The destacada's membership lives in `section_games` (`section_id`, `game_id`, `position`), managed by `PukllayClub.Catalog.Sections` (`lib/pukllay_club/catalog/sections.ex`). Today the only write that adds a game is `add_game/2`, which **appends** at `max(position)+1`; `move_game/3` only swaps with an adjacent neighbour. Positions are dense **`1..n`** in the code and its test — *not* `0..n-1` as the ROADMAP success criterion words it (Discrepancy D1, needs a user nod; recommendation: keep `1..n` stored, use a 0-based *slot index* at the API). There is no row lock around the cap check today, and `add_game/2` crashes the LiveView for an unknown or out-of-bigint game id (both verified by running it).

The page (`lib/pukllay_club_web/live/admin/section_live/index.ex`) already renders a destacada rail (reusing the public `.pk-rail`/`.pk-poster-card`), a member options sheet with `Quitar de la fila`, and the inline `Agregar un juego` form + `#web-search-results`. Everything needed for the new UI already exists as shared vocabulary in `AdminComponents` (`sheet/1`, `snackbar/1`, `list_row/1`, `list_section_label/1`) and Estantes already ships a near-identical flow (`«¿Qué juego va acá?»` sheet, full-height class `pk-estantes-sheet--full`, `landed_copy_id`, `snapshot_ids` stale guard, `Shelves.place_copy/3` with Multi + advisory lock). The work is mostly *composition of existing parts* plus five genuinely new pieces: positional insert/move in `Sections`, a ranked game search + recents query, the 70-style slot rail CSS (no `gap`, 44px hit box), one opt-in autofocus line in `admin_sheet.js`, and a 520ms landing class.

**Primary recommendation:** Build `Sections.insert_game_at/3` and `Sections.move_game_to/3` first (own plan, TDD, `FOR UPDATE` on the section row, load-ordered-ids → splice → rewrite positions `1..n`), then a Catalog ranked-search + recents query (verified to work with `unaccent`), then the rail + sheet in `index.ex`, deleting the inline field and its handlers in the same plan that ships the sheet. Mirror Estantes' flow (`snapshot_ids` stale guard, `landed_*` assign, single `undo` snapshot) rather than inventing new mechanisms.

## Answers to the eight research questions

### 1. The existing context / section API

**Module:** `PukllayClub.Catalog.Sections` — `lib/pukllay_club/catalog/sections.ex` (304 lines). Schemas: `PukllayClub.Catalog.Section` (`section.ex`) and `PukllayClub.Catalog.SectionGame` (`section_game.ex`, fields `section_id`, `game_id`, `position`, `timestamps()`).

- **Cap:** `sections.ex:27` → `@featured_cap 20`, enforced in `add_game/2` `sections.ex:177-191`:
  ```elixir
  def add_game(%Section{kind: :manual} = section, game_id) do
    Repo.transaction(fn ->
      cond do
        already_member?(section.id, game_id) -> Repo.rollback(:already_member)
        section.featured and member_count(section.id) >= @featured_cap -> Repo.rollback(:featured_full)
        true -> Repo.insert!(%SectionGame{section_id: section.id, game_id: game_id, position: next_member_position(section.id)}); section
  ```
  Return shape `{:ok, section}` | `{:error, :already_member | :featured_full | :automatic_section}`. **It is a plain `Repo.transaction/1`, no `Ecto.Multi`, and no lock** — the comment "T-01.8.1-56 … two concurrent adds can never push the featured section past the cap" is not actually guaranteed under READ COMMITTED (count-then-insert without a lock). [VERIFIED: sections.ex:23-27, 177-191]
- **Positions:** appended at `max+1` (first = 1) `sections.ex:203-208`; `remove_game/2` `215-221` deletes then `repack_positions/1` `223-230` (`order_by [asc: sg.position, asc: sg.id]` → `Enum.with_index(1)` → single-row `change(position:) |> Repo.update()`). `move_game/3` `238-259` only swaps with the adjacent member via `swap_member_positions/2` in a transaction. [VERIFIED]
- **Indexes:** `create unique_index(:section_games, [:section_id, :game_id])` and `create index(:section_games, [:section_id, :position])` (`20260914150000_create_sections.exs:82-83`) — position is **not unique**, so bulk shifts cannot transiently collide (contrast Shelves, below). [VERIFIED]
- **Members read:** `section_members/1` `149-155` — all `section_games` rows for the section ordered `[asc: sg.position, asc: sg.id]`, `Repo.preload(:game)` (includes retired/draft games; no status filter).
- **Transaction precedent to copy:** `PukllayClub.Catalog.Shelves.place_copy/3` (`shelves.ex:717-740`): `Multi.new() |> Multi.run(:copy…) |> Multi.run(:lock, … lock_estantes …) |> Multi.run(:fresh_copy …) |> … |> Repo.transaction()` → returns `{:ok, %{moved: copy, previous_shelf_id: …, previous_position: …}}`; locks via `repo.query!("SELECT pg_advisory_xact_lock($1, $2)", [@estante_lock_namespace, id])` (`shelves.ex:~787`); `insert_at/4` clamps the index to `0..count` of the *other* copies (`shelves.ex:831-848`). Estantes positions are **0-based** and Shelves has a *unique* `(shelf_id, position)` index (hence single-row updates in careful order) — Sections has neither property, so do **not** copy its shift loops; copy its *shape* (lock → re-read → write → return previous location).

**What insert/move must build on / what to build** (recommendation):

```elixir
# CTX-01 — slot index: 0 = before first … n = after last (n = current member count)
@spec insert_game_at(Section.t(), integer(), integer()) ::
        {:ok, %{section: Section.t(), index: non_neg_integer()}}
        | {:error, :automatic_section | :already_member | :featured_full
                   | :index_out_of_range | :game_not_found}
# CTX-02 — index is into the list WITHOUT the moving game (matches the ¿Dónde va? rail of 01.8.5)
@spec move_game_to(Section.t(), integer(), integer()) ::
        {:ok, %{section: Section.t(), from: non_neg_integer(), index: non_neg_integer()}}
        | {:error, :automatic_section | :not_member | :index_out_of_range}
# the ONE place the off-by-one lives; the add sheet draws slots over the FULL list (mover present)
@spec rest_index(from :: non_neg_integer(), slot :: non_neg_integer()) :: non_neg_integer()
def rest_index(from, slot) when from < slot, do: slot - 1
def rest_index(_from, slot), do: slot
# same spot  ⇔  slot in [from, from + 1]   (070/index.html:404 `from === pos || from === pos - 1`)
```

Implementation recipe (all inside one `Repo.transaction`): (1) re-read the section row `from s in Section, where: s.id == ^id, lock: "FOR UPDATE"` — serialises writers per section, needs no new advisory namespace, works in the SQL sandbox, and gives the **live** `featured`/`kind` (the socket's struct can be stale); (2) load ordered members (`position, id`); (3) check member / bounds (`0..count`, with the mover removed first for a move) / cap (only for a *net-new* member) / game exists and `status != :retired` (`Repo.get`, guard id with `in 1..@max_bigint`); (4) splice the id list (`List.insert_at/3`), then **rewrite positions `1..n` from the new order**, updating only rows whose value changed and inserting the new row at its final position. Renumbering from order (not "shift rows ≥ i by +1") is required: the test fixture `add_game_to_section/3` inserts arbitrary non-dense positions (`System.unique_integer([:positive, :monotonic])`, `sections_fixtures.ex:38-42`), so shift-by-value would be wrong on non-dense data, and renumbering self-heals it.

Optional consolidation (planner's call): make `add_game/2` call `insert_game_at(section, game_id, member_count)` so one code path owns cap + density + the new lock; its four existing tests (`sections_test.exs:187-243`) keep their assertions. `set_game_sections/2` (`sections.ex:284-296`) calls `add_game` inside its own transaction (nested is fine; note two concurrent calls locking different sections in different order could deadlock — Postgres aborts one; acceptable at this scale).

Undo inverses (no new context API needed): add → `remove_game(section, game_id)` (repacks); move → `move_game_to(section, game_id, from)` where `from` is returned by the original move (rest-index of the original spot equals the original 0-based index).

### 2. The `:manual` vs `:automatic` guard

It is a **function-head pattern match** on the section struct: `def add_game(%Section{kind: :manual} = section, game_id)` and the fallback `def add_game(%Section{}, _game_id), do: {:error, :automatic_section}` (`sections.ex:177`, `193`). `kind` is `Ecto.Enum` with `@kinds [:manual, :weight_band, :recent]` (`section.ex:29`); `weight_band`/`recent` membership is derived from `games` columns and has **no** `section_games` rows (`sections.ex:143-148` doc). Facts that make it safe for this phase:

- `Index` only ever mutates `socket.assigns.featured` (loaded server-side by `load_sections/1`, `index.ex:58-67`); **no event takes a section id from the client**. New events must keep that: never add a `section-id` param.
- `Section.create_changeset/2` forces `kind: :manual`, `featured: false` (`section.ex:102-111`); only the migration backfill makes a featured row.
- New context functions must replicate both heads (manual clause + `{:error, :automatic_section}` fallback) **and** re-read `kind` from the locked row. Add a test: `insert_game_at/3` and `move_game_to/3` on a `:weight_band` and a `:recent` section return `{:error, :automatic_section}` and write nothing (mirrors `sections_test.exs:210-222`).
- Cap applies only when the *locked* row has `featured == true` (today's behaviour) — CTX-03 (01.8.7) will later move that flag, which is exactly why the fresh read matters.

### 5. Search

Today: `Catalog.list_admin_games/1` (`catalog.ex:481-492`) = contains-only `ilike` (`maybe_search_admin_name/2` → `ilike(g.name, ^pattern)` with `escape_ilike/1` private at `catalog.ex:573-577`), `order_by [asc: g.name, asc: g.id]`, no status filter; `Index.search_candidates/2` post-filters `status == :retired or id in members` in Elixir and cuts at 20. `Shelves.search_games/1` is the same contains-only shape (a third copy of `escape_ilike`). **No starts-with-first ranking exists anywhere.**

**Recommended** (new functions next to `list_admin_games/1` so they reuse the private `escape_ilike/1`; query shape verified against the test DB — inserted `["Catán","El Catan Jr","Everdell","100% Raro","Explorers of Catan"]` in a rolled-back transaction):

```elixir
# [VERIFIED: ran] "cat" -> ["Catán","El Catan Jr","Explorers of Catan"]; "100%" -> ["100% Raro"]; "ev" -> ["Everdell"]; "zzz" -> []
escaped  = escape_ilike(q)
starts   = escaped <> "%"
contains = "%" <> escaped <> "%"
from g in Game,
  where: g.status != :retired,
  where: fragment("unaccent(?) ILIKE unaccent(?)", g.name, ^contains),
  order_by: [
    asc: fragment("CASE WHEN unaccent(?) ILIKE unaccent(?) THEN 0 ELSE 1 END", g.name, ^starts),
    asc: g.name, asc: g.id
  ],
  limit: ^limit            # 6
```
`unaccent` matches the artefact's `norm` (NFD strip + lowercase, `070/index.html:317`), the extension exists (`20260810172415_add_games_search_and_indexes.exs`: `CREATE EXTENSION IF NOT EXISTS unaccent`), and ~400 rows need no index. Cap the query string like Estantes does (`String.slice(q, 0, 120)`, `estante_live/index.ex:157`, `@max_search_query_length 120` in `shelves.ex`). Recents: `where g.status != :retired and g.id not in ^member_ids, order_by [desc: g.inserted_at, desc: g.id], limit 6` — `automatic_order_by(:recent)` already orders `[desc: g.inserted_at, asc: g.id]` (`catalog.ex:1038-1040`) but `timestamps()` is second-precision, so tie-break on `id desc` (newer insert = higher id) for determinism. Whether drafts and thumbnail-less games are eligible for the idle list is Q5 (the artefact filters `g.thumb`).

### 8. Param safety (CTX-04)

Existing idiom: `Integer.parse(id)` with `{int_id, ""}` accepted, else silently ignored — in `index.ex` handlers (`add-game` l.115-133, `open-member-sheet`, `remove-game`), a shared private `parse_id/1` accepting integer-or-binary (`index.ex:267-276`, duplicated in `edit.ex:229-238` and `estante_live/index.ex:539-546`), Estantes' WR-03 comment ("a raising `String.to_integer/1` crashes the LiveView on a forged/tampered client payload"). Neither does any **range** check. Verified crash modes:

- game id above bigint: `Repo.delete_all(from sg in SectionGame, where: sg.game_id == ^99_999_999_999_999_999_999)` → **raised `DBConnection.EncodeError`** "Postgrex expected an integer in -9223372036854775808..9223372036854775807" [VERIFIED: ran]. Existing `remove-game` would crash the LV on that payload. `Catalog` already has the idiom: `@max_bigint 9_223_372_036_854_775_807` + `defp fetch_by_id!(int_id) when int_id in 1..@max_bigint` (`catalog.ex:143`, `179`).
- unknown-but-in-range game id: `Sections.add_game(featured, 987_654_321)` → **raised `Ecto.ConstraintError` `"section_games_game_id_fkey" (foreign_key_constraint)`** [VERIFIED: ran].

Recommendation: a small shared module (e.g. `PukllayClubWeb.Admin.Params`, `parse_int(raw, range)` → `{:ok, int} | :error`, accepting integer or binary) with its own unit tests, used by every new event, because the ROADMAP says later phases follow "that same pattern". Slot index: `0..@featured_cap` upper bound is wrong for non-featured rows, so parse with `0..length(live_ids)` taken from a fresh read; game id: `1..9_223_372_036_854_775_807`. Then **compare against the sheet's snapshot** (Estantes `que-va-aca-pick`: `current_ids == qva.snapshot_ids` else "El estante cambió mientras elegías un juego. Probá de nuevo.", `estante_live/index.ex:255-272`) — a count-only check misses "someone added a game, count still in range, spot now different". Finally the context re-validates under the lock (`:index_out_of_range`, `:game_not_found`) so even a bypass cannot corrupt state.

**`phx-value-value` warning (project memory, binding):** LiveView overwrites a key named `value` with the element's native `.value` for buttons/inputs. Use **`phx-value-index`** for the slot (the same key Estantes uses, `phx-value-index={index}`) and **`phx-value-game-id`** for the pick; never `phx-value-value`. `render_click`/`render_hook` tests build params by hand and cannot catch this class of bug — verify once in a real browser (dev-console `HANDLE EVENT … Parameters:` line).

### Anti-patterns
- Reusing `.pk-rail`/`.pk-rail-wrap`/`.pk-poster-card` (gap, fades, 160px width — D7).
- `disabled` on dimmed slots: D-24 forbids dead controls; `AdminComponents.action/1` even raises on `disabled` without `commit`. Dim with opacity and explain on tap.
- Shifting rows by `position >= i` instead of renumbering from order (breaks on non-dense data).
- Trusting the socket's `@featured` struct for `featured`/cap (stale after CTX-03); trusting `length(@featured_members)` for bounds.
- Two simultaneous snackbars (fixed, same position).
- `phx-value-value`; accepting a section id from the client; `refute html =~ "Agregar un juego"`.

| Problem | Don't build | Use instead | Why |
|---------|-------------|-------------|-----|

## Common Pitfalls

1. **Off-by-one on move.** The add sheet draws slots over the list *with* the mover; CTX-02's index excludes it. Convert once with `rest_index/2`; test `[A,B,C,D]`: move A to rest-index 2 → `[B,C,A,D]`; D to 0 → `[D,A,B,C]`; B to rest-index 1 → unchanged; slot∈{from, from+1} → no write.
2. **Cap on moves.** Count only grows for a net-new member; a move at 20/20 must not trip `:featured_full` in the context. (The artefact bails before opening the sheet at the cap, `070/index.html:384`, so staff cannot move via the sheet at 20 — keep that parity.)
3. **Stale `@featured`.** Re-read `kind`/`featured` under the lock.
4. **Undo of a move after other edits.** `move_game_to(…, from)` may return `:index_out_of_range`/`:not_member` — swallow and clear the snackbar.
5. **Snackbar stacking** (D6/§4): clear `@removed`, `@undo_snapshot`, and the new add snackbar whenever one is set.
6. **Focus.** Without the hook change the ✕ gets focus (D5). On iOS, `focus()` outside the originating tap gesture may not raise the keyboard — the sheet is server-rendered after a round trip. [ASSUMED] Mitigation if it bites: pre-mount the sheet (`open={…}` stay-mounted pattern like Juegos) and `JS.add_class("pk-admin-overlay--open") |> JS.focus(to: "#…")` in the slot's own click. Not verifiable here; the real-device pass is already planned in 01.8.8.
7. **Stray `*/` in CSS comments** silently drops rules (documented incident in `stylesheet_integrity_test.exs`).
8. **Composition guard** bans `btn-ghost`/`font-display` etc. in `index.ex` source even inside strings.
9. **A8 probe passes trivially** for slots (height only) — don't treat it as proof of the 44px width.
10. **Retired members** still render on the rail and count toward 20 (existing behaviour of `section_members/1`/`member_count/1`); do not "fix" here.
11. **CLAUDE.md git sync:** local `main` is `ahead 1` of `origin/main` (`git status -sb`: `## main...origin/main [ahead 1]`; the unpushed commit is `1bd09ce9 docs(v1.2): open milestone`).

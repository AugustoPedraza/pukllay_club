## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Postgres deadlock between concurrent LiveView tests**
- **Found during:** Task 2 (verifying the new move tests)
- **Issue:** `insert_game_at/3` and `move_game_to/3` re-read the seeded (committed, shared) featured section row `FOR UPDATE`. Seeding a member first takes a `KEY SHARE` lock on that row through the foreign key. Two concurrent async tests that both seed and then lock each wait on the other's `KEY SHARE`; Postgres reports `40P01 deadlock_detected`. It reproduced in 3 of 4 runs once the move tests existed, and failed a plan 01 test in `sections_test.exs`.
- **Fix:** `section_live_test.exs` is now `async: false` with a comment explaining why. Sync modules run after the async ones, so it is out of the cycle, and `sections_test.exs` has no concurrent peer left to deadlock against.
- **Files modified:** `test/pukllay_club_web/live/admin/section_live_test.exs`
- **Verification:** five consecutive runs of both files: 129 tests, 0 failures; full suite green.
- **Committed in:** `394dd1e9`

**2. [Rule 1 - Spec conflict] Acceptance line `La sección destacada ya tiene 20 juegos` appears nowhere in lib/ cannot hold**
- **Found during:** Task 3 verification
- **Issue:** `edit.ex` (line 294) still carries that string in its own `add_error_message/1`. The plan also requires `edit.ex` to be byte-identical (RAIL-05 is Index-only; phase 01.8.6 owns it).
- **Fix:** none; the stricter, explicitly locked must-have (edit.ex untouched) wins. The string is gone from `index.ex`, which is the file this plan owns.

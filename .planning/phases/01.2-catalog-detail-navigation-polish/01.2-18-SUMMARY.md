**Closed G-01.2-10's last two mechanical asks: a shared-token content-column boundary before the recommendations shelf, and a mobile CTA bar collapsed from two controls to one — with the reserved body padding recomputed and measured, not just derived.**

## Accomplishments

- **One shared width token, three consumers (Task 1).** `.pk-detail-masthead` and `.pk-cta-bar-inner`
  used to each independently write `max-width: 68.75rem`, tied together only by a comment. Both now
  read a single `--pk-detail-col-width: 1100px` custom property declared once in `app.css`'s existing
  `:root` token block (alongside `--pk-gutter`), and a third rule — `.pk-shelf-separator`, capping the
  new boundary line to the reading column's width — reads the same property. Written in `px` rather
  than restating the old `rem` literal, satisfying the acceptance criterion that no line added by
  this substitution re-introduces the literal (`git diff | grep -cE '^\+.*68\.75rem'` returns 0)
  while the computed width is provably unchanged: this app's root font-size is an unmodified 16px
  (confirmed live via headless-Chrome CDP), so 1100px == 68.75rem exactly.
- **Masthead↔shelf boundary, both passes (Task 1).** A `<div class="divider pk-divider
  pk-shelf-separator" role="separator">` — the second call site of 01.2-17's own `.pk-divider`
  declaration, reused verbatim — now sits between the masthead's outer wrapper and the "Juegos
  similares" shelf, inside the same `space-y-4` vertical-rhythm wrapper. It renders on both the
  loading pass (ahead of the skeleton shelf, so the boundary doesn't pop in only after connect) and
  the connected pass, gated on the exact same emptiness check the shelf itself uses
  (`@loading or @similar_games != []`).
- **One control in the mobile CTA bar (Task 2).** The bar's own `<.share_control variant={:bar}>`
  call — a full-width labelled share pill stacked below Reservar, duplicating the poster's own corner
  share icon — is gone. `.pk-cta-bar-inner` now has one child.
- **Dead surface removed, not left "in case" (Task 2).** `share_control/1`'s `variant` attribute, its
  conditional visible "Compartir" label, its conditional `aria-label`, and the
  `share_trigger_class/1` two-clause helper behind them all collapsed to one shape together (the
  buy-box panel's bordered circle) — the plan's own reversibility note flags this as a "costly" revert
  precisely because a partial restore leaves either an unstyled control or a mismatched bar height.
  The dead `.pk-share-trigger--bar` CSS rule (and its `:hover`) were deleted; grepped for zero
  remaining references across `assets/` and `lib/` before removal.
- **Reserved body padding recomputed and measured, not just derived (Task 2).** `body.pk-has-cta-bar`'s
  `padding-bottom` returns from 12.5rem/200px (the stacked layout's two-row clearance) to
  9.25rem/148px — subtracting exactly the removed 44px share row plus its 8px gap, landing back on
  the value this rule held before the Phase 01.2 stacked-layout gap-closure ever shipped. The existing
  comment's own measured collapse-travel numbers (68.9px/3.2px first-frame figures) were already
  computed against this exact pre-stacked value, so they became accurate again unchanged rather than
  needing re-measurement. **Empirically verified via headless-Chrome CDP** (not trusted from
  arithmetic alone, per the plan's own threat mitigation T-01.2-18-03): with `pk-has-cta-bar` applied
  and the transition settled, `getComputedStyle(document.body).paddingBottom` measured **148px**,
  comfortably clearing the bar's own rendered height (**69px**); after simulating the parked state
  (`pk-cta-parked` + `is-parked`, mirroring `.DetailChrome`'s own class toggles), the padding measured
  **0px**. The ~160px visual gap remaining between the shelf's last content and the real `<footer>`
  in the parked state is unrelated ambient page spacing (`<main>`'s pre-existing `pb-20` plus
  `.pk-shelf`'s own `margin-bottom: 3rem`, both untouched by this plan) — not a leftover artifact of
  the removed share row.
- **Regression-pin test group (Task 3).** A new `describe "G-01.2-10 mobile detail-page contract
  (regression pin, 01.2-18 task 3)"` block gathers one assertion per ask from the UAT's `missing`
  list (pills in both wrappers present on every render; description immediately after the title;
  poster/bar reserve buttons separately addressable with exactly one breakpoint-gated; no chip
  row/hashtags before the description; no publisher row and a publishers-only game renders no spec
  section; a separator between masthead and shelf; the bar holds exactly one control; the checkpoint
  D3 gallery renders both the thumbnail strip and the dot affordance), plus a ninth DOM-level proxy
  assertion ("exactly two reserve controls exist in the document, and exactly one of them is
  breakpoint-gated") for the per-viewport visual invariant that CSS alone can't be asserted for
  server-side.

## Issues Encountered

- **Headless-Chrome CDP measurement required a working test-env-only asset pipeline, not a running
  dev server.** `mix phx.server` in `MIX_ENV=dev` failed to start in this sandbox — `Tidewave.MCP`
  (a dev-only MCP tool, `only: :dev` in `mix.exs`) raised `UndefinedFunctionError:
  PukllayClub.Repo.__adapter__/0 is undefined` during its own supervision-tree init, aborting the
  whole `mix phx.server` boot. This is a pre-existing dev-tooling issue unrelated to this plan's
  changes (confirmed reproducible on a clean retry, not a transient race) and out of scope per the
  scope-boundary rule. Worked around it entirely: `mix tailwind pukllay_club` compiles
  `priv/static/assets/css/app.css` without starting the OTP application at all, and a throwaway
  `Phoenix.LiveViewTest` case (not committed) dumped the real rendered HTML to a scratch file, which
  headless Chrome then loaded from `file://` with the compiled CSS linked by absolute path — giving
  real rendered/computed-style measurements without ever needing the dev server or Tidewave to start.
- **`document.styleSheets[*].cssRules` throws under `file://` in headless Chrome** (a same-origin-like
  restriction even file://-to-file://), which produced a red herring during the padding-clearance
  measurement (an early debug script's `.some()` callback silently coerced a caught error string to
  `true`, making a broken CSSOM-introspection check look like a passing one). Resolved by measuring
  via `getComputedStyle` alone (never `cssRules` introspection) and — separately — discovering that
  multiple DOM mutations plus a `getComputedStyle` read packed into one single `Runtime.evaluate`
  call returned stale (mid-transition or pre-mutation) values in this headless build; splitting each
  mutation and each read into its own sequential `Runtime.evaluate` round-trip (with a wait exceeding
  the 180ms `--duration-base` CSS transition) produced consistent, settled measurements. Neither issue
  reflects a defect in the shipped code — both are quirks of the ad hoc measurement harness — but are
  recorded here since a future plan measuring this page's CSS via the same technique will hit them
  identically.
- **Worktree had no `deps/`/`_build/`.** Symlinked both from the main checkout (`mix.lock` confirmed
  byte-identical) rather than re-fetching/recompiling — standard practice for a compiled-language
  worktree, not a deviation from the plan.

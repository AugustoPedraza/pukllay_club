# Phase 01.2 Plan 05: Vertical Infinite Scroll Summary

**The search/filter results grid now auto-loads its next page via a `.GridScroll` colocated IntersectionObserver hook (the vertical twin of `.CarouselScroll`) instead of a manual "Cargar más" button, backed by a reply-carrying, clamped `load-more` handler and a second `:more_error` channel that renders a compact inline retry line — never the full-page banner — on a mid-scroll failure.**

## Accomplishments
- Added `:more_error` (mount/3), documented at the assign as a deliberately separate error
  channel from `:load_error` — `:load_error` owns the full-page banner (initial catalog read
  failure), `:more_error` owns a compact inline line under the grid (one additional page failing
  mid-scroll). `apply_filters/1` resets `:more_error` to `false` on both branches so a filter
  change never leaves a stale mid-scroll failure behind.
- Rewrote `handle_event("load-more", ...)` to return `{:reply, map, socket}` on all three paths:
  a pre-query guard (`offset >= total` replies `%{exhausted: true}` with zero database calls,
  mirroring `fetch_row_page/3`'s clamp-before-query discipline), a success path carrying both the
  appended stream page and the exhausted flag in one round trip, and a failure path that sets
  `:more_error` only — never `:load_error`.
- Replaced the manual `Cargar más` button with UI-SPEC's compact inline retry block (a muted
  `text-neutral text-sm` line plus a `variant="secondary"` `Reintentar` button), gated on
  `browsing_results?(assigns) and @more_error`, deliberately not a `.pk-state` block.
- Wrapped `#games` in a new `.GridScroll` colocated hook (`id="grid-scroll"`): reuses
  `.CarouselScroll`'s `pending`/`exhausted` guard-flag pair and single
  `pushEvent(..., reply => ...)` round trip verbatim, adapted to an `IntersectionObserver` on a
  1px sentinel with a ~400px `rootMargin` lead instead of a rail scroll listener.
  `data-exhausted` folds in `@more_error` so a mid-scroll failure parks the hook (no auto-retry
  loop) until the member's own `Reintentar` click (a plain `phx-click`, not routed through the
  hook) recovers it.
- Added four permanent trailing `CarouselRow.skeleton_card` placeholders inside `#games`
  (`pk-trailing-skel`), toggled by a new `.pk-grid[data-loading]` CSS rule placed directly beside
  the existing `.pk-rail[data-loading]` rule — one new rule, no other CSS changed.
- Added a `vertical infinite scroll: .GridScroll sentinel-driven load-more (D-03)` describe block
  (7 tests) pinning: `data-exhausted` false/true transitions, the sentinel + exactly four
  trailing skeleton ids, absence of an inline `<script>` tag, stream-append without disturbing
  already-rendered cards, the clamp guard's no-op past exhaustion, the manual control's full
  removal, and a filter change resetting pagination and clearing error state.
- Swapped the two pre-existing pagination tests' button click for a direct `load-more` event
  dispatch so they kept passing once Task 1 removed the button (their `"Cargar más"` text
  assertions were replaced with `card_count/1` checks — the search matches full tsvector tokens,
  not substrings, so the "changing any filter resets pagination" test now expects exactly 1 card
  for `q=G1` rather than 11).

## Decisions Made
- `apply_filters/1`'s failure branch uses an explicit `socket = assign(socket, :load_error, true)`
  line (not piped) so the plan's own acceptance-criteria grep — a literal, non-piped substring
  match — resolves to exactly one occurrence, now scoped to `apply_filters/1` since `load-more`
  no longer touches `:load_error` at all. Functionally identical to the prior piped form.
- The inline retry block uses `flex items-center justify-center gap-2`, not a `.pk-state` box,
  per UI-SPEC's explicit instruction that content already exists above it and a padded
  empty-state treatment would misread as the whole page having failed.
- `rootMargin: "400px"` (all sides, not bottom-only) — matches UI-SPEC's "~400px lead" language
  literally; a bottom-only margin was considered but the flat value is simpler and the sentinel
  only ever sits at the bottom of a vertically-scrolling page, so the top/side margins are inert.

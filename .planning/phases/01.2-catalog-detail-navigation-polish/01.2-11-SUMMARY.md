# Phase 01.2 Plan 11: Server-owned search-morph state Summary

**Moved the catalog header's search-box open/closed state from a client-only JS class toggle to a server-rendered LiveView assign, deleted the document-level outside-click listener that fought the filter modal, and pinned the regression plus the previously-unreachable href-parity contract in tests.**

## Performance

- **Duration:** 40 min
- **Completed:** 2026-08-26
- **Tasks:** 3
- **Files modified:** 5

## Accomplishments

- `Layouts.header_inner/1` now renders `.pk-search-morph`'s `is-open`, `.pk-nav-inner`'s
  `is-search-open`, and the toggle/close buttons' `aria-expanded`/`tabindex` entirely from the
  new `search_expanded` attr — no client JS adds or removes a class, so no LiveView patch (a
  query flipping, a filter badge appearing, a sibling slot disappearing) can strip it
- `CatalogLive.Index` gained a member-owned `:search_expanded` assign: seeded from the mount
  URL, widened only on a genuine transition into "has active filters" in `handle_params/3`,
  set explicitly by the two new `open-search`/`close-search` handlers, and never touched by
  `apply_filters/1`
- `.CatalogNav`'s colocated hook lost `openMorph`/`closeMorph`/`syncMorph` and the
  document-level outside-click listener; its search block now only moves focus on a
  `data-search-expanded` value transition, and wires first among six independently
  `try`/`catch`-isolated `mounted()` blocks
- Added pinning tests for both render directions of `search_expanded`, the strip regression,
  close-then-no-resurrect, filter-modal non-interference, and the card-vs-preview href-parity
  claim from G-01.2-1 — all previously unreachable/untested because the search box itself was
  the blocker

## Decisions Made

- **Transition-based widen, not plain OR.** Task 1's first draft derived
  `search_expanded = existing or filters_active?(new_assigns)` in `handle_params/3`. Writing
  Task 3's "close-search then a same-query handle_params must not restore it" test caught that
  this formula reopens the box whenever the URL still carries the query that was active at
  close time. Fixed by comparing `filters_active?` *before* vs. *after* this specific params
  application — only a genuine false→true transition can open it; a false→false or true→true
  no-op leaves the member's close decision alone.
- **CatalogLive.Show needs no-op handlers, not silence.** `header_inner/1`'s buttons now
  dispatch `open-search`/`close-search` unconditionally on every page filling the `nav_search`
  slot. Show renders that slot with a plain native GET form and never varies
  `search_expanded` — but the icon is still clickable there, and an unhandled event would have
  crashed the LiveView. Added two explicit no-op clauses and documented the contract on the
  slot itself so the next page filling `nav_search` doesn't rediscover this the same way.
- **Delete, don't scope, the outside-click listener.** G-01.2-3/G-01.2-4's defect A was that
  the listener treated any FilterModal click as "outside" because the modal is a DOM sibling,
  never a descendant, of `.pk-search-morph`. Scoping the listener to also recognize the modal's
  subtree was considered and rejected — it would hardcode one page's knowledge of another
  component's DOM. The pill's always-visible close button and Escape binding were never its
  only dismissal path, so deletion is the fix, not a smarter check.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] `CatalogLive.Show` had no `open-search`/`close-search` handlers**
- **Found during:** Task 1 (adding unconditional `phx-click` to the toggle/close buttons)
- **Issue:** `header_inner/1` is shared by every page passing a `nav_search` slot. Adding
  `phx-click="open-search"`/`"close-search"` to the toggle/close buttons means clicking the
  search icon on `/juegos/:id` (Show) now dispatches an event Show has no matching
  `handle_event` clause for — an unhandled LiveView event raises and crashes the process.
- **Fix:** Added two explicit no-op `handle_event` clauses to `CatalogLive.Show`, with a
  comment explaining why they're safe no-ops (Show's `search_expanded` is hardcoded `false`
  and never varies).
- **Files modified:** `lib/pukllay_club_web/live/catalog_live/show.ex`
- **Verification:** `mix test test/pukllay_club_web/live/catalog_show_test.exs` (71 tests, 0
  failures)
- **Committed in:** `2798cd5` (Task 1 commit)

**2. [Rule 1 - Bug] `handle_params/3`'s widen-only formula could resurrect a closed box**
- **Found during:** Task 3 (writing the close-then-same-query test)
- **Issue:** Task 1's `socket.assigns.search_expanded or filters_active?(socket.assigns)`
  reopens the box on any subsequent `handle_params` call whose URL still carries the filter
  that was active when the member closed it — directly failing the "no subsequent
  `handle_params` restores it" requirement in Task 3's own test text.
- **Fix:** Compare `filters_active?/1` before vs. after this specific params application;
  widen only on a false→true transition.
- **Files modified:** `lib/pukllay_club_web/live/catalog_live/index.ex`
- **Verification:** New test passes; full `catalog_live_test.exs` suite (103 tests, 0
  failures) still green.
- **Committed in:** `f0e548c` (Task 3 commit)

**3. [Rule 1 - Bug] One pre-existing test asserted behavior the plan intentionally removes**
- **Found during:** Task 1 (`mix test` regression run)
- **Issue:** `catalog_live_test.exs` had a test asserting that toggling a facet force-opens the
  search pill (the old `@q != "" or filters_active?(assigns)` inline computation). The plan's
  own Task 1 action explicitly retires this behavior ("a member who applies filters from the
  modal while the pill is closed no longer gets the pill force-opened... Plan 01.2-12 adds a
  visible active-filters summary... the correct place for that information").
  Under the new contract this test failed for the intended reason, not a bug.
  - **Fix:** Renamed and inverted the assertion to pin the new contract (toggling a facet from
    a closed pill does NOT force it open), with a comment pointing at the plan's own stated
    rationale.
- **Files modified:** `test/pukllay_club_web/live/catalog_live_test.exs`
- **Verification:** Full suite green after the change.
- **Committed in:** `2798cd5` (Task 1 commit)

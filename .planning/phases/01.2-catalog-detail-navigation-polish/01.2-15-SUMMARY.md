## Decisions Made

- **No restyle-in-place.** The stock `#client-error`/`#server-error` `<.flash>` calls were deleted wholesale (markup + their 3 `gettext/1` calls), not modified — `connection-feedback.md` and sketch 030 are explicit that the toast's `position: fixed` placement was itself the defect, not just its missing branding.
- **Placement: sibling of `#app-header`, inside the LiveView root, outside the header element.** Both properties are load-bearing and documented inline in a comment: LiveView's binding scan only fires for elements it manages (inside its root container), and `#app-header`'s own `getBoundingClientRect().height` feeds `--pk-header-h`, which `.pk-shelf`/`.DetailChrome` both consume — a bar nested inside the header would shift both measurements at the exact moment the socket drops.
- **Reduced-motion approach diverges from the plan's literal snippet.** The plan's `<action>` specified an unconditional `animation: pk-spin ...` declaration plus a separate `@media (prefers-reduced-motion: reduce) { .pk-conn-spinner { animation: none } }` override. `app.css`'s own "REDUCED-MOTION GUARD" section (documented at the end of the file) explicitly records that this exact per-selector reduce-block pattern was retired in favor of one universal `*` guard with `!important` that already forces `animation-duration: 1ms !important` on every element, keyframes included — reintroducing a local reduce block would be dead weight duplicating that guard, not a second line of defense, and directly contradicts the file's own documented architecture. Used `@media (prefers-reduced-motion: no-preference)` wrapping the animation declaration instead, matching `.pk-scroll-top`'s existing idiom in the same file. This still satisfies the letter of the plan's acceptance criterion ("`grep -n 'prefers-reduced-motion'` gains a match scoped to `.pk-conn-spinner`") since the `no-preference` media query directly wraps that selector.
- **UI-SPEC row-count arithmetic was already wrong before this plan touched it.** The plan's own text quoted the existing header as "36 rows total — 31 covered ... 3 backstop ... 2 unresolved," and that is what the file said — but a literal recount of the table's data rows (113-149, pre-edit) found 37 rows / 32 covered, not 36/31 (an off-by-one that predates this plan and is not attributable to any change made here). After adding the new `connection-status` row, the corrected, verified total is 38 rows / 33 covered / 3 backstop / 2 unresolved — recounted programmatically via `sed`+`grep`, not incremented blindly from the old (already-wrong) numbers.
- **`setContainerClasses` confirmation.** Grepped `deps/phoenix_live_view/priv/static/phoenix_live_view.min.js` and found `setContainerClasses(...e){this.el.classList.remove(...); this.el.classList.add(...e)}` — confirms LiveView toggles `phx-connected`/`phx-error`/`phx-client-error`/`phx-server-error` classes on the View's own container element (`this.el`), never on `<body>`. No `body.phx-client-error`-style selector was ported, per the plan's instruction.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Codebase-convention conflict] Reduced-motion CSS pattern changed from the plan's literal snippet to the file's own established idiom**
- **Found during:** Task 1 (CSS authoring)
- **Issue:** The plan's `<action>` specified a new `@media (prefers-reduced-motion: reduce) { .pk-conn-spinner { animation: none } }` block. `app.css` already contains a documented "REDUCED-MOTION GUARD" section explaining that this exact per-selector reduce-block pattern was deliberately retired (a debug session found 8 of 14 selectors in the old list were silently non-functional due to source-order/specificity interactions) in favor of one universal `*` guard with `!important`. Adding the plan's literal snippet would reintroduce the retired anti-pattern and be fully redundant with the existing universal guard.
- **Fix:** Used `@media (prefers-reduced-motion: no-preference) { .pk-conn-spinner { animation: pk-spin 0.7s linear infinite; } }` instead, matching `.pk-scroll-top`'s existing belt-and-braces idiom in the same file (gate the animation's existence, rely on the universal guard as the second line of defense).
- **Files modified:** assets/css/app.css
- **Verification:** `grep -n 'prefers-reduced-motion' assets/css/app.css` still gains a match scoped to `.pk-conn-spinner`, satisfying the plan's literal acceptance criterion; `mix assets.build` and `mix compile --warnings-as-errors` both exit 0.
- **Committed in:** af3d49b (Task 1 commit)

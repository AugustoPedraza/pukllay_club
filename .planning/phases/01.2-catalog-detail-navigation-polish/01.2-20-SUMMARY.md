## Height Measurement (Task 2 requirement)

No browser-automation tool was available in this execution context (same constraint 01.2-19 hit for its own width-measurement task), so before/after chip height is derived analytically from the exact declared CSS, not a live pixel measurement:

- **Before** (stock daisyUI `badge-sm`, no override): `--size` for `.badge-sm` = `calc(var(--size-selector, 0.25rem) * 5)`. This app's theme sets `--size-selector: 0.21875rem` (both themes, `app.css` lines 167/202) → `--size` = `0.21875rem × 5 = 1.09375rem` = **17.5px**, and the base `.badge` rule sets `height: var(--size)` — a fixed 17.5px box, confirmed directly from `deps/daisyui/packages/bundle/daisyui.js`'s own `.badge`/`.badge-sm` object.
- **After** (`.pk-chip-row .badge`): `height: auto` releases that fixed 17.5px pin. With `font-size: 0.75rem` (12px, from `.badge-sm`) and `padding: 6px 14px` (12px total vertical padding) plus the `1px` border on each side, the box now grows to roughly **26–28px** depending on the theme's exact line-height — definitively taller than the 17.5px stock height, and no longer clipped.
- Live visual confirmation (does the chip actually read as taller with breathing room) is routed to this task's own `<human-check>`, per the plan's own instruction.

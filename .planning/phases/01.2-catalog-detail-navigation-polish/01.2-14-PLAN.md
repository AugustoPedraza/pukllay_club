<objective>
Make the "Juegos similares" shelf structurally incapable of going sparse.

`Catalog.similar_games/1` hard-filters candidates to `weight_band == ^weight_band` with zero
widening logic — a deliberate, documented backstop flagged in `01.2-UI-SPEC.md`'s zero-one-many row
and verified present-and-working. The UAT response rejects that premise outright: "1-2 isn't
acceptable. This 'juegos similares' must to be fulled." With today's real catalog (434 games; bands
of 46/179/183 plus 26 with no band) a literal 1-2-card rail cannot occur, so this is a
forward-looking guarantee request rather than a reproduced broken render — but the guarantee is what
was asked for, and a `weight_band: nil` game already gets no shelf at all today, which is the same
complaint one step further along.

Sketch 031 answered the design half with variant C, **Always-Full Guarantee**: fix it at the query
layer so the shelf's layout never has to have a second mode. A compact sparse-cluster layout
(variant B) was tried and rejected. The title stays "Juegos similares"; a small "Ampliado" badge
beside it plus a subtitle swap to "Otras opciones que te van a encantar" is the entire visible
signal.

Purpose: the detail page's exit hook back into browsing is the difference between a dead end and a
catalog, and a half-empty rail reads as a bug regardless of why it happened.
Output: one bounded widening query that always fills the shelf, band-mates still first and still
ordered exactly as D-06 shipped, and an honest badge when the pool had to be widened.
</objective>

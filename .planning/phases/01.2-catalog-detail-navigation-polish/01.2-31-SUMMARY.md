# Phase 01.2 Plan 31: Lightbox Full-Screen Backdrop Opacity Summary

**`.pk-lightbox`'s background changed from a 72% translucent scrim to a bare, full-strength read of `--pk-shadow-color` — string-identical to the photo stage's own fill — closing the third and final UAT report that the lightbox background wasn't covering the whole screen.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 2
- **Files modified:** 3

## Accomplishments

- Fixed `.pk-lightbox`'s background: was `var(--pk-overlay-scrim)` (a 72%-strength translucent scrim), now a bare `var(--pk-shadow-color)` (opaque, full strength) — the container and the photo stage (`.pk-lightbox-img`) now share the identical background declaration, closing the band/sliver the user reported twice at desktop and mobile.
- `--pk-overlay-scrim`'s value is unchanged; it now has exactly one reader (`.pk-sheet-backdrop`, the mobile preview sheet's backdrop), down from two — the token split by reader instead of being retuned, since the sheet still needs the translucent 72% mix.
- Re-pointed the existing overlay-scrim test to assert the new contract (opaque container, refuted scrim read, preserved token value, preserved sheet-backdrop reader) and added a new dedicated equality test pinning the container's and the stage's background values as the identical string — the guard against a future near-miss retune.
- Corrected three now-stale present-tense comments in `app.css` (the scrim token's reader count, the shadow token's full-strength-consumer list, and the round-2 claim above `.pk-lightbox`) and added a new five-point G-01.2-19 provenance paragraph.
- Recorded the container-not-child lesson in `detail-page-mobile-interaction.md`, directly after round 7's height paragraph — completing the round-6/round-7/round-9 coverage story and explicitly superseding round 7's closing claim that "the stage IS the full-screen background."

## Decisions Made

- **The fix is the container's paint, not the child's size.** `.pk-lightbox` is `position: fixed; inset: 0` and has always covered the whole viewport — what the user photographed around the photo stage was never uncovered page, it was this element's own 72% scrim compositing over the page beneath it. Growing the stage (rounds 6 and 7) could never have closed this gap because the stage is deliberately width-capped by a shared boundary token.
- **`--pk-overlay-scrim` splits by reader instead of being retuned.** The mobile preview sheet's backdrop (`.pk-sheet-backdrop`) still needs exactly 72%; the lightbox needed a genuinely different value (100%), not a different setting of the same token. Retuning the shared token to 100% would have silently turned the sheet's translucent backdrop opaque — a regression on a surface nobody reported, on a different page than the one being fixed.
- **The photo stage (`.pk-lightbox-img`) is completely untouched.** Widening it to `100vw` was the other option and was rejected: its width reads the same `--pk-shell-content-width` boundary both chevron inset rules read, and that chevron/stage alignment was measured and signed off at 1920px (01.2-28). Every pre-existing assertion on the stage still passes untouched, proving this.
- **A string-equality test, not a pattern match, guards against drift.** The failure mode this plan is most worried about isn't a revert (loud, easy to catch) but a future edit giving the container its own slightly different dark — a near-miss that reintroduces the identical band a few percent fainter and reads as "probably intentional." The new test asserts the two rules' background values are the exact same string.

## Deviations from Plan

None — plan executed exactly as written, with one adjustment worth noting explicitly:

**Test name length limit forced two test-name shortenings (not a Rule 1-4 deviation).** The plan's action text describes descriptive test names for the re-pointed test and the new equality test, but Elixir/ExUnit enforces a 255-character limit on the combined `describe` + `test` name. The parent `describe` block's own name is already ~130 characters (unchanged, pre-existing), leaving roughly 124 characters of budget per test name. Both new/re-pointed test names were shortened to fit (e.g. "the container paints an opaque shadow-token field; the scrim token keeps its value for its sole reader (G-01.2-19)" and "the container and stage backgrounds are the identical string (G-01.2-19)") while preserving the gap-closure ID (`G-01.2-19`) for traceability. All the descriptive detail the plan wanted preserved lives in the assertion failure messages instead, which are unconstrained in length and carry the full rationale (the measured figures, the "reader moving off a token, not a licence to retune it" framing, etc.) verbatim.

# Phase 01.2 Plan 25: Lightbox Shell-Width Photo, Chevron Stacking, and Split Selection Summary

**Lightbox photo now caps to the shell's own `--container-7xl`/`--pk-gutter` content width, both chevrons paint above it via a shared explicit-z-index class, and the lightbox's own `@lightbox_image` assign is split from the page's `@selected_image` so navigating inside the lightbox never drags the poster/thumbnails/dots along with it.**

## Performance

- **Duration:** ~55 min
- **Completed:** 2026-08-27T23:03:08Z

## Accomplishments

- Re-derived `.pk-lightbox-img`'s `max-width` from Tailwind's own `--container-7xl` custom property (confirmed emitted in the built stylesheet) minus two `--pk-gutter`s, matching the header/footer/masthead's content width at desktop instead of the old standalone `min(90vw, 60rem)` cap — the confirmed root cause of the "use same width that defined for shell" UAT report.
- Gave both lightbox chevrons a shared `.pk-lightbox-chevron` class carrying an explicit `z-index`, fixing the mobile left-chevron-behind-the-image defect (a DOM-order paint accident) on both buttons, not just the one that happened to be visibly broken.
- Split the lightbox's own selection (`@lightbox_image`) from the page's (`@selected_image`): opening the lightbox seeds it from the page's current selection; stepping through the lightbox's chevrons/keyboard only moves `@lightbox_image`; closing deliberately does not sync back.
- Factored the image-selection membership check into `valid_gallery_image?/2`, called by both `select-image` and the new `select-lightbox-image` handler — one whitelist, two callers, pinned by a negative test on each caller.
- Corrected the `--pk-gutter` token's own comment, which had drifted to falsely claim `.pk-gutter` was its only reader — listed the real readers found via a read-first audit and restated the invariant the token actually enforces.
- Deliberately did NOT touch `--pk-overlay-scrim`, `.pk-lightbox`'s background/inset/z-index/transitions, or the `.Lightbox` colocated hook — all confirmed byte-identical to HEAD, per the plan's own verification gate.

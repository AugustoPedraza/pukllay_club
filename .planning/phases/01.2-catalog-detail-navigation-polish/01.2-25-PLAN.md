<objective>
Make the lightbox use the page's own width, put its left arrow back in front of the photo, and stop it
from dragging the gallery underneath along with it.

UAT test 12 reported four things: "for desktop we should use same width that defined for shell (header
and footer)"; "the overlay isn't correct, it displays background"; "when I navigate inside the lightbox,
that must not affect the carousel"; and "on the mobile version the left arrow looks like behind the
current image".

Three of the four are unambiguous code defects with confirmed mechanisms. The fourth — the overlay — was
investigated hard and does not reproduce as a stacking, positioning or compositing bug: the overlay
measured full-viewport at the highest z-index on the page, precisely centred, with the scrim compositing
uniformly over every sampled region including the buttons and body text the reporter could see. The
best-evidenced explanation is that it is the width defect wearing a different face: a photo capped at
960px inside a 1440px window leaves a wide field of a deliberately semi-transparent scrim, which reads
as "not obscuring enough". So the width gets fixed first and the overlay gets looked at again
afterwards, rather than tuning a shared design token against a symptom whose cause is already accounted
for.

Purpose: an image viewer that fills the page's width, keeps both its controls reachable, and leaves the
page it was opened from exactly as it found it.
Output: a shell-width photo, a chevron that paints above it, and a lightbox with its own selection.
</objective>

# Phase 01.2 — UI Design Contract

> Visual and interaction contract for Catalog & Detail Navigation Polish. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This is a refinement phase on an already-shipped, brand-locked design system
(Phase 1 / 1.1, validated by 36+ sketch rounds — see `.claude/skills/sketch-findings-pukllay_club/`).
Nothing below invents a new visual language. Sections that restate existing tokens do so because
the template requires them; the load-bearing new content is the **Phase-Specific Layout &
Interaction Decisions** section, which resolves D-01 through D-08 from
`01.2-CONTEXT.md` into concrete, implementable values — most centrally **D-07 (buy-box redesign)**,
which `01.2-CONTEXT.md` explicitly flagged for this agent rather than blind planning.

## Spacing Scale

Declared values (all multiples of 4px, matching Tailwind's default scale — this project has never
overridden `--spacing-*`):

| Token | Value | Usage in this phase's scope |
|-------|-------|------------------------------|
| xs | 4px | `gap-1` chip/pill rows (weight-band, mechanic/theme chips — unchanged) |
| sm | 8px | `gap-2` icon+text pairs; `space-y-2` card-body rhythm |
| md | 16px | `p-4` card/panel padding — **used by D-07's new buy-box panel** (see below); `gap-4` grid/carousel gaps (grid columns unchanged: `grid-cols-2 sm:grid-cols-3 lg:grid-cols-4`) |
| lg | 24px | `space-y-6` between major page sections |
| xl | 32px | not currently used anywhere this phase touches; do not introduce without a documented reason |
| 2xl | 48px | `.pk-detail-masthead`'s `gap: 3rem` between poster-col and text-col — an already-established exception to the space-y-6/3/2 rhythm scale (mirrors sketch 005's `--space-8` token), unchanged by this phase |
| 3xl | 64px | not used |

Exceptions:
- `.pk-poster-col` width = **20rem (320px)**, a fixed layout dimension (not a spacing token), unchanged by this phase — D-07's panel padding (`p-4`, 16px each side) is applied *inside* this width, so the poster image's own content area becomes ~288px, which sits comfortably above `.pk-poster-card.is-hero`'s 240px card tier.
- **48rem (768px)** is the one detail-page-specific breakpoint beyond `ux-responsive`'s documented `sm`/`lg` set (introduced in 01.1-04 for the masthead's 1-col→2-col flip). D-07 does not change this breakpoint or introduce a new one.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 (semibold emphasis tier — this app's sanctioned way to differentiate without a 4th size, per `ui-design-system`'s measured inventory) |

Muted/secondary tier (not a template row, but real and load-bearing on this screen): 12px/400,
`text-xs text-neutral`. This app is already at its documented **3-tier cap** (heading/body/muted,
weight as the body tier's emphasis lever) — do not add a 4th size for anything in this phase,
including the D-07 buy-box redesign (use `btn-lg`'s built-in sizing, not a custom font-size bump,
for CTA prominence — see below).

## Phase-Specific Layout & Interaction Decisions

Resolves `01.2-CONTEXT.md`'s D-01 through D-08. Cross-reference by ID.

### D-07 — Buy-box redesign (the load-bearing new visual decision in this phase)

`01.2-CONTEXT.md` flagged this explicitly: "is `btn-primary` alone enough visual weight for the
page's one primary action?", "column split/order", and "how the mobile CTA bar reads in practice" —
without a specific fix in mind, routed to this agent rather than decided blind in plan-phase.
Resolution:

1. **Cover image aspect ratio: `aspect-video` (16:9) → `1 / 1.05`.**
   The buy-box's primary image (`.pk-poster-col`'s main `<img>`, show.ex:293) currently reuses
   `aspect-video` — the ratio `.pk-preview-poster` uses for the unrelated hover-preview surface
   (app.css:494-497). Every *other* place a game's cover renders (`.pk-card-poster`, app.css:476-478)
   uses `1 / 1.05` — a near-square ratio matched to how board-game box art actually looks. Using the
   wrong, wide ratio here is a real, fixable contributor to weak prominence: it letterboxes or
   crops a portrait/square cover awkwardly, and it means the page's single most important image (the
   "buy box" hero shot) uses a *different* visual identity for the same game than the card the
   visitor just clicked through. **Fix: change the buy-box `<img>`'s aspect ratio class to match
   `.pk-card-poster`'s `1 / 1.05`, not `.pk-preview-poster`'s `16 / 9`.**

2. **Panel treatment: give the buy-box a visible surface boundary.**
   Today `.pk-poster-col` is bare — image, thumbnails, and buttons sit directly on the page
   background with no elevation or boundary, competing visually with the reading column beside it
   for attention with nothing marking it as "the decision panel." **Fix: wrap the poster-col's
   contents in `bg-base-200 rounded-box p-4`** — reusing the exact secondary-surface token already
   used for cards/nav/footer (no new color), not inventing a shadow/border treatment. This is the
   single highest-leverage, lowest-risk fix for "does this read as a self-contained buy box" per the
   sketch's own original framing (`detail-page-layout.md`: "the image + primary CTA live together
   as one self-contained decision panel").

3. **CTA prominence: `btn-primary` → `btn-primary btn-lg`, own full-width row.**
   Today the reserve button and the share button sit in one `flex items-center gap-2` row as
   effectively co-equal siblings (`flex-1` on the CTA, a same-height circular button beside it) —
   this dilutes the CTA's visual weight instead of establishing it as the page's one primary action.
   **Fix: promote the reserve button to daisyUI's `btn-lg` size modifier** (a built-in size step, not
   a custom font-size — respects the 3-tier type cap) **and give it its own full-width row**; move
   the share control to a small `btn-circle btn-outline btn-primary btn-sm min-h-11 min-w-11` icon
   anchored top-right of the new panel (near the image, Amazon/Airbnb's own convention for a
   secondary "share the listing" action), not sharing a row with the primary CTA.

4. **Column split/order: keep image-left / text-right, sticky poster-col on desktop.** No change —
   this is the validated Amazon/Shopify/Airbnb "buy box beside a reading column" pattern (already
   documented, already shipped), and nothing in the user's feedback targeted the fundamental
   left/right order. `.pk-detail-masthead`'s `20rem 1fr` grid and `.pk-poster-col`'s
   `position: sticky` (≥768px) are unchanged.

5. **Mobile CTA bar: keep the validated 3-state scroll mechanism unchanged; fix the internal weight
   split instead.** The hide-while-scrolling / park-at-footer state machine (`.DetailChrome`,
   plain `scroll` + `getBoundingClientRect()`, not `IntersectionObserver`) took two separate debug
   rounds to get right (sketch 011's throttling fix, plus the equal-specificity cascade-order bug) —
   re-litigating its timing/trigger mechanism is high-risk for low reward and nothing in the user's
   feedback pointed at the mechanism itself being broken. The more likely, lower-risk contributor to
   "reads unsatisfying" is the same co-equal-buttons issue as the desktop panel: today's
   `.pk-mobile-cta-bar` gives the reserve button and the share button near-equal visual weight
   (`flex-1` + a same-height circular button). **Fix: change the bar's internal split so the reserve
   button visually dominates the bar** (e.g. `flex-[3]` on the CTA vs. the share button's natural
   `flex-[0_0_auto]` circular footprint) **without changing the bar's height, padding, timing, or
   trigger mechanism.** This directly answers the "prominence" complaint without touching what
   already works.

### D-01 / D-02 — Grid becomes exclusively the filtered/search view

No new visual tokens. Gate the existing heading (index.ex:612-615), empty state (617-623), loading
skeleton (625-629), grid (631-642), and load-more control (644-648) on `filters_active?/1` — the
same predicate that already gates carousel visibility (line 578) — instead of always-rendering the
grid block. `main_grid_heading/1` already returns "Resultados" (filtered) vs. "El catálogo completo"
(unfiltered) — no copy change needed. **See the flagged `⚠ unresolved` row above**: D-02's "submit
empty filters → grid" claim needs a mechanism decision this UI-SPEC cannot resolve on its own
(it's a state-plumbing question, not a visual one) — surfaced for the planner.

### D-03 — Auto-loading infinite scroll replaces "Cargar más"

Remove the manual button (index.ex:646) entirely from the default rendered state. Replace with an
IntersectionObserver-driven sentinel element at the bottom of `#games` (adapt `.CarouselScroll`'s
existing pattern to the vertical axis), firing `push-event("load-more")` with enough `rootMargin`
lead (e.g. ~400px) that the next page is already loading before the visitor reaches the literal
bottom — no visible pause. Visual contract: see the `loading`/`error` UI Considerations rows above
(trailing skeleton row; compact inline retry on failure). The existing `handle_event("load-more",
...)` stream-append logic (index.ex:319-331) is unchanged — only the trigger mechanism changes.

### D-04 / D-05 — Ficha técnica cleanup

Remove the two permanently-"No disponible" rows (Ilustrador, Puesto en el ranking BGG) entirely —
no placeholder, no "coming soon" copy, per `detail-page-layout.md`'s "ground every field in the real
schema, including its gaps" rule applied to its logical conclusion (these two fields have zero path
to ever populating, unlike a conditionally-missing field). Players/duration de-duplication (D-05):
**keep the compact `GamePreview.facts_row/1` treatment near the title, drop the Ficha técnica
duplicate rows for Jugadores/Duración** — the facts-row pills are already the more prominent,
already-linked-to-filters representation (`GamePreview.facts_row game={@game} linked={true}`,
show.ex:335), consistent with the sketch's own original framing ("facts pills sit with the title,"
`detail-page-layout.md`). Ficha técnica keeps Edad mínima, Año, Diseñadores, Editorial, and the BGG
link — a shorter but still 2-column grid, unchanged `.pk-spec-row`/`.pk-spec-row--wide` CSS.

### D-06 — "Juegos similares" ranking

No new visual component — reuses `CarouselRow`/`GameCard` unchanged (see UI Considerations above).
The only visible-to-a-user change is which games appear and in what order; no new CSS, no new copy
beyond the existing `similares_subtitle/1` (unchanged).

### D-08 — Breadcrumb carries forward catalog filter state

No new visual component. The "Ludoteca" breadcrumb link's `href`/`navigate` target gains a
query-string payload (mechanism is plan-phase's discretion per `01.2-CONTEXT.md`); the rendered
label, styling, and narrow-viewport collapse behavior are all unchanged (see UI Considerations
above).

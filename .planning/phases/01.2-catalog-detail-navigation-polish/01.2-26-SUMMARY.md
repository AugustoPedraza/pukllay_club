- Declared the one base pill representation (`.pk-pill`) plus its variant set in `assets/css/app.css`'s `PK CATALOG SURFACES` block: four tones (neutral/accent/outline/selected), two non-default sizes (comfortable/large), and an interactive variant — each declaring only the properties its own name promises (base owns shape/type/padding/layout, tones own fill/border-color/text-color, sizes own type-size/padding, interactive owns cursor/transition/hover).

- Left `weight_band_badge/1`'s markup byte-identical to HEAD (standing instruction, no call site) and gave its shape a documented home in the new `.pk-pill-large` size variant.
- Added a source-level drift gate (`catalog_show_test.exs`) that fails if any tone variant ever grows a `border-radius`, `padding`, or `font-size` declaration — the exact drift that broke this rhythm three separate times before this plan.
- Added a negative assertion that no rendered chip in the detail page's reading column or facts row still carries a daisyUI `badge` class, pinning the migration against a future partial re-migration.

# Phase 01.2 Plan 16: Search/Filter Transition Affordance Summary

**Branded in-flight progress bar, a self-clearing results-region dim, and an entry/surface-flip fade wired through LiveView's own `phx:page-loading-start`/`stop` window events — closing G-01.2-9's "instant jump" gap.**

## Accomplishments

- The catalog's search/filter round trip (`phx-change="search"` on the header search box, each active-filter chip removal, and "Limpiar filtros") now dispatches LiveView's own `phx:page-loading-start`/`phx:page-loading-stop` window events via `Phoenix.LiveView.JS.push(event, page_loading: true)`
- A new `.ResultsLoading` colocated hook mirrors those events onto the results wrapper (`#results-region`) as a `data-loading` attribute, with a 5-second self-clearing failsafe timer so a dropped response, transport blip, or backgrounded tab can never strand the surface dimmed (T-01.2-16-01)
- The results region dims (`.pk-dimmable[data-loading]`, opacity `0.55`) while a request is in flight, riding the *existing* `.pk-dimmable` transition shorthand extended with an `opacity`/`--duration-fast` pair alongside the untouched `filter`/`--duration-base` pair — never a second competing shorthand
- A new `pk-fade-in` CSS animation (opacity 0→1) replaces the instant `stream(:games, games, reset: true)` pop: scoped to `.pk-grid .pk-card:not(.pk-trailing-skel)` for individual card entries, and to a new shared `.pk-surface-fade` marker class (applied to both `#carousel-rows` and the `#grid-scroll` wrapper) for the carousel↔grid surface flip
- The progress bar's colour is read live from the theme's own `--color-primary` custom property at show time, replacing the hardcoded `#29d` scaffolding-blue literal — correct in both light and dark themes with no extra theme-change listener
- A new `G-01.2-9 search/filter transition wiring` test describe block (4 tests) pins the three connections invisible to the compiler: the annotation count, the hook's id/attribute, and both results regions' fade marker — each mutation-verified during authoring (see Deviations)

## Decisions Made

See `key-decisions` in frontmatter — the `phx-page-loading` → `JS.push(..., page_loading: true)` correction, the filter-modal scope boundary, and the `:not(.pk-trailing-skel)` exclusion.

**LiveView 1.2.9's `phx:page-loading-start`/`stop` payload shape** (per Task 2's `read_first` instruction to record what was found): `withPageLoading`/`pushWithReply` dispatch `{ detail: info }` where `info` varies by call site — `{to, kind: "initial"|"patch"|"redirect"|"error", ...}` for navigation/error paths, `{kind: "element", target: el}` for a `page_loading: true` push (`view.ts` line ~1447). The `.ResultsLoading` hook deliberately does not inspect this payload (per the plan's own instruction) — only the three annotated controls plus a live navigation away from this page can produce these events here, and a momentary dim during a page-leave is harmless.

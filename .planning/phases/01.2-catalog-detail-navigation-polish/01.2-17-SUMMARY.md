## Accomplishments

- **Pills overlay over the poster (Task 2, ask #1).** `GamePreview.facts_row/1` now renders twice
  with byte-identical arguments — once in `.pk-facts-inline` (desktop, beside the title) and once in
  `.pk-facts-overlay` (mobile, over the poster's top-left corner) — with the swap declared in the
  single existing 48rem detail-layout media block.
- **One Reservar control on the phone (Task 2, ask #3).** The poster panel's inline Reservar button
  now carries `.pk-poster-reserve` (hidden below 48rem, restored to `inline-flex` — daisyUI's own
  `.btn` display value — at/above it), so exactly one reserve control is ever on screen.
- **Dot affordance on mobile (Task 2, ask #8, D3).** A second gallery control list (`#gallery-dots`)
  renders from the same `gallery_thumbnails/1` list the thumbnails use, dispatching the identical
  `select-image` event/param — the existing membership-check whitelist stays the single guarded
  image-selection path. Thumbnails/dots swap in the same 48rem block.
- **Measured, not guessed.** Loaded the real page at 390px via headless Chrome CDP: the pill row's
  own content width (279px) overflowed the overlay's available width (256px) by 23px, invisibly
  bleeding under the share control. Fixed with a wrapper-scoped `flex-wrap: wrap` override, re-
  measured to confirm the overflow was gone.
- **Reading order fixed (Task 3, ask #2/#4/#6).** Text column reordered to title → description →
  `divider` boundary → editorial hashtags → weight-band badge → mecánicas → temáticas → ficha
  técnica. daisyUI's own `.divider` used as-is (checked first, per project convention); only its
  default margin was overridden since `.pk-text-col`'s existing flex gap already supplied the
  spacing.
- **Publisher row gone (Task 3, ask #5).** Removed unconditionally at every viewport width;
  `ficha_tecnica?/1`'s zero-one-many guard narrowed from five fields to four in the same edit, so a
  publisher-only game shows no empty-looking section.
- **Mutation-tested the ordered-children assertion.** Temporarily reinserted an element between the
  title and description, confirmed the new test failed (`0` vs expected `1`), reverted, confirmed
  the full suite (84 tests) passed again.

## Issues Encountered

- **Dev-sandbox image loading blocked by CSP.** The seeded games' R2-hosted cover images are
  publicly reachable (confirmed `curl` returns 200), but this environment's Phoenix dev server
  applies a `Content-Security-Policy: img-src 'self' data: <configured origin>` header
  (`lib/pukllay_club_web/csp.ex`) and the runtime-configured image-CDN origin wasn't set in this
  worktree's dev config, so the browser blocked the image fetch and rendered the `<img>` element's
  `alt` text in its place. This is a pre-existing environment-configuration gap unrelated to this
  plan's changes (the `js-cover-fallback` mechanism and CSP itself both predate this plan) — not
  auto-fixed per the scope-boundary rule. All layout/positioning facts in this SUMMARY were measured
  via `getBoundingClientRect()`/`scrollWidth` against the real DOM, which is accurate regardless of
  whether the underlying image resource loaded; only the "legible against a busy cover" pixel check
  (D1's `human_judgment: true` item) is affected, and it is routed to the phase's end-of-phase human
  UAT harvest where a properly configured environment can confirm it visually.

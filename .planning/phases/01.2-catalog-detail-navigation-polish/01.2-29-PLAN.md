<objective>
Give the lightbox's stage the whole screen's height, so the last two bands of see-through scrim
disappear.

Plan 01.2-28 turned the photo's box into a real, opaque, shell-width stage and the user confirmed
it ("That is better") — then asked for one more thing: "the background should be full screen." The
stage still stops at four fifths of the viewport's height, and because `.pk-lightbox` centres its
child rather than stretching it, the unclaimed fifth renders as two equal translucent bands, one
above and one below, at every viewport. That number was not an oversight: 01.2-28 carried it
forward deliberately and wrote down why — "picking a different number is a design decision with its
own UAT item, not part of this fix." This is that UAT item, arriving on schedule.

So this plan changes exactly one dimension of one rule, and does it with the idiom this file
already uses for the same intent everywhere else: the older viewport unit declared first as a
fallback, the dynamic-viewport unit declared immediately after, so a mobile browser's collapsing
toolbar cannot leave the stage taller than the screen it is covering.

Two things arrive underneath the taller stage that were not underneath it before, and both are
looked at rather than assumed. The close button, anchored to the viewport's own top-right corner,
sits in clear scrim margin above the stage today; once the stage reaches the top edge it sits
inside the stage's own band instead. And the mobile letterbox gets larger, not smaller — the photo
keeps its size while the solid field around it grows. Neither is fixed here (the close button's
anchoring is a recorded decision, the letterboxing is G-01.2-17's accepted territory); both get an
explicit question in the human check so the answers are recorded rather than rediscovered next
round.

Purpose: close G-01.2-18 — the single remaining open item on the lightbox, severity minor, one
declaration deep.
Output: a full-height stage, a corrected design record, and an assertion whose failure message
explains why one height is written twice.
</objective>

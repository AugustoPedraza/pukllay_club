# Phase 01.2 Plan 01: Breadcrumb Filter Forwarding Summary

**Breadcrumb "Ludoteca" link now round-trips catalog filters through a new `PukllayClubWeb.CatalogFilters` sanitiser, replacing a hardcoded `~p"/"` target with a decode-revalidate-reencode pipeline that can never echo attacker-controlled input into a navigate href.**

- **Duration:** 50min
- **Started:** 2026-08-25T22:24:44-03:00 (approx., from prior plan-doc commit)
- **Completed:** 2026-08-26T02:15:16Z
- **Tasks:** 2
- **Files modified:** 7 (2 created, 5 modified)

## Accomplishments
- Created `PukllayClubWeb.CatalogFilters`, the single authority for catalog filter parsing,
  validation and re-encoding (`q/1`, `parse_int/1`, `from_params/1`, `to_query/1`,
  `catalog_path/1`), moving (not copying) `CatalogLive.Index`'s four private parsers verbatim so
  there is exactly one copy of each rule.
- `CatalogLive.Index` now calls `CatalogFilters.from_params/1` once in `handle_params/3`, and
  recomputes a `:from_query` assign in `apply_filters/1` (empty string when unfiltered), passed to
  every grid card as `from={@from_query}`.
- `GameCard.game_card/1` gained an optional `:from` attr and a `detail_path/2` helper (three
  literal clauses, never a dynamic path assembled from raw strings) so a card's link carries
  `?from=` only when a real filter is active.
- `CatalogLive.Show`'s `mount/3` sanitises `params["from"]` via `CatalogFilters.catalog_path/1`
  into a `:catalog_path` assign, which the breadcrumb's `navigate` now targets instead of the
  hardcoded `~p"/"`. `catalog_path/1` never echoes its input — it decodes, re-validates every
  key/value through the closed Vocabulary whitelist, then re-encodes from scratch, so an absolute
  URL, protocol-relative URL, or `javascript:` URI is a structurally unreachable output.
- `GamePreview.preview_body/1` and `preview_template/1` gained a mirrored `:from` attr and
  `detail_path/2` helper so the hover/tap preview's "Ver detalles" CTA carries the same forwarded
  filter state as a resting card click — both routes into the detail page now behave identically.
- `test/pukllay_club_web/catalog_filters_test.exs`: a table-driven hostile-input contract (8
  shapes: absolute URL, protocol-relative URL, `javascript:` URI, unknown key, unknown facet
  value, 5000-character junk, a malformed percent escape that raises `Plug.Conn.InvalidQueryError`
  inside `Plug.Conn.Query.decode/1`, and empty string — each asserting exactly `"/"`), a
  preserved-state round trip, `to_query/1`'s empty-string default case, `from_params/1`'s q/list
  bounds, and full `to_query`/`from_params` idempotence.
- `test/pukllay_club_web/live/catalog_show_test.exs` gained a `breadcrumb carries forward catalog
  filters (D-08)` describe block with 3 passing end-to-end tests: the filtered round trip (mount
  `/`, search, follow the rendered card href, assert the breadcrumb target), the no-`from` root
  fallback, and the absolute-foreign-URL rejection.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `CatalogFilters.stringify/1` missing a binary clause**
- **Found during:** Task 1, while running the new tracer end-to-end test
- **Issue:** `stringify/1` only had `is_atom/1`, `is_integer/1` and `is_list/1` clauses. The `:q`
  field is a plain binary (e.g. `"Catán"`), so `to_query/1` raised `FunctionClauseError` the moment
  a search query was active — caught immediately by the LiveView test's `render_change` on the
  search form, not by `mix compile`.
- **Fix:** added `defp stringify(value) when is_binary(value), do: value` as the first clause.
- **Files modified:** `lib/pukllay_club_web/catalog_filters.ex`
- **Verification:** re-ran `test/pukllay_club_web/live/catalog_show_test.exs` (56 tests) and
  `test/pukllay_club_web/live/catalog_live_test.exs` (88 tests) — all green.
- **Commit:** folded into `944515d` (found and fixed before the task's own commit).

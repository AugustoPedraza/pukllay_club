## Phase Goal

**As a** club staff member (the owner or one of up to 3 invited staff), **I want to** sign in and
manage the ludoteca, record where each physical game lives, curate the home page's sections, and fix
mis-banded games, **so that** Saturday operations run smoothly and the home page stays alive.

> Transcribed from the ROADMAP `**Goal:**` line (role, capability and outcome are all stated there).
> The Goal line itself is not in canonical user-story form; `/gsd mvp-phase 01.8.1` can reframe it.

<objective>
Ship the phase's tracer: invite-only, passwordless staff sign-in end to end — an owner account,
a magic-link email, a confirmation page, a remember-me session, and a staff-gated `/admin`
dashboard shell. Built from `mix phx.gen.auth` by subtraction (registration, password log-in and
settings removed), never hand-rolled token auth.

Purpose: every other plan in this phase (games, shelves, sections, band audit, staff invites)
lives behind this gate. Proving session + token + role gate + LiveView mount work together on the
first commit is exactly the architectural risk tracer-first exists to retire early.

Output: the `Accounts` context and `users`/`users_tokens` tables with an explicit `role`, the
`/admin/ingresar` sign-in flow, `UserAuth`'s staff gate, `Admin.DashboardLive`, and
`Release.create_owner/1`.

Spec-less probe fallback skipped: phase has no requirement IDs to probe (visible skip) — the five
ROADMAP success criteria (SC-1..SC-5) and CONTEXT decisions stand in as the requirement set.
</objective>

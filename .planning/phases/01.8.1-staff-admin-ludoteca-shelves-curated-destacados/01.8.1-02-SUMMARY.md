# Phase 01.8.1 Plan 02: Games Status Lifecycle Summary

**games.status (draft/published/retired) added with a `published` column default so the live ~434-game catalog stays public on deploy, and every public Catalog read path (grid, count, carousels, similar-games, sitemap, the GameSEO plug, and CatalogLive.Show) now filters on it — a draft or retired game 404s identically to an unknown id.**

## Accomplishments

- `add_status_to_games` migration: `games.status` string column, `null: false, default: "published"` (backfills all existing rows for free via the column default — no data-migration `UPDATE` needed, unlike the `is_expansion` precedent it mirrors), plus a `games_status_must_be_known` check constraint.
- `Game.status` (`Ecto.Enum`, `[:draft, :published, :retired]`, default `:published`) and `Game.status_changeset/2`.
- `Catalog.get_published_game!/1` — a dedicated public-only read (never a flag on `get_game!/1`) wired into `PukllayClubWeb.Plugs.GameSEO` and `CatalogLive.Show.mount/3`, so a draft or retired game's `/juegos/:id` 404s end-to-end through both the crawler-facing plug and the LiveView mount path.
- Non-optional `published_only/1` predicate composed into `base_filtered_query/2` (covering `filter_games/1`/`count_games/1`), `list_games/1`, `sitemap_entries/0`, `similar_games/1`, and the three carousel helpers (`tags_query/1`, `weight_band_query/1`, `recent_query/0`) — every public read path in `Catalog` now excludes draft/retired games.
- `Catalog.publish_game/1`, `retire_game/1`, `restore_game/1` — the three staff-facing lifecycle transitions, ready for plan 05/06 to wire to admin buttons.
- `game_fixture/1` gained an optional `:status` attr (default `:published`) so tests can seed draft/retired games without touching `seed_changeset/2` (which never casts `:status`).
- Table-driven test coverage: a 9-test "published-only public reads" describe block in `catalog_test.exs` covering every read function by name, a 6-test "status transitions" block, plus targeted 404/200 tests in `game_seo_test.exs`/`catalog_show_test.exs`, exclusion tests in `sitemap_controller_test.exs`, and a visitor-render test in `catalog_live_test.exs`.

## Decisions Made

- **Task 1 (user-selected at orchestrator dispatch): status-404.** `games.status` (draft/published/retired, NOT NULL, column default `published`); a retired game's old `/juegos/:id` link returns the same branded 404 as an unknown id — no new "ya no está en la ludoteca" page/copy/SEO handling. Drafts always 404 either way, since they were never public. Recorded in the plan's threat register as `T-01.8.1-12` (accepted, low severity — reveals nothing beyond "not found").
- `get_published_game!/1` implemented as its own function with its own private `fetch_published_by_id!/1`, mirroring `get_game!/1`'s exact id-parsing contract (bare id / id-slug / non-numeric / out-of-bigint), rather than a boolean flag on `get_game!/1` — per RESEARCH.md Pitfall 2's explicit warning against that shape.
- Implementation ordering: the shared `published_only/1` pipeline and the three transition functions landed in the same commit as Task 2's `get_published_game!/1` (both tasks list `catalog.ex`); Task 3's commit is test-only, adding that work's dedicated coverage. See Deviations.

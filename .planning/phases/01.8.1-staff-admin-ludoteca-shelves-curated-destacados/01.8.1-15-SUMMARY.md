## Decisions Made

- Implemented D-03 revised via a per-BGG-id `pg_advisory_xact_lock` as the first `Ecto.Multi` step,
  with the existing-editions re-check as its own subsequent `Multi.run` step (fresh READ COMMITTED
  read) — never a second unguarded read-then-write, which is exactly what caused gap CR-B-01.
- `acknowledged_game_ids` is always sourced from the server-side `:edition_prompt` assign in the
  `"confirm-edition"` handler, never from client event params (T-01.8.1-69) — a forged event payload
  can't claim an id it was never shown.
- No unique or partial-unique index added to `games.bgg_id` (REVIEW.md's drafted fix — explicitly
  rejected by the user's 2026-09-14 decision, since it would reject the real Patchwork/Patchwork
  Andino editions and fail the production migration). A `pg_indexes` guard test fails if one is ever
  added later.

### SC-3 In-Shelf Order Assessment (scope note finding)

`.planning/notes/admin-redesign-scope.md` and `01.8.1-14-SUMMARY.md` both say "SC-3 was never
correctly met" because `game.ex:84` says "at most one shelf per game, no in-shelf position" and
`games_on_shelf/1` (`shelves.ex:170-177`) orders by name. I checked that claim against SC-3's actual
ROADMAP wording and the phase's locked decisions:

- SC-3 sets the granularity itself: "Each game carries a **shelf-level** storage location".
- `01.8.1-CONTEXT.md` **D-11** (locked): "One location per game (shelf only, no in-shelf position)".
  **D-15** (locked): "Pick/restore list = games grouped by shelf in walking order, names inside each".
- The shipped `Shelves.pick_list/1` does exactly that, and a test covers it.

**Verdict:** at the granularity SC-3 declares, "games listed in shelf order" is met. The claim that
SC-3 was never met relies on sketch 065 R8's premise that on-shelf order is the physical
left-to-right order. That premise came from sketches made after the SC and D-11 were locked, and
D-11 deliberately rejected it. So this is **not an SC-3 shortfall as written**. It is a real product
requirement that the redesign surfaced: without it, the zone bar, rail and ↑/↓ have no data. It is
recorded in `deferred:` as scope that **Phase 01.8.2 owns** (its goal names it, and scope slices
#1a-#1c come first).

**Flag for the user:** the 01.8.2 ROADMAP goal calls this "closing the SC-3 defect". This report does
not agree with the word "defect". Nothing is lost either way, because 01.8.2 owns the work. If you
want it recorded as an SC-3 gap instead (for example, if "shelf order" was always meant to include
the order within a shelf), it moves into Acknowledged Gaps with the same owner. The status stays
`passed`.

## Re-Verification Summary

The prior verification (2026-09-14T18:00:00Z) found 5/6 truths verified, with one blocking gap:
**CR-B-01** — `Catalog.add_game_from_bgg/1`'s duplicate-BGG-id rejection had no database-level
backstop (plain non-unique index + unguarded read-then-write), so a double-submit could create two
draft games sharing one `bgg_id` with no way to detect or merge the duplicate. After that
verification, the user revised D-03 itself (2026-09-14): the existing Patchwork/Patchwork Andino
pair (bgg_id 163412) is two legitimate editions, not a data error, so a unique/partial-unique index
on `bgg_id` — the originally-drafted fix — would have been wrong (it would reject real editions and
fail the production migration). Plan `01.8.1-15` implemented the REVISED D-03: **warn, then allow as
an edition**, serialized by a per-BGG-id Postgres advisory lock inside one `Ecto.Multi`, never a DB
uniqueness constraint.

This re-verification checked the revised gap against the revised decision, not the original one:

- **Code inspection** confirms `games.bgg_id` still has no unique constraint anywhere (`game.ex`'s
  only `unique_constraint` is `:csv_row`; the migration history has no `unique_index` migration for
  `bgg_id`) — correct, per the revised D-03.
- `Catalog.add_game_from_bgg/2` (`lib/pukllay_club/catalog.ex:307-357`) now returns
  `{:existing_editions, games}` for a known BGG id and only inserts when every current holder's id is
  in the caller-supplied `acknowledged_game_ids` — verified by direct read of
  `insert_draft_with_edition_check/2` and `check_bgg_id_editions/3`.
- A per-BGG-id `pg_advisory_xact_lock(8_811_015, bgg_id)` is the **first** step of the `Ecto.Multi`,
  with the editions re-check as its own subsequent `Multi.run` step (a fresh READ COMMITTED read that
  sees whatever a prior lock holder just committed) — this is the actual DB-level serialization
  mechanism that replaces the rejected unique-index fix.

  the concurrency invariant itself on **real, unboxed Postgres connections** — a 3-caller lock-

  `bgg_id` that yields exactly one draft and exactly one Oban job. This verifier independently re-ran

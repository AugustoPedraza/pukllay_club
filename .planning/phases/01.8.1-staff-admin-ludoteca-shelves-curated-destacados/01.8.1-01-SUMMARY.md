# Phase 01.8.1 Plan 01: Staff Auth Tracer & Invite-Only Hardening Summary

**`phx.gen.auth`-by-subtraction magic-link staff sign-in (pbkdf2 hashing, no password/registration path) gated behind a DB-backed `owner`/`staff` role enum, landing on a new `PukllayClubWeb.Admin.DashboardLive` shell.**

## Performance

- **Duration:** ~95 min
- **Started:** ~2026-09-14T01:22:00Z
- **Completed:** 2026-09-14T01:57:58Z
- **Tasks:** 2 (Task 1 tracer, Task 2 TDD hardening)
- **Files modified:** 28

## Accomplishments

- End-to-end magic-link sign-in: an owner created via `Accounts.create_owner/1` requests a link at `/admin/ingresar`, confirms it, and lands signed-in on a staff-gated `/admin` dashboard shell with the generator's long-lived remember-me cookie.
- `users.role` is an explicit `Ecto.Enum(:owner/:staff)` with **no column default**, backed by a `users_role_must_be_known` Postgres check constraint — verified live to reject a raw-SQL insert of an unknown role while accepting `owner`/`staff`.
- Both the `require_staff_user` plug (HTTP) and the `:require_staff` `on_mount` hook (LiveView) enforce the same role gate, redirecting a non-staff scope to `/` with no flash — a non-staff account learns nothing about the admin area.
- No public registration, password log-in, or account-settings path exists: `registration.ex`/`settings.ex` deleted, the password `<.form>`/divider/sign-up link stripped from `UserLive.Login`, `update_password` removed from `UserSessionController`, and every generator default `/users/*` path 404s.
- Invite-only hardening (Task 2, TDD): sign-in shows the identical neutral copy `Si el email es del staff, te llegó un link para entrar. Revisá tu casilla.` regardless of whether the address is staff, non-staff, or unknown — delivery is gated server-side on `User.staff?/1`, verified with `assert_email_sent`/`assert_no_email_sent`.
- An expired/used magic link renders in-page (`El link venció o ya se usó. Pedí uno nuevo.` + `Enviarme otro link`) instead of the generator's flash-and-redirect.
- `UserNotifier`'s two email variants rewritten in Rioplatense voseo with distinct subjects (`Te invitaron al staff de Pukllay Club` for an invite, `Tu link para entrar a Pukllay Club` for a returning login), both stating the 15-minute expiry.
- `PukllayClub.Release.create_owner/1` added as the SSH release-shell entry point (`bin/pukllay_club eval 'PukllayClub.Release.create_owner("owner@example.com")'`), delegating to `Accounts.create_owner/1` inside `Ecto.Migrator.with_repo/2`.

## Decisions Made

- `pbkdf2` over the generator's `bcrypt` default — pure-Elixir hashing dependency, no NIF compile added to the release image; password hashing is never exercised in production since no password-login path ships (recorded per the plan's own instruction).
- `signed_in_path/1` simplified to unconditionally return `~p"/admin"` — the generator's "already logged in, go to settings" branch has no settings page to target in this app.
- Confirmation LiveView collapses the generator's two-button confirm/login choice (stay logged in vs. this-time-only) into a single always-remember-me form, matching D-31's "long-lived session, always on."
- Left the generator's password-changeset/`valid_password?` code and `hashed_password` column in place (dead but harmless, per the plan's own instruction) and restored small `set_password/1`/`valid_user_password/0` test helpers so that dead-code path keeps unit coverage rather than going untested silently.

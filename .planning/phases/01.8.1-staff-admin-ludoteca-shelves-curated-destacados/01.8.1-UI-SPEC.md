# Phase 01.8.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** this phase adds a *new admin surface* (staff-only, task/CRUD-oriented — dashboard,
tables, forms, a phone-first tap-to-assign flow) plus small, surgical changes to the *existing
public surface* (an "Admin"/"Editar" affordance when a staff session exists; the home page's first
carousel row becomes a hand-picked hero, the rest become staff-manageable rails). The public
surface's own visual language (poster-forward cards, full-bleed edge-fade rails, hover/tap preview)
is already locked by `sketch-findings-pukllay_club` and by `01-UI-SPEC.md` — this document does
**not** re-litigate it. It (1) extends that locked system with the small set of net-new admin
patterns this phase needs (status badges, an undo toast, task-dashboard cards, a tap-to-assign
list), and (2) states exactly how the two public-surface changes plug into the existing components.

## Spacing Scale

Declared values (must be multiples of 4) — unchanged from the app-wide scale, reused verbatim:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Chip/pill row gaps (`gap-1`) — status badges, shelf-order chips |
| sm | 8px | Icon+text gaps (`gap-2`); in-card vertical rhythm (`space-y-2`) |
| md | 16px | Card body padding (`p-4`); grid/table cell gaps; default admin form field spacing |
| lg | 24px | Section padding; between-section rhythm (`space-y-6`) — dashboard card grid to page heading, form to form |
| xl | 32px | Layout gaps between major dashboard zones (e.g. task-card grid to a below-the-fold list) |
| 2xl | 48px | Major section breaks (rare in a dense admin UI — reserve for genuine top-level separators) |
| 3xl | 64px | Page-level spacing (top of an admin page before its header, matching public-page rhythm) |

Exceptions:
- Touch targets: `min-h-11` (44px) on any tappable control under that size — not a multiple-of-4
  spacing value, it's the project's documented touch-target floor (`ui-design-system` /
  `ux-responsive`), applies to every tap-to-assign game row and every admin table row action.
- Tappable pills (shelf chips, section-membership chips) use the pill hit-layer exception
  (`pk-pill-interactive`'s `::after`, invisible 44px hit area over a visually compact 28–32px
  pill) — never add `min-h-11` directly to a pill, per the existing rule.

## Typography

Admin surfaces cap at **3** sizes (below the app's own 3–4 cap) — a dense CRUD/dashboard UI needs
less type variety than the marketing/catalog surfaces, not more.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`text-base`, `font-sans`) | 400 | 1.5 |
| Label | 14px (`text-sm`, `font-sans`) | 600 for table headers/form labels/status badges; 400 for muted/help text (`text-neutral text-sm`) | 1.4 |
| Heading | 24px (`text-2xl`, `font-display`) | 400 (Bebas Neue has no meaningful weight axis, matches the public site's own heading tier) | 1.2 |
| Display | not used | — | — | Admin has no marketing-scale display type; reserve `font-display`'s larger sizes (hero/wordmark scale) for the public site only. |

Weight (600 vs 400 within the Label tier) is this phase's one emphasis lever, per the existing
app-wide rule — never introduce a 4th size to distinguish a table header from a form label.

## Color

Reuses the locked daisyUI theme tokens in `assets/css/app.css` — no new colors, no hex literals
in markup (banned per `ui-design-system`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `base-100` (theme token — `#FFFFFF` light / `#2E154E` dark) | Admin page background, form backgrounds |
| Secondary (30%) | `base-200` / `base-300` | Dashboard task cards, table zebra stripe, section/shelf list rows, the read-only BGG-facts block on the edit-game screen |
| Accent (10%) | `primary` | **Exactly one filled `variant="primary"` button per admin screen** — Agregar juego, Publicar, Guardar cambios, Invitar, Confirmar asignación. Never two filled primaries competing on one screen (matches the existing `button/1` convention: "the page's one action"). |
| Destructive | `error` | Retirar juego confirmation, Quitar staff confirmation, and the BGG-fetch-failure error banner (D-03) only. Never used decoratively (e.g. NOT the retired-game badge — see below). |

Accent reserved for: the single primary CTA button on each admin screen, listed above — nothing
else (not table row highlights, not badges, not the tap-to-assign button's resting state).

Additional semantic uses (not new colors, existing tokens applied to new elements):
- `warning`: draft-game badge, band-audit mismatch row indicator (a "needs review" state, not a
  destructive one)
- `success`: published-game badge, the walk-the-shelf "N/400 ubicados" progress affordance once
  it reaches 400/400
- `neutral`: retired-game badge (retiring is reversible and routine, not an error state — reserve
  `error` for destructive confirmations and real failures only)

## Visual Hierarchy

- **Admin dashboard (D-35):** cards in a single column on mobile (`grid-cols-1`, `sm:grid-cols-2`),
  fixed order Juegos → Estantes → Secciones → Revisar niveles → Staff. The focal cue is **pending
  work**, not position: a card with work to do (borradores > 0, discrepancias > 0, ubicados < 400)
  shows a `badge-warning` count; cards with nothing pending show no badge. The page itself has no
  filled primary button — each card is a full-card link (`min-h-11` hit area).
- **Home page (D-18/D-23/D-28):** the hand-picked featured section is **pinned first** and is the
  only one with the `CarouselRow variant=:hero` treatment. Section reordering in `/admin` only
  sorts the sections *below* it; the featured section has no ↑/↓ controls (it can still be
  renamed, and is hidden when it has no visible games per D-24).

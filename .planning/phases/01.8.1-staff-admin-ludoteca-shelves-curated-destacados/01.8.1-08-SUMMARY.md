# Phase 01.8.1 Plan 08: Add-by-BGG Hardening — Failure/Retry, Duplicates, URLs, Expansions, Production Secrets Summary

**`EnrichGameWorker` now cancels-and-fails-fast on non-transient BGG errors while exhausting transient ones through Oban's own retry budget first, `Catalog.parse_bgg_input/1` accepts a bare id or a `boardgamegeek.com` URL for a game or expansion, duplicate BGG ids are rejected up front with a link to the existing game, and the six BGG/R2/Gemini credentials now flow from GitHub secrets through `config/deploy.yml`'s `env.secret` — locked in by a new contract test.**

## Performance

- **Duration:** ~50 min
- **Tasks:** 2 (1 tracer, 1 auto/tdd)
- **Files modified:** 14 (13 modified, 1 created)

## Accomplishments

- `"failed"` added to `Game`'s enrichment statuses; `EnrichGameWorker.backoff/1` grows linearly (`attempt * 30s`) so `max_attempts` (3) exhausts within ~90 seconds instead of Oban's default exponential hours-scale curve.
- `perform/1` splits failures into non-transient (BGG has no matching item, or credentials are missing — `{:cancel, reason}`, marks failed immediately since retrying cannot help) and transient (any other error — only marks failed once `job.attempt >= job.max_attempts`, otherwise returns `{:error, reason}` and lets Oban's own retry schedule run). Both paths broadcast `{:game_enriched, id}` on `"admin:games"` so a failed row updates live.
- `Catalog.retry_enrichment/1`: only for `enrichment_status == "failed"`; sets it back to `"pending"` and inserts a fresh `EnrichGameWorker` job in one `Ecto.Multi`. Returns `{:error, :not_failed}` for anything else.
- Both `Admin.GameLive.Index`'s list row and `Admin.GameLive.Form`'s editor render a daisyUI `alert alert-error` with `Error al traer datos de BGG.` and a `Reintentar` button (`phx-value-game-id`, never the reserved `value` key) wired to a `handle_event("retry-enrichment", ...)` that parses the id, loads the game, and calls `retry_enrichment/1`.
- `Catalog.parse_bgg_input/1`: trims, tries a digits-only bare id first, then a `boardgamegeek.com`/`www.boardgamegeek.com` URL whose path starts `/boardgame/<digits>` or `/boardgameexpansion/<digits>` (`URI.parse/1` for the host check — an off-host URL like `https://evil.example/...` is rejected, T-01.8.1-37); the extracted integer must fall in `1..2_147_483_647` (the `games.bgg_id` column's real range).
- `add_game_from_bgg/1` now uses `parse_bgg_input/1` and checks `Repo.get_by(Game, bgg_id: ...)` before inserting — a bgg_id already on ANY game (draft, published, or retired) returns `{:error, {:duplicate, existing}}` and nothing is inserted. The admin add form renders `Este juego ya está en la ludoteca.` with a `Ver juego` link to the existing editor.
- `BggClient` now requests `type: "boardgame,boardgameexpansion"` (was `"boardgame"` only) and extracts each item's own `type` attribute (`~x"./@type"s`). `Enrichment.enrich/2` sets a still-placeholder draft's `is_expansion` from that type on first enrichment only — after that it is staff-owned (D-07), matching `maybe_put_name/3`'s existing placeholder-guard pattern.
- `Credentials.env_var_names/0` is a new introspectable list (every required + optional env var name) that `test/pukllay_club/deploy_secrets_contract_test.exs` derives its expected secret list from, rather than hardcoding a second copy. `config/deploy.yml`'s `env.secret` and `.github/workflows/deploy.yml`'s `.kamal/secrets` heredoc + `Deploy with Kamal` env block now carry `BGG_API_TOKEN`, `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_CATALOG_BUCKET`, and `GEMINI_API_KEY` (mirroring plan 03's `MAILER_API_KEY` pattern) — `R2_PUBLIC_BASE_URL` stays under `env.clear` since it's already public.

## Decisions Made

- `EnrichGameWorker.backoff/1` linear at `attempt * 30s` (not Oban's exponential default) so a broken record's `max_attempts` (3) exhausts within ~90 seconds — staff see `Reintentar` promptly, not after a multi-hour exponential curve.
- `add_game_from_bgg/1`'s duplicate check is a single `Repo.get_by/2` (not a separate `Repo.exists?` + fetch) — same D-03 behavior, one query, and the struct is already what the UI link needs.
- `Credentials.env_var_names/0` added as a new public function purely to give the deploy-secrets contract test a single source of truth to introspect, rather than hardcoding a parallel list that could silently drift.

**`R2_ENDPOINT` vs `R2_ACCOUNT_ID` — no mismatch, two independent secrets confirmed by code reading:**
- `R2_ENDPOINT` (already an existing GitHub secret) is used ONLY by `.github/workflows/backup.yml`'s nightly `pg_dump` job, passed as a literal `--endpoint-url` argument to an S3-compatible CLI. It is a fully-formed URL (e.g. `https://<account-id>.r2.cloudflarestorage.com`).
- `R2_ACCOUNT_ID` (new, this plan) is what `PukllayClub.Catalog.Seed.R2Storage` uses to derive the SAME endpoint shape at runtime: `"#{credentials.r2_account_id}.r2.cloudflarestorage.com"` (`lib/pukllay_club/catalog/seed/r2_storage.ex:89`).
- These are two independently-configured secrets serving two independent code paths (the nightly backup script vs. the application's own image-upload pipeline) — not a duplicate or a drift risk in the code. The only operational care needed when the user sets `R2_ACCOUNT_ID`: it must be the account id embedded in the SAME `R2_ENDPOINT` URL already in use, so both paths write to the same Cloudflare account. Nothing in this plan's code changes touches or depends on `backup.yml`/`R2_ENDPOINT`.

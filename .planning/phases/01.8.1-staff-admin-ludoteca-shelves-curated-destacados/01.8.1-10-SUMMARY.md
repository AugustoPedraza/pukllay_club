# Phase 01.8.1 Plan 10: DB-Driven Home Sections Summary

**Replaced the eight hardcoded carousel rows with staff-owned `sections`/`section_games` tables, migrated the three editorial hashtags into sections keeping their members, and gave the home page a hand-picked featured hero row.**

## Performance

- **Duration:** ~150 min
- **Tasks:** 3 (checkpoint decision + tracer + TDD-tagged proof/cleanup)
- **Files modified:** 11 (5 created, 6 modified) across `lib`, `priv/repo/migrations`, and `test`

## Accomplishments

- `sections` (name/subtitle/position/featured/hidden/kind/rule_value/sort) and `section_games`
  (section/game/position) tables, with check constraints for `kind`/`sort`/the weight_band rule
  invariant and a partial unique index enforcing at most one featured section.
- A deploy-time backfill (`backfill_statements/0`, public and replayable) migrates
  `#CreaConexiones`/`#EquipoGanador`/`#DuelosMemorables` from `games.tags` into three manual
  sections, sorted by name exactly as the retired hardcoded rows were, and creates an empty
  featured section — `games.tags` itself is never touched.
- `Catalog.list_home_sections/0` and `section_page/3` replace `list_carousel_rows/0`,
  `carousel_page/3`, `carousel_row_specs/0`, and the tag/weight_band/recent query helpers. A
  section's `kind` dispatches which predicate runs (manual join, weight_band column match, or
  non-expansion recent), and `sort` dispatches the `order_by` — every variant ends with a `g.id`
  tiebreaker so page 1 and page N never diverge.
- `CatalogLive.Index` renders these sections: the featured row (once it has a published member)
  leads as a `CarouselRow variant=:hero`, capped at 20 games; every other section renders as a
  `variant=:standard` rail with the pre-existing in-row infinite scroll. Stream names derive from
  the server-loaded section id (`carousel_section_<id>`), never from client input.
- Empty sections, and sections whose only members are draft/retired, never render (D-24) — proven
  by dedicated tests.
- Task 1's checkpoint (D-22, resolved by the user before dispatch): **option A** — `games.tags`
  stays as frozen history; public hashtag chips switch to section names in plan 11.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `List.first/1` on a LazyHTML query result raised `FunctionClauseError`**
- **Found during:** Task 2, the new featured-hero test
- **Issue:** `LazyHTML.query/2` returns a `%LazyHTML{}` struct, not a plain list; `List.first/1`
  only pattern-matches on `[]`/`[h|_]`.
- **Fix:** Used `Enum.at(result, 0)` instead (LazyHTML implements `Enumerable`).
- **Files modified:** test/pukllay_club_web/live/catalog_live_test.exs
- **Verification:** Test passes.
- **Committed in:** `eff8892`

**2. [Rule 3 - Blocking] A test assertion on "Ingenio estratega" collided with the filter modal's own always-rendered facet checklist**
- **Found during:** Task 2, the "after applying a filter" test
- **Issue:** The filter modal's weight_band checklist renders the same label text
  ("Ingenio estratega") regardless of filter state, so asserting its absence after filtering was
  never a valid signal.
- **Fix:** Rewrote the assertion to check for `id="carousel-rows"` presence/absence instead — the
  actual behavior under test.
- **Files modified:** test/pukllay_club_web/live/catalog_live_test.exs
- **Committed in:** `eff8892`

**3. [Rule 3 - Blocking] `apply/3` on a runtime-loaded migration module tripped Credo's Refactor.Apply check**
- **Found during:** Task 3, `mix quality` review before committing
- **Issue:** `Code.require_file/1`-loaded modules aren't known at compile time, so a literal
  `Migration.backfill_statements()` call warns "function is undefined" under
  `--warnings-as-errors`; using `apply/3` to dodge that instead tripped Credo's
  `Refactor.Apply` check (enabled, non-zero exit_status in this repo's `.credo.exs`).
  Assigning the module via a plain variable still gets constant-folded by the compiler and
  re-triggers the same warning.
- **Fix:** `Module.concat(PukllayClub.Repo.Migrations, CreateSections)` builds the atom
  dynamically, satisfying both the compiler (no static resolution) and Credo (not an `apply` call).
- **Files modified:** test/pukllay_club/catalog/sections_backfill_test.exs
- **Verification:** `mix compile --warnings-as-errors` and `mix credo --strict` both clean.
- **Committed in:** `2612bff`

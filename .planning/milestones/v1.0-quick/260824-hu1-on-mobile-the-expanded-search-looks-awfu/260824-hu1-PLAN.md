<diagnosis>
Already performed — do not re-derive it, but do confirm the line numbers still match before editing (the file has been edited recently).

The header markup is `header.pk-nav > div.pk-nav-inner.mx-auto.w-full.max-w-7xl.pk-gutter`, built by `header_inner/1` in `lib/pukllay_club_web/components/layouts.ex` (~line 404). `.pk-nav-inner` carries `position: relative` (app.css ~line 893), so it is the containing block for the absolutely-positioned open morph.

Inside the trailing `@media (max-width: 480px)` block (app.css ~lines 2150-2168), `.pk-search-morph.is-open` switches to `position: absolute` with a zero inset. For an absolutely-positioned element the inset is resolved against the containing block's **padding edge**, not its content edge — so a zero inset puts the box's left and right edges on `.pk-nav-inner`'s outer edge, which at ≤480px is the viewport edge. The `.pk-gutter` padding is stepped straight over. That is the reported bug: the open box is the only element on the page that reaches the viewport edge.

The rule tries to compensate with its own horizontal padding equal to the gutter, but that only insets the box's *contents*. The box's own background, border, shadow and bottom-rounded corners still run edge-to-edge — which is exactly what reads as "full width, ignoring the margin, breaking rhythm."

Everything above 480px is unaffected: the desktop path never leaves static flow (`flex: 0 0 auto` + `margin-left: auto` + a 17.5rem open width), so this fix is entirely contained in the narrow-viewport block.
</diagnosis>

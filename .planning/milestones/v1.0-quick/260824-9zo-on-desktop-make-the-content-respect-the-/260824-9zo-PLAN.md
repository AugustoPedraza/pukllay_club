<objective>
On desktop, make the catalogue's carousel shelves sit in the same capped column as the site
shell, so the row titles, the poster cards and the scroll controls line up with the header, the
footer and the main grid instead of bleeding to the viewport edge.

Purpose: the header/footer/grid are capped at `max-w-7xl`; the shelves are not. At 1920px that is
a ~320px misalignment on each side (screenshot: header wordmark at x≈352, "RECIENTEMENTE AÑADIDOS"
at x≈32), which reads as a broken page rather than a deliberate full-bleed treatment.

This is not an override of a validated design decision — it is shipping one that was already
validated and never ported. `sketch-findings-pukllay_club/references/layout-navigation.md` records
it explicitly: *"Content-width alignment: cap every row's own box to the same 1280px the
header/footer use. Found via 011: shelves originally had padding only, no `max-width` — full-bleed
on any viewport. Once the header/footer got capped at 1280px, shelves that stayed uncapped visibly
overflowed past both on a wide monitor. `.row-header`/`.rail-wrap` now carry
`max-width: 1280px; margin: 0 auto;` alongside their existing padding."* Sketch 011's source
(`sources/011-full-shell-composition/index.html:236,250`) carries exactly those rules. Production
kept the pre-011 shape. The `ui-design-system` skill still documents the pre-011 shape as
deliberate, which is why the same misalignment survived three subsequent UI passes.

Output: four `class` attributes in `CarouselRow`, four updated test assertions, and one corrected
paragraph in the design-system skill so the next UI agent does not revert it.
</objective>

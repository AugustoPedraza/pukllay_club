<objective>
Give the mobile drawer's bottom block a real content/footer distinction: social links lead as
full-width, high-contrast CONTENT (Task 1, already shipped), and the theme control trails as a
small, centered, label-free FOOTER anchored to the drawer's true bottom edge (Task 2) — applying
sketch 021's own validated Round-6 conclusion (E1 — Icon-Only, Centered) and mirroring the
treatment already shipped and human-confirmed on the desktop footer.

**Revision history, stated explicitly because this plan changed direction twice.** The first pass
imported sketch 021's centering/sr-only decision without it being asked. It was reverted on the
grounds that the request never asked to touch the theme control's own design, and that a comment
in this codebase documented the drawer's visible label as a *deliberate* difference from the
footer's sr-only one. That revert shipped as Task 1. The developer then reported the result still
felt unbalanced and asked what industry does here — which surfaced that the "deliberate
difference" comment's premise had already been reversed once, for the exact same reason, on the
desktop footer: a debug session (`footer-theme-toggle-balance`, human-confirmed 2026-08-24)
researched Vercel Geist's canonical theme-switcher guidance and converted the footer's label to
sr-only because "the footer IS the canonical home for this control" — falsifying the original
"users aren't used to looking here" premise. Sketch 021 reached the *same* conclusion for the
drawer independently, over 6 rounds of this same developer's own feedback, converging on "Tema"
as a small centered icon-only strip with no visible label. Task 2 below applies that already-twice
-validated conclusion to the drawer. This is not new scope creep — it is the answer the project's
own prior research already gave to the question the developer is now asking directly.

Purpose: `.pk-drawer-bottom` should read as two different KINDS of things — social links are
places you tap to leave the app (content, first, full-strength, full-width), Tema is a config
control that changes how the current page looks (a footer-like utility, last, quiet, centered, no
visible label). Task 1 fixed the content half. Task 2 fixes the footer half.
</objective>

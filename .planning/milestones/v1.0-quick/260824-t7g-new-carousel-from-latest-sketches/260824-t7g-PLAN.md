    Implement sketch 023's winner B for the arrow-driven curve. `carousel-mechanics.md` flags this
    as a nice-to-have rather than a correctness requirement — it is in scope here because it is
    what makes an arrow click feel like the same material as the free-momentum touch scroll that
    already ships, and because it is a handful of lines in a hook this plan is already rewriting.

    (a) CSS prerequisite — flip `.pk-rail`'s `scroll-behavior` from `smooth` to `auto`.

    This is load-bearing, not tidying: while the browser's own smooth-scroll mode is in force,
    EVERY `scrollLeft` assignment the per-frame loop makes kicks off its own browser-driven
    animation toward that value, so the two curves fight and the rail visibly stutters instead of
    easing. Sketch 026's rail is set to `auto` for exactly this reason. Write that reason into a
    comment on the declaration so a later reader does not "restore" it — phrase the comment as
    prose about the browser's smooth-scroll mode, and do NOT paste the old declaration text into
    it, since the verify gate below greps this file for that declaration. Nothing else scrolls
    `.pk-rail` programmatically (`about_live.ex` uses its own `.pk-about-rail`; the chip-nav anchor
    jump targets `.pk-shelf`, not the rail), so no other behavior regresses. Leave
    `overscroll-behavior-x: contain` and `touch-action: manipulation` exactly as they are — both
    are documented, deliberate choices.

    (b) Hook — rewrite `.CarouselScroll`'s `onClick` body in `carousel_row.ex`.

    Keep the existing delegated-click guard verbatim (`e.target.closest("[data-scroll]")` plus the
    `this.el.contains(button)` check) — it is what lets one listener on the section serve both
    chevrons, and it must keep working now that the buttons live in a different subtree.

    Replace the `this.rail.scrollBy({..., behavior: "smooth"})` call with a per-frame scroller:
    compute `delta = direction * this.rail.clientWidth * 0.85` and `start = this.rail.scrollLeft`;
    cancel any stored frame id first (`cancelAnimationFrame(this.frame)`); if
    `window.matchMedia("(prefers-reduced-motion: reduce)").matches`, assign
    `this.rail.scrollLeft = start + delta` and return; otherwise run a
    `requestAnimationFrame` loop over a 200ms window applying
    `t => 1 - Math.pow(1 - t, 5)` — the JS twin of this stylesheet's `--ease-out-soft`
    (`cubic-bezier(0.16, 1, 0.3, 1)`), which is the motion-system curve sketch 006-D validated —
    storing each returned id in `this.frame` so the next click can cancel it.

    Query the media list at click time rather than caching it at mount: a visitor can change the OS
    setting mid-session, and a fresh `matchMedia` read costs nothing on a click handler.

    Add `cancelAnimationFrame(this.frame)` to `destroyed()`, beside the existing listener removal
    and `resizeObserver?.disconnect()`.

    Do not add `scroll-snap-type` anywhere, and do not add a position or pagination indicator —
    `carousel-mechanics.md` lists both under What to Avoid; free momentum and edge-fade-only are

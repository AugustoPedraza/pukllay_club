## Deviations from the literal task description — implement as written here, and RE-STATE all four in the SUMMARY

These are mechanism corrections that preserve the stated outcome. They are not scope reductions.

1. **`preferred_cli_env` goes in `cli/0`, not `project/0`.** The description says "add a
   `preferred_cli_env` entry" to `project/0`. This project already defines `def cli/0` with
   `preferred_envs: [precommit: :test, quality: :test]` (mix.exs lines 29-33). On Elixir 1.19.5
   (confirmed: `elixir --version` -> 1.19.5 / OTP 28), `project/0`'s `:preferred_cli_env` is
   deprecated and superseded by `cli/0`. Adding it to `project/0` would be a silent no-op and
   `mix coveralls` would run under MIX_ENV=dev. Add the coveralls entries to the EXISTING
   `preferred_envs` list in `cli/0` instead. Same outcome (coveralls runs in :test), correct
   mechanism.

2. **dialyxir is `only: [:dev, :test]`, not `only: [:dev]`.** The description's item 1 says
   `only: [:dev]`, but its item 6 requires `quality.full` = quality steps + dialyzer. `quality`
   ends in `test --warnings-as-errors` so `quality.full` must run under MIX_ENV=test, and a
   :dev-only dep's Mix task does not exist there. `only: [:dev]` would make item 6 non-functional.
   `[:dev, :test]` satisfies both and matches the existing convention for every other tooling dep
   in this file (credo, sobelow, styler, mix_audit are all `only: [:dev, :test], runtime: false`).
   **Also note for the user in the SUMMARY:** because `quality.full` runs dialyzer under
   MIX_ENV=test against the single fixed `priv/plts/dialyzer.plt` path, their manual PLT build
   should be `MIX_ENV=test mix dialyzer --plt` to target that same PLT; alternating with a plain
   dev-env `mix dialyzer` makes the two envs repeatedly update the same PLT file. Offer
   `plt_file: {:no_warn, "priv/plts/dialyzer-#{Mix.env()}.plt"}` as a one-line follow-up they can
   accept or reject — do NOT apply it in this task.

3. **`.gitignore` also covers `*.plt.hash`.** dialyxir writes a hash sidecar next to the PLT;
   ignoring only `*.plt` would leave that artifact tracked.

4. **`"quality.full": :test` is added to `preferred_envs` too.** Without it, `mix quality.full`
   runs under MIX_ENV=dev and its nested `test --warnings-as-errors` step executes the suite in the
   dev environment (wrong DB, wrong sandbox config).

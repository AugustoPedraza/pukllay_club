# Plan 01-02 — Brand identity: theme tokens, self-hosted type, header lockup

**Phase goal (verbatim from ROADMAP.md):** Members can browse, filter, sort, and search a public
catalog of ~400 games, with UX that teaches complexity instead of assuming hobbyist vocabulary.

<objective>
Replace the stock phx.new visual identity with the approved brand contract from 01-UI-SPEC.md, so
that the tracer slice (01-03) and every later catalog surface renders on-brand from its very first
commit rather than being restyled at the end of the phase.

Purpose: 01-UI-SPEC.md is an approved design contract — it supersedes D-11, whose planned Google
Stitch export was never produced, and installs the brand identity PDF as the visual source of truth
instead. Its Color section explicitly states the
existing `light`/`dark` `@plugin "daisyui-theme"` blocks in `assets/css/app.css` "must be overridden
to the values in this document, not treated as authoritative". The brand manual's own example of a
*wrong* logo treatment is rendering it in orange — which is exactly the hue the stock theme uses
today. Doing this first means no catalog component is ever authored against throwaway colors.

Output: brand-correct daisyUI theme variables for both themes, self-hosted Bebas Neue + Inter, and a
real site header carrying the wordmark lockup.
</objective>

  </read_first>
  <action>
  Resolve the woff2 URLs for Bebas Neue (single weight 400) and Inter (weights 400 and 600) by
  requesting the Google Fonts CSS API with a modern-browser User-Agent so it returns woff2 rather
  than ttf: `curl -sH 'User-Agent: Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like
  Gecko) Chrome/120 Safari/537.36' 'https://fonts.googleapis.com/css2?family=Bebas+Neue&family=Inter:wght@400;600&display=swap'`.
  Download the `latin` and `latin-ext` subset files only (Spanish needs `latin-ext` for full
  coverage; other subsets are dead weight) into `priv/static/fonts/`, named
  `bebas-neue-400-latin.woff2`, `bebas-neue-400-latin-ext.woff2`, `inter-400-latin.woff2`,
  `inter-400-latin-ext.woff2`, `inter-600-latin.woff2`, `inter-600-latin-ext.woff2`. Both families
  are OFL-licensed, so self-hosting is permitted; add a short comment in `app.css` recording that.

  In `assets/css/app.css`, immediately after the `@import`/`@source` block, add one `@font-face`
  rule per downloaded file with `font-display: swap`, the matching `unicode-range` copied from the
  Google CSS response, `src: url("/fonts/<file>") format("woff2")`, and the correct
  `font-weight`/`font-style`. Use absolute `/fonts/...` paths — `static_paths/0` already serves
  `fonts`, so no endpoint change is needed.

  Add a Tailwind v4 `@theme` block setting `--font-sans` to `"Inter", ui-sans-serif, system-ui,
  sans-serif` and `--font-display` to `"Bebas Neue", ui-sans-serif, sans-serif`. Do not set
  `font-family` directly on `body` — later components use the `font-sans` / `font-display`
  utilities so the mapping stays in one place.

  Do not add a `<link>` to `fonts.googleapis.com` anywhere; the whole point of self-hosting is that
  no third-party font request happens at runtime.
  </action>
  <verify>
    <automated>mix assets.build &amp;&amp; ls priv/static/fonts/*.woff2 | wc -l | grep -qx 6 &amp;&amp; grep -qF -- "--font-display" assets/css/app.css &amp;&amp; echo FONTS-OK</automated>
  </verify>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → third-party font CDN | Eliminated by this plan: fonts move to the app's own origin, so no visitor request leaves to a Google-controlled host. |
| build machine → Google Fonts API | A one-time, build-time download of static font binaries. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-05 | Information Disclosure | Runtime font requests to `fonts.gstatic.com` | low | mitigate | Task 1 self-hosts every woff2 under `priv/static/fonts/` and its acceptance criteria grep for the absence of any remaining `fonts.googleapis.com`/`fonts.gstatic.com` reference in `assets/` and `lib/`. Visitor IP and Referer never reach a third party, which also removes an EU-privacy exposure for a Spanish-language member-facing site. |
| T-01-06 | Tampering | Font binaries downloaded at build time | low | accept | Files are fetched once over TLS from Google's CDN and committed to the repo, so the exact bytes are reviewable in the diff and pinned thereafter — later builds do not re-fetch. Accepted: no Subresource-Integrity equivalent exists for a one-time committed binary, and the assets are same-origin thereafter. |
| T-01-07 | Spoofing | Brand logo misuse / off-brand recoloring | low | mitigate | `brand_logo/1` renders only the supplied asset or the typographic wordmark; Task 3 explicitly forbids tracing or approximating the mark, and no recolor utility is applied to it. |
</threat_model>

# Plan 01-06 — Complexity-teaching UX: bands, chips, detail page, and CSP

**Phase goal (verbatim from ROADMAP.md):** Members can browse, filter, sort, and search a public
catalog of ~400 games, with UX that teaches complexity instead of assuming hobbyist vocabulary.

> **Expansion of the 01-03 tracer.** The tracer's card showed a cover and a title. This plan makes
> that same card teach — plain-Spanish complexity bands, curated chips, club editorial signals — and
> adds the detail page a member reaches from it. It also closes an inherited obligation: Phase 0
> deferred its Sobelow Config.CSP finding to "Phase 1, once there is real page content to scope a
> policy against". That content now exists.

<objective>
Deliver the part of Phase 1 that is the product's actual differentiator: a catalog that teaches
board-game complexity to a casual or new player instead of assuming hobbyist vocabulary.

Purpose: CATALOG-05, CATALOG-06, and CATALOG-07 are what separate this catalog from BoardGameGeek.
REQUIREMENTS.md's Out of Scope table is explicit that icon-only complexity indicators and raw
BGG-depth taxonomy are both rejected precisely because they increase cognitive load for
non-hobbyists. Every number and every English term that would have been shown raw is either
translated through the reviewed vocabulary or not shown at all.

Output: weight-band badges with their descriptors, plain-Spanish chip rows with overflow handling,
uniform editorial hashtag chips, a game detail page with the gallery, an explicit resolved list of
per-field omission behavior, a reconciled glossary, and a real Content-Security-Policy.
</objective>

## Resolved: UI-SPEC "partial" state, previously marked ⚠ unresolved

01-UI-SPEC.md's UI Considerations table left one row unresolved — "Game card with missing optional
enriched field … the exact per-field fallback list needs planner confirmation once real seed output
is available". The 01-04 seed run has now produced that output, so this plan resolves it explicitly
rather than leaving it to the executor's judgment. The behavior is uniformly **omit the element**,
never render a blank, a zero, or an empty label:

| Field | When absent | Rendered behavior |
|---|---|---|
| `weight_band` | 26 games (no clean hashtag and no usable `Peso_BGG`) | No band badge and no descriptor line. The card keeps its other content; nothing shifts into the gap. |
| `min_age` | games with no BGG enrichment | No age chip. |
| `min_players` / `max_players` | either absent | No player-count line at all — a half-range is more confusing than none. |
| `playing_time` and both playtime bounds | all absent | No playtime line. |
| `mechanics` | empty after glossary filtering | No mechanic chip row. |
| `themes` | empty after glossary filtering | No theme chip row. |
| `tags` (editorial hashtags) | empty | No editorial chip row. |
| `thumbnail_url` / `cover_url` | absent | Brand placeholder illustration from the UI-SPEC Copywriting Contract; `alt` retains the game title. |
| `gallery_urls` | empty | Detail page shows the cover alone; no gallery strip, no padded slots. |
| `designers` / `publishers` | empty | That metadata row is omitted on the detail page. |
| `description` | absent | No description section. |

This applies to the 41 games with no `BGG_ID` (D-18) and to any individually-missing field on an
otherwise-enriched game.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous browser → detail LiveView | Public route with a client-supplied game id and a client-supplied image-selection parameter. |
| stored image URLs → browser `img src` | Values written by the seed pipeline are rendered into markup. |
| browser rendering context → third-party origins | Governed by the Content-Security-Policy introduced here. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-26 | Tampering | `select-image` echoing a client-supplied url into an `img src` | medium | mitigate | `handle_event("select-image", ...)` asserts membership in the loaded game's own `[cover_url \| gallery_urls]` list before assigning; a non-member url leaves the assign unchanged. Without this, a crafted event turns the detail page into an arbitrary-image renderer and a referrer-leak vector. |
| T-01-27 | Tampering | Cross-site scripting through the BGG-sourced `description` field | medium | mitigate | The description is rendered as escaped text through HEEx interpolation — it is never passed through `raw/1` or `Phoenix.HTML.raw/1`.

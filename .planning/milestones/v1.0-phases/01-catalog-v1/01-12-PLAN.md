<objective>
Implement sketch 001 (shelf-structure, variant D)'s navigation half: a real sticky top nav whose
horizontal padding is the same declaration the row content uses, going flat-translucent on scroll
with no blur, carrying the catalogue's shelf anchor links and its search box — and, below roughly
480px where those anchor links do not fit, a horizontally scrollable row of category chips that
becomes the mobile navigation dimension.

Purpose: the shipped header is a non-sticky brand bar with a theme toggle and nothing else, and
the search box sits inside the page body where its right edge does not line up with anything. The
sketch found that the misalignment was caused by the nav and the row content each choosing their
own spacing token — plan 01-11 already reduced that to a single `--pk-gutter` token consumed by a
single rule, so this plan simply opts the header into that same rule. Below 480px the four anchor
links stop fitting, which is why mobile gets chips instead: it is a second navigation dimension,
not a smaller copy of the first.

Output: a `sticky` mode plus `nav_links`, `nav_search` and `subnav` slots on `Layouts.app`, the
`.CatalogNav` colocated hook (scroll tint plus chip scroll-spy), the chip row, and a recorded
`pk-*` layer in the project's design-system skill so later UI work extends it rather than
reinventing it.

## Decisions locked by this plan

- **The header links and the chip row flip at the same breakpoint, declared once.** Plan 01-11
  created exactly one `@media (max-width: 480px)` block for the whole density set. This plan
  extends that same block rather than adding a second one, and puts the links' and chips'
  visibility switch inside it. Using Tailwind's `sm:` (640px) for the links while the chips flip
  at 480px would leave a 160px-wide band of viewports with neither navigation dimension — the
  exact class of "two independently-chosen values" failure the sketch findings exist to prevent.
- **The chip row's end margins are spacer flex items, not container padding.** iOS Safari drops
  the trailing padding of a horizontally scrolling element once it is scrolled to its end, so the
  left margin survives and the right one silently vanishes. Real flex-item spacers at both ends
  cannot be clipped.
- **The nav-on-scroll treatment is a flat translucent tint with a hairline border and a small
  shadow, and explicitly not a blurred backdrop.** Variant C's blur was rejected in favour of
  variant B's clarity during sketching.
- **The search form keeps its existing `#catalog-search-form` id and its `phx-change`/
  `phx-debounce` bindings** — only its position in the DOM moves, so every existing search,
  filter-combination and pagination-reset test keeps driving it unchanged.
- **Out of scope here:** the logged pending todo about the sort dropdown overlapping the Filtros
  button. It is a toolbar-stacking bug unrelated to any sketch decision and is tracked separately
  in STATE.md; do not opportunistically restyle the sort control in this plan.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser scroll position -> `.CatalogNav` hook | scroll and intersection callbacks fire at high frequency on untrusted client timing |
| in-page anchor targets -> document ids | chip and nav link targets are server-generated but resolved client-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-42 | Denial of service | `.CatalogNav` scroll listener and IntersectionObserver | medium | mitigate | The scroll listener is registered `{passive: true}` and does nothing but toggle one class; the observer is created only when at least one chip and one resolvable section exist, and both are torn down in `destroyed()` so repeated live navigation cannot accumulate handlers. |
| T-01-43 | Tampering | chip and nav anchor targets | low | mitigate | Every `href` and target attribute is server-generated from the catalogue context's own row keys; no client-supplied value reaches them, and both are rendered through escaping HEEx interpolation. |
| T-01-44 | Tampering | Content-Security-Policy compliance of `.CatalogNav` | medium | mitigate | The hook is a colocated hook extracted to a bundled asset at compile time, so the page carries no inline script body under `script-src 'self'`; the landing-render test that refutes an inline hook body covers it. |
| T-01-45 | Spoofing | sticky header overlaying page content | low | accept | Same-origin chrome only; `frame-ancestors 'none'` already blocks the framing case, and shelf sections carry a scroll offset so anchored content is never hidden beneath the header. |
| T-01-46 | Repudiation | none applicable | low | accept | This plan adds no state-changing or audited action; the only new interaction is in-page navigation. |

No package-manager installs occur in this plan, so no package-legitimacy gate applies.

<objective>
Close three UAT gaps that all live in the same visual surface — the browse card's
chip stack and the app's plain form controls.

- G-01-2 (major): daisyUI `.badge` pins `height: var(--size)` with no
  `white-space`/`overflow` guard, so the 3-word label `Descubre el hobby`
  wraps at 2-column mobile widths and bleeds upward across the `card-body`
  gap into the game title.
- G-01-6 (major): the card stacks three chip/badge rows at near-identical
  visual weight (two of them at the exact same badge size, separated only by
  hue), and the editorial-tag row has no cap at all — unlike its sibling
  `chip_row/1`.
- G-01-7 (minor): daisyUI's `.input`/`.select` render two concentric focus
  indicators by design (a full-opacity border bump *and* a 2px offset outline
  in the same color), which reads as a double black border on every plain form
  control in the app.

Purpose: the browse card is the product's primary complexity-teaching surface
(CATALOG-05/06/07). A card whose badge collides with its own title, and whose
three information rows compete at equal weight, actively works against
CLAUDE.md's "teach complexity, don't overwhelm" principle for a casual player.

Output: an overflow-safe, three-tier card chip stack; a capped editorial row
with a documented density rule; and a single clean focus ring app-wide.
</objective>

<design_system_contract>
Load and obey these before writing any markup. They are the project's own
codified rules and they are the reason these three gaps are defects rather
than opinions:

- `Skill(skill="ui-design-system")` — the banned-patterns list (no arbitrary
  Tailwind values, no raw hex, no inline style), the semantic-modifier rule
  ("use `badge-accent`, not a raw background/foreground colour pair"), the
  emphasis rule ("weight and color, not a new size, are the emphasis lever —
  reserve a size bump for a genuinely larger content unit, since a large
  enough size gap still outranks weight alone"), the 3-level type cap, and
  the `space-y-2`-inside-a-card-body / `gap-1`-for-chip-rows spacing scale.
- `Skill(skill="ux-responsive")` — `sm` is 640px; the catalog grid is
  `grid-cols-2` below it, which is exactly the width band where G-01-2
  reproduces.

Load-bearing cascade fact (already verified against
`priv/static/assets/css/app.css`, do not re-derive): daisyUI v5 emits its
component rules into nested `@layer daisyui.l1.l2.l3` sublayers *inside*
`@layer utilities`, while plain Tailwind utilities are emitted unlayered in
that same layer. Unlayered rules beat sublayered rules in the CSS cascade, so
a plain utility class overrides a daisyUI component property with no
specificity hack. Never reach for `!important` in this plan.
</design_system_contract>

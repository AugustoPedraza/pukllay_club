<objective>
Run D-01's Spanish translation over the real catalog, after a human has looked at a sample.

`ideas.txt` states the requirement plainly — "the details of the game must to be on spanish" — and
385 of the club's games currently carry raw English pulled straight from BoardGameGeek. This plan
spends the quota and does the writing. It is deliberately separate from 01.3-03 so that every moving
part was built, reviewed and tested before any third-party call was made.

Two gates sit in front of the full run. The first is unavoidable: no CLI or API can mint a Gemini
API key on the developer's behalf, so the key is a genuine human-action gate rather than something
to automate. The second is judgment: machine translation of board-game prose fails in a specific,
predictable way — it translates the proper nouns a member would search for — and that failure is
invisible in an automated check but obvious to a Spanish reader looking at five samples. A bad prompt
applied to 385 games is 385 bad descriptions, and the English original survives only inside
`bgg_payload`.

Purpose: make the detail page actually read in Spanish, which is the phase's most member-visible
content fix.
Output: translated descriptions across the catalog and a committed run record naming every failure.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Human → gitignored config file | A real API key is handled in cleartext once and written to disk |
| Stored BGG description → Gemini prompt | Third-party content crosses into an LLM prompt, at catalog scale |
| Gemini response → `games.description` → HEEx render | Model-generated text crosses into the database and then into rendered HTML |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01.3-18 | Information Disclosure | The real Gemini key entering a tracked file, a plan, a SUMMARY or a commit message | high | mitigate | The key is written only to the gitignored `config/dev.secret.exs`; verification reads it back through `Credentials.redacted/1` rather than printing it; the acceptance criteria include a repository-wide scan for a Google-key-shaped string across every artifact this plan writes, plus a `git status` check on the config directory. |
| T-01.3-19 | Tampering | Prompt injection reaching a member-visible description at catalog scale | medium | mitigate | Structural controls carried over from 01.3-03 — schema-constrained response, explicit JSON schema, `validate_required`, HEEx auto-escaping — mean an injected instruction cannot change the response shape or become live HTML. This plan adds the behavioural control the structural ones cannot provide: a mandatory human review of five real translations against their originals, with leaked-instruction text named explicitly as one of the four things to look for. |
| T-01.3-20 | Tampering | A bad prompt silently degrading 385 descriptions | high | mitigate | The sample-then-full-run sequence is the gate. Recovery is guaranteed rather than hoped for: the English original is preserved in `bgg_payload`, the job reads from there and never from the column it writes, so re-running after a prompt fix fully restores correctness with no backup needed. The prohibition against hand-editing rows protects that property. |
| T-01.3-21 | Denial of Service | Free-tier rate limiting partway through the batch | low | mitigate | Per-game failures are logged and skipped, the limit switch makes the batch resumable across sessions, and every failure lands in the committed run record so a targeted re-run is possible. No throttle derived from an unverified published figure is added. |
| T-01.3-22 | Information Disclosure | Third-party catalog text sent to Google at scale | low | accept | BGG descriptions are already-public third-party content; no club-member data, credentials or internal identifiers appear in any prompt. |
| T-01.3-SC | Tampering | Supply chain — package installs | low | accept | This plan installs nothing. The one new dependency was audited and installed in 01.3-03. |
</threat_model>

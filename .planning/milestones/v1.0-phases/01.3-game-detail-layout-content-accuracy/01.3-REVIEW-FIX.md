## Fixed Issues

### WR-01: Dry-run mode in the two new Mix tasks silently reports counts as if real writes happened

**Files modified:** `lib/mix/tasks/catalog.enrich_bgg_stats.ex`, `lib/mix/tasks/catalog.backfill_artists.ex`
**Commit:** `da9dc21`
**Applied fix:** Threaded `dry_run?` through both mix tasks' console output and (for
`catalog.enrich_bgg_stats`) the persisted Markdown report, prefixing `"[DRY RUN] "` on the summary
line and inserting a `"**[DRY RUN]**"` banner in the report body when `--dry-run` is passed —
mirroring `catalog.seed.ex`'s existing `"[dry-run] ..."` convention exactly, per the review's
suggested Fix option 2. Chose this over renaming/gating the `:updated`/`:deduplicated` counters
(Fix option 1) because it's the smaller, lower-risk change that directly closes the actual
complaint ("nothing distinguishes a preview from an executed run") without touching counter
semantics any existing or future code might rely on for the preview count.

### WR-02: `ficha_tecnica?/1` was not extended to cover the new `artists`/advanced-stats fields

**Files modified:** `lib/pukllay_club_web/live/catalog_live/show.ex`
**Commit:** `ce57546`
**Applied fix:** Added `game.artists != []` to the `ficha_tecnica?/1` or-chain exactly as the
review's Fix suggested, and updated the guard's own doc comment (which referenced "four remaining
carriable fields") to reflect the fifth field and explain why the addition was needed — a game
carrying only `artists` (no `bgg_id`, `designers`, `min_age`, or `year_published`) would otherwise
have had its populated Ilustradores/Avanzado data silently never render.

### WR-03: `StatsEnricher.enrich_from_bgg/2`'s public `:batch_size` option has no upper-bound check against `BggClient`'s hard cap

**Files modified:** `lib/pukllay_club/catalog/seed/bgg_client.ex`, `lib/pukllay_club/catalog/seed/stats_enricher.ex`
**Commit:** `3804f5b`
**Applied fix:** Added `BggClient.max_batch_size/0` (exposing the existing `@max_batch_size`
module attribute, mirroring how `dedup_artists/1` is already exposed for cross-module reuse per
the review's suggested Fix), and clamped `enrich_from_bgg/2`'s `batch_size` against it with
`min(Keyword.get(opts, :batch_size, @default_batch_size), BggClient.max_batch_size())`. Also
updated the `:batch_size` option's `@doc` line to note the clamp. A caller passing
`batch_size: 25` (previously a `FunctionClauseError` crash) now silently clamps to 20 instead of
aborting the whole enrichment run.

### Investigated, Not a Deviation

**1. Task 1's acceptance-criteria grep `:gemini_api_key` count returned 3, not the expected "at least 4"**

- **Found during:** Task 1 acceptance-criteria verification
- **Issue:** The criterion expected 4 occurrences (optional-key entry, defstruct, type, secret-fields list). `grep -c ":gemini_api_key"` (colon-prefixed) found only 3.
- **Investigation:** The `@type t ::` struct typespec in this codebase (and in every existing field, e.g. `bgg_api_token: String.t()`) writes field types as `field: type`, without a leading colon — that's Elixir's own struct-typespec convention, not a stylistic choice made for this field. `gemini_api_key: String.t() | nil` (line 48) is present and correct but doesn't match the colon-prefixed grep pattern the criterion specified.
- **Resolution:** No code change — forcing a `:gemini_api_key => type` syntax onto just this one field would be inconsistent with every other field in the same struct for no functional benefit. All four conceptual locations (defstruct, type, `@optional_keys`, `@secret_fields`) are present and correct; verified directly by reading the file (see `lib/pukllay_club/catalog/seed/credentials.ex` lines 38, 48, 68, 71).
- **Verification:** `grep -n ":gemini_api_key\|gemini_api_key:" lib/pukllay_club/catalog/seed/credentials.ex` shows all four lines.

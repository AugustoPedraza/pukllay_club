# Phase 01.3 Plan 05: Reading-Column Hierarchy + Ilustradores/Avanzado Stats Summary

**Two-tier spacing rhythm (8px/32px) replaces the detail page's flat 1rem reading-column gap, plus a real Ilustradores row and a labelled Avanzado BGG stats sub-group (weight/rating/rank, each linking to BGG) — implementing the approved 01.3-UI-SPEC.md verbatim.**

## Performance

- **Duration:** ~50 min
- **Started:** 2026-08-30 (session start)
- **Completed:** 2026-08-31T00:35:00Z
- **Tasks:** 3
- **Files modified:** 3

## Accomplishments

- Raised `.pk-text-col`'s flex gap from `1rem` to `2rem` and added a new chrome-free
  `.pk-reading-section` wrapper class (8px internal gap) — the two-tier spacing system that fixes
  the "reads as one continuous flat block" complaint (D-03/D-04).
- `.pk-section-heading` gained `text-transform: uppercase` and `letter-spacing: 0.04em`, and lost
  its ad-hoc `margin-top` — the heading now reads as a structural label instead of a slightly
  bigger paragraph, with spacing owned entirely by the wrapper/gap system.
- Wrapped the four reading-column groups (title+description, Mecánicas, Temáticas, Ficha técnica)
  in `.pk-reading-section`, moving each optional group's `:if` guard from the heading onto the new
  wrapper — the load-bearing detail that keeps flex gap from leaving dead space behind an
  unrendered section.
- Added the Ilustradores spec row (D-05), reusing the exact conditional-render/comma-join
  mechanism the existing Diseñadores row already uses.
- Added the Avanzado sub-group (D-06): a new `.pk-spec-group-label` CSS rule, `advanced_stats?/1`
  guard, and three independently-gated stat rows (Peso BGG, Valoración BGG, Ranking BGG), each
  linking to the game's own BoardGameGeek page. The 01.3-01 tracer's standalone Valoración BGG row
  was moved into the group, not duplicated.
- Rewrote the Phase 01.2 test that had locked in the *removal* of the Ilustrador/BGG-ranking rows
  (correct when written — those fields didn't exist yet) into a conditional-render test, keeping
  the "never a placeholder" assertion intact with a comment explaining why the design rule
  survives the reversal in assertion direction.
- Added full new coverage: Ilustradores (single/comma-joined/absent), Avanzado group
  (all-nil/one-of-three/all-three/no-ranking), and structural wrapping counts (4 wrappers full
  data, 2 wrappers sparse).

## Decisions Made

See `key-decisions` in the frontmatter. The two most consequential: (1) followed the UI-SPEC's
exact CSS for `.pk-spec-group-label` (including `font-weight: 600`) even though the existing
`dt` rule it's described as reusing "verbatim" doesn't itself declare a font-weight — the UI-SPEC
CSS block is the authoritative source and no acceptance criterion tested weight, so there was
nothing to reconcile; (2) fixed 3 pre-existing tests broken by the wrapper structural change
inside Task 2 rather than deferring to Task 3, since Task 2's own `<verify>` command runs the full
show test file and would otherwise fail before Task 3 ever ran.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed two sibling-adjacency test selectors broken by the new wrapper nesting**
- **Found during:** Task 2's own `<verify>` run (`mix test test/pukllay_club_web/live/catalog_show_test.exs`)
- **Issue:** Two pre-existing tests asserted direct-sibling CSS relationships
  (`.pk-description + .divider`, `.pk-divider + div + h2.pk-section-heading`) that broke once
  Task 2 wrapped the title+description block and the Mecánicas heading in `.pk-reading-section` —
  the heading/description are now one level deeper in the DOM.
- **Fix:** Updated the selectors to `.pk-reading-section + .divider` and
  `.pk-divider + div + div.pk-reading-section > h2.pk-section-heading`, preserving each test's
  original intent (adjacency/ordering, not the specific nesting depth).
- **Files modified:** `test/pukllay_club_web/live/catalog_show_test.exs`
- **Verification:** Both tests pass; full show test file green (139/139 at that point).
- **Committed in:** `1aa439a` (Task 2 commit)

**2. [Rule 1 - Bug] Overrode a shared-fixture default in an existing BGG-link test**
- **Found during:** Task 2's own `<verify>` run
- **Issue:** The existing "a game with a bgg_id renders a boardgamegeek.com link... one without
  renders none" test built its `bgg_id: nil` game without also overriding `bgg_weight` (the shared
  fixture default holds `2.3`). Once `advanced_stats?/1` existed, that game rendered a Peso BGG
  row with an empty-domain href, breaking the test's "no boardgamegeek.com anywhere" assertion —
  the exact impossible weight-without-BGG-id combination `01.3-UI-SPEC.md` and the plan's own
  prohibitions warn about.
- **Fix:** Added `bgg_weight: nil` to that fixture's overrides.
- **Files modified:** `test/pukllay_club_web/live/catalog_show_test.exs`
- **Verification:** Test passes; full show test file green.
- **Committed in:** `1aa439a` (Task 2 commit)

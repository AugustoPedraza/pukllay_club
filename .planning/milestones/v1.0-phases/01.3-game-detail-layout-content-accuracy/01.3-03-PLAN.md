<objective>
Build the tooling for D-01 and D-02: a description cleanup step grounded in what the database
actually holds, and a one-off LLM translation job — without making a single live call yet.

`01.3-CONTEXT.md` D-02 assumed BGG's noise was line-break escapes and BBCode markers.
`01.3-RESEARCH.md` disproved that by querying all 385 stored descriptions: zero of either pattern,
but 261 rows carrying named character escapes drawn from a set of exactly 30, re-confirmed against
the live dev database during planning. D-02's decision — clean at seed time, not render time,
following the `hashtag_normalizer.ex` convention — stands unchanged; only the target pattern moves.

D-01 pulls Phase 2's LLM integration forward by exactly one batch job. The load-bearing constraints
are that it stays off the request path, that a per-game failure never blanks an existing description,
and that the new secret joins the existing `Credentials` module rather than growing a second,
parallel secrets convention. One more constraint is structural and easy to get wrong: `fetch!/0`
today raises unless *every* key resolves, so adding the Gemini key to the required list would break
`mix catalog.seed` and two existing test modules for anyone without a Gemini account.

Purpose: have every moving part built, tested and reviewable before any third-party quota is spent.
Output: a normalizer, a validated LLM response model, a testable translator with an injectable call
seam, one Mix task, and an optional credential that masks itself in logs.
</objective>

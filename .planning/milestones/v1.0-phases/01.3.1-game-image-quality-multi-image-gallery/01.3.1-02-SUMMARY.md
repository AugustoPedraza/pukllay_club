# Phase 01.3.1 Plan 02: Letterbox/Contain Poster Rendering Summary

**Single shared `.pk-poster-img` CSS class (object-fit: contain, no background) applied verbatim to the resting card, hover-preview/mobile-sheet, and detail-page cover `<img>` elements, replacing crop-to-fill `object-cover` everywhere box art renders except the lightbox (already correct) and the 64x64 gallery selector chips (deliberately excluded).**

## Accomplishments

- Added `.pk-poster-img` (`width: 100%`, `height: 100%`, `object-fit: contain`, no `background`) to `assets/css/app.css` immediately after `.pk-card-poster`, with an explanatory comment covering why box art is not near-square, why the stored WebP variants are already aspect-ratio-preserving, and why the fill comes from each container's own `bg-base-300` rather than a second background declaration.
- Swapped the crop-to-fill class list (`h-full w-full object-cover js-cover-fallback`) for `pk-poster-img js-cover-fallback` on the cover `<img>` in all three remaining artwork surfaces: `game_card.ex` (resting catalog/carousel card), `game_preview.ex` (desktop hover portal + mobile full-screen sheet, one function serving both), and `catalog_live/show.ex` (detail-page main cover inside `#detail-lightbox-trigger`).

## Decisions Made

- `.pk-poster-img` declares no `background` — the letterbox fill is the `bg-base-300` already on every container, per `app.css`'s own "one field, one declaration" rule and D-05's exact wording. Verified by a dedicated test and a `git diff | grep -cE '^-.*bg-base-300'` acceptance check returning 0.
- The 64x64 gallery selector chips and the lightbox image are left exactly as they were, per RESEARCH.md's recommendation (Open Question 1) and Code Insights (the lightbox already implements this treatment against an intentionally dark `var(--pk-shadow-color)` stage from the Phase 01.2 rebuild) — both exclusions are pinned by test assertions and diff-scoped grep checks, not left to memory.
- Container aspect-ratios (`.pk-card-poster: 1 / 1.05`, `.pk-preview-poster: 16 / 9`) are unchanged — this plan changes only how an image fits its box, per Pitfall 3's explicit warning against reading D-06 as "unify every poster's shape."

## Deviations from Plan

None - plan executed exactly as written. Two minor test-implementation bugs were caught and fixed during self-verification, not deviations from the plan's intent:

1. The rendered-component tests for both `game_card.ex` and `game_preview.ex` initially scoped their `<img>` search over the whole rendered component rather than the poster `<figure>` specifically — `game_card.ex` also embeds `GamePreview.preview_template/1` (an inert `<template>` clone target), which contributed a second `<img>` to an unscoped search. Fixed by scoping the regex to the `<figure class="pk-card-poster...">`/`<figure class="pk-preview-poster...">` block before counting `<img>` elements — this is a test-authoring correction, not a change to plan-specified behavior.
2. A `Regex.scan/2` destructuring bug (`[img] = imgs` instead of `[[img]] = imgs`, since `Regex.scan/2` returns a list of match-lists) was caught by the test itself failing with a `FunctionClauseError` and fixed inline.

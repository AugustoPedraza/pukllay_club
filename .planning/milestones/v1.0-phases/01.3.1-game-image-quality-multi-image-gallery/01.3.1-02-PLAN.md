<objective>
Make the whole of a game's box art visible everywhere the catalog renders it, instead of cropping it
to fill a fixed near-square frame.

Every artwork surface today sizes an `<img>` to fill its container and crops whatever does not fit.
Box art is not near-square — publishers ship tall, wide and square boxes — so the catalog silently
slices the top and bottom off a large share of its own covers. Research settled the one question
that decided this plan's shape: the stored WebP variants are **not** cropped at generation time.
`ImagePipeline.resize_and_upload/4` calls `Image.thumbnail/2` with no options, and that function's
documented default preserves aspect ratio. The full image is already in R2. Only CSS is throwing it
away.

Purpose: this is the catalog's primary visual content. A cropped cover misrepresents the product on
the shelf, and on mobile — where the grid shows the most covers at once — it is the dominant
impression the app makes.

Output: one new shared CSS class, three `<img>` elements pointed at it, and a guard test that fails
if a fourth surface ever grows its own copy of the treatment.
</objective>

The binding constraints for this plan:

- **`ui-design-system`** — no arbitrary Tailwind values, no raw hex colours, no inline `style=`.
  The letterbox fill must be the existing `bg-base-300` token already on each container, never a
  hand-written colour.
- **`app.css`'s own rule at lines 33-36** (read it in full before editing): when a `.pk-*` rule and
  a Tailwind utility both want to set one property on one element, delete the utility from the
  markup and keep the property in the `.pk-*` rule. This is why the new class takes over sizing as
  well as fit, rather than sitting alongside the existing sizing utilities.
- **`sketch-findings-pukllay_club/references/card-interaction.md`, lines 45-55** — the source of
  D-06. Read it before deciding what "one shared mechanism" covers: the documented bug was two
  surfaces *meant to look identical* (hover portal and mobile sheet) drifting to different ratios.
  It is not a mandate to give unrelated surfaces the same shape. The same document also describes
  the resting card's poster-first, minimal-metadata design, which this change must not disturb.
- **`ux-responsive`** — mobile is the primary surface for this project. The catalog grid on a phone
  shows more covers at once than any other view, so it is where the letterbox treatment is judged.
  Touch targets are unaffected by this change (the detail cover button keeps its `min-h-11`).

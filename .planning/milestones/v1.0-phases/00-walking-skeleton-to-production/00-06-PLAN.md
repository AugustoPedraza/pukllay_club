<assumption_delta_decision>
Backup mechanism (CONTEXT.md "Claude's Discretion"): chosen = scheduled GitHub Actions workflow over SSH (research recommendation A3), NOT a host systemd timer. Rationale: keeps R2 credentials in GitHub secrets (D-08 consistency) rather than persisting them on host disk. This is a reversible workflow choice (a one-way door was NOT created), so it is recorded here as a documented assumption instead of a blocking `checkpoint:decision`. If the operator later prefers host-side simplicity, swapping to a systemd timer is a contained change.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI job -> host (SSH) | The backup job authenticates to the host with the deploy SSH key loaded transiently |
| host -> R2 | The dump is uploaded to R2 with credentials injected transiently into the job/SSH session |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-0-01 | Information Disclosure | R2 credentials | high | mitigate | R2 keys live only as GitHub repo secrets, exported transiently into the job env — never written to host disk or committed (D-08 pattern) |
| T-0-04 | Spoofing / Elevation of Privilege | deploy SSH key (reused) | high | mitigate | Same key handling as the deploy job: private half stays a GitHub secret loaded transiently via ssh-agent; no plaintext copy persists on the runner |
| T-0-BK | Tampering / Repudiation | backup validity | medium | accept | Phase 0 accepts that a successful upload is not proven-restorable; mitigated only by a periodic MANUAL restore-test (prohibition + AGENTS.md non-goal) — automation deferred |
</threat_model>

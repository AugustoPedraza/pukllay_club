<objective>
Build the mobile navigation drawer sketch 011 designed and sketch 017 Rounds 4 and 5 finished, and
which was never carried into real code — the shipped stylesheet only hides the nav links and shows a
shelf-jump chip row below 480px. Then move the theme toggle and social links into that drawer's
pinned bottom edge on mobile, and give the About page its own mobile sticky join-CTA bar.

Purpose: plan 01.1-08 took the theme toggle out of the header and put it in the footer, which is
correct on desktop and wrong on a phone — reaching the footer there means scrolling the entire page,
while a drawer is one tap from anywhere. The drawer is also the only place a mobile visitor can see
which page they are on, since the header's nav links are `display: none` below 480px and 015-A's
underline therefore never renders there.

Output: a real hamburger-and-drawer, a drawer with genuine list-row affordance and its own active-
state language, the toggle and socials pinned to its bottom, and an About-scoped sticky CTA bar.

## Scope boundary

This plan is the mobile half of the shared shell. It does not touch the About page's own body
content (plan 01.1-02), the detail page's per-game reservation chrome (plans 01.1-04 and 01.1-05),
or the filter surface (plan 01.1-06). The `.pk-about-cta-bar` built here and the `.pk-mobile-cta-bar`
plan 01.1-04 builds are **different bars for different CTAs on different pages** — the club-wide
"Sumate" join CTA versus the per-game "Quiero jugarlo" reservation CTA — and share no CSS.
</objective>

Build the drawer as one production-quality path through every layer — markup, stylesheet, hook JS,
all three call sites, tests — before adding its content affordance in Task 2. This slice proves the
two architectural bets: the drawer's link list is shell-owned rather than slot-owned (so Detalle,

**1. `header_inner/1` — the trigger.**
Add as the **first** child of `.pk-nav-inner`, before the brand:
`<button type="button" class="pk-nav-hamburger" aria-label="Abrir menú" aria-expanded="false"
aria-controls="pk-nav-drawer"><.icon name="hero-bars-3" class="size-6" /></button>`.
Keep the `class` attribute a static literal — the hook owns `aria-expanded`, and plan 01.1-08's
static-class rule applies to every element the hook mutates.

**2. `app/1` — the panel, and a caller-declared active state.**
Add `attr :active_nav, :atom, default: nil, doc: "which top-level nav entry is current — :inicio,
:quienes_somos, or nil for a drill-down page that is neither"`. The drawer's link list cannot come
from the `nav_links` slot: `CatalogLive.Show` passes a `crumb` and no `nav_links`, so a slot-driven
drawer would be empty on exactly the page a lost visitor most needs a menu. Defining the two links
once in `layouts.ex` is what makes the drawer identical on all three routes, which is SHELL-01's
no-per-page-fork rule.

Render the backdrop and panel **inside** both `#app-header` branches, after `header_inner/1` and
after the `subnav` slot, so `.CatalogNav` can reach them via `this.el.querySelector` and never
touches DOM outside its own element:

- `<div class="pk-drawer-backdrop" aria-hidden="true"></div>`
- `<aside id="pk-nav-drawer" class="pk-drawer" role="dialog" aria-modal="true" aria-label="Menú"
  inert>` containing a `.pk-drawer-header` (a display-font "Menú" plus a
  `.pk-drawer-close` button with `aria-label="Cerrar menú"` and a `hero-x-mark` icon), a
  `<nav class="pk-drawer-links" aria-label="Navegación principal">` with the two
  `<.link navigate={...}>` entries (Inicio → `~p"/"`, Quiénes Somos → `~p"/quienes-somos"`), each
  carrying `aria-current={@active_nav == :inicio && "page"}` / `:quienes_somos` respectively, and an
  empty `<div class="pk-drawer-bottom">` placeholder that Task 2 fills.

`inert` is the closed state's a11y mechanism: it removes the whole panel from the tab order and the
accessibility tree without `display: none`, which would kill the slide transition. The hook adds and
removes it. Do not use the `hidden` attribute for this.

`.pk-header-sticky` carries `z-index: 50` and therefore creates a stacking context; the drawer is a
`position: fixed` child of it and needs a z-index above `.pk-nav` within that context. `position:
sticky` does **not** create a containing block for fixed descendants, so viewport anchoring is safe —
but per Pitfall 4, do not add `transform`, `filter`, `contain` or `will-change` to `#app-header` or
any ancestor while building this.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| colocated-hook JS → `document.body` | The drawer adds a scroll-lock class to a node outside its own element, which must be released on every close path including LiveView teardown. |
| colocated-hook JS → focus management | The drawer moves and traps keyboard focus, and must restore it — a trap that cannot be escaped is a real lockout, not a cosmetic issue. |
| render → third-party site | The drawer's social cluster and the About sticky bar open the club's public WhatsApp / Facebook / Instagram destinations in a new browsing context. |
| `AboutLive` render → viewport-anchored element | A `position: fixed` bar depends on no ancestor having become its containing block. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01.1-34 | Denial of Service | the drawer's body scroll lock | medium | mitigate | `pk-drawer-open` is removed on every close path — the close button, the backdrop, `Escape`, and the hook's `updated()` navigation close — and defensively again in `destroyed()`, so a LiveView teardown while the drawer is open can never leave the page permanently unscrollable. Asserted by a grep for at least three removal sites in Task 1. |
| T-01.1-35 | Denial of Service | the drawer's focus trap | medium | mitigate | The trap is `game_preview.ex`'s already-shipped `onSheetKeydown` first/last-wrap implementation, copied rather than re-derived, and `Escape` is bound as an unconditional escape hatch alongside the close button and the backdrop — three independent exits, so no single broken path locks a keyboard user in. |
| T-01.1-36 | Tampering | `.CatalogNav`'s drawer code | low | mitigate | The hook toggles classes and the `inert`/`aria-expanded` attributes on nodes resolved via `this.el.querySelector`, plus one class on `document.body`.

<domain>
## Phase Boundary

Turn the sketch-validated designs (`.claude/skills/sketch-findings-pukllay_club/`) into real
Phoenix/LiveView code: a shared page shell (header + footer), the about/landing page, an upgraded
game detail page, the filter/search modal, and empty/loading/error states. This phase **implements**
what the sketch rounds already designed — it does not design from scratch. Almost every visual/
interaction decision is already locked in the sketch findings skill; this discussion covers the
implementation gray areas the sketches left open (content, real-world framing, and one requirement
that the sketches never actually designed).

Two areas were selected for deep discussion: **Page Shell** (header/footer real content — route,
footer links, logo, BGG wording) and **About page** (real content — the user supplied a finished
design that supersedes sketch 004's structure). Three other candidate areas were surfaced but
**not discussed** and remain open for planning: **Filter UI (modal vs. drawer)**, **Reservation
flow specifics** (WhatsApp number, exact message copy), and **"Juegos similares" selection logic**.
See `<deferred>` for how to handle those.

</domain>

<decisions>
## Implementation Decisions

### Page Shell — Header & Footer
- **D-01:** The about/landing page is reachable at **two URL aliases pointing to the same
  LiveView**: `/club` and `/quienes-somos`. Both must resolve to the same page — this is a
  deliberate dual-route, not a redirect-vs-canonical decision to make.
- **D-02:** Footer's three Club links (FAQ / Contacto / Juntadas) **all point to the about page,
  at different anchors**: FAQ → `#faq` (the existing FAQ band, see D-07/D-08 below), Contacto → a
  contact band/section to be added to the about page, Juntadas → a meetups band/section to be
  added to the about page. Contacto and Juntadas bands don't exist yet in the supplied design —
  Claude's discretion on exact placement/content, flagged for review (see Claude's Discretion).
- **D-03:** No real logo/isologo asset exists in the repo yet. **User will provide a logo file**
  before/during planning — keep the sketch's placeholder mark (hexagon/wordmark) until then. Note
  as an expected input, same pattern as Phase 1's D-11 (Google Stitch export).
- **D-04:** The footer's BGG attribution wording ("datos de BoardGameGeek") was a sketch
  placeholder. **User already knows the exact required wording/format** and will provide it —
  do not invent or guess this text; do not ship the placeholder as final.
- **D-05:** A **"Sumate" (join) CTA button, linking to the club's WhatsApp group invite**, is
  added to the header **site-wide** (catalog, detail, and about pages) — not just on the about
  page. This is a deviation from `page-shell.md`'s locked header spec (which only had logo /
  nav-links or breadcrumb / search or nothing / theme-toggle) — the shared header component gains
  a 4th persistent element across all three of its states. — **Reversibility:** reversible — it's
  one more header element, easy to remove/relabel later.

### About Page — Content & Structure
- **D-06:** The user supplied a finished design (`about-page-design-source.html`, in this phase
  directory — originally a Claude Design canvas export) with **real, final copy** — not a rough
  draft. Use its text verbatim (see `<specifics>` for the full extracted copy). This **replaces**
  sketch 004's "alternating tinted bands, mission/how-it-works/the-club/FAQ, one carousel per
  band" structure entirely for the About page.
- **D-07:** **New page structure** (supersedes sketch 004 for the About page specifically): hero
  (eyebrow + H1 + subhead) → one shared photo carousel (4 slides, auto-advancing ~4.5s + dot nav +
  scroll-snap) → two-column band ("Qué hacemos" / "Nuestra historia") → a dark-background FAQ band
  → closing CTA band (WhatsApp + Instagram links + footer-style meta line). Sketch 004's
  alternating-tint/per-band-carousel pattern is **not** used here.
- **D-08:** **Visual system: restyle to match the site's established brand**, not the supplied
  design's own type/color system. The design file uses Bricolage Grotesque + Instrument Sans +
  JetBrains Mono fonts and a #6D3FA6 purple / #FBF8F3 cream palette — these are **reference for
  content/structure only**. Implement using the site's actual brand tokens (Bebas Neue + Inter,
  `assets/css/app.css` / `sources/themes/default.css` palette) so the About page matches
  catalog/detail/header/footer, not a one-off visual identity.
- **D-09:** **Club model confirmed: play-at-the-club only.** Members come play on Saturdays at a
  physical venue (Club de Emprendedores, San Salvador de Jujuy); the club brings the games, no
  games are checked out to take home. This is the real-world model the FAQ describes and it is
  authoritative — it is **not** a lending library where members borrow individual copies. This
  reframes SHELL-03's detail-page "reservation" language (see D-10).
- **D-10:** Given D-09, the detail page's buy-box CTA (SHELL-03) means **"reserve to play this
  game at the next Saturday session"**, not "take this game home." Keep the sketch's per-game
  WhatsApp deep-link mechanism (name-capture → pre-filled `wa.me` message), but the pre-filled
  message content must ask the club to have/set up that specific game at the next session — not
  ask to borrow/take it home. Exact message copy is Claude's discretion during planning (see
  Claude's Discretion), grounded in this framing.
- **D-11:** SHELL-02's "FAQ/**vocabulary** section" is **dropped as a distinct section**. The
  supplied FAQ (4 logistics Q&As: when/where, cost, do-I-need-to-know-how-to-play, can-I-come-alone)
  is the real content and is sufficient — no separate glossary of hobby terms (weight/mechanic
  vocabulary) is added to the About page. The catalog's existing plain-Spanish weight bands and
  mechanic/theme chips (Phase 1, CATALOG-05/06) already cover the "teach the hobby" need at the
  point where it matters (browsing a game), so this isn't a gap.
- **D-12:** Club photos: the supplied design's carousel slides are explicitly gradient-placeholder
  images with captions describing what should eventually be there ("foto — mesa llena un sábado",
  "foto — explicando un juego", "foto — la ludoteca", "foto — la comunidad"). **No real photos
  exist yet** — ship with placeholders, matching the sketch's own established pattern for this
  (about-page-content.md: "structurally this is a real `<img>` carousel once photography exists").

### Claude's Discretion
- Exact placement/content of the Contacto and Juntadas footer-link destinations on the about page
  (D-02) — these bands don't exist in the supplied design; draft reasonable content during
  planning, flagged for review.
- Exact pre-filled WhatsApp message copy for the reframed "reserve to play Saturday" detail-page
  CTA (D-10) — draft during planning, grounded in D-09/D-10's framing, flagged for review.
- Whether/how the about page's dark FAQ band's specific dark colors (#241C2E, #CFC4DC in the
  supplied design) map onto the site's existing theme tokens, given D-08's "restyle to match site
  brand" decision — pick the closest existing dark/contrast tokens from the established theme
  rather than introducing new one-off colors.

</decisions>

<deferred>
## Deferred Ideas

Three gray areas were surfaced during analysis but **the user chose not to discuss them** in this
session (deliberately scoped to Page Shell + About page only). They remain real open questions —
do not silently resolve them during planning; either re-surface for a quick user check-in or flag
prominently in the plan for review:

- **Filter UI: modal vs. drawer.** SHELL-04 says "centered modal with checklist-style facets,
  reachable from a nav search box with live narrowing" — but no sketch ever designed this, and
  Phase 1 already shipped and UAT-fixed a working slide-over **drawer** (`01-05-PLAN.md` D-13,
  recently touched by quick task 260821-dah). Rebuilding as a true centered modal is a real,
  undiscussed scope question — resolve before/during planning, not by assumption.
- **Reservation flow mechanics.** The WhatsApp business number is still a placeholder
  (`detail-page-mobile-interaction.md` explicitly flags this as sketch-only, "belongs in runtime
  env config"). The real number needs to come from the user before this ships — likely the same
  WhatsApp group/number referenced in the About page design source, but not confirmed as the same
  number to use for the per-game reservation flow (D-10) vs. the general "Sumate"/"Grupo de
  WhatsApp" join links.
- **"Juegos similares" selection logic.** `detail-page-layout.md` says the shelf reuses the real
  `CarouselRow`/`GameCard` components but never defines what makes a game "similar" (same weight
  band? shared mechanics/themes? shared editorial tag? something else). Needs a decision before
  the query behind that shelf can be written.

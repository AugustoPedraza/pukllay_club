## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Made `.CatalogNav`'s `closeDrawer()` idempotent**
- **Found during:** Task 1
- **Issue:** The plan's "simplest correct form" calls `closeDrawer()` unconditionally from `updated()` on every server round trip. Implemented literally (no guard), this would steal focus back onto the hamburger on any unrelated re-render (e.g. a debounced search keystroke on a page that also has an open drawer), not just on the navigation the plan's reasoning assumed was the only trigger.
- **Fix:** `closeDrawer()` now early-returns when the panel doesn't carry `is-open`, so it's a true no-op when already closed — the unconditional call site is unchanged, only the function's own side effects are gated.
- **Files modified:** `lib/pukllay_club_web/components/layouts.ex`
- **Verification:** `mix test test/pukllay_club_web/components/layouts_test.exs` green; the guard is inline JS, exercised at end-of-phase human verification alongside the rest of the drawer's focus behaviour.
- **Committed in:** `d2e9142`

**2. [Rule 1 - Bug] Rescoped a pre-existing 01.1-08 test that the drawer's own social row now legitimately false-fails**
- **Found during:** Task 2
- **Issue:** `layouts_test.exs`'s "the #app-header subtree contains neither the CTA label nor the WhatsApp URL" test used the WhatsApp URL as a proxy signal for "no join CTA in the header." Task 2's `.pk-drawer-social` row (inside `#app-header`) now legitimately links that same URL as its WhatsApp icon — an unrelated consumer, not the CTA — which broke the proxy.
- **Fix:** Rescoped the URL assertion to `#app-header :not(.pk-drawer-social) > a`, excluding the drawer's social row's own children while keeping the direct "Sumate" label check unscoped. The test still guards exactly what it always guarded (no CTA reintroduction into the header).
- **Files modified:** `test/pukllay_club_web/components/layouts_test.exs`
- **Verification:** `mix test test/pukllay_club_web/components/layouts_test.exs` green (56/56 in that file).
- **Committed in:** `1bf3587`

**3. [Rule 1 - Bug] Reworded a CSS comment that broke the plan's own "exactly one media block" grep invariant**
- **Found during:** Task 3
- **Issue:** A new comment above `.pk-about-cta-bar` used the literal string `@media (max-width: 480px)` in prose, which made `grep -c '@media (max-width: 480px)' assets/css/app.css` return 2 instead of the required 1 — a false positive for "a second media block was added," even though only one real block exists.
- **Fix:** Reworded to "the single trailing narrow-viewport media block," matching how Task 1's own comments already referred to it without the literal substring.
- **Files modified:** `assets/css/app.css`
- **Verification:** `grep -c '@media (max-width: 480px)' assets/css/app.css` => 1.
- **Committed in:** `ee782a0`

> **D-05 superseded — plan 01.1-08 (2026-08-22).**
>
> The paragraph above, and plan 01.1-01's implemented deviation from it (`sumate_cta/1` hardcoded as
> an always-rendered non-slot inside `header_inner/1`, chosen because *a slot can be omitted by a
> caller* and silent omission would reintroduce the per-page-fork risk SHELL-01 exists to prevent),
> are both **superseded**. The join CTA is no longer a header element in any form — not a slot, not a
> built-in. It renders on the About page only: in the hero (plan 01.1-08) and, below 480px, in a
> page-scoped `.pk-about-cta-bar` (plan 01.1-09).
>
> **Why the constraint changed.** Sketch 013 asked the scope question, deferred it, and recorded the
> D-05 implementation cost; sketch 017 Round 3 reopened it on the developer's direct, twice-repeated
> instruction. The reasoning, in one line: *search and the CTA moved in opposite directions for the
> same underlying reason.* Search became cheap enough to put on **more** pages — Catálogo **and**
> Detalle, reopening 003/011's Catálogo-only rule — precisely because it stopped needing a permanent
> 220px box and became a 44px icon (sketch 017 Round 4 point 4). The CTA was never a space problem; it
> was a **context** problem. "Sumate al club" asks for a commitment before the value case has been
> made, and the only page that makes that case is Quiénes Somos. On Detalle it competes with someone
> mid-way through reading one game's rules. Cheap-to-show follows space; worth-showing follows
> context. They are different axes and they pointed opposite ways.
>
> **The guarantee D-05 was protecting is not lost — it is strengthened.** D-05 chose unconditional
> rendering because slot omission is silent. Plan 01.1-08 replaces that with tests asserting the CTA
> is **absent** from `#app-header` on `/` and `/juegos/:id` **and present** in the hero of both
> `/club` and `/quienes-somos` (D-01's two aliases). That is strictly stronger than "always renders":
> it also catches accidental *reintroduction* into the header, which the original mechanism could not.
>
> Sources: `.planning/sketches/013-header-action-cluster/README.md` (Round 1 variant B and its
> implementation-cost note), `.planning/sketches/017-header-composition/README.md` (Round 2's CTA-
> placement research, Round 3 point 3 and its "Implementation flag, not resolved here" paragraph).

## Shared Patterns

### Slot-based per-page shell state (no branching inside `Layouts.app`)
**Source:** `lib/pukllay_club_web/components/layouts.ex:79-84, 163-188`
**Apply to:** `about_live.ex`, `catalog_live/show.ex`, `catalog_live/index.ex` (all three consumers of `Layouts.app`)
```elixir
slot :nav_links, doc: "shelf anchor links, rendered between the brand and the search box"
slot :nav_search, doc: "the search form, rendered inside the header aligned with row content"
# NEW, same doc-comment convention:
slot :crumb, doc: "breadcrumb content for a genuine drill-down page (Detalle only)"
```
The caller's slot usage is the state machine — `Layouts.app` itself never branches on "what page am I."

**Two amendments from the sketch 013–017 header rework (plans 01.1-08 / 01.1-09):**

1. **The join CTA is not a shell slot and never was one in the end.** `sumate_cta/1` is a public
   page-level component owned by `AboutLive`, not a header slot and not a header built-in — see the
   `D-05 superseded` note in the `layouts.ex` section above.
2. **Two pieces of shell state are attrs, not slots, and that is deliberate.** `search_expanded`
   (plan 01.1-08) and `active_nav` (plan 01.1-09) are `attr`s on `Layouts.app`. The slot-as-state-
   machine convention holds for *content* the caller supplies; it breaks for state the shell must
   render into markup the caller does not own. The mobile nav drawer is the concrete case:
   `CatalogLive.Show` passes a `crumb` and no `nav_links`, so a slot-driven drawer would be **empty
   on the detail page** — exactly the page a lost visitor most needs a menu. The link list therefore
   lives once in `layouts.ex` (no per-page fork, SHELL-01's actual rule) and the caller declares only
   *which* entry is current. Same principle, expressed as an attr because the content is shell-owned.

### Colocated hooks for all client-only interaction (never a third-party JS package)
**Source:** `lib/pukllay_club_web/components/layouts.ex:97-147` (`.CatalogNav`), `lib/pukllay_club_web/components/carousel_row.ex:43-74` (`.CarouselScroll`)
**Apply to:** About page's photo carousel, detail page's sticky title-bar/mobile CTA bar
```elixir
<section id={@id} phx-hook=".CarouselScroll">
  <script :type={Phoenix.LiveView.ColocatedHook} name=".CarouselScroll">
    export default {
      mounted() { /* plain addEventListener/IntersectionObserver, no npm package */ },
      destroyed() { /* explicit cleanup — removeEventListener/disconnect */ }
    }
  </script>
```
**Critical constraint:** use plain `scroll` + `getBoundingClientRect()` for any new visibility-toggle (sticky bar/CTA bar show-hide) — do NOT extend `IntersectionObserver` to new toggle use cases (Pitfall 3); the existing chip scroll-spy `IntersectionObserver` use is a different, lower-stakes case (nav highlight) that stays as-is.

### Event-contract-first component design (stateless `Phoenix.Component`, state lives in parent LiveView)
**Source:** `lib/pukllay_club_web/components/filter_drawer.ex:1-16` (moduledoc), `31-138` (implementation)
**Apply to:** `filter_modal.ex` (if built), any other new presentational component
```elixir

# This is a `Phoenix.Component`, not a `Phoenix.LiveComponent` — no state of its own.
use Phoenix.Component
```
Emit the same named events (`toggle-facet`, `set-scalar`, `clear-filters`, `select-image`-style whitelisted echoes) rather than inventing new handler names when reskinning existing functionality.

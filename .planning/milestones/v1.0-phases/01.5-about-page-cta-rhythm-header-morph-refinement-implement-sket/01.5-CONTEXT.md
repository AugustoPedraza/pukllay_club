# Phase 01.5: About Page CTA Rhythm & Header Morph Refinement - Context

**Gathered:** 2026-09-08
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase implements sketches 050-051 — a second, follow-on revision pass over the About page
(`lib/pukllay_club_web/live/about_live.ex`), on top of the already-shipped Phase 01.4 work (which
implemented sketches 045-049). Both sketches are already-validated, real-developer-feedback
findings from `.claude/skills/sketch-findings-pukllay_club/references/about-page-content.md`'s
"Isologo Scroll-Morph Companion Wordmark (sketch 050)" and "About Page — CTA Rhythm & Band
Backgrounds (sketch 051, 14 rounds)" sections — this phase's job is implementation, plus resolving
the few items those findings explicitly left open.

**In scope (from the 2 sketches):**
- 050: bake a "PUKLLAY CLUB" companion wordmark into the existing isologo scroll-morph mark (045,
  already shipped) so it travels/shrinks with the mark; sync the hero eyebrow's hide/reveal to the
  same docked-state boolean; a header `.brand-slot` box-reservation fix so the docked mark doesn't
  overlap the header wordmark's first letters.
- 051 (14 rounds): drop all card chrome from the Contacto card so it reads as one plain column pair
  with Juntadas; redesign Contacto's contact links as soft accent-tinted chips (icon-only + circular
  on mobile); relocate the Maps thumbnail/embed from Contacto to Juntadas; make Cierre full-screen
  on desktop with one gap-based spacing rhythm; alternate plain/tint band backgrounds page-wide
  (FAQ's dark band stays a one-off highlight, not folded into the alternation).

**Out of scope:** any page other than `/quienes-somos` (`/club`); generalizing the isologo-morph
into a shared header capability (still deferred, per 01.4's D-10); the description-truncation/
chevron system (unrelated area); adding Email as a 4th Contacto channel (explicitly decided against
below); sourcing any new photography or copy beyond what 050/051 already lock.

**Relationship to Phase 01.4:** 01.4 shipped 045-049, including a mid-phase revision (D-11 through
D-14 in `01.4-CONTEXT.md`) that replaced the Contacto card's static Maps screenshot with a **live,
keyless Google Maps iframe embed** (CSP `frame-src` already scoped to `https://www.google.com`).
Sketch 051 (dated after that revision) calls this the "Maps thumbnail" when describing the move to
Juntadas — this phase relocates the **existing live embed as-is**, not the retired static screenshot
concept. No CSP change is needed (same page, same origin).

<decisions>
## Implementation Decisions

### Isologo companion wordmark (050)
- **D-01:** Bake a "PUKLLAY CLUB" companion wordmark into the morph mark's own element —
  absolutely positioned below the isologo image, not affecting the box's own size math — so it
  travels and shrinks in lockstep with the mark as it docks into the header. — **Reversibility:**
  reversible — markup/CSS only, no data migration.
- **D-02:** Companion text sizing: ~25px at rest (`nameScale: 0.135` of the mark's own size), tight
  letter-spacing (`0.02em`), `font-weight: 400` always (Bebas Neue is self-hosted at weight 400 ONLY
  in the real app — verify no heavier weight gets silently browser-faked here).
- **D-03:** The hero's eyebrow line ("Club de juegos de mesa · Jujuy") hides the instant the mark
  docks and reappears the instant it undocks — reads the *same* docked-state boolean that already
  drives the header reveal (045, shipped), so header reveal + companion-text fade + eyebrow
  visibility all change at the identical crossing-point instant, both scroll directions. Do not gate
  this on a separate scroll-position/viewport-height check.
- **D-04:** The mark anchors to an in-flow spacer as the first child of `.hero` (not the hero
  section's own top edge) so mark + companion + eyebrow + H1 + subtext + CTA all center together as
  one grouped flex-column block via the column's own `gap`. The real code already has a
  `data-morph-anchor` / `.pk-about-mark-anchor` element in this position (see `code_context` below)
  — verify during research whether it already satisfies this "in-flow spacer" requirement or needs
  adjustment; do not assume a rebuild is needed.

### Contacto card & full-page CTA rhythm (051)
- **D-05:** Drop the Contacto card's chrome entirely (background, border-radius, padding) at every
  width, so it reads as one plain two-column pair with Juntadas rather than a boxed card beside a
  boxed Juntadas' worth of plain text. Keep the existing flex/gap internal layout — only the outer
  chrome (currently `.pk-about-contact-card`'s `background: var(--color-base-200)` +
  `border-radius` + `padding`) goes away. — **Reversibility:** reversible — CSS-only.
- **D-06:** Contacto's contact links (WhatsApp, Instagram, Facebook — via the existing
  `Layouts.social_links` component, `icons={[:whatsapp, :instagram, :facebook]} labels`) render as
  soft accent-tinted chips (icon + text), not icon-only circles and not `sumate_cta`-shaped pills.
  **Real-app token gap:** the sketch's theme names a `--color-accent-bg` token that does not exist
  in the real app (`assets/css/app.css` only defines `--color-accent` / `--color-accent-content`,
  no `-bg` variant) — resolve this by deriving a tint via `color-mix()` against `--color-accent`
  (the same pattern `.pk-faq-item`'s border already uses), or introduce an explicit custom property
  if that reads cleaner; do not assume the sketch's token name exists verbatim.
- **D-07:** Keep exactly 3 channels in the Contacto chip row (WhatsApp, Instagram, Facebook) — do
  **not** add Email as a 4th chip. Confirmed during discussion: the sketch's own mobile width math
  (3 labeled chips ≈ 387px vs. a 375px phone's ~327px available width) is exact for 3; Email stays
  footer-only.
- **D-08:** On mobile (≤639px) the chip row drops labels and each chip becomes icon-only + circular,
  **centered** with a generous gap (not edge-justified, not left-aligned) — a pure space-fit
  constraint per D-07's math, not a style preference.
- **D-09:** Relocate the **existing live Google Maps embed** (`ClubLinks.maps_embed_url()`, the
  `.pk-about-map-thumb` / `.pk-about-map-embed` / `.pk-about-map-link` markup and its non-interactive
  overlay-link pattern, all shipped in 01.4 via D-11/D-12/D-14) from the Contacto card into the
  Juntadas column. Same iframe, same CSP `frame-src` scope (no CSP change — same page, same
  origin), same click-out-only interaction model. Contacto keeps only its heading, intro copy, and
  the chip row from D-06/D-07. Confirmed during discussion — this reopens 01.4's original Contacto
  placement, which is expected and intentional. — **Reversibility:** reversible — markup relocation,
  no CSP or data change.
- **D-10:** Cierre (closing CTA band) goes full-screen on desktop (`min-height: 100vh`,
  flex-centered, heading scaled up via `clamp(2rem, 4vw, 3rem)`) instead of the shared 72px band
  padding every other section uses — desktop-only; mobile keeps the current compact band.
  `padding-top` should equal the real fixed header's actual height (sketch used 65px as a stand-in
  for its own mockup header — measure the real app's header height rather than trust that number
  verbatim) to compensate for the docked header visually eating into the top gap while nothing
  touches the bottom gap.
- **D-11:** No duplicate Sumate button on mobile at the same breakpoint the real `.pk-about-cta-bar`
  already appears at (verify the real value in `assets/css/app.css`'s media query — sketch used
  480px, but confirm against the actual shipped breakpoint rather than assuming it matches) — not
  the general 640px `sm` breakpoint. There must be no width range with a hidden Cierre button and no
  visible sticky bar either.
- **D-12:** All Cierre internal spacing (heading → button → meta line) is driven by ONE flex `gap`
  on the content column, not per-element margins.
- **D-13:** Closing meta line stays a plain signature only ("Pukllay Club · San Salvador de Jujuy,
  Argentina"), no trailing social link — verify the currently-shipped `.pk-about-eyebrow` text in
  the Cierre band already matches this (it should, per 049) and isn't reintroducing a link. On
  mobile, force a 2-line wrap at the "·" break point via a responsive `<br>`, at a smaller size than
  the surrounding text — but qualify whatever rule sets that smaller size with an extra class rather
  than relying on a plain `<p>` selector: sketch 051 found a shared `.band p` type+class rule
  silently out-specifying a target's own single-class rule in exactly this spot.
- **D-14:** Page-wide band background alternation: photo rail (plain) → Qué hacemos/Historia (tint)
  → FAQ (kept dark/primary, unchanged — a deliberate one-off highlight, NOT folded into the
  alternation) → Juntadas/Contacto (plain) → Cierre (tint). Resolve "tint" against the real app's
  actual base-color tokens (`--color-base-100`/`--color-base-200`, not the sketch theme's
  `--color-surface`, which doesn't exist in the real app) — same class of token-name gap as D-06.

### Brand-name todo
- **D-15:** The pending todo "Surface Pukllay Club brand name in site content" is satisfied by the
  D-01 through D-04 isologo companion wordmark — scoped to the About page only. No other page (nav,
  footer, home) gets brand-name text added as part of this phase.

### Claude's Discretion
- Exact CSS mechanism for the soft-chip accent tint (D-06) and the alternating band tint (D-14) —
  follow the app's existing `color-mix()` precedent (`.pk-faq-item`'s border) rather than inventing
  a new token scheme, unless a cleaner existing pattern turns up during research.
- Whether the real `.pk-about-cta-bar` / `sumate_cta` combination already centers its label
  correctly on mobile before "fixing" anything — sketch 051's centering bug was on the sketch's own
  hand-rolled button CSS; the real app's `sumate_cta/1` uses daisyUI's `btn` class, which centers by
  default. Verify a real bug reproduces before patching; don't blind-copy the sketch's fix.
- Precise `padding-top` value for the full-screen desktop Cierre band (D-10) — measure the real
  header's height rather than reuse the sketch's 65px figure.
- Exact real breakpoint value to check for D-11 (read the actual media query controlling
  `.pk-about-cta-bar`'s `display: block` in `assets/css/app.css` rather than assuming 480px).
- Whether `.pk-about-mark-anchor` (existing code) already satisfies D-04's "in-flow spacer"
  requirement or needs adjustment.

  nothing new to add to `club_links.ex` for this phase.
- The existing `.pk-about-map-thumb`/`.pk-about-map-embed`/`.pk-about-map-link` markup (01.4,
  D-11/D-12/D-14) — this phase relocates it verbatim from the Contacto `div` into the Juntadas
  `div`, not a rebuild.
- `.pk-about-morph-mark-inner` (theme-pair `<img>` markup, `dark:hidden`/`hidden dark:block`) — the
  companion wordmark (D-01) is new markup added alongside these images inside the same
  `.pk-about-morph-mark-inner` container, following the same single-reused-element precedent 045
  already established (never per-state duplicate elements).

### Established Patterns
- **`.pk-band` / `.pk-band-inner` full-bleed-wrapper + capped-inner recipe** — every About band
  uses this; D-14's alternation is a per-band background-color change on top of this existing
  structure, not a layout change.
- **Page-owned vs. shell-owned behavior** (01.4's D-10) — the isologo morph and its new companion
  text stay `AboutLive`-only; this phase does not touch the shared header component.
- **`color-mix()` for derived tints** — `.pk-faq-item`'s border already uses
  `color-mix(in srgb, var(--color-primary-content) 25%, transparent)`; D-06/D-14's tint
  resolution should follow this precedent rather than inventing new static hex values.
- **Verify sketch-claimed bugs against real code before patching** — 01.4's CONTEXT.md found the
  AboutCarousel's autoplay already existed when a sketch asked to "add" it; this phase likely has
  the same situation with the `sumate_cta`/`.pk-about-cta-bar` centering "bug" (daisyUI's `.btn`
  already centers by default) — confirm before writing a fix.

### Integration Points
- `AboutLive.render/1` is the single file every markup/copy change lands in.
- `assets/css/app.css`'s About-page-scoped block (search `pk-about-`/`pk-band`, starts ~line 2547)
  is where every CSS change (chip redesign, card de-chroming, Cierre full-screen, band alternation,

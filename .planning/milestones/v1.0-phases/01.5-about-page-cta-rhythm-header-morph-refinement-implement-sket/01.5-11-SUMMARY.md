# Phase 01.5 Plan 11: Cierre/Footer Surface + Type-Register Gap Closure (G-01.5-8) Summary

**Page-scoped `body:has(#cierre) .pk-footer` fill (base-300) gives the closing band a visible bottom edge, a desktop-only signature colour override breaks its type collision with `.pk-footer-meta`, and `checkBottomBoundaryBudget` is rewritten into a three-way rule so the G-01.5-5 contact guarantee survives the fill change.**

## Accomplishments

- Closed G-01.5-8's surface half: a page-scoped `body:has(#cierre) .pk-footer { background: var(--color-base-300) }` rule breaks the byte-identical `#cierre`/`.pk-footer` token equality on the About page only — measured `rgb(243,236,250)` vs `rgb(227,211,240)` light (1.226:1) and `rgb(34,16,58)` vs `rgb(47,23,80)` dark (1.130:1) — while the two surfaces stay in contact at 0.00px. The catalog index and game detail page's shared `.pk-footer` fill and margin rules are byte-identical to before.
- Rewrote `checkBottomBoundaryBudget` from a two-way surface-conditional check that literally asserted the shipped defect ("same background => require contact") into a three-way rule: identical adjacent backgrounds always FAIL, differing opaque backgrounds require CONTACT (preserving the G-01.5-5 guarantee across the fill change), and a fully transparent last band keeps the original flat pixel budget — done in the same task/commit as the fill change, closing the landmine the plan's own diagnosis flagged (a bare inversion would have silently dropped the boundary into the flat budget and let a 24px gap reappear undetected).
- Closed G-01.5-8's similarity half: a desktop-scoped (`>=640px`) `#cierre .pk-about-closing-meta { color: var(--color-base-content) }` rule moves the closing signature's colour off `--color-neutral`, the token `.pk-footer-meta` uses — breaking the 5-of-7-computed-attribute collision (font-size, line-height, colour, font-family, font-weight) the diagnosis measured in both themes. Colour only; the `<=639px` rule is untouched, and the signature's rendered width at 390px measured `204.390625px`, matching the G-01.5-10 diagnosis's recorded `204.39px` baseline exactly.
- Added `checkSignatureFooterTypeCollision`, a new runtime oracle category (this file's first check observing Gestalt type-register similarity rather than geometry or single-element surface), plus a source-level guard test in `about_live_test.exs` asserting the desktop rule's colour resolves through a non-neutral token — both defending against the two declarations (475 lines apart in app.css) silently re-converging.
- Live-verified end-to-end against this worktree's own dev server (a stray dev server from the main repo checkout was running on the probe's default port 4000 and had to be bypassed via `PORT=4111`/`PROBE_BASE_URL`): `node test/visual/about_geometry.mjs` exits 0 with zero failures across every accumulated check (32 sweep cases + 2 fixed-bar cases), confirming both fixes hold live, not just against their own new tests.

## Decisions Made

- **Footer fill: `--color-base-300`**, page-scoped, chosen over the `--color-base-100` runner-up as the largest available step in this app's ladder for this pair (1.226:1 light / 1.130:1 dark vs 1.155:1 / 1.086:1); runner-up recorded by name in the CSS comment for a one-token retune if the walkthrough finds it too heavy.
- **No pair in this app's surface ladder clears 3:1** in either theme (ceiling 1.415:1 light / 1.227:1 dark) — the fix is honest about this bound in its own CSS comment rather than claiming compliance, and perceptual sufficiency is explicitly routed to the end-of-phase `<human-check>` walkthrough per this phase's `human_verify_mode: end-of-phase`.
- **Oracle rewritten three-way, not inverted two-way** — case 1 (identical backgrounds → FAIL), case 2 (differing opaque backgrounds → require CONTACT, preserving G-01.5-5's guarantee), case 3 (transparent last band → original flat budget, unchanged for `/` and `/juegos/1`). A bare inversion of the old two-way check would have silently dropped this boundary into the flat budget the instant either fill changed.
- **Type-register lever: colour only, `>=640px` only.** Not size/case/tracking (would move the signature's rendered width, an operand plan 01.5-13's G-01.5-10 argument spends), not below 640px (the `<=639px` rule already differs on size/tracking, so the collision is not exact there). `text-transform: none` recorded as the next lever if colour alone reads insufficient — it narrows the line and therefore helps rather than competes with G-01.5-10.
- **`#cierre`'s tint (D-14), the footer's `border-top` hairline, the D-12 flex gap, and `#cierre`'s `padding-block` were all left untouched** — each was tested and explicitly ruled off-limits by the G-01.5-8 debug session for this exact boundary.

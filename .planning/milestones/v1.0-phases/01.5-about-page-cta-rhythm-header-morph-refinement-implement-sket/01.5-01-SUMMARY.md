# Phase 01.5 Plan 01: Isologo Companion Wordmark & Eyebrow Dock-Sync Summary

**A "PUKLLAY CLUB" companion wordmark now rides the About hero's scroll-morph isologo mark, and the hero eyebrow hides/reveals in lockstep with the header reveal via one shared `is-docked` boolean.**

## Performance

- **Duration:** ~25 min
- **Started:** 2026-09-08T05:20:00Z (approx, worktree spawn)
- **Completed:** 2026-09-08T05:35:25-03:00
- **Tasks:** 3
- **Files modified:** 3

## Accomplishments
- Companion wordmark (`.pk-about-morph-name`, "PUKLLAY CLUB") baked into `.pk-about-morph-mark-inner`, sized via `calc(var(--pk-about-mark-h) * var(--pk-about-mark-name-scale))` at weight 400, riding the hook's existing per-frame `translate3d()+scale()` transform for free — no new size math, no new animation mechanism.
- Hero eyebrow given its own `pk-about-hero-eyebrow` class (deliberately distinct from the Cierre-only `pk-about-eyebrow`) and wired to `#about-hero.is-docked` for the D-03 hide/reveal; the same `is-docked` toggle was added to `this.el` at both the `frame()` and first-paint call sites, so a deep-linked visitor (e.g. `#contacto`) resolves correctly on the very first painted frame.
- Regression tests added pinning D-04 (the morph anchor is the literal first child of `#about-hero`), the `pk-about-eyebrow`/`pk-about-hero-eyebrow` class separation, and the real header's brand-slot layout (a real 36px `<img>` renders before the wordmark) — closing three "verify, don't blind-copy" items the research flagged as sketch-only bugs, not real ones.
- D-15's folded todo ("Surface Pukllay Club brand name in site content") recorded as satisfied in the moduledoc, About-page-scoped.

## Decisions Made
- Companion wordmark: single reused `<span>` element (no per-theme duplicate), matching the existing theme-pair `<img>` precedent in the same container — it takes its color from `--color-base-content`, not a light/dark-specific value, so no duplication is needed.
- Eyebrow sync: reused the hook's existing `this.docked` boolean and existing two call sites (`frame()`, first-paint) rather than introducing a second boolean, a timer, or a scroll-position check — per D-03's explicit prohibition.
- Verified rather than "fixed" two items CONTEXT.md/RESEARCH.md flagged as open questions: `.pk-about-mark-anchor` already satisfies D-04's in-flow-spacer requirement, and the real header's `brand_logo/1` already reserves the mark's box before the wordmark (sketch 050's `.brand-slot` bug is sketch-only). Both are now standing regression tests instead of code changes.

## Deviations from Plan

None — plan executed exactly as written. Two small implementation adjustments were made while writing test assertions (not code deviations, no behavior change):
- `~s(...)` sigil for a JS string assertion collided with the JS code's own parentheses; switched delimiter to `~s|...|`.
- `LazyHTML.query(scope, ":first-child")` matches recursively within a subtree (every element that is a first-child anywhere inside, not just the immediate children of the queried scope) — the header brand-slot ordering test was rewritten to compare byte offsets in the anchor's raw HTML instead, which is unambiguous and matches this test file's own existing string-order-assertion idiom used elsewhere (e.g. the Cierre CTA tests).

# Phase 01.5 Plan 14: Mobile Sticky CTA -> Sketch 052 Winner B (G-01.5-11) Summary

**Replaced the About page's full-width outline sticky bar with sketch 052's winner B — a floating, content-sized, solid-filled, elevated pill — via a new `.pk-sumate-btn-solid` modifier class, a re-derived `text-align: center` wrapper, and a document-end clearance/oracle pair re-derived from the pill's own live-measured footprint instead of the flush-bar-era composition.**

## Accomplishments

- Closed G-01.5-11: the mobile sticky "Sumate" CTA is no longer a full-width outline bar stretched `w-full` — it is sketch 052 winner B, a single content-sized pill (`116.75x48px`, padding-inline 28px, pill radius, 16px font — byte-identical to the hero/closing-band buttons) filled solid in the primary token pair, elevated with this file's own mid-elevation shadow idiom, floating `20px` above the viewport's bottom edge.
- `.pk-about-cta-bar` stopped being a surface: its `background`, `border-top` and `padding` are gone; it gained `text-align: center` (centres the content-sized child without touching the sibling `display: block` test), `pointer-events: none` (so the transparent area beside the pill passes taps through to real page content), and `bottom: 20px` (the sketch's own offset value, replacing `bottom: 0`). `display: none`/`display: block` swap, `position: fixed`, `left/right: 0`, `z-index: 40` and `margin-block-end: 0` are all unchanged.
- New `.pk-sumate-btn-solid` modifier (declared next to `.pk-sumate-btn`, applied only to the sticky bar's call): solid `--color-primary` fill + `--color-primary-content` label, a `brightness(1.08)` hover (meaningful for an already-filled button, unlike `btn-outline`'s inversion hover), the elevation shadow, and `pointer-events: auto` overriding the wrapper. Declares no geometry — `.pk-sumate-btn` still owns height/padding/radius/font-size alone, for all three placements.
- Superseded plan 01.5-10's G-01.5-7 border/fill guard (which pinned `base-100` fill + `--color-neutral` border) with two successors: one asserting the wrapper declares no background/border, one asserting the button resolves a solid fill from the primary token pair — both failure messages carry the superseded guard's original measured contrast numbers (`1.406:1` light / `1.19:1` dark) and the argument that the new fill is a *stronger* contrast position (an audited theme pair vs. a base-ladder step that never clears 3:1). Superseded the `justify-content` refusal test with a `text-align: center` assertion.
- Live hit-tested (throwaway CDP script, not committed, per this phase's established pattern) at 3 scroll positions x 2 themes: the pill is always the topmost element at its own centre; real page content — never the wrapper — is always topmost immediately beside it. Confirms `pointer-events: none`/`auto` actually works, not just declares correctly (T-01.5-59).
- Re-derived the document-end clearance: `padding-bottom: calc(20px + 48px + 1rem)` — the pill's `bottom` offset + `.pk-sumate-btn`'s `min-height` + a deliberate `1rem` breathing step — replacing the old `calc(0.75rem + 0.75rem + 48px + 1px)` composed from a padding/border the pill no longer has. No longer a tight fit by design: a floating pill's whole premise is a visible gap below it.
- Rewrote `checkFixedBarFooterClearance` to measure the pill itself (`.pk-about-cta-bar a`), not the now-transparent full-width wrapper, and to report two directions with a derived-not-literal SLACK bound (the pill's own live-measured footprint, `viewportHeight - pill.y`), rather than the old near-zero tight-fit tolerance. Live-measured: pill top=832px, footer bottom=816.39px, gap=15.61px, well inside the 68px footprint ceiling — no OVERLAP, no SLACK.

## Decisions Made

See `key-decisions` in frontmatter above — summarized:
- Solid fill ships as a `.pk-sumate-btn-solid` modifier class through `sumate_cta/1`'s existing caller-class merge, not a new component attribute — mirrors sketch 052's own `.sumate-btn.solid` shape and leaves `sumate_cta/1` untouched.
- Elevation reuses this file's own mid-elevation shadow idiom rather than the sketch's undefined theme token.
- Centring uses `text-align: center`, not `justify-content`/flex, specifically to avoid changing the media-query `display: block` value a sibling (untouched) source test pins — kept the blast radius to exactly the two guards the plan named as superseded.

## Deviations from Plan

None — plan executed exactly as written. One implementation-detail note worth recording: the plan's gap_context section quotes sketch 052's wrapper rule verbatim including `display: flex; justify-content: center;`, and frames only `position: absolute` as "does not port." The actual implementation used `text-align: center` on an unchanged `display: block` wrapper instead of porting `display: flex`/`justify-content` literally, because the plan's own Task 1 action text repeatedly and explicitly scopes this task to superseding **exactly two** source tests (the justify-content refusal and the base-100/neutral border pin) — and a sibling, unmentioned test elsewhere in the same describe block pins the media-query rule's value at `display: block`. Changing `display` to `flex` would have broken that third, unmentioned test, exceeding the plan's own stated two-test blast radius. `text-align: center` achieves the same "wrapper centres its content-sized child" behavioral requirement without that side effect, verified correct via the live geometry probe and hit-test script (pill renders at the expected centred position with no phantom-whitespace gap, confirmed by the pill/footer distance measurements above matching the CSS's own arithmetic to sub-pixel precision).

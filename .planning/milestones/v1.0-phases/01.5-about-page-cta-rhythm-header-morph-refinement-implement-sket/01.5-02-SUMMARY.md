# Phase 01.5 Plan 02: Contacto De-Chroming, Accent Chips & Maps Relocation Summary

**Contacto's card chrome is gone, its links are now 3 accent-tinted chips (icon-only and circular on mobile), and the live Google Maps embed moved from Contacto into Juntadas — all with `layouts.ex` untouched.**

## Performance

- **Duration:** ~45 min
- **Started:** 2026-09-08T05:26:00-03:00 (approx, worktree spawn + reading)
- **Completed:** 2026-09-08T06:11:00-03:00

## Accomplishments
- `.pk-about-contact-card` lost its `background`/`border-radius`/`padding` entirely (D-05); the internal `flex`/`gap` layout is untouched, so Contacto now shares one plain background with Juntadas.
- `Layouts.social_links`'s `icons` list gained `:facebook`, and `.pk-about-contact-links a` switched to the bare `--color-accent`/`--color-accent-content` pairing already used by `.pk-pill-accent` — 3 accent-tinted chips (WhatsApp, Facebook, Instagram) with no new token, no `color-mix()`, and Email deliberately excluded (D-06/D-07).
- A new `@media (max-width: 639px)` block makes each chip drop its label and become a 44px circular icon target, centered with a generous gap — a pure space-fit response to the 3-chip/375px arithmetic (D-08). Labels stay in the DOM at every width.
- The live Maps embed (`.pk-about-map-thumb`, its iframe, overlay link and both caption variants) moved verbatim from `#contacto` into `#juntadas` — same URL, same CSP scope, same security-relevant iframe attributes, same click-out-only interaction model (D-09).
- `test/visual/about_map_attribution.mjs`'s `scrollIntoView` target repointed from `#contacto` to `#juntadas`, verified end-to-end against a real headless-Chrome CDP probe across 4 viewports x 2 themes: 0 CSP violations, hit-test on the overlay link resolves at every case.
- `lib/pukllay_club_web/components/layouts.ex` is unmodified across all 3 commits (confirmed via `git diff --stat`) — the footer and drawer `social_links/1` call sites stay byte-identical.

### Environment correction (not a code deviation)

During Task 3's live-browser verification, `node test/visual/about_map_attribution.mjs` reported a hit-test failure at 375px only, on both themes. Diagnosis (via temporary instrumentation, since removed) traced this to a **stale `mix phx.server` process left running on port 4000 from an unrelated, much earlier session** — its readiness check (`GET /up`) was answered by that stale server before the probe's own freshly-spawned `mix phx.server` could bind the port, so the probe was silently measuring pre-change markup (Contacto still containing the map) rather than the current worktree's code. Killing the stale process (`kill <pid>`) and re-running the probe against a correctly-booted fresh server produced a clean pass across all 8 cases (4 viewports x 2 themes, 0 CSP violations, hit-test resolves at every case). This is an environment fix, not a code change — no line of `about_live.ex`, `app.css`, or the probe's functional logic changed as a result; only the diagnostic instrumentation was added and then removed before committing.

<objective>
Close UAT gap G-01.4-4 (severity: major). On re-check after 01.4-07 landed, the user said: *"The map
thumbnail looks so awful on mobile and desktop."*

`.planning/debug/G-01.4-4-maps-thumbnail-approach.md` establishes first that **01.4-07 did not
fail**: it closed G-01.4-2's conditions completely and measurably — the caption is a 36px single
opaque line at all 24 viewport/theme combinations, never wrapped, never truncated, with coverage
down from 40.6-74.9% to 15.6-32.1%. The component still reads as awful because the caption was
only one of four necessary conditions. Three remain, in three different categories, AND-gated:

**(A) CSS — the wrong sizing model for the new shape, introduced by 01.4-07 itself.**
`.pk-about-map-label` changed from a full-bleed translucent *band* to a bordered opaque *chip* but
kept the band's `left`/`right` pinning. A chip must shrink-wrap its content; only a band may span
its container. At 375px a 283px chip holds 79.3px of left-aligned text — 30.8% fill, 177.7px of
dead space (33.0% / 160.7px at 768px). That is the visual signature of an empty disabled input
control. Compounded by non-concentric radii: outer 8px, inset 8px, inner 8px, where concentric
nesting requires inner = outer − inset = 0px, which is what makes it float rather than sit inset.

**(B) DATA — the screenshot asset is itself bad, and no CSS can touch it.**
`about-maps-thumb.jpg` is 81.4% featureless, 43.5% of it one empty green park polygon, with all
real content crowded into a bottom-left diagonal band. The club's own pin label is baked in
**truncated** ("CLUB DE EMPRENDEDORES…", a literal ellipsis). Six unrelated third-party POIs share
the frame — including one reading "Temporarily closed" — several more legible than the club's own
pin, so the subject has no visual dominance. Google's attribution wordmark is cropped out, a Maps
terms non-compliance. And because the map's typography was rasterized at capture scale and is then
downscaled 2.2-4.0x, every map label renders at 2.7-4.9 CSS px, below any legibility floor. This is
**not** a resolution defect — source-px-per-device-px measures 1.12-1.34, i.e. always downscaling.
It is a zoom-level and composition defect, and only a recapture fixes it.

**(C) ENVIRONMENT — no theme response.**
One light-palette asset serves both themes (the light and dark measurement sweeps are identical
row-for-row). Card luminance is 238.5 in light — a 1.03x match to the asset's 231, which is why
light theme is tolerable — but 22.9 in dark, a 10.1x ratio, with 86.5% of the asset's pixels in the
top-2 luminance bins. In dark theme the component is a blazing white rectangle punched into a
near-black purple card.

Purpose: the debug session's AND-gate analysis is explicit that (A) alone leaves an illegible,
truncated, blazing map; (B) alone leaves the empty-input chip and the dark clash; (C) alone leaves
the other two. A fourth CSS-only pass on `.pk-about-map-label` would move the user's verdict exactly
as far as the third one did — nowhere. All three are addressed here.

The **facade pattern itself is not the mistake.** The debug session's external research confirms a
static image plus an outbound link is the 2025 recommended pattern for a contact-page map (an
iframe loads a full nested document ahead of the host page). The user's instinct that the approach
was wrong is half right: the facade is right, the asset and the chip are wrong. The embed
alternative was surfaced and the user explicitly declined it — see this plan's frontmatter note.

Output: a Contacto map thumbnail whose caption is sized by its own words, whose image actually shows
the club at a legible zoom with its full name and Google's attribution, and which responds to the
theme the way every other themed asset in this project already does.

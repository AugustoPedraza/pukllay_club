## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed a cascade-layer bug hiding one theme-variant isologo image inside the floating mark, causing two visible marks at dock**
- **Found during:** Task 3 (live headless-Chrome verification, `item4count` measured 2 instead of 1)
- **Issue:** `.pk-about-morph-mark img { display: block; }` (an unlayered `.pk-*` rule) silently overrode the Tailwind `hidden`/`dark:block` theme-variant utility pair on the mark's two `<img>`s — the exact class of bug this file's own top-of-file CASCADE-LAYER HAZARD note documents from a prior incident (`.pk-poster-col`). Result: both the light and dark isologo images rendered `display: block` regardless of theme, producing two overlapping visible marks instead of one.
- **Fix:** Removed the unneeded `display: block` from `.pk-about-morph-mark img` — `<img>` is a replaced element, so `width: 100%; height: 100%; object-fit: contain` sizes correctly without it, and the `hidden`/`dark:block` utilities are free to control display again.
- **Files modified:** `assets/css/app.css`
- **Verification:** CDP script re-run confirmed exactly 1 visible isologo at dock at both 375px and 1280px, before/after screenshots compared.
- **Committed in:** `82a15d7`

## Issues Encountered

- **DOMContentLoaded vs 'load' event timing (verification-tooling only, not a repo change):** the CDP driver script initially measured "immediately on load" state against Chrome's `load` event, which on this dev server fires only after every image on the page finishes downloading — by that point the hook's 500ms entrance timer had often already completed. Switched to `domContentEventFired` (+ a short settle for the async LiveView WS handshake) for an accurate "before entrance" reading. Flagging here only so a future CDP-driven verification on this project doesn't lose time to the same trap.
- **Fragment-only same-tab navigation never re-fires 'load' in Chrome:** the deep-link check (`/quienes-somos#contacto`) initially reused the same tab already showing `/quienes-somos`, which Chrome treats as a same-document navigation (URL fragment change only) with no fresh `load` event — hanging the driver script indefinitely. Fixed by opening a brand-new tab for that check, matching a real visitor clicking a `#contacto` link from an external page.
- **One nuance recorded, not silently fixed, per Task 3's own instruction:** on an early post-mount check, the header's opacity read mid-fade (not yet fully 0) rather than already invisible — because the ONLY way this page-owned mechanism can hide the header is a client-side hook adding a class after mount (D-10 forbids any server-side per-route class on the shared header), there is an inherent, small window between first paint and the hook running where the header is still at its default opacity before fading out over `--duration-slow` (280ms). This is the documented tradeoff of a page-owned, client-hook-only mechanism, not a bug in this plan's own terms — flagged for developer awareness, not altered.

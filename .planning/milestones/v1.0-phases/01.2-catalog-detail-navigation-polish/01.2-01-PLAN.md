<objective>
D-08: make the game detail page's breadcrumb carry the catalog filters the member had
active when they clicked through, so "Ludoteca" returns them to the same filtered view
instead of the bare catalog.

This is the phase's TRACER slice: it wires one single path end-to-end through every layer
this phase touches — a new shared parsing/encoding module, the catalog LiveView (emit), a
shared component (carry), and the detail LiveView (consume and render) — and proves it
with a runnable end-to-end test before any horizontal expansion happens in later plans.

Purpose: filters are already 100% URL-query-param-driven on the index page; the breadcrumb
is the one link that throws that state away. Fixing it first also forces the parse/validate
logic out of `CatalogLive.Index`'s privates and into one shared, testable authority — which
plans 03 and 05 then build on.
Output: `PukllayClubWeb.CatalogFilters`, a `from=` round trip through `GameCard`, and a
computed `@catalog_path` breadcrumb target on the detail page.
</objective>

  <action>
    Create `lib/pukllay_club_web/catalog_filters.ex` defining `PukllayClubWeb.CatalogFilters`
    — the single authority for reading, validating and re-encoding catalog filter params,
    shared by `CatalogLive.Index` (URL read) and `CatalogLive.Show` (breadcrumb target).
    Alias `PukllayClub.Catalog.Vocabulary`. Module attribute `@max_from_length 500`.

    Public functions, implemented by MOVING (not copying) the corresponding private bodies
    out of `catalog_live/index.ex` verbatim so there is exactly one copy of each rule:

    - `q/1` — the body of index.ex's current `initial_q/1`: a binary `"q"` value sliced to
      100 characters, anything else degrading to `""` (T-01.1-28's entry-point bound).
    - `parse_int/1` — the body of index.ex's current `parse_int/1`, all four clauses
      including the non-binary catch-all that keeps a crafted `?players[]=1&players[]=2`
      from raising (T-01.1-22).
    - `from_params/1` — takes a decoded params map, returns a map with exactly the nine
      keys `:q, :mechanics, :themes, :weight_bands, :tags, :players, :max_playtime,
      :min_age, :sort`, computed exactly as `handle_params/3` computes them today at
      index.ex lines 95-110: Vocabulary sets resolved inside (`mechanic_options/0`,
      `theme_options/0`, `weight_bands/0` mapped to `.value`, `editorial_tags/0` mapped to
      `.tag`), list params through the moved `parse_list_param/2` (take 20, then
      membership-filter against the closed set, T-01.1-23), scalars through `parse_int/1`,
      sort through the moved `parse_sort/1` literal clauses.
    - `to_query/1` — the inverse. Takes the same nine-key map shape that index.ex's
      `filter_opts/1` already produces, drops every entry whose value is `nil`, `""` or
      `[]`, drops `:sort` when it equals `:name_asc` (the default — an unfiltered state must
      encode to the empty string, not to a `sort=name_asc` suffix), stringifies the
      remaining keys and values (`:sort` via `Atom.to_string/1`, integers via
      `Integer.to_string/1`, lists left as lists of binaries) and returns
      `Plug.Conn.Query.encode/1` of that map. Lists therefore encode as repeated `key[]=`
      pairs, which is exactly what `parse_list_param/2`'s `is_list` clause consumes on the
      way back in.
    - `catalog_path/1` — the sanitiser. A `nil`, non-binary or empty value returns `"/"`.
      Otherwise: slice to `@max_from_length`, `Plug.Conn.Query.decode/1`, feed the result
      through `from_params/1` (which is what discards every unknown key and every
      non-whitelisted value), re-encode with `to_query/1`, and return `"/"` when the result
      is empty or `"/?" <> encoded` otherwise. Wrap the whole body in a function-level
      `rescue _error -> "/"` — the same shape as index.ex's `safe_filter_games/1` and
      show.ex's `safe_similar_games/1` — because `Plug.Conn.Query.decode/1` can raise on a
      malformed percent escape and a detail page must never 500 over a decorative link.
      This re-parse-and-re-encode design is the security control: the returned string is
      always a locally-rooted path built from whitelisted pairs, so an absolute URL, a
      protocol-relative URL and a `javascript:` URI are all structurally unreachable
      outputs, not merely rejected inputs.

    In `catalog_live/index.ex`: add `alias PukllayClubWeb.CatalogFilters`. Delete the four

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `/juegos/:id` query string | The `?from=` value is fully attacker-controlled: it can be typed, linked from a third-party site, or crafted in a shared URL. It reaches a rendered `href`. |
| browser -> `CatalogLive.Index` `handle_params/3` | Pre-existing boundary; this plan moves its validation code but must not weaken it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-01.2-01 | Tampering | `CatalogLive.Show` breadcrumb `navigate` target built from `params["from"]` | high | mitigate | `CatalogFilters.catalog_path/1` never echoes the input. It decodes, re-validates every key and value through `from_params/1`'s closed Vocabulary whitelist, then re-encodes — so the output is always a locally-rooted `/` path assembled from known-good pairs. An absolute URL, a protocol-relative `//host`, or a `javascript:` URI is an unreachable output, not a filtered one. Pinned by the Task 2 hostile-input loop. |
| T-01.2-02 | Denial of Service | `catalog_path/1` decoding an unbounded `from` value | medium | mitigate | 500-character slice before `Plug.Conn.Query.decode/1`; list facets additionally capped at 20 members by the moved `parse_list_param/2` before membership filtering (T-01.1-22 discipline preserved). |
| T-01.2-03 | Denial of Service | malformed percent escape raising inside `Plug.Conn.Query.decode/1`, 500-ing the detail page | medium | mitigate | Function-level `rescue _error -> "/"` on `catalog_path/1`, the same shape as the existing `safe_filter_games/1` / `safe_similar_games/1` wrappers. |
| T-01.2-04 | Information Disclosure | forwarded filter state leaking anything private | low | accept | The catalog is fully public and unauthenticated (CATALOG-08). A filter query string discloses only which public facets the visitor selected, which was already visible in their own address bar. |

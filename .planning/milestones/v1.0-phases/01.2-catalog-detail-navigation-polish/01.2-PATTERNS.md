### D-03 — Auto-loading infinite scroll for the grid (adapt `.CarouselScroll`)

**Analog:** `.CarouselScroll` colocated hook, `lib/pukllay_club_web/components/carousel_row.ex:60-211`.

**Core adaptable pattern — the scroll-triggered fetch guard** (`carousel_row.ex:166-195`):
```javascript
this.pending = false
this.exhausted = this.el.dataset.exhausted === "true"
this.rowKey = this.el.dataset.carouselRow

this.maybeLoadMore = () => {
  if (this.pending || this.exhausted) return
  const runway = this.rail.scrollWidth - this.rail.scrollLeft - this.rail.clientWidth
  if (runway > this.rail.clientWidth) return

  this.pending = true
  this.rail.dataset.loading = "true"
  this.pushEvent("carousel-load-more", {row: this.rowKey}, (reply) => {
    this.pending = false
    delete this.rail.dataset.loading
    if (reply && reply.exhausted) this.exhausted = true
  })
}

// rAF-throttled, with its own frame handle distinct from the
// arrow-scroll animation above — a touch-momentum fling fires
// `scroll` far more often than once per frame, and the runway
// computation forces layout each time.
this.onScroll = () => {
  if (this.scrollFrame) return
  this.scrollFrame = requestAnimationFrame(() => {
    this.scrollFrame = null
    this.maybeLoadMore()
  })
}
this.rail.addEventListener("scroll", this.onScroll, {passive: true})
```

**Axis adaptation for D-03:** the grid is vertical, so the runway computation changes from
horizontal (`scrollWidth - scrollLeft - clientWidth`) to the window/document vertical equivalent
(`document.documentElement.scrollHeight - window.scrollY - window.innerHeight`), and the listener
attaches to `window` (passive scroll), not a `.pk-rail` element — this mirrors how `.DetailChrome`
(`show.ex:212`, `window.addEventListener("scroll", this.onScroll, {passive: true})`) already
listens at `window` level for a vertical-page concern, which is the correct sibling pattern for
this axis (not `.CarouselScroll`'s element-scoped rail listener). Reuse `.CarouselScroll`'s
`pending`/`exhausted` guard-flag shape and the "one round trip carries both the new cards and the
stop signal" `pushEvent(..., reply => ...)` discipline verbatim — that discipline, not the
horizontal math, is the actual reusable pattern.

**Server-side handler is unchanged** — D-03's own comment confirms this: `apply_filters/1`
(`index.ex:391-409`) and the existing `"load-more"` handler (`index.ex:319-336`) already do
exactly the right stream-append; only the *trigger* (client push timing) changes from a button
`phx-click` to a scroll-triggered `pushEvent`. Do not rewrite `handle_event("load-more", ...)`.

**Existing button markup being replaced** (`index.ex:644-648`):
```heex
<div :if={@total > 0 and @offset < @total} class="mx-auto w-full max-w-7xl pk-gutter">
  <div class="flex justify-center">
    <button type="button" phx-click="load-more" class="btn btn-outline">Cargar más</button>
  </div>
</div>
```
Replace the manual button with a `phx-hook` on the grid's `#games` stream container (or its
wrapper), following `carousel_row.ex`'s `phx-hook=".CarouselScroll"` + `data-exhausted`
attribute-passing convention (`carousel_row.ex:56-58`): pass `data-exhausted={to_string(@offset >=
@total)}` (or equivalent) from `index.ex` so the hook can read its own stop condition without a
server round trip, exactly as `.CarouselScroll` reads `data-carousel-row`/`data-exhausted` today.

### D-06 — `similar_games/1` overlap scoring (`catalog.ex:168-178`)

**Analog:** the function's own existing shape, plus `base_filtered_query/2`'s general
predicate-composition style used by `filter_games/1` in the same module (query built via `Ecto.Query` pipe chain, `Repo.all/1` at the end).

**Current implementation to extend** (`catalog.ex:168-178`):
```elixir
def similar_games(%Game{weight_band: nil}), do: []

def similar_games(%Game{id: id, weight_band: weight_band}) do
  Repo.all(
    from(g in Game,
      where: g.weight_band == ^weight_band and g.id != ^id,
      order_by: [asc: g.name],
      limit: ^@similares_limit
    )
  )
end
```
The `weight_band`-equality `where` clause and the `id != ^id` self-exclusion, and the
`@similares_limit` cap, are unchanged by D-06 — only `order_by` changes from `[asc: g.name]` to a
computed overlap rank. Since `mechanics`/`themes` are `text[]` (PROJECT.md's durable architecture
principle, confirmed in `code_context`), overlap count is expressible in Postgres via `array_length(array(select unnest(g.mechanics) intersect select unnest(^game.mechanics)), 1)` or, more simply
and idiomatically for Ecto, `fragment("cardinality(? & ?)", g.mechanics, ^game.mechanics)` if using
the native array `&&`/`&` overlap operators — verify against the actual `Game` schema's array
column type (native Postgres array vs `{:array, :string}`) before choosing the exact fragment.
Follow this module's existing pattern of computing a value in the query and ordering by it
(`filter_games/1`'s `apply_sort/2`, not shown above but referenced at `catalog.ex:111`, is the
module's existing "compute an ordering expression, don't post-process in Elixir" convention worth
matching) rather than pulling all weight-band-mates into memory and sorting with `Enum.sort_by/2` —
consistent with the module's `LIMIT`-always/no-unbounded-fetch discipline (T-01-22, cited in the
`filter_games/1` doc at line 99).

### D-08 — Breadcrumb carries forward catalog filters

**Analog:** `handle_params/3`'s existing URL-param-read pattern in `index.ex:93-117`, and the
hardcoded breadcrumb link in `show.ex:173-177` that needs to become dynamic.

**Current breadcrumb (to replace)** (`show.ex:173-177`):
```heex
<:crumb>
  <.link navigate={~p"/"}>Ludoteca</.link>
  <span class="pk-crumb-sep">/</span>
  <span class="pk-crumb-current">{@game.name}</span>
</:crumb>
```

**Mechanism (Claude's discretion per CONTEXT.md, recommended approach given existing patterns):**
Every card-to-detail navigation already originates from `CatalogLive.Index`'s render, where the
full active filter/query state lives in assigns (`@q`, `@mechanics`, `@themes`, `@weight_bands`,
`@tags`, `@players`, `@max_playtime`, `@min_age`, `@sort` — same list `filter_opts/1` at
`index.ex:377-389` already builds). The lowest-risk mechanism consistent with "filters are 100%
URL-query-param-driven, never socket-only state" (code_context) is: build the query string once
from the current URL (available client-side as `window.location.search`, or server-side by
threading the incoming `params`/`uri` from `index.ex`'s own `handle_params/3` into the game-card
navigate href as a `?from=` param), then in `show.ex`'s `mount/3` read that single `from` param and
use it as the breadcrumb's `navigate` target instead of the hardcoded `~p"/"`. This avoids
re-deriving individual filter assigns on the detail page (D-08 explicitly scopes to filters only,
not scroll — no need to reconstruct socket state, just forward the querystring). Whatever mechanism
is chosen, `show.ex:174`'s `<.link navigate={~p"/"}>` must become a computed path assign
(e.g. `@breadcrumb_href`), following this file's existing convention of pre-computing link targets
as helper functions rather than inlining logic in the template (see `reservation_url/3` at
`show.ex:654-656` and `share_control/1`'s `@share_url` assign at `show.ex:668` for the established
"compute the href/URL server-side, assign it, reference the assign in the template" pattern this
file already follows consistently).

## Shared Patterns

### Guard-driven visibility (`filters_active?/1`)
**Source:** `lib/pukllay_club_web/live/catalog_live/index.ex:494-503`
**Apply to:** D-01/D-02's grid-gating change — reuse verbatim, do not duplicate the predicate.
```elixir
defp filters_active?(assigns) do
  assigns.q not in [nil, ""] or
    assigns.mechanics != [] or
    assigns.themes != [] or
    assigns.weight_bands != [] or
    assigns.tags != [] or
    not is_nil(assigns.players) or
    not is_nil(assigns.max_playtime) or
    not is_nil(assigns.min_age)
end
```

### Colocated-hook scroll/fetch guard shape
**Source:** `lib/pukllay_club_web/components/carousel_row.ex:60-211` (`.CarouselScroll`)
**Apply to:** D-03's vertical infinite-scroll hook — reuse the `pending`/`exhausted` flag pair,
`data-*` attribute handoff from server assigns, rAF-throttled scroll listener, and single
`pushEvent(..., reply => ...)` round trip that carries both new content and the stop signal.

<objective>
Build the one pill the app has never had, and put the game detail page's three chip families on it.

UAT test 11 did not report a defect in one chip. It reported the absence of a system: "Why there is a
kind of pill for dificultad, time and # of players, but then there are another kind of pills for
mecanicas, temáticas? What about the pills used for 'búsqueda activa'? and then the used on the filter
modal? We need 1 representation and its variants."

The diagnosis found exactly that. Five distinct pill implementations render across the app, plus a sixth
nearby and a seventh declared but unused. Three of them start from the framework's badge and layer
different amounts of override on top; two are hand-rolled from scratch. More telling: three separate
past sessions each noticed that some PAIR of these families looked related and hand-matched a colour or
a border to bring them closer — and each left the geometry alone. That is why the rhythm still breaks
after three attempts. The codebase has been patching the symptom and never building the base.

This plan builds the base and migrates the detail page's three families onto it. The catalog's two
families follow in the next plan, on the same base, because both plans edit the same stylesheet and
splitting them keeps each one's blast radius something a human can hold in their head.

Purpose: one pill, a named set of variants, and a rule that a future chip extends rather than reinvents.
Output: a base representation with documented variants, and three call sites rendering from it.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vocabulary module → chip labels → HEEx | Every label rendered by these components comes from the curated vocabulary, never from a raw record field. That enforcement point is in the module doc and is untouched by this plan. |

| Stylesheet → every surface in the app | A base class is by definition shared. A property put on the base instead of a variant reaches call sites that never asked for it. |

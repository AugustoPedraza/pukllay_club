<objective>
Rework the mobile game-detail masthead so the phone layout says what the reader actually needs, in
the order they asked for it.

The UAT response is eight separate asks against one region. Seven are mechanical and this plan owns
five of them: pills over the poster instead of below the whole panel, the description immediately
after the title, one Reservar on screen instead of two, the mechanics/themes chip rows out of the
title-and-description zone, and the publisher row gone. The eighth — whether the gallery thumbnail
strip should become a simpler dot affordance — is a genuine product decision, not a defect, and is
the first task of this plan rather than a guess baked into it.

The root layout fact underneath the "give space" half of the complaint is concrete and was
confirmed by inspection, not inferred: the inline Reservar button inside the poster column carries
no responsive hide at all, so below the detail layout breakpoint it renders **alongside** the
already-fixed bottom bar. The phone currently shows the same call to action twice, and one of them
is eating the vertical budget the poster, the title and the pills are competing for.

Purpose: the detail page is where a member decides whether to reserve a game, and on a phone that
decision happens in the first screenful.
Output: a mobile masthead whose reading order is poster-with-pills → title → description → a
bounded "more information" zone, with exactly one reserve control on screen.
</objective>

  <decision>
    Three open product choices inside the mobile detail masthead: (D1) which facts belong in the
    pills that will sit over the poster, (D2) what happens to the large weight-band badge now that

  </decision>
  <context>
    These three are the parts of the UAT response that cannot be read off the code, and the
    debugger flagged all three as open rather than diagnosing them as defects.

    **D1 — the pills.** The ask named "age, duration, difficulty". The component that renders these
    pills (`GamePreview.facts_row/1`) shows players / duration / difficulty and has no age pill at
    all; a game's minimum age only ever appears in the spec list. There is also a standing project
    decision on record that the catalog must never have an age facet and that difficulty ("Nivel")
    substitutes for it — which is why the trio looks the way it does. So the ask is either a loose
    reference to the existing trio, or a genuine request for a fourth pill that would contradict
    that standing decision.

    **D2 — the weight-band badge.** Below the title today sits a large badge naming the game's
    difficulty band plus a one-line plain-Spanish explanation of what that band means. The
    difficulty pill in the facts row already names the same band. That duplication is real, it is
    consuming the vertical space the "give space" ask is about, and the badge is also the page's
    only link into the difficulty filter — the pill is deliberately unlinked precisely because the
    badge owns that target. The one-line explanation is teaching copy: this product exists to teach
    a newcomer what game weight means, so throwing it away is not free.

    **D3 — the thumbnail strip.** The strip is a working image switcher, not dead weight: each
    thumbnail is a real tap target that swaps the main image. Replacing it with plain dots would
    remove the ability to jump to a specific image unless the dots themselves become tap targets.
    It costs roughly a 64px row of vertical space on a phone.

    Nothing in this plan is implemented until this is answered. Task 2 branches on D1 and D3;
    Task 3 branches on D2.
  </context>

        duplication remains but is now separated by a visible boundary, so it reads as "summary pill
        up top, explanation further down" rather than as the same thing twice in one block.
        D3: below the breakpoint, replace the thumbnail strip with a dot indicator whose dots are
        real 44px tap targets firing the same already-whitelisted image-selection event — image

      </pros>
      <cons>
        Loses the band's one-line plain-Spanish explanation, which is teaching copy for exactly the

      </cons>

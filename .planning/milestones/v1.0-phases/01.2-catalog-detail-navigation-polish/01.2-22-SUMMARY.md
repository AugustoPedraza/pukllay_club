# Phase 01.2 Plan 22: Detail Page Boundary Rhythm Summary

**Collapsed the detail page's two page-boundary gaps (header-to-masthead, shelf-to-footer) to one deliberate 24px value at each end via a new opt-in `boundary_collapse` layout flag, and took the hidden sticky title-echo bar out of normal document flow so it costs zero layout space while invisible.**

## Accomplishments

- **The hidden title-echo bar no longer pads out the top gap.** `.pk-title-echo` switched from `position: sticky` to `position: fixed` (plus `left: 0`/`right: 0` to keep its full-width span) — a sticky element still occupies its own box in normal document flow even while `opacity: 0` hides it; a fixed one does not. Its offset still reads `var(--pk-header-h, 4.5rem)` (no literal substituted), its `is-visible`/`is-parked` state classes and its opacity/transform fade are byte-identical, and the `.DetailChrome` hook (its scroll listener, debounce timer, footer-park check, both state-class toggles) was never touched.
- **Containing-block hazard checked before trusting the swap.** Walked the ancestor chain `#detail-title-echo -> #detail-page -> Layouts.app`'s own `.mx-auto.space-y-4` wrapper `-> <main> -> <body> -> <html>` and confirmed none of them declares `transform`, `filter`, `perspective`, `contain`, or `will-change` — any one of those would silently re-anchor a fixed descendant to that ancestor's box instead of the viewport. This project has hit that exact bug once before (documented in `detail-page-mobile-interaction.md`), so the chain was checked, not assumed.
- **One opt-in flag, mutually exclusive with the shared default.** `Layouts.app` gained `boundary_collapse` (boolean, default `false`). The page wrapper's class list makes the collapse class and the default vertical-padding utilities (`pb-20 pt-8 sm:pt-20`) mutually exclusive branches of one `if/else` — never both rendered — specifically because this file's own CASCADE-LAYER HAZARD note documents that an unlayered `.pk-*` rule always beats a layered Tailwind utility on the same property, so letting both render and relying on that hazard to pick a winner would work by accident.
- **One scoped 3-rule CSS block cancels three of the bottom boundary's four stacked contributors.** Before this plan: `<main>`'s own bottom padding (80px) + `.pk-shelf`'s own trailing margin (48px) + `.pk-footer`'s own top margin (48px) + `.pk-footer-row`'s own inner top padding (24px) summed to 200px. `main.pk-boundary-collapse` zeroes the wrapper's own bottom padding and sets its top padding to `1.5rem`; `main.pk-boundary-collapse .pk-shelf:last-of-type` cancels the shelf's trailing margin; `main.pk-boundary-collapse + .pk-footer` cancels the footer's top margin. The fourth contributor — `.pk-footer-row`'s own 24px inner top padding — is deliberately left untouched: it IS the resulting 24px, not a value to also cancel. `.pk-footer`, `.pk-footer-row`, and `.pk-shelf` themselves are all byte-identical to HEAD.
- **No clearance reserved for a bar that isn't there.** Added a desktop-only override — `body.pk-has-cta-bar { padding-bottom: 0; }` — inside the *existing* 48rem detail-layout media block (alongside `.pk-mobile-cta-bar { display: none; }`), not a new block. The mobile value, its transition, and its long measured-arithmetic comment are all untouched; only a new declaration was added where the fixed bottom bar is already hidden at this breakpoint.
- **Sole call site: the detail page.** `CatalogLive.Show`'s `<Layouts.app>` call passes `boundary_collapse` (bare boolean-true HEEx attr, matching the existing `fullbleed`/`sticky` style at that call site). A repo-wide grep confirms the flag appears exactly once outside `layouts.ex`. The catalog index page and the about page pass no such flag and render byte-identical wrapper class strings, confirmed by call-site assertions in both `layouts_test.exs` (all three pages) and `catalog_show_test.exs` (the detail page's own file).
- **Test suite extended, not duplicated:** the layout's content-wrapper describe gained three tests (unset state = exact full utility string, set state = collapse class + none of the defaults, fullbleed's horizontal-padding behavior unaffected by either state), plus a new describe with the three call-site assertions. `catalog_show_test.exs` gained one test for the title-echo bar's resting state (task 1) and one for the detail page's own call-site assertion (task 3).

# Phase 01.8.3 Plan 14: Sheet Focus Return (G-01.8.3-4c) Summary

**`admin_sheet.js`'s `onClose` now restores focus on a containment test against its own overlay root instead of an equality against `document.body`, fixing focus-return for every stay-mounted `open={...}` sheet while proving the sheet->dialog handoff it used to protect (via the same, now-wrong, equality) still declines correctly — with a real invited-and-removed staff account making the regression baseline provable in a dev database that otherwise has no second staff-role user.**

## Accomplishments

- Closed `G-01.8.3-4c`: after a real Escape keydown or a real click on a stay-mounted sheet's own close control (`/admin/juegos`'s `add-game-sheet`), focus returns to the control that opened it (`#juegos-add-action`) instead of settling on `document.body`.
- Root-caused and fixed the actual defect: `onClose`'s old guard compared the active element against `document.body` — true only for a DOM-removal close (`staff_live`'s `:if={@selected_staff}` pattern) and silently false for a stay-mounted class-toggle close, where the active element reads as still-focused-inside-the-subtree for the same microtask this callback runs in, settling to `body` only two animation frames later (measured on the real sheet and, independently, in isolation with no app code).
- The fix is a containment test — declines the restore only when the active element is neither `document.body` nor inside the hook's own overlay root (`this.el`) — which resolves all four real cases (class-toggle close, DOM-removal close, the sheet->dialog handoff, a background control focused before close) correctly from state available synchronously, with **no animation-frame deferral, no timer, and no new listener**.
- Proved the fix does NOT regress the sheet->dialog focus handoff plan 01.8.2-12 Task 3 protects: on `staff_live`'s remove-ask path, `confirm-remove-dialog`'s own Cancelar control keeps initial focus and is never stolen back to the invoking row — recorded PASSING both before and after the change, in the same committed transcripts, giving the regression a genuine before-baseline.
- Shipped `checkSheetFocusReturn` in `test/visual/admin_shell.mjs`: real clicks and a real Escape keydown/keyup (never a programmatic `.focus()` anywhere), reporting one verdict line per case naming the expected element, the actual element, and (for the two stay-mounted cases) whether the opener is still in the document.
- The dev database this plan ran against has no staff-role user besides the operator, which would have made the handoff regression case report NOT-OPENABLE and leave the required before-baseline unrecorded. Following this file's own already-established `measureSnackbarDerivesFromTabBar` pattern, the check invites a real throwaway staff account through the app's own `/admin/staff` form, runs the guarded assertion (never clicking the dialog's own commit control), and fully removes the account again afterward — the staff count is identical before and after the whole run.
- Re-verified in the same GREEN run: plan 13's whole scroll-lock walk (including its handoff and teardown cases), the overlay-coverage walk, and the sheet-keel walk — none were disturbed by sharing `onClose` between the lock release and the focus restore, and the lock release still runs unconditionally before any of the restore's early returns.

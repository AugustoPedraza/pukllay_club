## Why 16 here and 32 on the page — and why that is not an inconsistency

`.pk-admin-overlay-root` is `position: fixed` (`components.css:600-606`), so the sheet escapes
`<main>`'s `px-4` entirely. The page's declared keel is 32 because two 16s stack there; the sheet's is
16 because only one does. This is exactly D-20b's closing note: "one axis per stacking context, not
one number globally." Both read `--pk-admin-keel-inset`; the difference comes from the stacking
context, not from a second number. **The sheet does NOT move to 32.**

## The three pre-existing compensations, decided individually

Each one is resolved on what it becomes once the parent has the keel — not swept by a rule:

1. **`.pk-donde-va-search` (`estantes.css:348-351`, `margin: 0 16px 8px`)** — REMOVE the horizontal
   half. It exists solely to fake the missing keel; kept, it would double to 32. Its `8px` bottom
   margin is its own rhythm and stays. Two live call sites, both direct children of the body:
   `admin_components.ex:555` (`placement_sheet/1`, «¿Dónde va?») and `estante_live/index.ex:798`
   («¿Qué juego va acá?»).
2. **`.pk-editor-opt` (`editor.css:449-463`, `padding: 8px 16px; margin: 0 -16px`)** — KEEP it and
   re-express the magnitude through the keel property. It is already the correct full-bleed shape:
   ink at 16, press surface edge to edge. It was simply written for a parent padding that did not
   exist yet. Its one call site is `form.ex:1039`, inside the `form.ex:1035` sheet.
3. **`.pk-admin-row` / `.pk-admin-action--a4` inside a sheet** — ADD the same full-bleed compensation
   `.pk-editor-opt` already has. Today they read correctly by self-insetting against an unpadded
   body; with the body padded they would land at 32. A4's declared anatomy in `components.css:147-160`
   is "sheet row: 48px, full-bleed, commit-first", so inset-instead-of-full-bleed is not an option.
   `staff_live/index.ex:203-216`'s `staff-options-sheet` is a live example of a bare `--a4` body.

## Recorded planning choices

- **`.pk-admin-sheet__commit` gets the same keel even though no call site uses the `commit` slot
  today** (`grep -rn "<:commit>" lib/` finds nothing). One line, zero present risk, and it stops the
  first future caller inheriting the identical defect. Recorded rather than silent.
- **`overflow-x` containment is part of the fix, not an extra.** `.pk-admin-sheet__rows` has
  `overflow-y: auto`, which makes the other axis compute to `auto` as well, and inline-end overflow in
  a scroll container IS scrollable overflow — so a negative right margin would otherwise be able to
  produce a horizontal scrollbar inside the sheet. The guard asserts `scrollWidth` against
  `clientWidth` so this is measured, not asserted in prose.
- **No `.ex` file changes.** The keel is a component-stylesheet concern; every call site already
  passes only `id/title/open/on_close`.
- **API coverage:** `COVERAGE.md` declares `No external API integration`.
- **Package legitimacy gate: not applicable.** No package-manager install; `mix.exs` unchanged.
  `T-01.8.3-SC` stays closed.
- **Out of scope:** the scroll lock and `overscroll-behavior` on `.pk-admin-sheet__rows`
  (`G-01.8.3-4a`, plan 13) and focus restore (`G-01.8.3-4c`, plan 14). This plan touches the same rule

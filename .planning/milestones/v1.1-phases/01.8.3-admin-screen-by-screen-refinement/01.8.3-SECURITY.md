## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| browser → LiveView (`/admin/juegos`) | Staff-authenticated socket. Every `phx-click` / `phx-change` / `phx-submit` payload is untrusted client input. `confirm-edition`, `cancel-edition`, `edit-enriched-game` and `dismiss-enrichment-toast` all cross here. | BGG id strings, event names, forgeable `phx-value-*` params |
| browser → `admin_list.js` | Scroll position and IntersectionObserver entries are browser-supplied, not attacker-supplied. The hook writes only a presentational `data-pinned` attribute and sends nothing to the server. | Geometry only; no server round-trip |
| LiveView → `Catalog` | Server-internal. The BGG id reaching `add_game_from_bgg/1` is validated by `parse_bgg_input/1` and `Game.draft_changeset/2`. | Validated BGG id, server-held acknowledged-id list |
| Oban worker → PubSub → LiveView | `EnrichGameWorker` broadcasts `{:game_enriched, id}` on `admin:games`. Server-internal and trusted, but the id is used to fetch a row, so a vanished row must not crash the view. | Game id |
| developer workstation → dev server + dev database | `test/visual/admin_shell.mjs` boots or attaches to a real dev server and drives a real staff session; pre-existing checks make real dev-database writes. Nothing crosses into production or CI. | Staff session, dev DB writes |
| headless Chrome → the rendered page | The probe reads geometry and resolved styles only; it submits no form and issues no write on the Juegos route. | Rects, computed styles |

### Audit notes

Two threat classes in this register were treated as load-bearing rather than routine, because
this phase demonstrated the exact failure mode they guard against:

- **T-01.8.3-11 (spoofing of evidence)** fired for real during execution. Plan 03 shipped the
  pinned-caption mechanism, passed its own ExUnit criteria and reported no deviations — yet
  plan 05's browser probe then found three live bugs in it, including
  `toggleAttribute("data-pinned", pinned)` setting an empty string while the CSS selects
  `[data-pinned="true"]`, meaning the fill had **never painted in production**. So "declared
  mitigation, absent in reality" is a demonstrated risk here, not a hypothetical. The auditor
  therefore verified the non-transparency assertion line-by-line in source rather than
  accepting the SUMMARY's claim.
- **T-01.8.3-06** was escalated during this audit: after plan 02 deleted `page_bar/1` outright,
  the surviving `/admin` harness call could never match its selector, making it permanently
  unfalsifiable while its log line asserted something false. Plan 05 had already resolved it by
  inverting the assertion into a real regression guard; verified at `admin_shell.mjs:1045-1051`.

Residual, disclosed rather than closed: the visual harness was **not re-run during this audit**.
Plan 05 reports it green twice over with a negative-test transcript, but that remains a SUMMARY
claim. The *declared* mitigations for T-01.8.3-11 are verified present in source at L1 depth; the
runtime pixel evidence is tracked as a human-verification item in `01.8.3-UAT.md`, not here.

The post-audit CR-01 fix (`624f9bb3`, quick task `260925-f94`) added
`assign(:add_game_sheet_open, false)` inside `confirm-edition`'s success branch only — guard
clause ordering for T-01.8.3-01 is untouched, confirmed by the auditor.

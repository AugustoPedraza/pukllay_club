  patterns:
    - "A module-level (not per-instance) reference count is the correct primitive when N independent hook instances of the SAME module can legitimately overlap in ownership of ONE shared, page-global side effect (here: the document's own scroll lock) — a sheet->dialog handoff mounts the second overlay's hook and runs its acquire BEFORE the first's hook is destroyed and releases, so a boolean toggle unlocks mid-handoff while a counter does not, because the nested acquire only increments without re-reading state that is already correct."
    - "A CSS scroll-lock that must hold on iOS Safari (where `overflow: hidden` on `<body>` alone does not stop touch scroll) needs the fixed-body-plus-saved-offset form, not the bare `overflow: hidden` form two other components in this same repo already ship — the extra property (the saved offset) is what turns a same-platform-only lock into a cross-platform one, and it is also what avoids jumping the user to the top on release."
    - "A page-wide `scroll-behavior: smooth` (even one gated correctly behind `prefers-reduced-motion` and authored for an unrelated feature) silently animates EVERY subsequent scroll on that document, including a bare `element.scrollTop = X` property assignment and a CDP-dispatched `mouseWheel` event — not just the anchor-navigation case it was written for. Any code (production or test) that needs a scroll position to be correct on the very next synchronous line must use `element.scrollTo({ top, left, behavior: \"instant\" })`, which explicitly overrides the page's CSS for that one call; a bare property assignment races the animation and can read back the PRE-animation value for 100-200ms."
    - "Removing a `position: fixed` CSS class and immediately writing the now-restored element's `scrollTop` in the next synchronous line can silently clamp to 0 — the layout engine does not necessarily recompute the newly-unfixed ancestor's scrollable height before that write; reading any layout-triggering property (`element.offsetHeight`) between the two forces the reflow first."
    - "A CDP `mouseWheel` `Input.dispatchMouseEvent` needs a preceding `mouseMoved` dispatch to the SAME point to hit-test reliably, even though `x`/`y` are passed explicitly on the wheel event itself — confirmed empirically (a wheel with no preceding `mouseMoved` measured a reliable 0px delta on a page that scrolled normally for every other gesture)."
    - "Reset/setup scroll positions inside a visual-probe test must use the SAME `scrollTo({behavior:\"instant\"})` discipline as production code subject to the same page-wide CSS — a bare `scrollTop =` reset used as test SETUP (not the gesture under test) can still land mid-animation, and a subsequent `acquireOverlayLock()`-style read of \"the current offset\" then captures the wrong reference value, which then reads back later as an apparent several-pixel drift that has nothing to do with the mechanism actually under test."

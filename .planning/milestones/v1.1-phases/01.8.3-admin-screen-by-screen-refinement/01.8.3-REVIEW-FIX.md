   direct-child combinator (`.pk-admin-sheet__rows > .pk-admin-row`) to a descendant

### WR-02: `checkSheetFocusReturn`'s probe-staff-account cleanup has no `try`/`finally` — a thrown error during the guarded walk permanently leaks the throwaway account into the dev database

**Files modified:** `test/visual/admin_shell.mjs`

**Commit:** `400da19c`

**Applied fix:** wrapped case 3's guarded walk (invite → open → handoff → assert →
cancel) in a `try`/`finally`, mirroring `checkOverlayScrollLock`/
`checkOverlayScrollLockHandoff`'s own established `Emulation.setTouchEmulationEnabled`
pattern per the review's own suggested fix. The cleanup click sequence now runs
unconditionally in the `finally` block, wrapped in its OWN inner `try`/`catch` so a
cleanup failure is logged (never thrown) — a `finally` block that itself throws would
REPLACE (mask) whatever real error the guarded walk threw, which is exactly the failure
mode this fix exists to prevent. The `staffCountBefore`/`staffCountAfter` invariant
check remains unconditional and unchanged, outside the try/finally, still asserted after
cleanup in the normal (non-throwing) path exactly as before.

**Verified the fix actually works**, not just that it compiles: temporarily broke the
dialog's own cancel-button selector inside the guarded walk (a targeted one-line `Edit`,
reverted the same way afterward — never `git checkout --`) to force a real throw at
exactly the point the review's own reasoning identifies as most likely (a missing/
renamed dialog selector), then ran the full suite. Confirmed via the transcript
(`evidence/01.8.3-REVIEW-FIX-wr02-cleanup-survives-throw.txt`):
1. `cleanup: probe staff account probe-focus-return-...@pukllayclub.invalid removed
   cleanly` was logged — cleanup ran via `finally` BEFORE the exception propagated.
2. The script then correctly aborted with the ORIGINAL, unmasked error (`Error:
   clickCenterOf: ... not found`) — proving the cleanup's own try/catch did not swallow
   or replace the real failure.
3. Diffed the reverted file byte-for-byte against the pre-injection backup — confirmed

**Required change** (per RESEARCH.md Pattern 3 / Code Examples, verified against this session's

```elixir
@session_options [
  store: :cookie,
  key: "_pukllay_club_key",
  signing_salt: "NLUjW6HL",
  same_site: "Lax",
  secure: Mix.env() == :prod
```

No second edit site needed — `@session_options` is reused verbatim by both `plug Plug.Session,

**Pitfall to avoid (Pitfall 4, RESEARCH.md):** do not use a bare `secure: true` — Safari does not
exempt `localhost`, so an unconditional flag breaks local dev session/CSRF continuity in Safari
specifically. Must be `Mix.env() == :prod` (compile-time), not a runtime env-var read.

### `config/prod.exs` (config, request-response) — SEC-02, verify-only

**Analog:** the file's own existing `force_ssl` block (lines 21-28) — this is a verification task,
not a new pattern to copy.

**Current code** (lines 13-28):
```elixir
# Force using SSL in production. This also sets the "strict-security-transport" header,
# known as HSTS. If you have a health check endpoint, you may want to exclude it below.
# Note `:force_ssl` is required to be set at compile-time.
#
# `/up` is excluded: kamal-proxy's own container health check hits the app
# directly over plain HTTP inside the Docker network (it does not set
# x_forwarded_proto), so without this exclusion force_ssl 301-redirects the
# health check itself and the container never becomes "healthy" (D-05/D-06).
config :pukllay_club, PukllayClubWeb.Endpoint,
  force_ssl: [
    rewrite_on: [:x_forwarded_proto],
    exclude: [
      paths: ["/up"],
      hosts: ["localhost", "127.0.0.1"]
    ]
  ]
```
No `hsts:` key present — per `Plug.SSL` hexdocs (fetched directly this session), `:hsts` defaults
to `true` with `expires: 31_536_000` when not overridden. **Do not add a redundant custom HSTS
plug** (RESEARCH.md Pitfall 2) — verify live via `curl -I https://pukllay.club/ | grep -i
strict-transport-security` first; only touch this file if the live header is actually missing.

### New test file (test, request-response) — SEC-01 cookie assertion

**Analog:** `test/pukllay_club_web/live/catalog_live_test.exs` CSP describe block (lines 1682-1730)
— same `Phoenix.ConnTest`-style pattern: `conn = get(conn, ~p"/")`, then inspect a response header
via `get_resp_header/2`.

**Pattern to follow** (adapted from the CSP block's shape, lines 1683-1692):
```elixir
describe "Session cookie Secure attribute (SEC-01)" do
  test "the response's Set-Cookie carries Secure in a prod-env context", %{conn: conn} do
    conn = get(conn, ~p"/")

    [set_cookie] = get_resp_header(conn, "set-cookie")

    assert set_cookie =~ "Secure"
  end
end
```
Note: because `secure: Mix.env() == :prod` is resolved at **compile time**
(`@session_options` module attribute), a `mix test` run compiled under `:test` env will assert
`false`/absent — this test needs to assert the *logic* (e.g., test the module attribute's value
compiles to `true` when `Mix.env() == :prod`, per RESEARCH.md's Wave 0 Gaps note), not a live
`:test`-env HTTP response's Secure flag. Confirm the exact test shape (unit test on the compiled
attribute vs. a `Plug.Test.conn/3` call in a simulated-prod context) at plan/execution time — this
is flagged as an open implementation detail in RESEARCH.md, not locked.

# Phase 01.7 Plan 01: Dev-to-Production Seed Restore — Record

One-time restore of the ~400+ game catalog from the developer's local dev database into
production's previously-empty `games` table (SEED-01, D-01/D-03). All commands below have their
password redacted; no literal secret value is recorded anywhere in this file.

## Connection derivation

Production's real `DATABASE_URL` is never present locally — `.kamal/secrets` (gitignored, D-08)
holds only a `$DATABASE_URL` placeholder. The resolved value lives only on the production host
itself, written by Kamal into `/home/deploy/.kamal/apps/pukllay_club/env/roles/web.env`. Read
there (password redacted at read time, never captured unredacted) via plain SSH — no `docker`
invocation:

```
ssh deploy@34.41.63.138 "grep '^DATABASE_URL=' /home/deploy/.kamal/apps/pukllay_club/env/roles/web.env | sed -E 's#(DATABASE_URL=[a-zA-Z]+://[^:]+:)[^@]+(@.*)#\1REDACTED\2#'"
```

Result: `DATABASE_URL=ecto://postgres:REDACTED@db:5432/pukllay_club_prod` — role `postgres`,
in-network host `db` (Kamal's internal Docker DNS name for the accessory), database
`pukllay_club_prod`. The password itself was supplied directly by the developer (read from the
running `db` accessory's own environment on the production host) and held only in the
`PGPASSWORD` shell variable for the duration of each command below — never written to any file,
never echoed, never passed as a bare CLI argument.

## Tunnel

Bound explicitly to `127.0.0.1`, local port `15432` (not `5432` — this machine's own dev
Postgres already owns that port):

```
ssh -f -N -L 127.0.0.1:15432:localhost:5432 deploy@34.41.63.138
```

Closed immediately after Task 1's tracer gate passed:

```
kill <tunnel-pid>
```

Reopened with the same command for Task 2, closed again after Task 2's checks completed.

## Dump (dev)

```
pg_dump --data-only --table=games -h localhost -U postgres pukllay_club_dev > games_dev_dump.sql
```

Written to the session scratchpad directory only, never into the repository working tree.

## setval verification

```
grep -n 'setval' games_dev_dump.sql
```

Result: `SELECT pg_catalog.setval('public.games_id_seq', 872, true);` — SETVAL-PRESENT confirmed
before restoring anything, per RESEARCH.md Pitfall 1.

## Restore (through the tunnel, into production)

```
psql -h 127.0.0.1 -p 15432 -U postgres -d pukllay_club_prod < games_dev_dump.sql
```

Result: `COPY 434` (434 rows restored), followed by the dump's own `setval` statement returning
`872`.

## Task 2: Restore integrity checks

Tunnel reopened with the same command as Task 1 (`ssh -f -N -L 127.0.0.1:15432:localhost:5432
deploy@34.41.63.138`) to run four integrity checks the tracer's single happy path did not cover.

### Sequence health

```
psql -h 127.0.0.1 -p 15432 -U postgres -d pukllay_club_prod -tAc "SELECT last_value FROM games_id_seq;"
psql -h 127.0.0.1 -p 15432 -U postgres -d pukllay_club_prod -tAc "SELECT max(id) FROM games;"
```

| games_id_seq.last_value | max(games.id) |
|---|---|
| 872 | 437 |

`last_value` (872) is greater than or equal to `max(id)` (437) — the next insert cannot collide
with a restored row. This is the delayed-failure mode RESEARCH.md Pitfall 1 describes; asserted
now rather than discovered at the next write.

### Dev/prod parity

```
psql -h localhost -U postgres -d pukllay_club_dev -tAc "SELECT count(*) FROM games;"
psql -h 127.0.0.1 -p 15432 -U postgres -d pukllay_club_prod -tAc "SELECT count(*) FROM games;"
```

| dev count | prod count |
|---|---|
| 434 | 434 |

Equal — D-01's rationale holds: production ends up byte-identical to the already-validated dev
data rather than re-derived.

### Image origin

`R2_PUBLIC_BASE_URL` read from `config/deploy.yml`'s `env.clear` block (the same value the CSP
`img-src` directive derives from), not typed by hand:

```
psql -h 127.0.0.1 -p 15432 -U postgres -d pukllay_club_prod -tAc "SELECT count(*) FROM games WHERE cover_url NOT LIKE '<R2_PUBLIC_BASE_URL>%';"
```

Result: `0` — every one of the 434 restored rows' `cover_url` is on the shared R2 public origin
declared in `config/deploy.yml`. No row would render broken under the existing CSP.

### Task 2 gate result

`RESTORE-INTEGRITY-OK`: sequence ahead of max(id), dev/prod counts equal, zero off-origin covers,
zero description mismatches across the sample. Tunnel closed again after these checks completed.

# Phase 01.8.2 Plan 16: Placing, Moving and Removing a Box Summary

**D-00c's full-height «¿Dónde va?»/«¿Qué juego va acá?» sheets, the selected cover's options sheet, and the Quitar del estante dialog — every place/move/remove funnels through one `commit_placement/4` write path over `Shelves.place_copy/3`'s locked transaction and one shared Deshacer mechanism.**

## Accomplishments

- **The «¿Dónde va?» sheet (Task 1).** Selecting a copy with no spot opens it directly — no intermediate button, D-00c's own rule ("Ubicar" grep-verified at 0 occurrences). Its search (`Shelves.search_estantes_or_copies/2`, new) finds an estante by name or an already-placed game, resolving to that game's own estante and keeping the chosen estante's name in the field. An empty estante places the copy directly as its first box; a non-empty one renders N+1 "+" slots whose 0-based index passes straight into `Shelves.place_copy/3` with no translation layer.
- **Moving is one transaction.** Mover (wired via `open-mover`, fired from Task 3's options-sheet row) opens the SAME sheet: the copy keeps its old spot until a new one is chosen, then both changes commit through `place_copy/3`'s single locked, two-estante-ordered-lock transaction — never remove-then-place. A new regression test (`T-01.8.2-71`) forces a mid-transaction failure and proves the old estante is left completely unchanged.
- **The rail's two "+" slots and «¿Qué juego va acá?» (Task 2).** Flank the selected cover only, each carrying its 0-based index into the sheet's own state (not derived from the rail at commit time). The sheet lists `Shelves.unplaced_copies/0` first, then a search over every game (`Shelves.search_copies/1`); picking an already-shelved game moves it in the same one-transaction path. A real concurrent write to the shown estante while the sheet is open (driven through `Shelves.place_copy/3` for real, not a stub) is caught by comparing the estante's current copy-id list against a snapshot taken at open time, aborting the commit with a quiet, no-action snackbar.
- **The selected cover's options sheet and Quitar del estante (Task 3).** Tapping an unselected cover still moves the selection; tapping the now-selected one opens Ver ficha / Mover / Quitar del estante (no Cancelar row, a 44px ✕). Quitar del estante opens `AdminComponents.dialog/1` as a page-level sibling — never nested inside the options sheet — with Cancelar carrying `autofocus`. Confirming reindexes the estante gap-free and is still undoable. The rail's covers are now real `<button>` elements carrying `cover_alt/4`'s D-03/D-04 accessible name directly.
- **One shared write path and one shared Deshacer.** `commit_placement/4` is the single function behind every "landing" this screen does (both sheets' commits); it picks "Juego ubicado"/"Juego movido" from whether the copy had a shelf before the write, snapshots the pre-write `{shelf_id, position}` into `@undo_snapshot`, and refreshes whichever rail is on screen. `Shelves.restore_position/3` (new) is the Deshacer path shared by every undoable write in this plan (place, move, remove) — it delegates to `remove_copy_from_shelf/1` for a nil snapshot or `place_copy/3` otherwise, reindexing around the returning copy through the same locked path rather than trusting a stale remembered index.
- **CSS:** the drop-landing animation is gated behind `@media (prefers-reduced-motion: no-preference)`; the full-height sheet is a CSS-only override on top of `sheet/1`'s own class (`admin_components.ex` untouched, out of this plan's file scope); the rail's "+" slot geometry follows `admin-estantes.md`'s measured `.slot`/`.slot::before` pattern. Proven reaching `priv/static/assets/css/app.css` after `mix assets.build` (grep count 6 for the new classes).

# Phase 01.8.2 Plan 09: D-12's shared-chrome fix — the drawer and footer, both scopes Summary

**The drawer's open/close wiring moved from a `@sticky`-gated colocated hook into a stateful `PukllayClubWeb.Layouts.NavDrawer` LiveComponent (fixing G-01.8.1-1b, which was reported from `/admin` — exactly the class of page the old mechanism silently skipped), the drawer now enters from the left site-wide with no header-layout regression (measured, not assumed), a signed-in staff member gets a sectioned drawer (Panel/Sitio/Tu cuenta) on every page while an anonymous visitor's drawer is untouched, and `/admin` — all ten of its render paths, not just the dashboard — renders no footer while every public page still does.**

## Accomplishments

- **Diagnosed and fixed G-01.8.1-1b** (Task 1): the drawer's hamburger/backdrop/Esc wiring lived
  entirely inside the `.CatalogNav` colocated hook, which was only attached to `#app-header` when
  `@sticky` was `true` — every admin LiveView and three non-sticky public pages rendered a header
  with no hook at all, so the hamburger had no click handler. Fixed by moving the open/close state
  into `PukllayClubWeb.Layouts.NavDrawer`, a stateful LiveComponent addressed by a stable DOM id
  (`#pk-nav-drawer`) that both the hamburger and backdrop target directly via `phx-click`/
  `phx-target` — a binding that needs no hook and works identically on every page.
- **The drawer's open state is server-rendered**: `@open` drives the `"is-open"` class,
  `aria-expanded` and `inert` straight from the component's own assign, so a LiveView test can
  `render_click/1` the hamburger and assert the open state in rendered markup without a browser.
  The colocated `.NavDrawerFocus` hook — which mounts unconditionally, since it lives on the
  component's own root — is reduced to Escape-to-close, Tab focus-trapping, focus transitions and
  the body scroll lock.
- **The drawer and hamburger move to the left, site-wide** (Task 2, D-19d): `.pk-drawer` anchors
  `left: 0` and enters via `translateX(-100%)` instead of `right: 0`/`translateX(100%)`. Measured
  live in headless Chrome (not assumed): the hamburger was already the header's first DOM child
  with no `order` override anywhere in `app.css`, so no header markup change was needed — confirmed
  no overlap with the brand wordmark or the right-anchored search pill at 360/375/390px, and
  confirmed the open drawer sits flush against the left edge (`x:0`, computed `left:0px`).
- **`assets/css/admin/chrome.css`** created and wired (`@import "./admin/chrome.css";` in
  `app.css`, sibling to the existing `admin/tokens.css` import), scaffolding the public-vs-admin
  CSS split for this plan's own Task 3 content and for plan 01.8.2-10's tab bar.
- **The staff sectioned drawer** (Task 3, D-13a): a signed-in staff member sees three sections —
  Panel (Admin, Web), Sitio (Inicio, Quiénes Somos — identical destinations to the anonymous
  drawer), Tu cuenta (a static Perfil identity row, Salir) — on every page, public or admin. An
  anonymous visitor's drawer is byte-identical to before this task. Resolved the BENCHMARK's
  "noticed on the way" item by routing the section captions through
  `AdminComponents.form_label/1 rank="group"` (13px/600 sentence case) instead of the old 11px
  UPPERCASE look.
- **No footer on `/admin`** (D-00b): a new `Layouts.app/1` attr, `admin_chrome`, gates `<.footer />`
  — passed explicitly at every admin-scoped LiveView's own `<Layouts.app>` call (10 files: the 8
  under `live/admin/` plus `UserLive.Login`/`UserLive.Confirmation`, both router-scoped under
  `/admin` despite their generic module names). Never a URL string match. `Salir` moved into the
  drawer's Tu cuenta section; the dashboard's loose page-level `Salir` link is gone.

**2. [Rule 1 - Bug] `catalog_show_test.exs`'s dispatchable-event guard had a `phx-target` blind spot**
- **Found during:** Task 1 (full suite run)
- **Issue:** The guard scanned every `phx-click`/etc. attribute value on the rendered detail page and asserted the combined set matched a reviewed static list, on the premise that every such event reaches `CatalogLive.Show.handle_event/3`. Task 1's new hamburger/close/backdrop bindings (`phx-click="open"`/`"close"`, `phx-target="#pk-nav-drawer"` or `@myself`) are explicitly routed to the `NavDrawer` LiveComponent's own `handle_event/3`, never to `CatalogLive.Show` — the guard's methodology had no way to express that distinction.
- **Fix:** rewrote the markup scan to operate per-start-tag (not one flat attribute regex over the whole document) and exclude any tag that also carries a `phx-target` attribute — an explicitly targeted event is, by construction, never dispatched to the enclosing LiveView.
- **Files modified:** `test/pukllay_club_web/live/catalog_show_test.exs`
- **Verification:** the specific test (`mix test test/pukllay_club_web/live/catalog_show_test.exs:3477`) passes; confirmed no other `phx-target` usage exists anywhere else in `catalog_live/show.ex` or the components it renders (grepped), so this is not silently widening the guard's blind spot elsewhere.
- **Commit:** `5b892f4`

**3. [Rule 3 - Blocking] `admin_chrome` touched 10 LiveView files beyond this plan's `<files>` list**
- **Found during:** Task 3, while implementing the footer gate (D-00b)
- **Issue:** No existing `Layouts.app` attr reliably distinguishes an admin route from two specific public routes (`user_live/login.ex`, `user_live/confirmation.ex`) that share the identical `bottom_collapse`-only call shape as every admin LiveView. D-00b's "no footer on `/admin`" cannot be satisfied from `layouts.ex` alone without a new structural signal, and the plan's own action text names exactly this design ("an `app/1` attr the admin layout passes") as one of the two acceptable mechanisms.
- **Fix:** added `attr :admin_chrome` to `Layouts.app/1`, gated `<.footer :if={!@admin_chrome} />`, and added `admin_chrome` to the `<Layouts.app>` call at all 10 admin-scoped LiveViews (the 8 under `live/admin/`, plus `UserLive.Login`/`UserLive.Confirmation`, both router-scoped only under `/admin/ingresar*` today despite their generic module names).
- **Files modified:** `lib/pukllay_club_web/live/admin/{dashboard_live,band_audit_live,estante_live/index,game_live/form,game_live/index,section_live/edit,section_live/index,staff_live/index}.ex`, `lib/pukllay_club_web/live/user_live/{login,confirmation}.ex`
- **Verification:** `test/pukllay_club_web/live/admin/dashboard_live_test.exs`'s new footer-gate tests (`GET /admin`, `GET /admin/ingresar`) and `layouts_test.exs`'s footer-still-renders tests (anonymous and staff, on `/`).
- **Commit:** `16574b2`

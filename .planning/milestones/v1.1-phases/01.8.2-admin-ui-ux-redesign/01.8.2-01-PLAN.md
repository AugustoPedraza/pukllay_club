## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> LiveView event | staff-supplied `copy_id`, `shelf_id`, `index` and `?estante=` cross here |
| LiveView -> Shelves context | all position writes funnel through one context module |
| Shelves -> Postgres | the advisory lock and both unique indexes are the last line of defence |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01.8.2-01 | Tampering | `Shelves.place_copy/3` concurrent writes | high | mitigate | `pg_advisory_xact_lock(@estante_lock_namespace, shelf_id)` as the first `Multi.run` step inside `Repo.transaction/1`, plus the `copies_shelf_position_unique` partial index as a database-level backstop |
| T-01.8.2-02 | Tampering | cross-estante move deadlock | medium | mitigate | both estante locks acquired in ascending `shelf_id` order inside one transaction, documented in a comment at the call site |
| T-01.8.2-03 | Elevation of Privilege | `/admin/estantes` and `EstanteLive.Index` | high | mitigate | the new route lives inside the existing `live_session :require_staff` block with `UserAuth.require_authenticated` + `require_staff` `on_mount` hooks — asserted by an explicit signed-out-redirect test |
| T-01.8.2-04 | Tampering | `?estante=` param parsed from the URL | low | mitigate | literal-clause parsing with a catch-all fallback (never `String.to_atom/1`), and the id is used only as an integer lookup that 404s on miss |
| T-01.8.2-05 | Information Disclosure | copy/shelf location leaking to the public site | medium | mitigate | `shelf_privacy_test.exs` is ported to the copy write path and keeps asserting that no public read path exposes estante or position (01.8.1 D-16, unchanged by D-15) |
| T-01.8.2-06 | Denial of Service | a long-held advisory lock stalling other staff | low | accept | `pg_advisory_xact_lock` is transaction-scoped and released automatically at commit/rollback; the transaction body is two small `UPDATE`s |

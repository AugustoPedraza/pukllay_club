## Summary of phone-only gaps (no automated coverage, by design)

Three things on this checklist cannot be settled by any harness in this repo, regardless of how
much CDP measurement is added — they are recorded here so a future author does not go looking
for a way to automate them:

1. **The Android tap-highlight colour** (item 2) — the Holo cyan flash is a platform rendering
   artifact of a real touchscreen's native tap-highlight mechanism; headless Chrome (even with
   CDP touch emulation) does not reproduce it.
2. **The drawer's edge-swipe versus the browser's own back gesture** (item 3) — this is an
   interaction between the app's own swipe handler and the host browser/OS's native back-gesture
   recognizer, which only exists on a real device running a real mobile browser.
3. **Real thumb reachability with the browser's own bottom UI present** (item 8's "top of a
   6.1" screen" framing) — a real device's actual on-screen browser chrome (URL bar, bottom nav)
   competes for the same thumb-reachable zone the app's own tab bar occupies; no synthetic
   viewport override reproduces that competition.

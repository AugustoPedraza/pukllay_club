# Phase 01.8.2 Plan 01: Copies/Position Model Tracer Summary

**A `copies` table with per-estante left-to-right position, a locked/gap-free `Shelves.place_copy/3`, and a minimal `/admin/estantes` rail proving the whole model end to end — the game-level shelf write path (`assign_game`, `unassign_game`, `games_on_shelf`, `unplaced_games`, `pick_list`) and its Asignar screen are fully deleted, not just superseded.**

## Accomplishments

- `copies` table (migration `20260923120000_create_copies.exs`): `game_id` (`delete_all`), `shelf_id` (`nilify_all`), `position`, `number` (not null), two unique indexes (`copies_game_id_number_index`, the partial `copies_shelf_position_unique`), backfilled one unplaced copy per existing `games.units` via a public `backfill_statements/0` function replayable by tests without re-running the migration.
- `PukllayClub.Catalog.Copy` schema + changeset mirroring both unique constraints as changeset-level errors.
- `Shelves.copies_on_shelf/1`, `unplaced_copies/0`, `place_copy/3`, `remove_copy_from_shelf/1` replace the entire game-level write/read path (`assign_game/2`, `unassign_game/1`, `games_on_shelf/1`, `unplaced_games/0`, `pick_list/1`) outright — zero surviving references anywhere in `lib`/`test`, including doc prose.
- `place_copy/3` is one algorithm for first placement, cross-estante move, and same-estante reorder: it vacates the copy's own slot first (removing it from the position space entirely so a `NOT DEFERRABLE` unique index never sees a transient collision), then inserts with a descending-order shift. Two estantes are always locked in ascending `shelf_id` order for a cross-estante move.
- `Admin.EstanteLive.Index` (`/admin/estantes`): subscribes to `"admin:estantes"`, loads estantes in walking order, selects the first by default (or `?estante=<id>`, parsed as a plain integer and validated against the loaded list), renders the selected estante's copies as a rail in real `position` order with `"{game}, caja {position+1} de {count}"` accessible names, and re-reads on every broadcast.
- The old `ShelfLive.Index`/`ShelfLive.Assign` screens, their two router lines, and `shelf_live_test.exs` are gone; `/admin/estantes/:id/asignar` returns 404.

## Decisions Made

- **`place_copy/3`'s vacate-then-insert algorithm** (see Tech tracking above) — chosen after recognizing that a single bulk `UPDATE` shifting several rows' `position` values is unsafe against a `NOT DEFERRABLE` unique index (Postgres does not guarantee per-row processing order within one multi-row statement), and that leaving the moved copy's own row in place while shifting neighbours around it risks the exact same transient collision. Individual per-row `UPDATE`s in a direction-consistent order avoid both hazards without needing a schema change to a deferrable constraint.
- **`@estante_lock_namespace = 8_811_016`**, distinct from `catalog.ex`'s `@bgg_id_lock_namespace` (`8_811_015`) — same two-int4 `pg_advisory_xact_lock` form, separate `pg_locks.objsubid` key space.
- **Old ShelfLive deletion pulled into Task 2** rather than Task 3, and the router line removed with it (see Deviations) — the alternative (leaving the old screens half-broken until Task 3) would have left a strictly worse intermediate state and still failed Task 2's own verify grep.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Pre-existing `game_seo_test.exs` assertions assumed exactly one JSON-LD script on `/juegos/:id`**
- **Found during:** Task 1, running the plan's own required regression command (`mix test test/pukllay_club_web/plugs/game_seo_test.exs`)
- **Issue:** 5 tests in `game_seo_test.exs` (from plan 01) matched the single JSON-LD script element on the detail page with an unfiltered regex scan, or asserted `count_occurrences(body, ~s(type="application/ld+json")) == 1`. Adding the site-wide `LocalBusiness` block to every page (including the detail page) made these assumptions false by design — the detail page now carries two scripts.
- **Fix:** Added a `game_json_ld_match/1` test helper that filters the scan for the `@type == "Game"` payload specifically, and updated the two count assertions to expect `2`.
- **Files modified:** `test/pukllay_club_web/plugs/game_seo_test.exs`
- **Verification:** `mix test test/pukllay_club_web/plugs/game_seo_test.exs test/pukllay_club_web/live/catalog_live_test.exs` — 145 tests, 0 failures.
- **Committed in:** `4a3c2b6`

**2. [Rule 1 - Bug] Two pre-existing byte-identical-markup assertions broke because they didn't normalize the new per-request JSON-LD nonce**
- **Found during:** Task 1, running the full `test/pukllay_club_web/` suite as an additional regression check beyond the plan's own listed commands
- **Issue:** `about_live_test.exs` (`/club` vs `/quienes-somos`) and `about_header_morph_test.exs` (`/quienes-somos#contacto` vs `/quienes-somos`) each assert two separately-rendered pages produce byte-identical HTML once a small set of per-connection fields (CSRF token, `phx-session`, `phx-static`, root element id) are normalized to a placeholder. The new `LocalBusiness` script now renders on both routes with a genuinely different CSP nonce per request, which these normalizers didn't know about.
- **Fix:** Extended both files' `normalize` helper with one more rule: `nonce="[^"]*"` → `nonce="X"` — normalizing only the nonce attribute value, never the JSON-LD payload content itself, so the assertions still catch a genuine content divergence.
- **Files modified:** `test/pukllay_club_web/live/about_live_test.exs`, `test/pukllay_club_web/about_header_morph_test.exs`
- **Verification:** `mix test test/pukllay_club_web/` — 826 tests, 0 failures.
- **Committed in:** `4a3c2b6`

**3. [Rule 1 - Bug] `og:image` meta tag's attribute order isn't fixed (`property=`/`content=`) — an exact-order regex silently matched nothing**
- **Found during:** Task 3, first run of the new served-response gate
- **Issue:** The plan's action described "fetching the asset at the path the Open Graph tags emit." A naive regex anchored on `<meta property="og:image" content="..."` matched zero occurrences — the actually-rendered markup interposes LiveView's `phx-r` debug/tracking attribute between the tag name and `property=` (`<meta phx-r property="og:image" content="...">`), which a fixed-order pattern doesn't anticipate.
- **Fix:** Rewrote the extraction regex to be attribute-order-agnostic (`<meta[^>]*\bproperty="og:image"[^>]*\bcontent="([^"]+)"`), matching regardless of what other attributes the tag carries or in what order.
- **Files modified:** `test/pukllay_club_web/structured_data_test.exs`
- **Verification:** `mix test test/pukllay_club_web/structured_data_test.exs` — 7 tests, 0 failures.
- **Committed in:** `42c6dfb`

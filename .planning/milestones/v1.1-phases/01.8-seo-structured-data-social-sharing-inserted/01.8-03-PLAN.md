<objective>
Serve a live, database-generated `sitemap.xml` and replace the unmodified Phoenix `robots.txt` stub
with real content that permits crawling and points at it.

Purpose: these are the two discovery primitives Google needs before any of the phase's other work
can be found. PITFALLS Pitfall 4 is explicit that a build-time or cached sitemap goes stale the
moment the catalog changes and that fabricated `priority`/`changefreq` values are noise — and this
app's Kamal build has no database access, so a compile-time sitemap could not be correct even once.

Output: `Catalog.sitemap_entries/0`, `SitemapController`, a dedicated router pipeline and route,
real `robots.txt` content, and two new controller test files.

Sequencing note: the ROADMAP places this work as independent of the CSP/`GameSEO` chain and
parallelisable with it. It is assigned to wave 2 purely because it edits `lib/pukllay_club_web/router.ex`,
which plan 01 also edits — a file-level conflict, not a logical dependency.
</objective>

    game id and `updated_at` — with an explicit `order_by` on `id`, so the entry order is a property
    of the query rather than of Postgres' physical row order. The ordering is what makes the
    byte-identical-across-requests behaviour above assertable at all. There is no visibility or
    soft-delete column on this schema today (RESEARCH.md confirmed this by direct read), so the
    query selects every row; say so in the `@doc` rather than leaving a future reader to infer that
    the absence of a filter was deliberate.

    machine-read XML document), and a single action ending in `put_resp_content_type/2` plus
    `send_resp/3`. Use an XML content type rather than the plain-text one the health endpoint uses.

    Build the document body by explicit string construction with an escape function applied to every
    interpolated value. RESEARCH.md's Don't Hand-Roll table permits exactly this shape — a plain
    builder that explicitly escapes — as an alternative to a template, and rejects only unescaped
    `Enum.join`/interpolation. Apply the escape even though the only interpolated values are derived
    from integer ids and dates and therefore cannot currently contain markup-significant characters:
    the escape is what stops that from becoming a latent hole if a future phase adds a slug segment.

    Handle `updated_at`'s struct type without guessing. RESEARCH.md Pitfall C records that
    `timestamps()` is called bare in both the schema and its migration, and that `config.exs`'s
    `generators: [timestamp_type: :utc_datetime]` key only affects newly generated files and does not
    retroactively change an already-written bare call — so the loaded Elixir struct type is not
    determinable from source alone. The sitemap protocol accepts a date-only `lastmod`, and `to_date/1`
    is defined on both candidate struct types, so format through a small private helper with a clause
    for each type rather than calling a type-specific ISO-8601 function directly. That sidesteps the
    ambiguity instead of betting on it; a wrong bet raises a `FunctionClauseError` at request time on
    a public URL.

    Emit no `priority` and no `changefreq` elements. PITFALLS Pitfall 4 is explicit that invented
    values for these are noise a crawler discounts, and this catalog has no real signal to base them on.

    Build the absolute `loc` values through the app's own URL helpers — the catalog index and the
    `/juegos/:id` detail route — rather than by concatenating a host literal, for the same reason
    plan 01 reuses `share_control/1`'s construction: a second URL-building site can silently
    disagree with the first.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| crawler → `/sitemap.xml` | An unauthenticated, uncached public endpoint that runs a full-table query on every request |
| `games` table → XML document body | Row-derived values are interpolated into a machine-parsed XML document |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01.8-09 | Tampering | Sitemap XML construction | high | mitigate | Apply an explicit XML-escape function to every interpolated value, even though the current inputs are integer-derived, so a future slug segment cannot open the hole silently. Assert escaping in the controller test. |
| T-01.8-10 | Denial of service | `/sitemap.xml` full-table query per request | medium | accept | The catalog is ~434 rows and the query selects two narrow columns with an indexed order; on a 1 GB e2-micro this is well inside budget. Caching would reintroduce exactly the staleness PITFALLS Pitfall 4 warns about. Revisit only if the catalog grows an order of magnitude. |
| T-01.8-11 | Information disclosure | Sitemap row selection | medium | mitigate | The `games` schema carries no visibility, draft or soft-delete column today (verified by direct read), so every row is already publicly reachable at `/juegos/:id` and the sitemap discloses nothing new. Record that fact in `sitemap_entries/0`'s `@doc` so a future phase adding such a column sees that this query must gain a filter at the same time. |
| T-01.8-12 | Tampering | `robots.txt` content | medium | mitigate | Remove the stub's commented-out ban directives entirely rather than leaving them as comments, closing the uncomment-by-accident path; gate with a comment-filtered check so comment prose can never satisfy or defeat the assertion. |
</threat_model>

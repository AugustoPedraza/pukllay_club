## Phase Goal (this gap slice)

**As a** club staff member adding games from my phone, **I want to** be told when a BGG id is
already in the ludoteca and explicitly confirm that I'm adding another edition, **so that** real
editions like Patchwork and Patchwork Andino can live side by side while an accidental double-tap
never creates a duplicate draft.

<objective>
Close verification gap 2b (CR-B-01) under the binding user decision of 2026-09-14 that revises D-03
from "always reject a second game with the same BGG id" to "warn, then allow as an edition".

Purpose: games that share a BGG id are legitimate editions. BGG 163412 already has "Patchwork"
(id 295) and "Patchwork Andino" (id 296) in production. That rules out a unique or partial-unique
index on `games.bgg_id` (REVIEW.md's drafted fix is REJECTED): it would reject real editions and
fail the production migration. Duplicate protection must come from elsewhere:
(1) `Catalog.add_game_from_bgg/2` runs the existing-games check and the insert under a per-BGG-id
`pg_advisory_xact_lock` inside one transaction;
(2) it inserts only when every game currently holding that BGG id was explicitly acknowledged by
the caller;
(3) `phx-disable-with` goes on both submit buttons (IN-B-02).

Found while planning: today's unguarded single-row lookup raises `Ecto.MultipleResultsError` for
BGG 163412, because two rows already share it. Pasting 163412 into production's admin would crash
the LiveView. The new multi-row read fixes this, and a regression test covers it.

Output: revised add-game contract + edition prompt UI, real-concurrency regression tests, and D-03
restated in every doc that carries it.

Ordering note: plan 14 (production rollout) is paused at its Task 2 human merge. This plan
(wave 8) must land before plan 14 resumes (wave 9). See `<output>` for the PR #63 handoff.
</objective>

manage the ludoteca, record where each physical game lives, curate the home page's sections, and fix
mis-banded games, **so that** Saturday operations run smoothly and the home page stays alive.

(user-confirmed per D-36), wire its Swoosh adapter and secret end to end, and get the domain's
SPF/DKIM/DMARC in place. The "a real email lands in Gmail" proof itself runs in plan 14 once the
whole phase is deployed.

receive a link. The provider choice is a genuine external-service decision the user has not yet
made (CONTEXT: "researcher compares, user confirms"), so it is gated.

`MAILER_API_KEY`, secret plumbing through the deploy workflow and `deploy.yml`, a single sender
config key, and verified DNS records.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → email provider API | Outbound HTTPS carrying a bearer API key and magic-link tokens inside email bodies |
| GitHub secrets → Kamal → container env | The API key crosses CI and the deploy host |
| DNS → recipient mail servers | SPF/DKIM/DMARC decide whether a spoofed "pukllay.club" email is accepted |

# Phase 01.8.1 Plan 06: Staff Add-Game by BGG ID with Async Oban Enrichment Summary

**`Catalog.add_game_from_bgg/1` inserts a draft and an Oban job atomically; `Workers.EnrichGameWorker` fetches BGG facts, uploads R2 images, letterboxes a 1200x630 OG card, and Gemini-translates the description, broadcasting the finished row live over PubSub.**

## Performance

- **Duration:** ~50 min
- **Started:** ~2026-09-14T11:16:00Z (approx.)
- **Completed:** 2026-09-14T12:06:23Z
- **Tasks:** 2 (1 tracer, 1 auto/tdd)
- **Files modified:** 15 (6 created, 9 modified)

## Accomplishments

- Oban 2.24 wired in for the first time: `config :pukllay_club, Oban` (queue `enrichment: 1`, `Oban.Plugins.Pruner`), an `oban_jobs` migration pinned to the installed dep's version 14, and an `Oban` child in `PukllayClub.Application` right after `PukllayClub.Repo`.
- `games.csv_row` made nullable (D-09) so admin-added games — which have no CSV history — can coexist with the ~434 historically-imported rows; the unique index is untouched (Postgres treats NULLs as distinct).
- `Game.draft_changeset/2` (casts only `:bgg_id`, sets `status: :draft`, `enrichment_status: "pending"`, `name: "Juego #<bgg_id>"`) and `Game.enrichment_changeset/2` (casts every BGG-derived column plus `:name`/`:description` under the caller's club-owned-value rules).
- `Catalog.add_game_from_bgg/1`: digits-only input parsing, then an `Ecto.Multi` inserting the draft and `Oban.insert/3`-ing the `EnrichGameWorker` job in one transaction.
- `Catalog.Enrichment.attrs_from_bgg_item/1` + `enrich/2`: fetches via `BggClient.fetch_batch/2`, downloads/uploads the cover via `ImagePipeline.select_cover/1` + `process/3` (an image failure returns `{:error, {:image, reason}}` before anything is persisted — no partial-field writes), generates and uploads the OG card via `ImagePipeline.og_card/1` + `Storage.impl().put/4` only after the row update succeeds with a cover, and translates a blank description to Spanish via `DescriptionTranslator.translate/3` (keeping the cleaned English text on any translator failure or missing Gemini key).
- `Workers.EnrichGameWorker` (`queue: :enrichment`, `max_attempts: 3`, unique per `game_id` across incomplete states) resolves credentials, calls `Enrichment.enrich/2`, and broadcasts `{:game_enriched, id}` on `"admin:games"` after success.
- `Admin.GameLive.Index` gained the `Agregar juego` form (BGG ID paste, field error on invalid input), subscribes to `"admin:games"` once connected, `stream_insert/3`s the updated row on broadcast, and renders a pending draft's Nombre cell as `Juego #<bgg_id> (cargando…)` next to a flat skeleton in place of the thumbnail.

## Decisions Made

- Oban migration pinned to version 14 (installed 2.24.1 dep's current version at authoring time), never left unversioned.

- `test/pukllay_club_web/live/admin/game_live_test.exs` flipped `async: true` → `async: false` (Rule 3 — see Deviations).

## Issues Encountered

- `DescriptionTranslator.translate/3` expects its injected `:call` function to return `{:ok, %TranslatedDescription{description_es: ...}}`, not a bare `{:ok, string}` — an early test stub returning a bare string was silently classified as a malformed response (`{:error, :empty_translation}`) rather than failing loudly, since that's `DescriptionTranslator`'s own designed fail-safe for a shape-mismatched LLM response. Caught by the first test run; fixed by wrapping every stub in the real response struct, matching `description_translator_test.exs`'s own established pattern.
- `Req`'s default retry-on-5xx behavior (unrelated to this plan, inherited from `ImagePipeline`/`BggClient`'s shared `Req.get/2` usage) adds a real multi-second backoff delay to the two tests that stub a `500`/`429` response — consistent with the same behavior already present in `bgg_client_test.exs` and `og_card_backfill_test.exs`; not a flake, just an inherent ~3-7s cost paid twice in this plan's suite.

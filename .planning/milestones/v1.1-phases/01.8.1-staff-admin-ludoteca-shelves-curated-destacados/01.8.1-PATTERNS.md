### `lib/pukllay_club/catalog/game.ex` (model, CRUD) — adding `status`/`shelf_id`/`band_reviewed_*`

**Analog:** itself, `lib/pukllay_club/catalog/game.ex:1-60` (current schema + `is_expansion` precedent)

**Existing field + comment convention** (lines 24-35):
```elixir
# Real, queryable expansion/promo flag (G-01-5) — derived at seed time
# by `PukllayClub.Catalog.Seed.ExpansionClassifier` and backfilled for
# pre-existing rows by the `add_games_is_expansion` migration. See that
# module's moduledoc for the marker + reviewed-override rules.
field :is_expansion, :boolean, default: false
```
Follow this exact shape for `status` (`Ecto.Enum` per RESEARCH A3, default `"published"`),
`shelf_id` (`belongs_to :shelf, PukllayClub.Catalog.Shelf`), and `band_reviewed_band`/
`band_reviewed_at` (A4's "implied band at time of review" snapshot, not a bare boolean).

**Changeset convention:** `seed_changeset/2` casts every seed-owned column and requires only
`:name`/`:csv_row`. The new admin-owned fields need a **separate** changeset function (e.g.
`admin_changeset/2`) that casts only D-07's club-owned fields — do not extend `seed_changeset/2`,
since D-09 retires the seed path entirely and a shared changeset would blur which fields the
admin vs. the (retired) seed pipeline may touch.

### `priv/repo/migrations/*_add_status_to_games.exs` (migration, batch)

**Analog:** `priv/repo/migrations/20260818222551_add_games_is_expansion.exs` (full file read above)

**Core pattern — column + inline backfill in one migration:**
```elixir
def change do
  alter table(:games) do
    add :is_expansion, :boolean, null: false, default: false
  end

  execute(
    """
    UPDATE games SET is_expansion = true
    WHERE name ILIKE '%(expa%' OR ...
    """,
    "UPDATE games SET is_expansion = false"
  )
end
```
Apply verbatim for `status`: `add :status, :string, null: false, default: "published"` — the
**column-level default already correctly backfills all ~434 existing rows** without a separate
`execute/2` UPDATE (RESEARCH Pitfall 1). Write the moduledoc explaining *why* the default is
`"published"` and not `"draft"`, mirroring this file's own moduledoc explanation style. Apply the
same file's pattern again, separately, for the D-22 `games.tags` → `sections`/`section_games`
backfill (a real `execute/2` UPDATE this time, since that data transform isn't a simple default).

### `lib/pukllay_club/catalog.ex` (service/context, CRUD) — status filtering + section queries

**Analog:** itself — `base_filtered_query/2` (lines ~460+), `carousel_row_specs/0`/`row_query/1`
(lines 409-459, quoted in full above)

**Status-filter core pattern** (extend `base_filtered_query/2`'s existing pipe chain shape):
```elixir
defp base_filtered_query(query, opts) do
  query
  |> maybe_search(Map.get(opts, :q))
  |> maybe_filter_mechanics(Map.get(opts, :mechanics))
  # ... existing maybe_* predicates ...
end
```
Add a **non-optional** `where(g.status == "published")` as the first clause in this pipeline
(not a `maybe_*`, since it's never conditional) — this is the single shared surface RESEARCH
Pitfall 2 identifies as covering `filter_games/1` AND `count_games/1` (which calls
`base_filtered_query/2` too) in one place.

**`get_game!/1` vs `get_published_game!/1` split** (RESEARCH Pitfall 2's recommended fix,
directly informed by this codebase's own `sitemap_entries/0` moduledoc warning at
`lib/pukllay_club/catalog.ex:188-200`): keep `get_game!/1` unfiltered for admin edit (needs to
open a draft), add a new `get_published_game!/1` with the status filter for
`CatalogLive.Show`/`GameSEO`/sitemap.

**Section-row dispatch replaces `row_query/1`'s literal-string clauses:**
```elixir
defp row_query("descubre_el_hobby"), do: weight_band_query("descubre_el_hobby")
defp row_query("recientemente_anadidos"), do: recent_query()
defp row_query(_unrecognized), do: nil
```
Keep this exact **literal-string clause + catch-all** shape (T-01-37 — never `String.to_atom` a
client-sent key) but change the source of the row list from `carousel_row_specs/0`'s hardcoded
list to a DB query over `sections` ordered by `position`; the 3 weight-band rows and
`recientemente_anadidos` keep their exact existing `row_query/1` bodies as automatic sections
(D-20/D-21) — only the 3 hashtag rows and `destacados_del_club` are replaced by DB-driven
membership (`section_games` join, manual `position` order per D-19).

**Tiebreaker convention to preserve** (from the same block, `tags_query/1`/`weight_band_query/1`):
```elixir
order_by: [asc: g.name, asc: g.id]
```
Every new section membership query (manual or automatic) must add an `:id` (or equivalent stable)
tiebreaker after its primary sort key, for the same reason documented inline here — otherwise
`fetch_row_page/3`'s paginator can duplicate/skip a row across pages.

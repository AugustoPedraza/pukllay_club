## Phase Goal

**As a** club staff member (the owner or one of up to 3 invited staff), **I want to** sign in and
manage the ludoteca, record where each physical game lives, curate the home page's sections, and fix
mis-banded games, **so that** Saturday operations run smoothly and the home page stays alive.

<objective>
Let staff add a new acquisition by BGG ID: a draft appears instantly, and a background job pulls
BGG facts, uploads images to R2, builds the OG card and translates the description.

Purpose: the "add" half of SC-2 (D-01, D-02, D-05, D-06). This introduces the app's first
background job runner (Oban — approved in RESEARCH's Package Legitimacy Audit) and runs the
formerly developer-only enrichment modules inside production for the first time.

Reversibility: D-02 is recorded `costly` in CONTEXT (BGG/R2/Gemini credentials move onto the
production host, reversing 01.7 D-04). That credential plumbing is plan 08's task and is flagged
there; this plan only runs the pipeline under test credentials.

Output: Oban dependency, config and table; nullable `csv_row`; `Game.draft_changeset/2` and
`enrichment_changeset/2`; `Catalog.add_game_from_bgg/1`; `Catalog.Enrichment`;
`Workers.EnrichGameWorker`; the `Agregar juego` form with a live-updating loading row.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff input → BGG id | Pasted text becomes an outbound request parameter |
| BGG XML/image bytes → app | Untrusted third-party content is parsed, decoded and re-encoded |
| Oban worker → R2 / Gemini | Production write credentials used by a background process |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01.8.1-27 | Injection | BGG id input | medium | mitigate | `add_game_from_bgg/1` accepts digits only and casts to a positive integer before `BggClient.fetch_batch/2` (which expects `[integer()]`); plan 08 adds URL extraction under the same rule. |
| T-01.8.1-28 | Tampering | BGG image download (SSRF / hostile image) | medium | mitigate | Reuse `ImagePipeline.process/3` unchanged — it validates the source URL against its allowed BGG hosts before downloading; re-encoding through libvips normalizes the bytes. |
| T-01.8.1-29 | Denial of service | Image processing on a 1 GB host | medium | mitigate | `enrichment` queue concurrency 1; jobs unique per game_id; max_attempts 3. |
| T-01.8.1-30 | Tampering | Re-enrichment overwriting staff edits | medium | mitigate | Name only replaces the placeholder; description only fills when empty; tested. |
| T-01.8.1-31 | Information disclosure | Credentials in job errors/logs | medium | mitigate | Missing credentials surface as env-var names only; never log the Credentials struct except via `Credentials.redacted/1`. |
| T-01.8.1-SC | Tampering | `oban` hex install | low | accept | Approved in RESEARCH Package Legitimacy Audit (oban-bg org, same package vetted in CLAUDE.md stack research); hex is outside the npm/pip/cargo gate; `mix deps.audit` covers advisories. |
</threat_model>

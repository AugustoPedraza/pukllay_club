## Phase Goal

**As a** club staff member (the owner or one of up to 3 invited staff), **I want to** sign in and
manage the ludoteca, record where each physical game lives, curate the home page's sections, and fix
mis-banded games, **so that** Saturday operations run smoothly and the home page stays alive.

<objective>
Introduce the draft / published / retired lifecycle on `games` and make every public read path
honour it, without unpublishing a single live game on deploy.

Purpose: D-04 (drafts never public) and D-08 (retire = restorable soft delete) both require a
status column that every public query filters on. RESEARCH Pitfall 1 (a wrong default empties
the live catalog) and Pitfall 2 (a missed read path leaks a draft) are the two highest-risk
mechanical steps of the phase, so they land first, in parallel with the auth tracer — nothing in
this plan touches auth files.

Reversibility: D-08 records this as one-way. The column itself was accepted in CONTEXT.md, so the
checkpoint below does not re-litigate it — it confirms the migration shape against the live
catalog and settles the one open sub-choice D-08 delegated (what a retired game's old URL shows)
before the agent walks through the door. The post-deploy "catalog count unchanged" proof is plan
14's job.

Output: the status migration, `Game.status`, `Catalog.get_published_game!/1`, the three status
transitions, and published-only filtering on grid, count, carousel rows, similar games and sitemap.
</objective>
